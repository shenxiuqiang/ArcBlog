## 0. 方案一句话

**平台的「外观」是唯一真源；桥（`.web/components/theme-bridge/`）是唯一的适配器；AUP 面不再有任何"我们自己的外观设置"。**

```
控制台 Appearance（~/.afs-data/auth.db: cs_settings.app:theme）
  ├─ 公开实时面：/theme/init.js（prefer）      ┐
  ├─ 公开实时面：/theme/styles.css（bg/text）  ├─→ 匿名访客（永远最新）
  ├─ 公开默认面：/__blocklet__.js（**不跟随**，不用）│
  └─ 登录态全量：/api/theme（完整调色板）      ─→ 登录访客（实时）
                                                  └─→ 回写公开快照 → 匿名访客（完整配色）
```

**每次导航**，桥把解析出的 `{mode, 18 个颜色 token}` 写到宿主 `<html>`；**tone 不参与**（平台没有 tone 概念，保持 `app.aup` 的 `editorial`）。

## 1. 为什么是这个形状（全部实测）

### 1.1 平台主题的通道矩阵

| 通道 | 内容 | 匿名 | 跟随控制台 |
| --- | --- | :-: | :-: |
| `/.well-known/service/theme/init.js` | `var p = '<prefer>'` | ✅ | **✅ 实时**（控制台 05:22:20 改 `prefer=dark` → 05:27 实测 `p='dark'`；`my-app` 仍 `'system'`） |
| `/.well-known/service/theme/styles.css` | `--blocklet-background-default-color` = `background.default`、`--blocklet-text-primary-color` = `text.primary`（light + `[data-theme=dark]`） | ✅ | **✅ 实时**（arcblog `#ffffff/#212121`、dark `#000000/#ffffff` = 存的主题；`my-app` `#fff/#18181b`、dark `#121212/#ffffff` = MUI 默认） |
| `/.well-known/service/login`（服务端渲染） | `appName`（=`app:branding.name`）、`appLogo`、`theme`（=prefer） | ✅ | **✅ 实时**（`"appName":"MyBlog"`、`"theme":"dark"`） |
| `/__blocklet__.js` → `window.blocklet.theme` | 完整 MUI 主题 | ✅ | **❌【实测】** arcblog 与 `my-app` 逐字段同款（`name:"Default"`、`primary:"#00bba7"`、`prefer:"system"`），而 arcblog 存的是 `#1976d2`/`dark` ⇒ 这是**平台默认主题** |
| `/api/theme`、`/api/branding` | 控制台编辑的那份（完整调色板） | ❌ 401 | ✅（登录态） |
| `~/.afs-data/auth.db` → `cs_settings` | 真源（控制台写这里） | ❌ | ✅ |

**推论（方案基石）**：完整调色板**只对登录态公开**；匿名面公开且实时的只有 `prefer` + `background` + `text`。所以匿名读者要拿到完整配色，只有"登录态抓取 → 写成 guest 可读快照"这条路 —— 而这条路的载体**已经存在**（`/instance/app/arcblog/node/appearance.json` + 桥的登录态回写，即今天的 `DEF-48` 机制）。本轮**只换源**，不新增架构。

### 1.2 AUP 面的"上色面"是封闭且可枚举的

```bash
python3 - <<'PY'   # 完整脚本见 §6
# 扫 /tmp/aup-core.css，列出所有在 [data-palette=…] 块里被赋值的颜色 token
PY
```

【实测】在 `[data-palette=<palette>][data-mode=<light|dark>]` 块里被赋值的 token 共 **22 个**（8 个 palette：`neutral/warm/vivid/natural/teal/electric/purple/telegram`），其中 **4 个是纯别名**，定义在 `:root,[data-palette]`，**不需要桥去写**：

| 别名 | 等值于 |
| --- | --- |
| `--color-fg` | `var(--color-text)` |
| `--color-muted` | `var(--color-dim)` |
| `--color-text-muted` | `var(--color-dim)` |
| `--color-danger` | `var(--color-error)` |

⇒ **桥需要写的正好是 18 个**：`--color-bg --color-surface --color-border --color-text --color-dim --color-accent --color-accent-bg --color-on-accent --color-accent-secondary --color-assistant --color-assistant-bg --color-success --color-success-bg --color-error --color-warning --color-info --color-info-bg` + `--surface-muted`。

其它相关事实（【代码】）：

- `--card-bg: var(--color-surface)`（或 `var(--surface-muted)`）、`--card-border: 1px solid var(--color-border)` ⇒ **别名，自动跟随**；
- 站点自有的 `--home-ink/-rule/-accent`、`--tab` 已经是 `var(--color-text/-border/-accent, …)` 派生（`.web/themes/default/components/site-home/style.css:10-15`、`book-reader/style.css:8`）；
- `[data-tone=…]` 只给排版与阴影（`--font-* --type-* --radius-* --page-* --space-* --shadow-*`），其中**唯一的颜色是 `color-mix(… var(--color-text) …)`**（阴影跟随文字色）⇒ tone 与平台主题**不相干**，保持编译值。

## 2. 映射表（平台 MUI 调色板 → AUP token；**逐条确定**）

对 `mode ∈ {light, dark}`，取该模式的 `palette` 对象（`P`）：

| # | AUP token | 取值（`P.<…>`） | 缺失时 |
| :-: | --- | --- | --- |
| 1 | `--color-bg` | `background.default` | 不写（保留 AUP 编译值） |
| 2 | `--color-surface` | `background.paper` → 回退 `background.default` | 不写 |
| 3 | `--surface-muted` | `grey["100"]` → 回退 `background.paper` | 不写 |
| 4 | `--color-border` | `divider` | 不写 |
| 5 | `--color-text` | `text.primary` | 不写 |
| 6 | `--color-dim` | `text.secondary` | 不写 |
| 7 | `--color-accent` | `primary.main` | 不写 |
| 8 | `--color-on-accent` | `primary.contrastText` → 回退亮度规则（L>0.6 → `#111111`，否则 `#ffffff`） | 用亮度规则 |
| 9 | `--color-accent-bg` | `color-mix(in srgb, <primary.main> 8%, transparent)` | 不写 |
| 10 | `--color-accent-secondary` | `secondary.main` → 回退 `primary.main` | 不写 |
| 11 | `--color-assistant` | `primary.main` | 不写 |
| 12 | `--color-assistant-bg` | `color-mix(in srgb, <primary.main> 6%, transparent)` | 不写 |
| 13 | `--color-success` | `success.main` | 不写 |
| 14 | `--color-success-bg` | `color-mix(in srgb, <success.main> 12%, transparent)` | 不写 |
| 15 | `--color-error` | `error.main` | 不写 |
| 16 | `--color-warning` | `warning.main` | 不写 |
| 17 | `--color-info` | `info.main` | 不写 |
| 18 | `--color-info-bg` | `color-mix(in srgb, <info.main> 10%, transparent)` | 不写 |

**三条硬规则**：

1. **"不写"= 保留 AUP 编译调色板的那个 token**（不是写空、不是写默认）——所以平台没定义的颜色不会把站点弄坏；
2. 颜色一律取自 `palette` 的**当前 mode**，不跨模式借用；
3. `color-mix()` 是平台运行时自己就在用的函数（`--shadow-*` 里），且本仓只跑现代 Chrome ⇒ 可用。

**载荷形状归一化（两种都吃）**——`/api/theme` 的形状【未验证，实现第 1 步实测，但方案不依赖结论】：

```
A 形（= /__blocklet__.js 的 theme 形状）：{ light:{palette:{…}}, dark:{palette:{…}}, prefer, name }
B 形（= cs_settings.app:theme 的形状）：{ concepts:[{id,name,prefer,themeConfig:{light:{palette:{…}},dark:{palette:{…}}}}], currentConceptId }
```

`normalizeTheme(payload)`：若 `payload.light?.palette` 存在 → A 形；否则若 `payload.concepts` → 取 `concepts.find(c => c.id === currentConceptId) ?? concepts[0]`，再取其 `themeConfig`。取不到任何 `palette` ⇒ 视为"无全量"，静默降级（第 3 节）。

## 3. 解析顺序（唯一、确定）

桥在**每次 boot 与每次导航**后执行，规则如下（无分支歧义）：

| 维度 | 顺序 |
| --- | --- |
| **mode** | ① 手动覆盖 `localStorage['web-mode']`（`light`/`dark` 直接用；`auto` → 跟随系统）② 平台 `prefer`（**实时**读 `init.js`；`dark`/`light` 直接用，`system`/缺失 → 跟随系统）③ 快照的 `prefer` |
| **18 个颜色 token** | ① 登录态 `/api/theme` 归一化后的完整调色板 ② 快照的调色板（**但**用 ③ 的实时 `bg`/`text` 覆盖同名的两个）③ 公开 `styles.css` 的 `background.default`/`text.primary` ④ AUP 编译值（即"不写"） |
| **tone** | 不参与（永远是 `app.aup` 编译的 `editorial`） |

配套（沿用既有行为，不改）：

- 解析结果写进 `localStorage['arcblog:theme:v1']`（形状升级为 `{v:2, mode, tokens}`），导航时**先按缓存立即重放**（免闪）；
- 解析出的 mode **镜像进平台 `arc_mode` cookie**（下一次预绘制就不会画错）；
- 客户端缓存 60 s：boot 时若缓存新鲜则先应用、后台再拉；导航时只在缓存过期才重新拉（与平台的 `max-age=60` 对齐，不额外压服务器）。

**快照回写**：`/api/theme` 成功（即**任何登录态浏览**，包括管理员自己看站点）时，桥把归一化结果写入 `/instance/app/arcblog/node/appearance.json`（**沿用现有路径**，避免动 `blocklet.yaml`/授权/文档），形状：

```json
{ "v": 2, "prefer": "dark", "themeName": "Default",
  "palette": { "light": { "<18 个 token>": "…" }, "dark": { … } },
  "source": "/.well-known/service/api/theme", "updatedAt": "2026-10-14T…Z" }
```

读者必须容忍**旧形状**（今天的 `{tone,palette,theme,source,updatedAt}`）⇒ 无 `v:2` 即视为"无快照"，降级到 ③/④。

**语义边界（明确接受，不再作为待裁定项）**：

- 管理员改主题后**自己刷新站点即生效**（登录态走 ①），同时快照被刷新 ⇒ 此后所有匿名访客跟着变；
- 匿名访客在快照刷新前：**mode 与 bg/text 已经是最新**（公开实时通道），**其余颜色滞后到上次登录态浏览**；
- 部署**不再**触碰主题（旧步骤 2c 删除）：新实例在首次登录态浏览前，匿名访客拿到 mode + bg/text + AUP 编译调色板。

## 10. 边界升级（2026-10-14 晚，人类追问"是否与登录有关 / 能否直接查数据库"）

本方案 §3/§7 里那条"**匿名读者的完整调色板滞后到上一次登录态浏览**"**不是必须的**——它来自"只走 HTTP 端点"这个前提。实测（见 [`S11-01 §1.5`](S11-01-品牌面清点-平台branding为唯一真源.md)）：**主题就在 daemon 的 sqlite 里**（`<home>/.afs-data/auth.db` → `cs_settings.app:theme`），而 **CLI 可以直接读，完全不需要会话**：

```bash
arc service status -i default --json    # → home
node -e "const{DatabaseSync}=require('node:sqlite');console.log(new DatabaseSync(process.env.HOME+'/.afs-data/auth.db',{readOnly:true}).prepare(\"select substr(value,1,80) from cs_settings where instance_did='arcblog' and key='app:theme'\").get())"
# { 'substr(value,1,80)': '{"concepts":[{"id":"default","name":"Custom","prefer":"dark","themeConfig":{"light":{"pale' }
```

**升级后的取值链（Δ，替换 §3 的快照来源）**：

| 层 | 旧（本方案 v2.0） | 升级后 |
| --- | --- | --- |
| 完整调色板（浏览器侧） | 登录态 `fetch('/api/theme')` → 桥回写快照 | **`node scripts/arcblog-branding.mjs sync`（读 DB，会话无关）→ 写 `node/appearance.json`（v2）**；桥只读快照，**不再 fetch `/api/theme`** |
| 刷新时机 | 管理员访问站点 / 部署 | **任何 CLI 运行**（部署管线步骤 2c 恢复为 DB 版；`doctor`/手工亦可） |
| 登录依赖 | 有（读 `/api/theme`） | **无** |
| 匿名滞后 | 上次管理员访问 | 上次 CLI 运行（可随时零成本刷新） |
| 公开实时子集 | 不变 | 不变（`init.js` 的 `prefer` + `styles.css` 的 bg/text） |

**要动的点**：① 新 `scripts/lib/platform-settings.mjs`（DB 读，fail-soft）；② `arcblog-deploy.mjs` 恢复步骤 2c 但内容改为 `sync`（同时发布 `appearance.json` 与 `branding.json`）；③ 桥删掉 `PLATFORM_API` 那段 fetch（`readApi`/`publishSnapshot` 的浏览器侧职责消失）；④ `arcblog-theme.test.mjs` 的 `PLATFORM_API` 断言改为"**不得** fetch `/api/theme`"（与 `blocklet.theme` 同类禁令）；⑤ 边界 `B28` 措辞从"只对登录态公开"改为"**HTTP 端点只对登录态公开；同一台机器的 sqlite 可被本仓 CLI 只读加载（未文档化 ⇒ fail-soft + 降级链）**"。

**代价/风险不变的部分**：`auth.db` 是未文档化的内部存储（新 `B*` 边界）；只在装了实例的机器上存在（远端部署走公开通道 + manifest，快照由能读到 DB 的机器发布）；公开面仍受平台 60 s 缓存影响。
