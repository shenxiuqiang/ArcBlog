**三条元规则（引用本表时不得违反）**

1. `arc dsl validate` 绿 **≠** 节点能渲染 —— schema 对 prop 是 `additionalProperties: true`，`role`/`aria`/`variant`/`disabled` 等键**在 schema 里根本不存在**，所以「过校验 + 渲染无效果」是常态（§25.5、`S3-02:7`）。
2. **「未验证」不得升级成「不支持」**；「平台支持」也**不得**写成「本项目已实现」（实现状态以 `docs/06-功能开发列表/` 的 `FP` 号为准）。
3. 每条断言必须带**来源**；来源分三层：`§N`（平台实测）> 审查报告（独立复现）> 仓库源码行（现状事实，非平台能力）。

## 3. 降级模式库

> 六条模式与 `S1-03 §3` 的 P1–P6 **同源、编号一致**；这里只补「适用于哪些 PRD + 本轮新增的验收证据」。

### P1 · 意图队列 + 本机 worker
- **适用场景**：需要写链、需要私钥 / 大计算、耗时超过一次交互（上链、索引重建、分类/媒体迁移、策略变更、授权签发）。→ `PRD-CNT-01/05`、`PRD-ECO-01/02`、`PRD-NET-02/05`、`PRD-AGT-03`、`PRD-OPS-05`。
- **实现要点**：页面只写 `<id>.json` 意图（`${args.*}` 走**隐藏 input**，**不得**直接写 `entry.*`/`$session.*`，§29.1/§34(2)）；队列目录全树 admin-only；worker 认领写 `running`；**终态必须带非空 `message`**；状态词表只有 `pending|running|applied|rejected|noop`（§33(1)）；`<id>.json` 之外的条目显式落诊断（§33(2)）；耗时写**真实** `elapsedMs`（§36(1)）。
- **验收判据**：AFS 记录本身变化（**不是 toast**，§29.4）；`afs-list subscribe=true` 能实时看到状态；终态带原因；只读对账四分类计数自洽（§36(2)）；页面与记录的 `elapsedMs` 逐字一致。
- **已知反例**：`config/chain-intents` 仍用旧词表 `pending|running|done|failed`，**改名会触发真实链写**，故未随 D36 改名（§33(1) 范围外残留，BUG-051）。

### P2 · 诚实降级（平台破折号 + 常驻说明）
- **适用场景**：首屏可能为空、动态值无法本地化、状态无法条件渲染、平台确实不提供该信息。→ `PRD-NET-04` A2/B2、`PRD-ECO-01` B7、`PRD-ECO-06` B2、`PRD-ECO-07` B2、`PRD-ECO-08` B2、`PRD-OPS-01`、`PRD-SET-03`。
- **实现要点**：空值渲染 `—`，同卡片内一句**恒定成立**的说明（把「—」读作「尚未绑定 / 暂不可用 / 未上链」）；不做「有数据才显示」的空态卡（§37(3)、§28.8、§36(2)）；常驻说明用 `scale=caption intent=muted`（`S3-03` 摘要 4）。
- **验收判据**：说明与数据状态**不矛盾**；**不同真实状态不得被同一句话断言成同一件事**（§28.8）；报告里不出现「链上已验证」除非真的 `verified`（§36(2)）；**不得**渲染成 `0` / `Online` / 绿灯 / 自造「尚无数据」字面。
- **已知反例**：BUG-001 用互斥 `visible` 做空态 ⇒ 27 条标签**同时**渲染空态卡；BUG-005 动态 `$t()` 三次探针全败；BUG-052/056/072（无条件空态断言）。

### P3 · CLI 折叠为高级 + 可复制命令
- **适用场景**：平台能力缺位（哈希、签名、迁移、媒体引用复核、内容运维、权限自证）。→ `PRD-OPS-02`、`PRD-ECO-08` A2、`PRD-AGT-03`。
- **实现要点**：页面**不假装能点**，渲染一条可复制的完整命令；命令走中央 flag 注册表（`--k v` ≡ `--k=v`，未知 flag fail-closed，§37(1)）；危险操作要求显式确认与**到期时间**（`arcblog-agent.mjs authorize` 强制 TTL）。
- **验收判据**：命令**原样可跑**且今天真能跑通（不是「将来会」）；`--help` 存在（已知缺口：`chain-worker` 无 help 面；`rss`/`query-posts`/`daily-report` 的 `--help` 不生效，§37(1)）。
- **已知反例**：`ops/agents.aup:16` 的授权签发即此模式（页面自认「AUP DSL 没有哈希原语，请用运营者 CLI」）。

### P6 · 用目录边界取代条件筛选
- **适用场景**：需要按「状态」隔离可见性，但表达式不支持比较。→ `PRD-CNT-03`（草稿/发布隔离）、`PRD-SITE-06`（主题继续逛）。

## 摘要（给主笔，10 条以内）

1. **一句话结论**：ArcBlog 的可承诺面 = 「AUP 动态页面 + AFS 记录 + 本机 CLI/worker」；凡涉及**逐条静态 HTML、root 级 HTTP 端点、页面内哈希/时间/签名、动态筛选、按能力显隐、跨节点同步**的产品承诺，今天都写不得（第 49/50/51/52/59/60/46 行）。
2. **最大的一条边界**：AFS 查询层只对 **≤ ~1.8 KB 内联**记录可靠（精确区间 (1883, 2376] B），超限记录 `where`/`select` **静默**漏掉或返回 `{}`（§44.2①）。⇒ 筛选/计数/搜索必须由自建索引或 CLI 承担，列表只能靠**目录边界**。
3. **产品形态被链上私钥边界钉死**：私钥永不进浏览器 ⇒ 上链类操作**必然**是「意图队列 + 本机 worker」，UI 必须显示 `pending→running→applied/rejected/noop` + 终态原因 + **真实耗时**（§33、§36）。今天 `transactionHash` **恒为空**，一切「已上链」都是声明式的。
4. **界面动态性是稀缺能力**：表达式只有 `! && ||`、`visible` 只在**同步 `$session.*`** 可靠、无 capability 求值 ⇒ 权限只分「登录 / 管理员」两档，状态差异靠**目录或页面**表达，其余退化为**常驻说明**（§28.1/§54/§56）。
5. **窄屏是「未实现的设计决策」，不是平台边界**（**本轮最重要的改判**）：平台**内置**了 `≤640px` `nav-sidebar → column/100%/40vh` 断点与两级导航 API，且基础规则自带 `overflow-y:auto`（实测 375×812 `overflowY:auto`、`maxHeight:324.8px`、内部可滚）；但 21 页侧栏**全无 variant**、`.aup/` **0 条 `@media`** ⇒ 规则永不命中。**唯一前置门 = U1（DSL 是否接受 `variant`）**。
6. **公开面就是 AUP SPA**：`/.well-known`、`/api/*`、`/rss.xml` 全被 4,462 字节 AUP 壳吞掉；Web Device 无 AFS；CMS 静态烘焙不可达 ⇒ 网络层以 **AFS 资源** + `/mcp` + `/p/llms.txt` 发布，逐条静态 SEO 记为**平台受限**。
7. **§2 禁止清单 24 条**（含 4 条**已被证伪的反向断言**：F2「平台不支持 `data:` URI」、F3「propBind 冷载必然为空」、F5「平台不支持跨节点同步」、F21「侧栏会自动折叠」）。写需求时逐条自检。
8. **§3 降级模式库 6 条**与 `S1-03 §3` 同源同编号（P1 意图队列 / P2 诚实降级 / P3 CLI 折叠 / P4 fail-closed / P5 生成器投影 / P6 目录边界），每条含**适用场景 + 实现要点 + 验收判据 + 已知反例**，可直接搬进需求的验收标准。
