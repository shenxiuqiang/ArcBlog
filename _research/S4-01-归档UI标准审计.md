## 2. 失效条款清单（9 条，逐条给"为何失效 + 反例"）

1. **§7 整节（响应式）**。为何失效：AUP 面**没有媒体查询入口**，仓库也没有断点逻辑；"侧栏折叠为顶部导航""列表降级为卡片堆叠""滚动归属随断点切换"三条**均无实现**。反例：`grep -rc '@media' .aup/ --include=*.aup` 全 `0`；`scripts/console-nav.mjs` / `scripts/arcblog-console-nav.mjs` 的 `innerWidth|matchMedia|breakpoint` 计数 `0/0`（S3-02 U1:176 同结论）。**唯一合法的"窄屏重排"是 §2.2 的 CSS grid `auto-fit`**（BUG-069:74 实测四视口 `over=0`）。
2. **§8「单记录空态用 `propBind` 探针 + `visible="!${state.x}"` 条件渲染引导卡」**。为何失效：`!${…}` 恒隐藏、互斥闸门在异步数据上不成立。反例：BUG-001（27 条标签**同时**渲染空态卡，S3-02:157）；S3-02:132 实测同一份构建双向皆反。正确形态 = §4.8 的"常驻说明 + 平台破折号"。
3. **§9 与 §2.6 的原「点击去向」断言（`.pop()` + `?? 0` 兜底）**。为何失效：候选集合与"取到哪个容器"随视口变化，会**空心通过**（作者自认 BUG-011）。反例：同一探针 1803×908 → `0`（候选为空、兜底放行）、1512×765 → `1`（命中侧栏页脚）；修复后缺陷换到 `?page=appearance` 重演。判定必须只用等价断言（`candidates ≥ 1 且 total = 0`）。
4. **§5.3「等待期倒计时实时递减」**。为何失效：平台**无时间原语**，`${generate.*}`（含 `timeiso`）在所有渲染位置原样输出、bundle 里 0 命中。反例：S3-02:119、:200；改画法 = "完成条件 + 真实耗时"。
5. **附录 A.1 的 `.page-head{position:sticky}`**。为何失效：safe-style 67 键白名单**没有 `position`**（`zIndex`/`transition` 同样未列），仓库 0 处使用；且与 §2.5「禁止页头脱离内容区悬浮」直接冲突。反例：`arc-contracts §29.8:1573`；S3-02:44。正确形态 = 页头置于滚动容器**之外**的兄弟节点（/S3-02:46 引 `media.aup:137-141`）。
6. **§2.7.6 的 shell「快速目视」段**。为何失效：它是**整文件**计数，与 §2.7.2 判定的**内容列**口径不同，两套数字并列会让读者误读进度。反例：`posts.aup` 整文件 `style` ≈92 处，内容列今天只有 **6** 处（`node scripts/arcblog-ui-budget.mjs --json` → `posts.styles=6`）；UI-016 §1.2 与 §2.1 就是这两套数字并存。工具头注也明写"不得静默回退到整文件数字"（`arcblog-ui-budget.mjs:10-20`）。
7. **§2.7.2 末句「重录基线**只允许下调**」**。为何失效：合法新增必然抬升指标，机械"只许下调"会把合法工作判成回归。反例：BUG-080（R28 的 D3/D4/D5 合法新增 → `npm test` 唯一的红灯 = ratchet 7 项；`--write-baseline` 后 55/55 绿；Lead 收口明写"新增控件必须**登记**而不是静默放行"）。正确口径 = "**显式重录 + 逐页 diff 留痕**"。
8. **§2.7.1「必须先声明属于下列 5 个原型**之一**」+「禁止混装」**。为何失效：与同节末的"复合原型合法"自相矛盾，且实际已有 `P1+P5` 在用。反例：`.aup/pages/ops/hub.aup:33`（`P1 + P5`）、`.aup/pages/ops/media.aup:131`（`原型 = P1 列表 + P5 运维`）；REVIEW G5（`:95`）、S3-03 Q2（`:198`）。另：原型**落地极稀** —— `grep -rl "Prototype\|原型 =" .aup/pages/` → **3** 文件，`.aup/man/*.yaml` 有 `synopsis:` **15/27**。

## 3. 缺失条款清单（12 条：归档标准没有、新标准必须写）

1. **`emptyText` 不承载空态**。平台运行期**不求值** `$t()`，且 `emptyText=:key` 会变成"活着的死键"（lint 视为已引用）。证据：`arc-contracts §20:745`、`§28.6:1422`；S3-01:110。**存量**：`grep -rho 'emptyText=:[a-z0-9-]*' .aup/pages/ | sort -u | wc -l` → **15 个键**、S3-01 计 **18 处 / 12 页**。条款须同时给"新页禁止"与"存量登记清理"。
2. **行点击不能导航**。`afs-list` 的 `select` 事件把 entry 合并进 args，`navigate` 失效；行跳转只能用行内 `view href`。证据：S3-02:191、:216；skill `runtime-gotchas.md:36-39`；仓库唯一 `select` 用法是 `set`（`.aup/pages/site/heroes.aup:184`）。
3. **`action` 的 `style` 走更窄通道**。丢 `minHeight`/`width`/`justifyContent`/`flexShrink`/`alignSelf`，留 `padding`/`borderRadius`/`border`/`color`/`background` ⇒ **命中区只能靠 `padding` 或平台 `size` 档**，对齐必须包一层 `row cross=start`，宽度不得写死。证据：`arc-contracts §29.6:1550`、`§29.8:1573`；S3-02:74、:95。
4. **i18n 三处同名 + 跨页 key 禁令**。门禁标题 == 页头标题（逐字）== 侧栏标签（短式），改名**同批改三处**；`$t(其它页.key)` = 引用但未声明。证据：v1 期审查报告 :52（`compose-edit` 借 compose 文案，两页文本逐字相同）。**现状**：本审计脚本 → 19/21 合规、**2 页违规**（`policy` gate=`Economy`；`general` gate=`Settings`），`posts`/`hub` 用 `h2 :title` 结构性合规。
5. **分页两分支 + 稳定 id + 常驻恢复说明**。`total > pageSize` 必须有可见可点真入口（URL `<id>.page=<n>`、真切片）；`total <= pageSize` **全量渲染 + 零假入口**；`<id>` 是 URL 与 localStorage 的**公开契约**，落地后不得改名；会分页的列表必须带四要素常驻说明。证据：`arc-contracts §38:1967`、BUG-063:34-55、BUG-064（探针残留纪律）。现状 39 处 `manual` / 0 处 `auto`。
6. **版本行与单行长度纪律**（归档最严重的形态问题，见 §5 数字）。新标准须写：**版本行 ≤80 字符**（版本号 + 日期 + 一句主题）、**变更进表**（版本/日期/节/改了什么/证据/裁决人）、**正文单行 ≤800 字符**、**禁止把多轮复盘/更正塞进条款行**（更正进独立"勘误表"，正文只留当前口径）。
7. **五类事实标签在 UI 文案上的应用**。页面文案（尤其链、网络、结算、角色卡）必须区分"平台事实 / 节点自述 / 派生态 / 记录残留 / 未验证"，mock/manual **永不得**出现"链上已验证"。唯一出处 = `docs/02-产品需求/00-需求地图与规范.md:13`、`docs/02-产品需求/_提纲.md:11`（五类：`【已实现】【规划中】【平台边界】【决策待定】【未验证】`）；⚠️ **前置冲突**：`docs/01-产品概念/04-概念与术语.md:146` 标题仍写"**四类**事实标签"只列 4 条 —— 新标准引用前须先统一真源。证据：S1-03:109、:121、:144。
8. **"常驻说明"是一个可验收的承载元素**。形态固定 `p :key scale=caption intent=muted`、**无条件渲染**、**不断言为空**；四处用途：分页恢复（BUG-063）、诚实降级（BUG-052/056/072）、空态（§4.4）、队列规则（§4.10）。取值 = `var(--type-caption)` 13px + `var(--color-dim)`。S3-03 摘要第 4 条已把它列为"平台的通用补丁位"。
9. **平台破折号 `—` 是唯一空值形态**：禁页面自造"暂无数据/No data"字面、禁渲染成 `0`/`Online`/绿灯/空串。证据：（R24 口径"页面零新增字串"）；S3-03 R3 判据（`grep -rn "尚无数据\|No data" .aup/pages/` = 0）。
10. **探针 / 测试纪律**：断言不得用 `.pop()` + `?? 0` 兜底（会空心通过）；`localStorage['aup-list-pagesize:<id>']` 是**共享 profile 残留**，探针必须**每个身份、每种语言新建 context**；读数用**第二次**（`propBind` 两段式）。证据：BUG-011、BUG-064（7 个残留键）、`arc-contracts §21.11:894`。
11. **页面上**不可表达**的可访问性，标准必须"不承诺"**：无 `<h1>` 语义层级、无 `label→input` 关联、无 `aria-live`、无焦点管理；`aria` 由平台负责（`active=true` → `aria-current`；`target=_blank` → 自动补 `rel`）；页面只有 `action ariaLabel=` 与 `view role=` 两个抓手，且 `afs-list` 行模板 `role=item` 是**必需**。证据：S3-02:170、`arc-contracts §28.3:1400`、`§23:1087`。
12. **两个"页面作者会踩"的运行时陷阱**：① `afs-list` 挂载即**自动聚焦**，页面底部有空列表会把最近滚动容器滚到底 ⇒ **空列表不要放在首屏之下**（`arc-contracts §21.3:812`、`§28.2:1391`）；② `pattern=` 不能放行内 `input`（服务端拿**未替换的模板字面量**校验，静默失败却弹成功）⇒ 取值约束只能用受控 `select`（`§29.5:1528`、BUG-070 同族）。

## 4. 预算与棘轮机制复核

**七项口径是否仍可用：可用，但须补三处口径声明。** 实跑 `node scripts/arcblog-ui-budget.mjs`：22 页（21 节 + `compose-edit`）、`11/22 page(s) over budget`、`regressions vs baseline: 0`、`baseline snapshot drift (unchanged pages): 0`（exit 0）；`--strict` → `exit=1`。七项 = `blocks / cards / nested / ctrl / styles / i18n / tech`，**内容列子树**口径（按侧栏锚点 `clamp(200px, 15vw, 280px)` 括号配对剔除侧栏；`arcblog-ui-budget.mjs:116-156`）。须补声明：

- **`ctrl` 不计 `input type=hidden`**（`:278`）——与 §2.7.2 原文"`action` + `input` 合计"不一致；不写明则数字不可复现。
- **`tech` 只算"渲染出来的"技术标识**（剥掉 `from "…"` / `path="…"` / `propBind` / `exec` 的 wiring，`:291-304`）。这是**口径变更**，正因它旧基线 22 页 `tech` 全部偏高（BUG-076:30、:92）。
- **`nested` 今日全页为 0（恒不触发）**——保留为回归位，但不得当作"已达标项"计入成绩。

**基线带源码 sha 的机制今天如何工作（BUG-076/080）。** 每页快照附 `_sources[page] = sha256(源码)[:16]`（`scripts/ui-budget-baseline.json:200-223`，22 条）。三种状态各有明确出口：

| 状态 | 判定 | 出口 |
| --- | --- | --- |
| 页面源码**未变** | 记录值必须与实测**逐值相等**，否则 `DRIFT`（BUG-076：`general.tech` 记录 32 / 实测 15，且 20/22 页至少一项不符） | `exit 1`，提示 `--write-baseline` |
| 页面源码**已变** | 列为 `STALE`，**只交棘轮**（不得比基线更差），**不红**（BUG-076:132 的设计理由：避免并行 lane 互相染红） | 棘轮；若变差 → `REGRESSION` → `exit 1`（BUG-080：7 项回归 = 快层唯一红灯） |
| 指标**超阈值** | `over[]`，仅 `--strict` 时 `exit 1`；今日 11/22 页超限，故 `--strict` 不能作默认门 | `--strict` 仅作"距目标的仪表盘" |

`--write-baseline` 会打印**逐页指标 diff**（`describeSnapshotChange`，`:410-429`）且**幂等自证**（第二次输出 `(no metric changed)`）——这就是 REQ-034 H9"显式重录、禁止静默抬升"的机器化落点。**残余风险**：重录权只在 Dev/Lead 写范围，页面一改（`STALE`）就必须有人重录，否则下一次同页合法新增会被判回归（BUG-080 的成因）。

**新标准应怎么写预算条款（四段式，建议照抄结构）：**

1. **口径**：内容列子树；七项定义逐项给"算什么 / 不算什么"（含 `input type=hidden` 豁免、`tech` 的 wiring 剔除、`nested` 恒 0）；命令 = `node scripts/arcblog-ui-budget.mjs --json`。
2. **阈值**：七项上限 + 两条豁免（P3 编辑页 `ctrl ≤16`/`styles ≤12`；P2 概览 `cards ≤3`），并写明**当前尚未达标**（今天 11/22），阈值是目标而非门。
3. **门**：`npm test` 快层跑的是**棘轮**（`scripts/arcblog-ui-budget.test.mjs`，`scripts/run-tests.mjs:74` 在 FAST_TESTS），语义 = "任何页不得比基线更差 + 未变页不得漂移"；`--strict` **不作为门**直到 0 页超限（并把"阈值是否可达"列为待裁决项，而不是默认承诺）。
4. **重录流程**：口径变更与重录**必须同批**；每次重录在变更记录里贴 `--write-baseline` 的逐页 diff 与逐项归因（先例 BUG-080 Lead 收口表）；页面改动的 lane 自己负责重录其页，**禁止手改数字**（BUG-076 的 `32` 就是手改，不可复现）。

## 5. 反模式实证数字与"形态纪律"

**归档标准自身的形态问题（实测，非引述）：**

| 指标 | 实测值 | 命令 |
| --- | --- | --- |
| 版本行（第 5 行）长度 | **5813 字符** | （原归档引用已移除） |
| 全文 | 899 行 / **97,747** 字符 | `wc -l / wc -c` |
| 单行 >800 字符的行数 | **10** 行 | `awk 'length($0)>800{n++} END{print n}'` |
| 单行 >400 字符的行数 | **48** 行 | 同上（阈值 400） |
| 最长 5 行 | 5813（`:5` 版本行）、1855（`:237` §2.6 更正段）、1800（`:462` §4.3 destructive 复盘）、1318（`:681` §8 局部刷新行）、1087（`:171` §2.5 侧栏滚动段） | `awk '{print length($0)"\t"NR}' \| sort -rn \| head -5` |

**病症（三条，均由上表可证）**：① **版本行成了变更日志** —— V1.8–V1.10 把 3 轮复盘塞进一行 5813 字符，读者无法 diff、无法定位"这版到底改了什么"；② **正文行内藏着多轮历史** —— `:237`/`:462`/`:681` 三行都在"当前口径"里夹带"更正/旧测量/实施经过"，同一事实在标准内出现 2–3 个版本；③ **进度数字自我漂移** —— 同一节内容区超预算页数在标准与两份内部分析里分别是 **19/22**（UI-016 §1.2）、**13/22**（REVIEW §1 第 9 条）、**11/22**（今天实跑），且标准正文写"19/22"，无法判断谁是最新。

**新标准的形态纪律（建议直写为规范条款）：**

1. **版本行 ≤80 字符**，只写 `V<major.minor>（<日期>）`+ 一句主题；**禁止**在版本行内描述改动清单。
2. **变更进表**：独立"修订记录"表 —— `版本 | 日期 | 触及节 | 改了什么（≤1 句） | 证据（文件:行/命令） | 裁决人`。第 5 行之外不再承载历史。
3. **正文单行 ≤800 字符**（例外：```代码块```与断言块，且必须整块可复制、块内不计）；>400 字符的行应在评审时被要求拆分（今天 48 行）。
4. **禁止把多轮复盘塞进条款行**：更正/推翻写进独立"勘误表"（`条款 | 旧口径 | 新口径 | 证据 | 日期`），正文只保留**当前唯一口径**；一个条款对应一个事实。
5. **每个数字必须自带可复跑命令**，且**同一数字全体系只有一个出处**（例：页数只从 `CONSOLE_SECTIONS.length` 读、预算只从 `--json` 读；标准正文写"以命令输出为准"，不写数字）。
6. **每条可判定条款必须给"证伪方式"**（反例或断言），否则标【未验证】+ 验证方法——本次审计中 §4.5 骨架、§5.2 金额三元组、§5.1 悬停可见三条即因此无法判定。

## 摘要（给主笔，10 条以内）

1. **归档标准的"骨架层"仍然可信，整节失效的只有 §7**：§2.1/§2.5/§2.6/§3/§4.6–§4.10/§5.5 今天全部成立；§7（响应式）三条承诺**无一条有实现**（`.aup` 面 `@media` 计数 0、无断点逻辑），必须删除重写。

5. **预算与棘轮机制健康但口径缺声明**：七项可跑（今天 11/22 超限、`drift 0`、`regressions 0`、`--strict exit 1`）；须写明 `ctrl` 不计 hidden input、`tech` 只算渲染文本、`nested` 恒 0。
6. **基线 `_sources` sha 机制今天工作正常且已闭环两次**：未变页漂移 = 红（BUG-076）、已变页交棘轮 = 不红但拦退化（BUG-080）；"基线只许下调"应改写为"**显式重录 + 逐页 diff 归因**"。

10. **可直接搬运的只有"纪律"与"工具口径"，条款表述几乎都要重写**：保留 §1/§2.1/§2.5/§2.6/§3/§4.6–§4.10/§5.5/§10 与 A.4；删除 §7、原断言、A.1 的 sticky；改写 §2.7（原型机检化、预算四段式）、§4.5、§5.1/§5.3、§6、§8、§9、A.3。
