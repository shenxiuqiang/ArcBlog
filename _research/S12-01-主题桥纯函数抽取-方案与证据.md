## 1. 问题

主题桥的纯映射（`TOKEN_ALIASES` / `mapPlatformPalette` / `normalizePlatformTheme` / `parseServiceTheme` / `parseServicePrefer`）与 IIFE 运行时逻辑混在 `.web/components/theme-bridge/script.js` 里，测试只能**正则匹配源码文本**：

- 改注释或换行就能让门变红（假阳性）；
- 测不出 shape A / shape B 两个平台载荷分支的**真实输出**；
- 22 = 18 + 4 的完备性靠"从函数体里抓 `'--xxx'` 字面量"，而不是"跑一遍看写到哪些 token"。

## 2. 做法（保住 DEF-47 契约）

| 步 | 内容 |
| --- | --- |
| ① | 新增 `.web/components/theme-bridge/theme-map.js`：**无 ESM 语法、无 DOM/AFS/fetch、加载无副作用**的纯片段（137 行），是这 5 个符号的**唯一来源** |
| ② | `script.js` 删掉这些声明，只留一行指向注释（IIFE 通过同一内联 `<script>` 的外层作用域闭包取用） |
| ③ | `scripts/arcblog-theme-bridge.mjs` 改为按 **theme-map.js → script.js → style.css** 拼接进 `render.js`（DEF-47 不变：内联 shell 仍是唯一交付通道，render 沙箱仍不读文件） |
| ④ | `scripts/arcblog-theme.test.mjs`：新增 `loadThemeMap()`（把片段求值成函数），把纯映射断言改成**行为断言**；契约类断言（禁用 `/api/theme|/api/branding`、禁用 `blocklet.theme/appName`、快照 v2/v1、render.js 与源同步）保留并加强，另加"单一来源"守卫（`script.js` 不得重复定义 + 片段必须无 ESM/DOM/AFS + `render.js` 必须含内联） |

## 3. 行为测试立刻抓到的一个真不一致

`mapPlatformPalette({})` 以前仍会写 `--color-on-accent: #ffffff` —— 因为 `contrastOn(null)` 会给出白色兜底。这违反片段自己成文的第一条规则"**源缺失即不写**（交给编译好的 AUP 调色板）"，18 个 token 里有 17 个守规矩、只有它例外。已修：`at(P,'primary.contrastText') || (primary ? contrastOn(primary) : null)`，并在测试里钉住 `mapPlatformPalette({}) === {}`。**文本匹配测试永远看不到这个**。

## 4. 验证

```bash
node --check .web/components/theme-bridge/theme-map.js      # 片段可独立解析
node scripts/arcblog-theme-bridge.mjs                        # 重新生成 render.js（含片段）
node scripts/arcblog-theme-bridge.mjs --check                # 同步（fast tier 的同一守卫）
node --test scripts/arcblog-theme.test.mjs                   # 12/12 通过（原 10）
npm test                                                     # 32 套件全绿
npm run build && npm run gate:docs                           # 绿 / 6-6
```

行为断言覆盖：18 个真 token 全写、4 个别名不写、22 完备、空/`null` 调色板不写、`contrastText` 缺失时按亮度判定（`#ffffff`→`#111111`）、shape A/B 两种载荷都归一化出 18 个 token、`parseServicePrefer` 三个样本、`parseServiceTheme` 用**平台真实字节**（`:root`/`[data-theme='dark']` + `--blocklet-*-color`）。
