### 2.3 为什么不全量跑 live
- 成本：~21 min（R7 实测 1236 s）**大于**它检查的实现量；用户裁定 2026-09-27 起不作常规门（`CLAUDE.md` Quality gates）。
- 非幂等：全部写**同一个** `default` 实例；ledger append-only，残渣永久累积（曾有 805 条；`runbook` Development instance hygiene）。
- 并行即污染：live 强制串行 `concurrency 1`（测试头注 `run-tests.mjs:34-38`：并行时 doctor 约 1/3 概率读到别人半写状态）。
- 替代：改动触及 CLI / AFS 记录 / 链适配器 / daemon 路由 → **定向单文件**（`npm run test:file`）。

### 2.4 `test:file` 的串行纪律（`.gate-lock`）
- 三条硬规则（§6.1）：① 同一时刻只允许一个进程用实例；② 跑写实例测试者**先**在 `docs/team/.gate-lock` 写 `owner + 开始时间`，跑完删除；③ 见锁存在就等，不并行。
- 快层 `npm test` **不受锁限制**（不写实例）。
- 部署脚本会检测锁并告警：`if (existsSync(join(repoRoot,'docs','team','.gate-lock')))`（`arcblog-deploy.mjs:100-102`）。
- **坑（实测）**：持锁期间跑 `arc blocklet build` 会把锁文件镜像进 `dist/docs/team/.gate-lock`，提交前必须删该镜像（`arc-contracts §36(5)`；本轮实测**当前 `dist/` 无该镜像**）。

### 2.5 判断「真红 / 假红」
1. **单跑失败文件**（`npm run test:file -- scripts/<f>.test.mjs`）：绿 = 并发污染（假红）；红 = 真 bug。
2. 看 runner 报告类型：`TIMEOUT`（`run-tests.mjs:302-307`，`SIGKILL` 后**后续文件未启动**）与 `BUDGET`（`:309-315`）都不是代码失败，调 `ARCBLOG_TEST_TIMEOUT_MS` / `ARCBLOG_TEST_BUDGET_MS` 或拆分。
3. live 失败时**保留残渣**（`:322`）供检视；`ARCBLOG_NO_CLEAN=1` 可主动保留，`ARCBLOG_CLEAN_DRY_RUN=1` 只报告不删（`:336-360`）。
4. 快层用 `--changed` 时，**未登记 GUARDS 的套件永远被选中**（`:137-144`）——「没跑」不等于「没覆盖」，不要在快层用假绿替代全量。

## 3. 构建与部署链路

```
.aup/**.aup + world/*.yaml + blocklet.yaml
   │ arc dsl generate --write（默认 dry-run，写 app.json/pages/*.json/locales）
   ▼
npm run build  ──► ① arc blocklet build（整树拷贝 → dist/ + dist/.afs/manifest.json 1183 条）
                  ② npm run scrub:dist-secrets（删 dist/node.key、dist/.env.local + 摘 manifest 条目）
   ▼
dist/  ──► arc blocklet instance deploy . --domain arcblog.localhost
   ▼
~/.arc/pages/projects/arcblog/deployments/deploy-<ts>-<rand>/{files,meta.json}
```

| 步 | 失败模式 | 回退 / 处置 |
| --- | --- | --- |
| generate | 漏 `--write` → 生成物未落盘（dry-run）；页面/文案与源码不一致 | 补 `--write` 后重跑 `npm test`（侧栏/预算/主题门会报漂移） |
| `arc blocklet build` | 密钥被拷进 `dist/`（BUG-067） | **不删源文件**；`npm run scrub:dist-secrets` 后 `--check` 归零 |
| `scrub:dist-secrets` | 越界（`assertInside` 抛）/ manifest 不可解析（跳过） | 拒绝理由是保护源密钥；只允许 `<repo>/dist`（`arcblog-dist-secrets.mjs:182-201`） |
| `verify:artifacts` | `dist` 或 Pages 通道带密钥 → `exit 1` + 列出路径 | `dist`：重 scrub；Pages：只删**副本**（`rm -f ~/.arc/pages/.../files/{node.key,.env.local}`，需人工批准，L-R26-4）后重跑 |
| `instance deploy` | `blocklet is not published` / 域名冲突 | `arc blocklet list .` 查发布状态；`--dry-run` 先看 |
| 部署后校验 | ① 新部署顶层有密钥 ② Pages 通道 `--check` 红 ③ HTTP 非 200 ④ 部署页与源码**字节数不一致**（`arcblog-deploy.mjs:148-157`） | ①③④ 分别查 build 并行覆盖 / daemon 状态 / 是否有别的构建在写 `dist/` |
| 部署历史 | 每次 `deploy` **新增**一个 `deploy-*`，历史不清（现 **159** 个） | 无修剪工具；删除属用户数据，需人工批准 |

**历史事故（必写进开发文档）**：裸 `arc blocklet build` 的语义是「把 repo 整包拷成 `dist/`」，因此把仓库根的 `node.key`（Ed25519 私钥 119 B）与 `.env.local`（链助记词 499 B）**原样复制**并写进 `dist/.afs/manifest.json`；平台**没有**排除开关（`arc blocklet build --help` 只有 `--output/--dry-run/--clean`，`.blockletignore` 不认；`arc-contracts §39(1)`）。被 publish 的正是 `dist/`。**现行防护**：`package.json:14` 把 build 定成 `arc blocklet build && npm run scrub:dist-secrets`；`scripts/arcblog-dist-secrets.mjs` 只删 `dist/**`（`assertInside` 运行时断言）并随手摘 manifest 条目；快层 `arcblog-dist-secrets.test.mjs` 断言真 `dist/` 与两条通道。**铁律**：仓库根 `node.key` / `.env.local` 永不删/移/改。
**另一条通道（BUG-074）**：`arc deploy` / `arc blocklet instance deploy` 曾把**仓库根**当发布根，导致 17–40 个历史 `deploy-*/files/node.key` 带真私钥、`bundle.json` 全文内联。`scrub:dist-secrets` 管不到 Pages，所以必须**两通道都扫**（`verify:artifacts`）。本轮实测：Pages 通道现已 **0** 份密钥副本；最新 `deploy-1790677432000-u071b2/files/` 顶层与 `dist/` 顶层逐项一致（26 项）⇒ 今天实际发布的是 `dist/`（与 `arc-contracts` §43(3) 的旧描述不一致，见 §8 Q3）。

## 4. `.aup` 改动的生效路径（可复制命令序列）

```bash
# 0) 改 .aup 源码后
arc dsl validate --json          # issues 必须 []
arc dsl generate --write         # 重新生成 app.json / pages/*.json / locales
npm test                         # 快层门（含侧栏漂移 / i18n / 运行时 id / 预算）
npm run build                    # 只有走这条才会 scrub 密钥并刷新 dist/
# 1) 让 :4939（daemon 挂载的源码树）生效 —— 唯一路径
arc service restart -i default
arc blocklet run . -i default    # ← 复挂：restart 会丢掉 /blocklets/<name>
# 2) 读证明恢复（不是看退出码）
arc afs exec /blocklets/arcblog/.actions/read \
  --args '{"path":"/instance/app/arcblog/node/profile.json"}' --json
# 3) 需要 Pages 面时才部署
node scripts/arcblog-deploy.mjs
```

**不重启会看到什么假象（实测，`arc-contracts §35(5)`）**：改 `.aup` → `generate --write` → `build` → `arc blocklet run` **连跑 3 次**甚至 `touch` 源文件，运行中的 daemon 仍渲染**旧**页面（daemon 启动时 `Resolved AUP app blocklet "arcblog" via AFS` 一次就缓存了 bundle；`daemon.log` 里没有 `dev watch` 事件）。⇒「页面没变」**不能**用来判定「改动没生效」，**也不能**用来判定「已修好」——页面/文案类验收必须包含**一次重启**。
**两个「面」别混**：`:4939` 服务的是 daemon **挂载的源码树**；`instance deploy` 更新的是 **Pages 面**（同域名、历史副本）。实测部署成功后 `:4939/?page=feeds` 仍是旧文案。`arc service url` 显示哪个面，就按那个面的路径刷新。另：本实例界面语言被强制 **zh**（`?locale=en` 会被改写），英文文案只能静态核对（页面 `i18n {}` / `.aup/locales/en.json`）——不要声称「已用英文界面目视验证」。

## 5. 密钥与安全纪律

- **绝不允许**：私钥/助记词进浏览器（链按钮只写 AFS 意图，签名在 worker 里、key 留在节点；`arcblog-chain-worker.mjs` 头注）；`.aup`/页面/DSL 里出现链地址或 token symbol。
- **两条泄漏通道**：① `dist/`（BUG-067，构建期）；② `~/.arc/pages/projects/<p>/deployments/*/files/`（BUG-074，部署期，`bundle.json` 还全文内联）。**只扫 dist 不够。**
- **扫描命令**（全只读）：
  ```bash
  node scripts/arcblog-dist-secrets.mjs --check                    # dist/（缺 dist 视为失败）
  node scripts/arcblog-dist-secrets.mjs --check --pages            # Pages 通道（缺目录 = 显式 skip, rc 0）
  node scripts/arcblog-dist-secrets.mjs --check --pages --project <id>
  node scripts/arcblog-dist-secrets.mjs --check --dir <any-path>   # 任意目录，只读；scrub 请求被拒 rc 2
  npm run verify:artifacts                                         # 两条通道一条命令，rc≠0 阻断发布
  ```
  输出字段：`files`（basename 命中 `node.key`/`.env.local`）、`privateKeyFiles`（key-ish 文件名 + `-----BEGIN … PRIVATE KEY-----` 内容）、`manifestEntries`（manifest 里列出的密钥路径）。
- **提交/CI 前检查清单**：① `arc dsl validate --json` → `issues:[]`；② `npm test` 全绿（含 `dist/` 密钥门与 guest 权限矩阵）；③ 改了 `.aup` → `npm run build` 且 `verify:artifacts` 绿；④ `test -e dist/docs/team/.gate-lock` 必须**不存在**；⑤ 仓库根 `node.key`/`.env.local` 的 sha256 与 mtime 未变；⑥ 没有把 `~/.arc/pages` 的历史副本当"已清"（159 个部署目录仍在）。
- `.node-pk.pem` 是**公钥**（114 B，`-----BEGIN PUBLIC KEY-----`），会随 `dist/` 与 Pages 一起发布，不是泄漏——但它命中 `KEYISH_RE`，会被内容扫描，改动它前先确认它仍不是私钥。

## 摘要（给主笔，10 条以内）

1. **门 = 快层**：`arc dsl validate --json`（`issues:[]`）+ `npm test`（10 文件 / 静态 57 用例 / ~0.8–2 s / 不写实例），改了 `.aup` 再加 `npm run build`。三者是唯一可写进开发文档的"必跑"集合。
2. **快层不是"零依赖"**：它要求 `dist/` 存在且已 scrub（`arcblog-dist-secrets.test.mjs:46-51`）、`arc` CLI 可用、daemon `:4939` 在跑（权限矩阵走 HTTP）。缺 `dist/` 会直接红。
3. **`npm run build` 是唯一安全构建入口**：裸 `arc blocklet build` 会把仓库根 `node.key`/`.env.local` 拷进 `dist/` 并写进 manifest，平台无排除开关（BUG-067）；`build` = 裸 build + `scrub:dist-secrets`。
4. **密钥有两条通道**：`dist/`（BUG-067）与 `~/.arc/pages/.../deployments/*/files/`（BUG-074，`bundle.json` 还全文内联；历史 17–40 份真私钥）。发布前必须 `npm run verify:artifacts`（两通道一条命令）。**只扫 dist 不够。**
5. **live 层不进常规门**：22 个文件全写共享实例、串行、~21 min；改为按影响面 `npm run test:file`，且**先写 `docs/team/.gate-lock`**。真红/假红 = 单跑一次失败文件。
6. **`.aup` 生效唯一路径 = `arc service restart -i default` + `arc blocklet run . -i default`**，再以一条 `/instance` 读作证；`arc blocklet run` 不是 reload，不重启会看到"改了没变"的假象，而 `:4939` 与 Pages 是两个面。
7. **`dist/` 与 `~/.arc/pages` 是两套产物**，被部署的是 `dist/`（本轮实测最新部署顶层与 dist 逐项一致）——与 `arc-contracts §43(3)` 的旧描述冲突，需订正（Q3）。
8. **运维第一诊断动作**：读 `/blocklets/<id>` 与 daemon 日志，不要用 CLI 退出码判定激活（`required:true` + 坏挂载 ⇒ 整站不激活且 `arc blocklet run` 静默 exit 0）。
9. **工具缺口 8 条**，其中 **G4 最急**：文档声称的 `arc dsl generate --check` 漂移门在代码里不存在（grep 命中 0）——开发文档不能把"文档有门"写成"有门"。
10. **只读边界**：本报告全部结论来自静态阅读 + `arc dsl validate --json`；未跑任何 build/test/deploy/restart，因此涉及时序的量级数字均标注了出处（R7/R23/R24F 实测）而非本轮新测。
