## 1. 结论

**装 `interface-design`（`Dammyjay93/interface-design`），并且只用它的「工艺纪律」部分。**
其余五个 skill 不是不好，是**与本项目的渲染介质和治理结构不兼容**：它们的产物是 React/Tailwind 组件、
调色板或色彩系统，而我们的界面是 **AUP DSL 页面 + 平台主题色**。

```bash
npx -y skills@1.7.4 add Dammyjay93/interface-design -s interface-design -a codex --copy -y
# → .agents/skills/interface-design/SKILL.md（29,614 B）+ skills-lock.json 追加 1 条
```

选中它的五条理由（按权重）：

1. **体裁对**：它的作用域原文就是 "dashboards, admin panels, SaaS apps, tools, settings pages, data interfaces"，
   并明确排除 marketing/landing。我们 14 个控制台页（`node -e "import('./scripts/console-nav.mjs')…"` → `CONSOLE_SECTIONS.length` = 14）全部落在里面。
2. **介质无关**：它的交付物是层级、字阶比、密度值、深度策略、状态清单——这些都能译成 AUP 的
   `style={…}` 键与 `--type-*` token；它不要求 React、不要求 Tailwind、不生成组件代码。
3. **它自己的 Rule 1 是「项目已有的系统优先」**（"Use What Exists" / "If the project has a design system, use it"）。
   我们有 [`docs/04`](../docs/04-UI设计规范/00-总则与形态纪律.md) 这套**有门禁的**条款库，这条规则让我们可以
   把它的建议落进现有条款，而不是另起一套。
4. **它有可复核的收尾检查**（swap / squint / signature / token 四问），与本仓「每个断言要有证据」的口径同构。
5. **安装物只有 SKILL.md**（+ `agents/`），没有可执行二进制、没有钩子、没有自动改写 UI 文件的行为。

| **interface-design** | 无（medium-agnostic） | 探索得出，**但可被 brief 钉死** | 决策 + 数值 + 系统文件 | ✅ | ✅ | ✅（我们把"调色板=平台"写成 brief 约束） | ✅（Rule 1 让我们复用 docs/04） | **选它** |

| frontend-design（Anthropic） | HTML/CSS | 要"鲜明视觉方向" | 品牌身份、hero、字体选择 | ✅ | ✅ | ❌ 品牌面 | ⚠️ | 排除（体裁是 Persuade，我们是 Operate） |
| web-design-guidelines（Vercel） | 任意 web | 无 | **审查清单**（远端拉取规则 → `file:line` 结论） | ⚠️ AUP 不在其规则词汇里 | ✅ | ✅ | ✅ | 不作设计体系；可留作末轮 a11y 复核 |

**为什么不是 impeccable**：它对本体裁的判断其实最准（"earned familiarity"、"no orchestrated page-load"、
"none of these states, none of these components"），`references/operate.md` 已被本次拆解吸收为 §4 的纪律。
但它机械上要求跑一个**自包含二进制**（首次运行下载）、并且会在 UI 文件改动后自动跑 design detector、
还要求写 repo 根的 `PRODUCT.md`/`DESIGN.md`。本仓的规矩是「每步的命令要可复算、设计唯一出处 = `docs/04`」，
这三条都踩线。**结论：吸收其规则，不装其机械。**

**为什么不是 yafa-ui**：它的 KPI 解剖（标题在上、安静分隔线、主值、对比值）、按钮 32/36/40 高度、
6px 语义点 + 中性文字这几条，是我们真正缺的"数值"。但它把外壳写死成「白色侧栏 + 紧凑顶栏 + `#f8fafd` 画布」，
而我们的侧栏是**生成物**（`scripts/arcblog-console-nav.mjs` → 每页一份），颜色来自平台主题。照它做等于同时违 K3 与 K4。
**结论：数值可抄，体系不能照搬。**

## 3. 方向（Interface Design 的四步探索）

**Domain（产品世界里真实存在的五个概念）**：编辑部 / 排版目录（masthead、standfirst、规则线）/ 手稿夹（drafts）/ 索引卡（分类白名单）/ 账本（链上身份与 tx 记录）/ 目录器（feed）。

**Color world（这个产品物理上有什么颜色）**：纸白、墨黑、灰阶的规则线、装订黑、警告赭。
——**这正是平台 tone=editorial / palette=natural 已经编译出来的那套**（实测 `/aup-app.<hash>.css`：
`--color-bg #fafafa` · `--color-surface #ffffff` · `--color-text`(墨) · `--color-border #e4e4e7` ·
`--color-dim #71717a` · `--color-accent #18181b` · `--color-warning #a16207`）。
所以"颜色来自某个世界"这件事**不需要发明**：本仓的调色板本身就是纸墨，我们只是此前把它当成了 SaaS 灰。

**Signature（只能长在这个产品上的那一个元素）**：**规则数字带（ruled metric band）**——
数字站在细线之间，标签是字距拉开的小型大写，没有卡片边框；它和页面其余部分的"分节细线"是同一套语法。
第二处显影：异常区左侧那根 2px 赭色竖线（整页唯一的颜色）。

**Rejecting the defaults**：

| 默认（我们会顺手做出来的） | 换成 | 证据 |
| --- | --- | --- |
| 四张同构圆角卡（每张都是 `border + radius 10 + padding 14`） | **只有异常区是卡**；其余是分节细线 + 留白 | `cards` 4 → **1** |
| 到处 `gap=sm/xs`、所有说明 `intent=muted` | 三档呼吸：行内 xs / 卡内 sm / 分节 18–20；三档文字：600 标题 / 400 正文 / muted 元信息 | §4 |
| 页标题 17px（与分节标题同字号） | 刊头 21.6px/600 + 13px standfirst + 一条基线细线 | `--type-heading` |
| 侧栏每一行之间一条 1px 线（24 条/页） | 分节线（待下一轮改生成器） | 见 §7 待办 |

## 4. 落地（首个页：`?page=dashboard`）

改动只在**内容列**，侧栏与门禁卡未动（侧栏是生成物，见 §7）。

| 段 | 之前 | 之后 |
| --- | --- | --- |
| 刊头 | `h2` 17px + `purpose` + 右侧主操作，`paddingTop 14` | `padding: 4px 0 16px` + `borderBottom 1px`；标题 21.6/600/−0.012em；主操作用 `padding: 9px 14px` + `--radius-md` |
| 计数带 | 卡片（`--card-bg` + 边框 + radius 10 + padding 14），刷新按钮浮在右上，数字 `scale=display` | 无卡片：上沿 1px 线 + `paddingTop 14`；四列 `flex: 1 1 0%`；标签 12px + 字距 .07em + 大写 + dim；时间/刷新压到底部一行两端对齐 |
| 异常区 | 卡片 + `h3` + 说明 + 行内「级别 中」重复 | 分节细线 + `h3` + 一行说明；**唯一卡片**：`--card-bg` + `--card-border` + **左 2px `--color-warning`** + `0 8 8 0` 圆角；「级别」只在列头出现一次 |
| 待处理草稿 / 最近发布 | 各一张卡片 | 分节细线；标题行右侧放次操作；行内标题默认字号、元信息 `scale=sm intent=muted` |
| 内容列 | `gap=md` + `paddingTop/Bottom 14` | `gap=0` + `paddingTop/Bottom 18`，三段之间 18–20px，全部由分节线承担分隔 |

**四个自查**（skill 的 The Checks）：

- **Swap test**：把标题换成通用仪表盘标题、把数字带换成 4 张 KPI 卡 —— 页面立刻退回"卡片拼贴"。差异来自结构，不是配色。
- **Squint test**：眯眼看只剩三条横向细线 + 一个赭色左缘；层级（刊头 > 分节 > 行）仍然分得开，没有刺眼边框。
- **Signature test**：① 数字带上下细线 ② 字距拉开的大写标签 ③ 分节细线取代卡片 ④ 异常区 2px 赭色左缘 ⑤ 列头一次性「级别」。
- **Token test**：读出来的变量是 `--type-heading/--type-subheading/--type-caption/--type-small/--type-display/--color-border/--color-dim/--color-warning/--radius-md` —— 全部是平台/运行时既有 token，没有一个新名字。

## 5. 验收（实测输出，2026-10-20）

```bash
arc dsl validate --json            # → ok: true, issues: []
npm test                           # → fast tier passed — this is the gate.
node scripts/arcblog-ui-budget.mjs # → dashboard: blocks 2 / cards 1 / nested 0 / ctrl 5 / styles 22 / i18n 25 / tech 0
npm run build                      # → 安全构建（build + scrub:dist-secrets）通过
```

**预算变动必须披露**（`scripts/ui-budget-baseline.json` 已重录，工具的 diff 原文）：

```
~ dashboard: cards: 4 -> 1, styles: 10 -> 22
~ pages:     styles: 22 -> 19, i18n: 38 -> 32, tech: 3 -> 0      （收紧：原快照已过期，实际值更低）
~ general:   ctrl: 12 -> 8, styles: 34 -> 30, i18n: 88 -> 84     （收紧）
- seo / media: page no longer measured                            （页面已删，快照遗留）
```

- **`dashboard.styles` 10 → 22 是本次唯一的放宽**：换来 `cards` 4 → 1（三张卡变分节线），并新增 6 处结构线
  （刊头下沿、带顶、三段分节）+ 4 处大写标签。22 与同代页面同量级（heroes 23 / categories 22 / tags 22 / factory 22）。
- **偿还路径已定**（§7 第 3 条）：把字号/字距/大写/悬停/焦点/tabular-nums 搬到桥注入的 CSS 层，页面只管结构
  ⇒ `styles` 可回到 12 以下。**这条没做之前，不允许对第二张页做同样的内联写法。**

## 6. 复现标本（页面级视觉复核的替代物）

控制台登录态渲染是**人类检查点**（`docs/team/human-checkpoints.md` §B），headless 只能看到门禁卡。
所以本轮先用**标本**做"改前/改后"的可视判断：`tmp/ui-specimen.html`（同一套 token 值，取自服务的
`/aup-app.<hash>.css`），用仓库自带探针出图：

```bash
python3 -m http.server 8791 --bind 127.0.0.1 --directory tmp &
node scripts/arcblog-browser-probe.mjs 'http://127.0.0.1:8791/ui-specimen.html?panel=after' \
  --fresh --width 1328 --height 1000 --screenshot /tmp/after.png
# --panel=before 出改前；--width/--height/--full 是本轮给探针补的能力（默认窗口 800x600 会把宽布局裁掉）
```

⚠️ 标本**不是**实现证据；实现证据是 §5 的三条门 + 人类登录后的一次目视（§7 第 1 条）。
