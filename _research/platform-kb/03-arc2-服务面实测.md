# 03 — arc 2.0 服务面实测（本机 `arcblog.localhost:4939`）

> **环境**：`arc --version` → `2.0.0-beta.66 (54a9b40e)` ｜ 进程：`lsof -nP -iTCP:4939 -sTCP:LISTEN` → `arc-darwi`（PID 随实例变）
> ｜ 二进制：`~/.arc/current` → `~/.arc/versions/2.0.0-beta.66/`（Bun 编译单文件 `arc-darwin-arm64`，140 MB）
> **方法**：只读 HTTP + 运行时产物（`.web-cache/_arc/assets/*.js`、`~/.arc/current/assets/**`），**没有**改动实例或仓库源码。
> **等级**：本文件所有结论都标了【实测】/【代码】/【推断】/【未验证】，可逐条复跑。

## 0. 三条最值钱的结论（先看这个）

1. **会话是平台提供的，而且浏览器侧已经有一份现成契约**：`/.well-known/service/api/did/session`（匿名 `{"authenticated":false,"user":null}`）+
   `/.well-known/service/user/avatar/<did>?s=N`（**任何 DID 都 200，返回生成的 SVG 头像，不需要登录**）+
   平台运行时自动在 `<html>` 上写 `data-authenticated` / `data-role`。
   → ArcBlog 现在**没有任何地方**用这三样（`grep -rn "did/session\|user/avatar" .aup .web pages` = 0）。
2. **分享卡（OG）不是"平台做不到"，而是"看你在哪个面上"**：AUP 绑定页 `/posts/{slug}` 确实只有 `<title>AFS</title>`（与既有边界
   `B19`/`U20` 一致），但**web 面 `/p/**` 输出完整 OG/Twitter meta，并且平台自己生成 `og.png`**
   （`/.well-known/service/blocklet/og.png?template=default&title=…&description=…&locale=…` → `200 image/png`）。
   → `PRD-SITE-04` 的"降级口径"需要重判：**web 面可用**，AUP 面不可用。
3. **平台的站点配置面 `.web/site.yaml` 是本仓库完全没用的能力**：
   `locale / locales / theme{library,tone} / color-scheme / seo{description,og-image,og-site-name,title-template} /
   template{layout,header,footer,navigation,header-actions}`。58 个随 arc 分发的**官方参考 blocklet** 里都在用
   （例：`~/.arc/current/assets/blocklets/showcase-dsl/.web/site.yaml`），ArcBlog 缺它 → `arc blocklet check` 的
   `og_image_source_missing` 警告就来自这里。

## 1. 路由面：`/.well-known/service/*` 在 arc 2.0 上还剩什么

复跑：

```bash
B=http://arcblog.localhost:4939
for p in /admin /admin/team /admin/navigation /user /login /api/env /api/did/session \
         /theme/styles.css /blocklet/logo /blocklet/og.png /static/assets/index-BXK8u7uM.js ; do
  printf '%s  %s\n' "$(curl -s -o /dev/null -w '%{http_code}' "$B/.well-known/service$p")" "$p"
done
```

| 路径 | arc 2.0 实测 | 1.17.x（包内基线） | 说明 |
| --- | --- | --- | --- |
| `/login` | **200**（直接是登录页，不重定向） | 有 | `?return_to=&cancel_to=&locale=&invitationId=` |
| `/admin` | **302 → login**（未登录时） | 有 | 登录后是服务台 SPA；`admin/team` → `301` → `admin` |
| `/admin/navigation` | **404** | 有 | 1.x 的菜单排序页在 2.0 上不存在 ⇒ **不要按 1.x 文档做集成** |
| `/user` | **302 → login** | 有 | 个人中心入口 |
| `/api/did/session` | **200 JSON** | 有 | 见 §3 |
| `/api/did/logout` | **302** | 有 | 运行时用的登出地址 |
| `/api/env` | **404** | 有（`dist/index.html` 里 `<script src="…/api/env">`） | 2.0 改为 `/__blocklet__.js` |
| `/static/**` | **404** | 有（`/.well-known/service/static/assets/…`） | 2.0 改为 `/assets/**` |
| `/theme/styles.css`、`/theme/init.js` | **200** | — | 服务台自己的主题壳（见 §4） |
| `/blocklet/logo`、`/blocklet/logo-dark`、`/blocklet/logo-rect` | **200** | 有 | 由 `blocklet.yaml` 的 logo 派生 |
| `/blocklet/og.png?template=default&…` | **200 `image/png`（132 832 B）** | — | **平台自带 OG 图生成器** |
| `/assets/<name>.<8hex>.{js,css}` | **200**（哈希文件名，无目录列表） | — | `assets/` 本身 404（不能枚举） |
| `/gen-access-key` | **200 `text/html`** | 有 | 1.x 同款授权页 |
| `/__blocklet__.js`（根级，不在 service 前缀下） | **200** | — | 注入 `window.blocklet`，见 §2 |

**术语陷阱【实测】**：`arc service` 是本地 AFS daemon 管理器（`arc service list|start|stop|url|logs`），
**和平台的 "Blocklet Service"（`/.well-known/service/*`）不是一回事**，`arc service --help` 里没有任何服务台路由。

## 3. 会话契约（平台给，ArcBlog 没用）

### 3.1 服务端

```bash
curl -s http://arcblog.localhost:4939/.well-known/service/api/did/session
# {"authenticated":false,"user":null}
```

已登录时的形状由**平台运行时自己的解析器**给出【代码，`.web-cache/_arc/assets/116ea4c0…js:105` `_sessionCtxFromApiResponse`】：

| 入参（响应字段） | 归一化后 | 备注 |
| --- | --- | --- |
| `authenticated: true` | `ctx.authenticated` | 非 `true` 一律当匿名 |
| `did` 或 `user.did` | `ctx.did` | |
| `user.displayName` → `user.fullName` → `user.name` | `ctx.displayName` | 三级回退，"不能退化成裸 DID" |
| `role` 或 `user.role` | `ctx.role` | |
| `sourceProvider` | `ctx.authMethod` | 登录方式（passkey / wallet / …） |
| 派生 | `ctx.isAdmin = role ∈ {owner, admin}`；`ctx.isOwner = role==="owner"` | **与 AUP DSL 的 `$session.isAdmin` 同源** |

### 3.2 浏览器侧副作用【代码，同上文件】

- 匿名 → 删除 `data-authenticated`、`data-role`；登录 → `<html data-authenticated data-role="<小写 role>">`。
  → **纯 CSS 就能按登录态分支**（`html[data-authenticated] …`），不必再依赖 `visible=` 这类实测不可靠的开关。
- 登出会清空 `sessionStorage` 里以 `afs:web:session:` 开头的键，然后跳 `/.well-known/service/api/did/logout`。
- `window.__arcSessionCtx` 是平台暴露的会话上下文；`window.__arcSessionWaiters` 可排队等首次解析完成（【代码】，未在页面里实测）。

### 3.3 平台自己的 URL 常量【代码，同文件顶部】

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `_SESSION_LOGIN_BASE` | `/.well-known/service/login` | 登录 |
| `_SESSION_LOGOUT_HREF` | `/.well-known/service/api/did/logout` | 登出 |
| `_SESSION_USER_CENTER` | `/.well-known/service/user` | 个人中心 |
| `_SESSION_ADMIN_CONSOLE` | `/.well-known/service/admin` | 管理控制台 |
| `_SESSION_AVATAR_BASE` | `/.well-known/service/user/avatar/` | 头像基址 |
| `_SESSION_AUP_PREFIX` | `afs:web:session:` | sessionStorage 前缀 |
| `<html data-arc-my>` | 实测 `"on"` | 值为 `off` 时隐藏 "My" 菜单项 |

头像实测：

```bash
curl -s -o /dev/null -w '%{http_code} %{content_type} %{size_download}\n' \
  'http://arcblog.localhost:4939/.well-known/service/user/avatar/did%3Akey%3AzDemo?s=56'
# 200 image/svg+xml 310   ← 任意字符串/DID 都 200，返回确定性生成的 SVG（无鉴权）
```
【实测】`?s=` 对**生成型**头像无效（仍是 200×200 `viewBox`）；真实头像才可能按尺寸裁剪。

## 4. 主题契约（平台两套机制并存，ArcBlog 只对齐了一半）

| 机制 | 位置 | 实测/代码 |
| --- | --- | --- |
| 服务台主题壳 | `/.well-known/service/theme/styles.css`（370 B） | 定义 `--blocklet-background-default-color`、`--blocklet-text-primary-color`；`[data-theme='dark']` 切暗色 |
| 服务台主题初始化 | `/.well-known/service/theme/init.js`（1 499 B） | 读 `localStorage['web-mode']`（`dark`/`light`/`auto`），迁移遗留键 `blocklet_theme_prefer`，改写 `<html data-theme>`；支持 `?theme=dark` 一次性覆盖 |
| **AUP 应用壳预绘制脚本** | `/?page=*` 的 HTML **内联**（`<head>` 第一个 script） | 读 `localStorage['web-mode']`；读 **`arc_mode` cookie**；若 `<html data-aup-mode="system">` 且无 cookie，则**删除** `web-mode` 并跟随系统；最后写 `data-mode` |
| `<html>` 属性（实测） | AUP 面 | `data-tone="clean" data-palette="neutral" data-mode="dark"`（**与 `app.aup` 的 `editorial/natural/light` 不一致 ⇒ 实参来自实例设置，app.aup 只是兜底**，与 `CLAUDE.md` 一致） |
|  | web 面 `/p/**` | 额外有 `data-arc-save-capability="floating" data-arc-my="on"` |
| `data-aup-mode` | — | 【实测】本版本 AUP/web 两个面都**没有**输出该属性，故预绘制脚本里"system 分流"分支当前是空转 |

**对 ArcBlog 的意义【推断】**：ArcBlog 的 theme-bridge 已经在读 `web-mode`（`.web/components/theme-bridge/script.js:254`、
`.web/themes/*/components/portal-header/script.js`），方向与平台一致；但平台现在还有 **`arc_mode` cookie** 这一层
（AUP 壳认它，服务台不认），且平台会在 `data-aup-mode="system"` 时**删掉** `web-mode`。这两点需要一次探针确认是否会互相打架
（见 [`04`](04-ArcBlog-改进建议.md) P1-3）。

## 5. 用户菜单（`user-menu`）DSL 契约【代码 + 实测】

ArcBlog 已在 `.aup/wrapper.aup:34` 使用 `{kind: user-menu, items:[…]}`。运行时实际支持的面比仓库记录的更宽
（`docs/05-开发文档/附件/arc-contracts.md` §13 写的是"官方示例菜单项只有 `{id,label,src,href}`"）：

| 能力 | 运行时实现 | ArcBlog 现状 |
| --- | --- | --- |
| 未登录渲染为登录按钮 | `_sessionRenderUserMenu()` 匿名分支 | 已用到（免手写登录卡） |
| 登录跳转 URL | `login?return_to=<encode(pathname+search+hash)>&cancel_to=<同一个值>` | 平台自动拼，无需手写 |
| 自定义项 `items[]` | `{id,label,icon,href,exec}`：`href` 直接跳转；`exec` 会派发 `user-menu-item` 事件 | ArcBlog 的项用 `href`，**但同时声明了 `events={user-menu-item:…}`** |
| 菜单文案覆盖 | `labels: {login,my,userCenter,adminConsole,signOut}` | ArcBlog 未用（走平台内置 i18n） |
| 隐藏个人中心项 | `showUserCenter: false` | 未用 |
| 内置项 | `My`（`data-arc-my!=="off"` 时）、`User Center`、`Admin Console`（仅 `isAdmin||isOwner`）、`Sign out` | 未用 |

> ⚠️ **死代码警告【代码】**：`events={user-menu-item: {…set: {page: $args.exec}}}` 只有在某个 item 带 `exec` 时才会触发；
> ArcBlog 唯一的 item 是 `{id: console, …, href: …}` ⇒ 该 handler 目前**永远不会执行**。要么把 item 改成 `exec: dashboard`，
> 要么删掉 handler（现状是"看起来接了、其实没接"）。

## 6. OG / 分享卡：两个面的实测差异

```bash
# AUP 绑定面（爬虫视角，无 JS）
curl -s http://arcblog.localhost:4939/posts/hello-arcblog | grep -oiE '<title>[^<]*</title>|<meta[^>]*(og:|twitter:)[^>]*>'
# <title>AFS</title>        ← 只有这一行

# web 面（SSR）
curl -s http://arcblog.localhost:4939/p/en/theme-bridge/ | grep -oiE '<title>[^<]*</title>|<meta[^>]*(og:|twitter:)[^>]*>'
# <title>ArcBlog theme bridge</title>
# <meta name="description" content="Internal bridge page …">
# <meta property="og:title" …> og:type og:url og:locale og:site_name og:description og:image og:image:alt
# <meta name="twitter:card" content="summary_large_image"> twitter:title/description/image
```

- web 面的 `og:image` **不是空的**，而是平台按模板生成：
  `/.well-known/service/blocklet/og.png?template=default&title=…&description=…&locale=…` → **200 `image/png`（132 832 B）**。
  `og:title`/`description` 来自 `pages/theme-bridge/seo/{title,description}` 这两个文件（本仓库已有）。
- 平台约定的覆盖入口（`arc blocklet check` 的原话 + 官方示例源码）：
  **`.web/seo/og-image`（站点默认）** 或 **`pages/<type>/seo/og-image`（按集合）**；官方示例把它写成
  `.web/site.yaml` 的 `seo: {description, og-image, og-site-name, title-template}`。
- 【推断】这些 `seo/*` 入口是**静态、按页面类型**的；**逐篇文章**的动态 OG 需要另一次探针（见 `04` P0-4）。

## 7. arc 2.0 vs 1.17.x 服务台对照（一句话版）

| 维度 | 1.17.x（`@abtnode/blocklet-services`） | arc 2.0（本机实测） |
| --- | --- | --- |
| 宿主 | 独立 npm 包，挂在 blocklet-server 里 | **编进 `arc` 二进制**，无独立包 |
| 静态产物 | `/.well-known/service/static/assets/**` | `/.well-known/service/assets/**` |
| 环境注入 | `/.well-known/service/api/env`（`<script src>`） | `/__blocklet__.js` → `window.blocklet` |
| 菜单配置页 | `/.well-known/service/admin/navigation` | **404**（2.0 参考实现里 blocklet.yaml 也不再声明 `navigation`） |
| 头部组件 | React（`@blocklet/ui-react` 系） | **原生 Web Component `<blocklet-header>`**（`assets/header.<hash>.js`，11.5 KB，实测可匿名下载） |
| 主题 | 组件库主题 | `web-mode` / `arc_mode` cookie / `data-theme` + `--blocklet-*` |

【未验证】`<blocklet-header>` 的资源名带哈希（`header.8703ab26.js`），且没有稳定别名（`/header.js`、`/assets/header.js` 实测 404）
⇒ 页面**不该硬编码**它；能否通过 `window.blocklet` 或某个稳定入口拿到当前哈希，需要一次探针。

## 8. 平台随 arc 分发的参考实现（最被低估的学习材料）

`~/.arc/current/assets/blocklets/` 下有 **58 个**官方 blocklet（`ls | wc -l`），其中可直接对照的：
`showcase` / `showcase-dsl`（AUP + web + surface + scaffold 全要素）、`did-space`（web 面 `site.yaml` + `.route/{web,app}`）、
`nimbus-demo`、`agent-surface`、`launch-kit`、`terminal`、`todo`。

它们暴露了三类 ArcBlog 尚未使用的**声明式目录约定**：

| 约定 | 例子 | 作用 |
| --- | --- | --- |
| `.web/site.yaml` | `showcase-dsl/.web/site.yaml` | web 面站点配置：`locale(s)`、`theme`、`color-scheme`、`seo{…}`、`template{layout,header,footer,navigation,header-actions}` |
| `.surface/definitions/*.surface.aup` + `.surface/overrides/*.values.aup` | `showcase-dsl/.surface/definitions/website.surface.aup` | **带类型的实例/用户设置 Schema**：`field … { scopes ["instance"] binding instance "/instance/settings/site/name" validation {…} policy {…} }`，与 `surface url=$state.loc` 那套是同一体系 |
| `.scaffold/{manifest,modules/*.module.dsl,shell/*.dsl,surfaces/*}` | `showcase-dsl/.scaffold/**` | 2.0 的模块/外壳脚手架；JSON 是产物、DSL 是源 |

【实测】58 个参考 blocklet 的 `blocklet.yaml` **没有任何一个**声明 `navigation:` 键 ⇒ 1.x 的
"在 blocklet.yaml 声明 userCenter 菜单"那套文档在 2.0 上已经不适用（与 §1 的 `admin/navigation = 404` 互相印证）。
