## 1. 两路独立审查（**互不代签**）

| 路 | 出场者 | 问什么 | 只写什么 | 实际形态 |
| :-: | --- | --- | --- | --- |
| **产品/架构路** | PM 审查 | 该不该这样、有没有兑现上游承诺、可追溯性、边界与"不做" | `docs/team/reviews/<Stage>*-产品审查.md` | `S1`–`S6-产品审查.md` 各 1 份 |
| **事实/判据路** | QA 独立验证 | 证据是否成立、判据能否变红、有没有臆造平台能力、独立复算 | `docs/team/reviews/<Stage>*-事实审查.md`（+`-闭合复核.md`） | `S1`–`S6-事实审查.md` 各 1 份；`S3` 另有 2 份专项实测 |

**硬规则**

1. **两路都要有，且各自是一份独立报告**；缺一路不定稿（README §2 五步的第 ③ 步）。
2. **审查者不改被审文件**：可写范围只有 `docs/team/reviews/**`（[`00 §2.2`](00-角色与写入范围.md) 的跨阶段通则：审查者**不改被审文件**，只写自己那一类报告）。
3. **互不代签**：一路的结论**不得**引用另一路的判断当自己的依据。**两路结论分歧时由 Lead 裁**（【已实现】`S5 §4` 就是一次真实分歧）。
4. **每条意见必须给证据**：`文件:行` / 命令输出 / **明确的反例**；**不接受"更好""更完善"**（README §2）。
5. **UI 条款**由 PM 审查侧按 [`docs/04`](../04-UI设计规范/00-总则与形态纪律.md) 条款库判，**不单开第三路**（已裁 T2）：**新增一路的门槛 = 它能独立报出另一路报不出的问题**；本会话 UI 条款问题由 PM 那一份报告全部报出（`S4 §3/§4`）⇒ 加路只增成本、不增判别力。**运行时量测类**（如 `S3` 窄屏实测）属**专项实测**，由 QA 路承担。
6. 报告落 `docs/team/reviews/`，文件名带**路名**与**阶段号**（例 `S4-事实审查.md`）。

> **为什么强调独立**：本轮出现过 **Lead 兼审查**（代行）与**两路分歧**两种情形——前者必须标注（§2），后者证明两路确实各查各的。

## 3. 判据自证：**能红**、变异**已生效**、缺失**不许跳过**（`P2`/`P13`）

### 3.1 变异必须自证已生效（`P2`）

| 规则 | 判据 |
| --- | --- |
| 变异前先断言**变异串在原文里存在** | 报 **before/after** 两段原样输出；**变异串 count == 1**（`P3` 的加强：`assert old in text` 不防"匹配太宽"） |
| 变异后必须**FAIL** | 变异后仍 PASS ⇒ 判据**不敏感**（不是"文档没错"） |

**来源事故（【已实现】）**：Lead **两次**因猜错行的加粗写法（`` `P-1` `` vs **`P-1`**）导致**变异静默失效**，外观却像"判据没抓到"（`stage-7 §3 P2`）；`S6 §8` 另记一次"变异注入了**正则认的那一版标点**，只验证了自己的假设"。
⇒ **同一条纪律的第二面**：**变异本身也要自证与文档同形**——改的是**数据**（正文），不是**表现**（显示格式）。

### 3.2 "跳过"是假绿通道（`P13`）

| 规则 | 判据 |
| --- | --- |
| 判据在**输入缺失**时**不得静默跳过** | "东西不存在"与"东西没问题"必须长得不一样：**找不到 ⇒ FAIL** |

**来源事故（【已实现】）**：`07 §3` 的脚本块被误删，而门的 `A5` 当时写"**找不到 ⇒ 跳过**" ⇒ **门照样 PASS**（`S4 §7 P13`）。
同族：这与"不能红的检查"（`P11`，→ [`01 §4`](01-工作流与阶段门.md)）、"只引有利那半"（`P9`，§5）都是**让缺失伪装成通过**。

### 3.3 与 `P1` 的分工

`P1`（**正本 PASS + 变异 FAIL**）与 `P11`（**不能变红的检查不得作为门**）的**定义点在 [`01 §4`](01-工作流与阶段门.md)**；本节只写**变异与跳过的操作形式**，不重复门制度。

## 4. 判据必须豁免"否定行"（`P4`）

**规则**：**定义禁令的文本必然提名被禁之物**（写"不得出现 X"就一定会出现 X）⇒ 任何"禁止某词/某形态"的判据，必须**豁免同行带否定标记**的行：`不得｜禁止｜不说｜无此｜已删｜作废`。

| 来源事故（【已实现】） | 后果 |
| --- | --- |
| Stage 2 的**禁用词判据** | 把**禁令声明行**判成违规（假红） |
| Stage 4 的 `BD-02` | 同上 ⇒ **第三次才成条件反射** |
| `S4 §1.3` 的 `grep 'always on'` | 会把 `.aup/pages/ops/agents.aup:37` 那句**对工具模型的真实陈述**判红 ⇒ 必须加**语义限定**（须与"分发面/产物已就绪"同现） |

⇒ **判据写法**：`grep -vE '(不得|禁止|不说|无此|已删|作废)'` **或** 用正则要求"**词 + 就绪语义**同现"，并在报告里写明该限定。

## 6. 抽验与分级：**抽验者先自证量法**（`P14`）+ 分级只引 `06/03 §0`

### 6.1 `P14`：核查他人产物前，先证明自己的量法正确

| 规则 | 判据 |
| --- | --- |
| 量之前先问"**这台机器上，这个量法与文档作者用的是不是同一个口径**" | 报出**量法 + 其输出** |
| **换一种方法复算一次** | **两个独立量法一致**才敢报缺陷 |
| 报缺陷时**同时给出我的量法与其输出** | 让对方能复核我的量法（不是只给结论） |

**来源事故（【已实现】，同一形状贯穿全会话）**：`awk length` 当行长（数**字节**）｜`len(split('\n'))` 当行数（≠ `wc -l`）｜bash `**` 未开 `globstar`（**30 个页面量成 22**）｜正则 `[A-Z]{1,3}[0-9]` **缺 `-?`**（漏掉整个 `BD-0x` 族）｜按 `` `P-1` `` 匹配而文档写 **`P-1`**（探针表只捞到 3 行）｜`require()` 读 ESM 失败后**静默退化**（10 项量成 7）。`S6 §8` 记本阶段又发生 **3 次**。

> **为什么单列一族**：`P1`/`P11`/`P13` 管判据"**能不能红**"；`P14` 管判据"**读不读得懂输入**"。量法错了会把"我的量法错"报成"**文档错**"，**制造假缺陷**——比漏报更有害。

### 6.2 缺陷分级（**只引，不重定义**）

| 档 | 判据（满足其一即入该档，取最高档） |
| :-: | --- |
| **P0** | **制造错误事实**（把"未就绪/未接/不存在"呈现为"可用/已就绪"） |
| **P1** | ① **阻断其它条目**；**或** ② 用户**可见**且**正确性受损** |
| **P2** | 可见但**局部**（单页/单字段/纯视觉），不改变事实判断 |
| **P3** | **不可见 且 登记即可（无需动手）** |

**两条附加规则**：**平台限制不评档**；**"未接"不评档**（属实现工作）——**只有"该对而错"才评档**。**唯一定义点 = [`06/03 §0`](../06-功能开发列表/03-缺陷与待修.md)**（含回扫 13 条的判定）。

### 6.3 闭合复核（只验"问题是否闭合 + 是否引入新缺陷"）

| 项 | 内容 |
| --- | --- |
| 输入 | 前一轮问题清单 + **当前**快照（hash） |
| 输出 | `closed / partial / new` 三分类计数，逐条给证据 |
| 不做 | **不重审全篇**（那是下一轮两路审查的事） |
| 为何不可省 | "已修"是**自述**；闭合复核是唯一能证伪它的动作 |

## 8. 冻结与受控修订（**六步照抄 + 两硬约束**）

**触发**：对已冻结文件（`docs/01`–`docs/06`，以及本阶段定稿后的 `docs/07`）的**任何实质改动**——事实错 / 证据缺 / **判据缺陷** / 跨阶段连带。

| 步 | 动作 | **若不做的后果（真实发生过）** |
| :-: | --- | --- |
| 1 | **Lead 裁决**：改 / 不改；**跨属主时由 Lead 协调** | 越界改他人文件 ⇒ 属主看到**无解释的 hash 漂移**，只能挂起上报（`S4 §1.1`） |
| 2 | **属主执行**改动（**非属主不得改**） | 同上；**非属主编辑必须在被编辑文件的变更记录留痕** |
| 3 | 在**被改文件**的变更记录留一行：**按 Lead 裁决 + 事由 + 源头** | 改动**无留痕** ⇒ 冻结记录与实况对不上 |
| 4 | **自证**：跑该阶段机检件（须仍 PASS）+ `arc dsl validate` + `npm test`；**报新 hash** | 改了冻结面却**没重跑门** ⇒ 静默破坏 |
| 5 | **Lead 回填** `S*-定稿核验-Lead.md`：新增**受控修订登记节**（事由/裁决/处置/新 hash/发现路径） | 冻结记录停留在旧值 ⇒ 读者以为记录自相矛盾 |
| 6 | 在 §1 的**旧 hash 行**标 **`~~…~~ ⇒ 见 §1.x`**，并**全量比对**：「有效 hash 一致 ｜ 已标记取代 ｜ **不一致 = 0**」 | 旧值不标取代 ⇒ **记录看似自相矛盾**（`S3`/`S4` 都出现过） |

**第 6 步的复算命令（R9：本步是全篇最可判的一条，必须能自己跑）**

```bash
$ python3 - <<'PY'
import re, os, hashlib, sys, glob
rec = sys.argv[1] if len(sys.argv) > 1 else 'docs/team/reviews/S6-定稿核验-Lead.md'
```
