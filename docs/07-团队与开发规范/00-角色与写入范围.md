## 1. 角色与职能位总表（**5 角色 + 3 职能位**）

来源 = 底稿 §1（Lead 裁决，2026-09-30）。**归档期四角色（PM/Dev/QA/UI）与本次实际跑的不是同一套**：本次实际出现的是 Lead、主笔、审查者、调研员；Dev/UI 本轮零出场（`S7-01 §1`）。

| 角色 | 职责 | 写入范围（**glob 级**，见 §2） |
| --- | --- | --- |
| **Lead** | 编排、裁决、冻结、**唯一提交人** | 常规：`docs/README.md`、`docs/team/**`；受控修订路径下另见 §2 例外条 |
| **主笔（author）** | 按阶段写正文；**先提纲后正文**；自查判据 | 本阶段目录 `docs/0X-*/**` + `docs/team/journal/**` |
| **审查者（reviewer）** | 两路独立审查（产品/架构 + 事实/判据）；**只写报告** | `docs/team/reviews/**`（**不改被审文件**） |
| **调研员（researcher）** | 阶段输入的事实底稿 | `docs/08-其他/调研/**`（只读仓库，不写别的） |
| **实现者（Dev）** | 按 Stage 6 台账实现 | 源码 glob（§2）+ `docs/06-功能开发列表/**` 的**状态回填** |
| 职能位：**UI** | 视觉/交互条款的**审查**侧（不单独开写范围） | 并入审查者（判据 = [`04-UI设计规范`](../04-UI设计规范/) 条款库） |
| 职能位：**人类（owner）** | 产品口径追认、资金/链审批、检查点批准 | **不写文件**，只在裁决点表态 |
| 职能位：**平台探针** | 需写权限的探针（改 `.aup` + 重启复挂） | 归**实现轮**，与 Dev 同域，执行者持 `docs/team/.gate-lock` |

**三条不变式**

1. **任何人不得写别人阶段的正文**；越界先报 Lead（§2.3）。
2. **同一时刻一名成员只持有一个 `in_progress` 任务**（总纲 §7 过渡表，本阶段上升为条文）。
3. **一个 Stage 只有一个主笔**；换人走"安全阀"（[`01 §5`](01-工作流与阶段门.md)）。

### 2.3 不重叠判据与"越界先报 Lead"

**判据（可判定）**：任取两名成员，其可写 glob 集合的交集，除 §2.2 两条例外外必须为 **空**。判据形态见 [`06 §5`](06-采纳与自检.md) 的机检脚本（同一条 `python3` 里含"glob 交集 = ∅"检查）。

**越界三步（本次已实战两次）**

| 步 | 动作 | 本次实证 |
| :-: | --- | --- |
| ① **停手** | 发现目标文件不在自己的 glob 内 ⇒ 立刻停止写入 | — |
| ② **报 Lead** | 一条消息写清：目标文件 + 为什么必须改 + 预计改动面 | 扩 `dev-doc` 到 Stage 5 的 `00`–`02a` |
| ③ **由 Lead 处置** | Lead 建任务 / 扩权 / 或**亲自做**（受控修订） | Lead 直改 Stage 1/2/3 |

> **反向纪律**：Lead **也不得**绕过 §2.2 直接改冻结正文——2026-09-30 那次 `04-ECO §8` 的一行残留就是走"Lead 一行修正 + 主笔补变更记录 + 登记 §1.1"完成的（[`S2-定稿核验-Lead.md`](../team/reviews/S2-定稿核验-Lead.md) §1.1）。

> **与现行入口文件的口径差（R9）**：本三步的②= **报 Lead**；而仍在生效的 [`AGENTS.md`](../../AGENTS.md) 铁律 3 写的是"给 **PM** 发消息，由 **PM** 建任务或升级 Lead"。⇒ **以本规范为准**（新体系里 PM 已并入审查/职能位，见 §1；**派活与扩权归 Lead**），`AGENTS.md` 待 **Stage 8b** 同步（已登记 §3.2）。
