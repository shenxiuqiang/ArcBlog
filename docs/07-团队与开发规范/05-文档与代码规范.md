## 2. 数字纪律（**"实测 + 口径 + 可复算命令"三件齐**）

| # | 规则 | 判据 |
| :-: | --- | --- |
| **D1** | **不写"预期条数/预期页面数"**；凡数字必须能追到**一条命令 + 原样输出**（[**P5/P16**](../team/stage-7-入口口径-Lead.md)） | 数字旁必须有**命令**；汇报同此（**汇报与文档同族**） |
| **D2** | **计数必须写清"量的是什么"**：[**glob 范围 + 原始出现数 + 行命中数**](../team/stage-7-入口口径-Lead.md) 三件齐（[**P10**](../team/stage-7-入口口径-Lead.md)） | ⚠️ **出现数与行命中数不可混用**（事故：`V08` 把"行 28"写成"出现 28"，真实 **出现 87 / 行 28**；`minHeight` 的"44"为两属性**混算**，仅 `minHeight` = **35**） |
| **D3** | 写死的数字**尽量换成脚本**（`P5`） | 能 `grep`/`node -e` 取的，不写进正文 |
| **D4** | **已有权威口径/工具时先用它**，不要另造一个更差的再质疑前者（[**P16**](../team/stage-7-入口口径-Lead.md)） | 例：需求计数用 [`docs/02-产品需求/_count.sh`](../02-产品需求/_count.sh)（口径A），**不手搓正则**（手搓曾得 44/59，真值 56） |
| **D5** | **给下游的差值/基线，自己先按口径跑一遍**；立了规则要**回头扫全部用法**（[**P6**](../team/stage-7-入口口径-Lead.md)） | 例：`待平台能力` 立规后回扫才发现 `SITE-04` 漏修 |

**口诀**：**"跑过 ≠ 写回"的下一层 = "量过 ≠ 口径写清"**（[**P8/P10**](../team/stage-7-入口口径-Lead.md)）。

## 3. 引用纪律（**来源 / 唯一出处 / 派生表**）

| # | 规则 | 判据 |
| :-: | --- | --- |
| **R1** | **引用原始证据必须读完整节**（只引有利那半 ⇒ 把【规划中】写成【已实现】；本项目**真实事故**） | 引用的行号要能覆盖**邻近的反证行** |
| **R2** | **引用任何来源必须读出"限定范围"**（[**P9**](../team/stage-7-入口口径-Lead.md)）：同行/同节要能回答"**作用在哪个元素/哪条路径上**"；答不出 ⇒ **不许写成通用条款** | 事故：§29.6 是 **`action`** 的限定事实，却被写成通用结论，而 §29.8 白名单**明含** `minHeight`/`minWidth` ⇒ 差点把**受限事实升级成假边界** |
| **R3** | **定义禁令的文本必然提名被禁之物** ⇒ 判据必须**豁免同行带否定标记**（`不得/禁止/不说/无此/已删/作废`）的行（[**P4**](../team/stage-7-入口口径-Lead.md)） | 同一根因犯过三次（Stage 2 的**禁用词判据** / Stage 4 `BD-02` / …） |
| **R4** | **唯一出处原则**：同一事实只在一处**定义**，其它地方**引用**（编号或取值） | 能 `grep` 到两处**同值** |
| **R5** | **【P17】派生表不得自造字段值**：派生表的每个**非引用性字段**，二选一 —— ① **直接引用唯一出处的值**；② **删掉该字段**。**不得"另行判定"**（含"我按同样规则重判一遍"——重判会分叉） | 事故（横跨四阶段）：**阻塞值**在 `01` 与 `06/04` 各写一份 ⇒ **3 处矛盾 + 5 条漏列**；**执行者**在 `05/07` 与 `06/04` **各一半**；**同一句事实**复述 **4 处**。**口诀**：唯一出处管"**谁定义**"，P17 管"**谁能再写一遍**"——答案是**谁都不能** |
| **R6** | **【P15】事实若被多处复述，修正必须扫全库**（"改一处"= 没改） | 定稿前对每句**事实性断言**做 `grep` 全库扫描列清单；**扫出后仍要逐条判断**（**相容的不必改**）。⚠️ 阶段门的"跨篇重复"（A0）**只抓 ID**，抓不到**自然语言复述**。⇒ **工具 = `bash docs/team/fact-sweep.sh '<短语>'`**（[`docs/team/fact-sweep.sh`](../team/fact-sweep.sh)）：**分工 = A0 抓 ID 重复，本工具抓自然语言复述**；口径 **默认命中行数**，`--count` 另给**出现次数**（**两者不可混用** — D2/P10）。工具**自己打印 P15 的反面提醒**（扫出后仍要逐条判断） |
| **R7** | 引用**未落盘**的后续阶段 ⇒ 标「（Stage N 未落盘）」；**不得**把不存在的路径当唯一出处（**唯一文档层 = `docs/`**） | **F6** 的链接自检 |
| **R8** | **脚本改文件：先算内容再写**（`open(p,"w").write(expr)` 会**先截断文件**再求值 `expr`；`expr` 抛异常 ⇒ 留下 **0 字节**文件。2026-10-12 真实事故：`docs/08/04` 被截成空文件，靠 `git checkout` 复原） | 改文档/数据的脚本必须：① 先把结果拼成字符串（可 `assert` 校验）② **最后一步**才 `open(...,"w").write(text)` ③ 写完 `wc -l`/`git diff --stat` 复核；批量改前先 `git status` 记干净基线 |
| **R9** | **契约变更必须重推所有"钉住它"的套件（快层 *与* live）**：改声明/参数/取值后，`grep` 该字面量在全仓的出现处，**逐个**更新——live 套件**不是每轮门**，陈旧断言可在全绿中潜伏（2026-10-12 真实事故：`ENG-21` 补全 `get_studio` 参数后，`scripts/arcblog-agent.test.mjs` 仍钉旧列表，**约 40 轮**无人发现，最终靠"抽检 live 套件"抓出） | 改完后 `grep -rn "<被改的字面量>" scripts/ docs/` 逐条判读；涉及 live 的补跑一次定向单跑（持 `.gate-lock`） |

## 6. 变更记录与留痕（**三类改动三种留痕**）

| 改动对象 | 留痕方式 | 判据 |
| --- | --- | --- |
| **未冻结的 `docs/**`** | 该文件**文末变更记录**加一行（日期/版本/变更） | 改了就有一行 |
| **已冻结面（`docs/01`–`docs/06`）** | **受控修订六步**（[`stage-7 §2.1`](../team/stage-7-入口口径-Lead.md)）：Lead 裁决 → **属主执行** → **在**被改**文件留痕** → 自证（跑该阶段 `_gate.sh` + `validate` + `npm test`，报**新 hash**）→ Lead 回填 `S*-定稿核验-Lead.md` → 旧 hash 标 **`~~…~~ ⇒ 见 §1.x`** | 六步齐 |
| **非属主编辑**（跨属主协作） | **必须在被编辑文件的变更记录留痕** | 事故：非属主编辑不留痕 ⇒ 属主看到**无解释的 hash 漂移**，只能挂起上报（Stage 4 `04` 事件） |

**两条硬约束**：① **连带面必须扫全库**（**R6/P15**）；② **判据缺陷与事实缺陷同权** —— `S4 §1.3` 必须改的主因**不是**"输出贴漏一行"，而是**那条负例判据会把真陈述判红**。
