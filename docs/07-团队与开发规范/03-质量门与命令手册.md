## 1. 三条门：判定式与必跑时机

| 门 | 命令 | **判定式（可复制）** | 必跑时机 | 谁负责 |
| --- | --- | --- | --- | --- |
| **DSL 门** | `arc dsl validate --json` | `issues == []` | **每步**（秒级；与改动类型无关） | 写者自跑 |
| **快层门** | `npm test` | 退出码 0 且 `fast tier passed`；**用例数只以 runner 输出为准** | **每轮收口**（改动落盘后、交接前） | 写者自跑 |
| **构建门** | `npm run build` | 退出码 0；且随后 `test -e dist/docs/team/.gate-lock` = 不存在（锁镜像，见 §3） | **仅当改了** `.aup/**`、`blocklet.yaml`、`world/**`（`05-开发文档 05 §7`） | Lead 收口（实现轮） |

**两条"红线"**

1. **红门不得交接**（`AGENTS.md` 铁律 2）：门红时自己回滚，**不要把红仓库交出去**；门红时**不得提交**。
2. **`npm run build` 是唯一安全构建入口**：裸 `arc blocklet build` 会把 `node.key`/`.env.local` 复制进 `dist/`（BUG-067），因此**只跑 `npm run build`**；这属于实现轮的收口动作，本阶段（纯文档）**未跑 build**。

## 2. 门清单的唯一出处 = **runner 代码**

### 2.1 为什么（两条失败教训）

| # | 教训 | 现象 |
| :-: | --- | --- |
| 6 | **文档有门、代码没门（假门）** | 三处文档称 `arc dsl generate --check` 在 `npm test` 内，代码**零命中** |
| 7 | **快层口径漂移** | `_docs/team/README.md:166` 写"6 文件 / 28 测试"、`CLAUDE.md:112` 写 35/36，实测白名单 **10** |

⇒ **纪律**：门清单的**唯一出处 = `scripts/run-tests.mjs`**（`FAST_TESTS` 常量与 runner 自己的报告）。文档**只准引用**两样东西：**常量的元素个数**与 **runner 的输出**；**禁止**手抄名单、**禁止**写"应该跑了什么"。

### 2.2 真实取证（原样输出）

```bash
$ ls scripts/*.test.mjs | wc -l
      32

$ python3 - <<'PY'   # 读 run-tests.mjs 的 FAST_TESTS 常量，只输出元素个数（不抄名单）
import re,io
s=io.open('scripts/run-tests.mjs',encoding='utf-8').read()
m=re.search(r'const FAST_TESTS = new Set\(\[(.*?)\]\)',s,re.S).group(1)
print("FAST_TESTS",len(re.findall(r"'([^']+)'",m)))
PY
FAST_TESTS 10

$ grep -rn "dsl validate" scripts/*.test.mjs scripts/run-tests.mjs | wc -l
       0
$ grep -rn "'generate'" scripts/*.test.mjs | wc -l
       0
```

**三条结论（都由上面的输出支撑）**

1. **`arc dsl validate` 与 `npm test` 是两个互不包含的门**（命中 **0**）⇒ 必须分别跑。
2. **`arc dsl generate --check` 漂移门在快层不存在**（命中 **0**）⇒ 文档**只准**写"今天没有这个门"；补门登记 Stage 6 `ENG-08`（= `S6-02 TOOL-02` / `05-开发文档 07 §6 G4` 的同一件事）。
3. 快层 = **10 个文件**（runner 常量），全仓 **32** 个测试文件 ⇒ **新测试文件默认算 live**。

### 2.3 判据必须"能红"：一条变异副本

"两门互不包含"这条判据的实现 = 一个 `grep`。**只给正本 0 不算成立**，必须证明它抓得住注入：

```bash
$ rm -rf /tmp/s7m && mkdir -p /tmp/s7m/scripts && cp scripts/*.test.mjs scripts/run-tests.mjs /tmp/s7m/scripts/
$ printf "\nimport {spawnSync} from 'node:child_process';\nspawnSync('arc dsl validate --json', {shell: true});\n" >> /tmp/s7m/scripts/arcblog-theme.test.mjs
$ echo "正本（仓库）："; grep -rn "dsl validate" scripts/*.test.mjs scripts/run-tests.mjs | wc -l
正本（仓库）：
       0
$ echo "变异副本（/tmp）："; grep -rn "dsl validate" /tmp/s7m/scripts/*.test.mjs /tmp/s7m/scripts/run-tests.mjs | wc -l
变异副本（/tmp）：
       1
$ grep -rn "dsl validate" /tmp/s7m/scripts/arcblog-theme.test.mjs | head -2
/tmp/s7m/scripts/arcblog-theme.test.mjs:59:spawnSync('arc dsl validate --json', {shell: true});
```

**判据能力边界（写在脸上）**：这条 `grep` 判据**能**抓"有人把 validate 接进快层"；**不能**分辨真实调用与**注释里提到该串**（注释也会命中 ⇒ 假红）。⇒ 升级路径 = 改成"解析 `spawnSync(...)` 实参"的判据；今天不升级，但**边界必须声明**。

## 3. live 分层与 `.gate-lock`（**操作面引 `05-开发文档 05 §5`**）

### 3.1 原则（纪律面）

| 原则 | 内容 |
| --- | --- |
| **分层不是按大小，是按"是否写共享实例"** | 写实例的一律为 live；`FAST_TESTS` 是**白名单**，新文件默认 live |
| **live 不作常规门** | 人类点名或批次末 QA 才跑；理由（成本 / 非幂等 / 并行即污染 / 可替代）见 `05-开发文档 05 §4`，本篇不复制 |
| **定向替代** | 改动触及 CLI / AFS 记录 / 链适配器 / daemon 路由 ⇒ 跑**受影响的单个文件**（`npm run test:file -- scripts/<f>.test.mjs`） |
| **快层不受锁** | `npm test` 不写实例 ⇒ **不需要** `.gate-lock` |

### 3.2 锁的四条纪律与两个坑（引 `05-开发文档 05 §5`，此处只给协作面）

| 项 | 协作面（本篇新增） |
| --- | --- |
| 谁持锁 | **要写实例的进程**（live 测试 / 需写权限探针）⇒ 执行者持 `docs/team/.gate-lock`，内容 = `<执行者> <UTC 时刻>` |
| 先锁后跑、见锁即等、跑完即删 | 三条都是**执行者义务**；等锁者不得"先跑跑看" |
| 坑①（`dist/` 镜像） | 持锁期间跑 `npm run build` ⇒ `dist/docs/team/.gate-lock` 出现；**提交前必须 `test -e` 检查并删除镜像** |
| 坑②（部署只告警） | 部署脚本检测到锁只打印提醒、**不阻塞** ⇒ 有锁时是否部署由**人**判断 |
| 现状 | 【已实现】本轮 `test -e docs/team/.gate-lock` → **ABSENT**（跑完即删，符合约定）；【规划中】工具化（TTL / owner 校验 / status）登记 `05-开发文档 07 §6 G6` |

```bash
$ test -e docs/team/.gate-lock && echo PRESENT || echo ABSENT
ABSENT
```

## 4. 「跑过 ≠ 写回」（本篇最重要的一条）

**判据**：凡声称"已修 / 已验证 / 已跑通"，必须在**文档内可复跑的产物**里落地——**判据的代码 + 命令 + 真实输出三样同处一篇**。

| 反例（实测过的） | 发生了什么 |
| --- | --- |
| 主笔只在 `/tmp` 跑通就声称"判据已修" | 闭合复核打开正本：**四个判据代码一字未改**（[`S3-事实审查-闭合复核`](../team/reviews/S3-事实审查-闭合复核.md)） |
| 主笔在正文写"本章判据已加敏感性" | 文字声称代替代码改动（同上） |
| `06/01 §10.2` 曾贴**没跑过的"预期输出"（假 PASS）** | 被"把脚本真跑一遍、把输出原样贴回"抓出（[`06/00 §6`](../06-功能开发列表/00-台账总览与规范.md)） |

**操作口径**：① 判据先在**正本**跑一遍；② 再造**变异副本**证明能红；③ 两段输出**原样粘贴**进文档（本篇 §1.1/§2.2/§2.3 就是示范）；④ 未跑的一律标【未验证】或写明"本轮未跑"，**不得**用预期输出充数。

## 5. 真红 / 假红 / 写入类验收

### 5.1 五条判据（引 `05-开发文档 05 §6`，此处只给"什么时候用哪条"）

| 症状 | 先做 | 结论 |
| --- | --- | --- |
| 快层/live 某文件红 | **单跑那个文件**（`npm run test:file`） | 绿 ⇒ 并发污染（**假红**）；仍红 ⇒ 真 bug |
| 报告类型 `TIMEOUT` | 调 `ARCBLOG_TEST_TIMEOUT_MS` 或拆文件 | **不是**代码失败（后续文件根本没启动） |
| 报告类型 `BUDGET` | 调 `ARCBLOG_TEST_BUDGET_MS` | **不是**代码失败（预算耗尽） |
| live 失败 | 看残渣（runner 保留；`ARCBLOG_NO_CLEAN=1` 主动保留） | 供检视 |
| `npm test -- --changed` 全绿 | **不得**当作"没覆盖" | 未登记 `GUARDS` 的套件**永远被选中**；"没跑" ≠ "没覆盖" |

### 5.2 元判据：平台 `arc` 出错时 `$?` 可能为 0

⇒ 断言**必须解析 JSON `success`/错误码**；只有**自建 CLI 脚本**的退出码可用（来源 = [`05-开发文档 00 §2`](../05-开发文档/00-架构总览.md) 共同铁律）。

### 5.3 写入类验收：**toast 不是证据**

| 反例 | 整改后的判据 |
| --- | --- |
| BUG-012：把模板字面量 `posts/${entry.content.slug}.json` 写进公开 feed，界面仍弹 "Published." | **真实操作 → AFS 读回前后对比**（`.actions/read` 取记录，逐字段比对）；未实测只准写"受限未验证" |

### 5.4 引用测试命令**两步核对**

| 步 | 命令 | 不通过的含义 |
| :-: | --- | --- |
| ① 存在性 | `test -e scripts/<f>.test.mjs` | 文件不存在 ⇒ 引用是**假门** |
| ② 分层 | 查 `FAST_TESTS`（`05-开发文档 05 §2`） | 不在白名单 ⇒ 它是 **live**，写进文档必须注明 |

```bash
$ test -e scripts/arcblog-media.test.mjs && echo EXISTS || echo MISSING
EXISTS
$ python3 -c "…读 FAST_TESTS…"
arcblog-media in FAST_TESTS: False
arcblog-theme  in FAST_TESTS: True
```

⇒ 引用 `scripts/arcblog-media.test.mjs` 时必须写"**live**（不在 `FAST_TESTS`）"，并提示先持锁；`arcblog-theme` 才是快层文件。
