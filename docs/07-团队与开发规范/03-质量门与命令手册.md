## 1. 每轮必过（**红门不得交接**）

| # | 门 | 命令 | 判据 | 何时 |
| :-: | --- | --- | --- | --- |
| **G-1** | **DSL 校验** | `arc dsl validate --json` | 解析出的 **`ok: true`** 且 **`issues: []`**（**不是**退出码） | **每一轮** |
| **G-2** | **快层** | `npm test` | 输出 **`fast tier passed`**；**不写实例** | **每一轮** |
| **G-3** | **构建 + 擦密** | `npm run build` | 见 §2 | **仅当**改了 `.aup/**`、`blocklet.yaml`、`world/**` |
| **G-4** | **交付门（全库卷门）** | `npm run gate:docs`（`--quiet` 只出汇总） | 六个卷门逐个 `VERDICT PASS`；任何一门失败 ⇒ **整条命令退出码 1** | 改 `docs/**` 后、以及**每个交付轮**（`ENG-53`；独立于 `npm test`：快层是"实现门" ~1–2 s，卷门是"交付门"） |

**三点纪律**：
1. **`npm test` 不调用 `arc dsl validate`** ⇒ 两道门**必须都跑**（只跑一个 = 漏门）；
2. **文件数与耗时一律"从运行输出取"**（[`P5/P10`](../team/stage-7-入口口径-Lead.md)），**不写死**；
3. **红门不得交接**：G-1/G-2 任一红 ⇒ **不得**进入下一轮/交接（[`05 §5`](../05-开发文档/05-测试分层与质量门.md)）。

## 2. `npm run build` 是**唯一安全入口**（**BUG-067** / [`05/02 B11`](../05-开发文档/02-平台能力与边界.md)）

| 项 | 内容 |
| --- | --- |
| **为什么唯一** | **裸 `arc blocklet build`** 会把仓库根的 **`node.key`**（Ed25519 私钥）与 **`.env.local`**（链助记词）**原样复制**进 `dist/`，并写进 `dist/.afs/manifest.json`；**平台无 ignore/exclude 开关**（[`05/02 B11`](../05-开发文档/02-平台能力与边界.md)） |
| **正确做法** | `npm run build` = `arc blocklet build` **+** `npm run scrub:dist-secrets`（**后置擦除**） |
| **后置守卫** | 快层 `arcblog-dist-secrets` 会检查 `dist/` 无密钥（并在 `npm run build` 里**擦除** `dist/` 的密钥与本地垃圾，`DEF-17`） |
| **本轮新增守卫族（2026-10-12）** | 文档命令漂移 `arcblog-doc-commands`（`ENG-17`）· 页面取数↔授权 `arcblog-page-grants`（`ENG-18`，含"授权集合必须有文档行"断言）· 破坏性默认旗标 `arcblog-fail-closed`（`ENG-19`）· 错误码索引 `arcblog-error-codes`（`ENG-20`）· agent 工具表 `arcblog-agent-tools`（`ENG-21`）· 转让接线 `arcblog-node-nft-transfer`（`ENG-06`） |
| **两条禁律** | ① **不得**把裸 `arc blocklet build` 写进任何流程/脚本；② **不得删除** `node.key` / `.env.local`（丢了等于丢节点身份；须**仓库之外**离线备份，绝不提交、绝不写进 AFS） |
| **复算** | `node -e "const p=require('./package.json');console.log(p.scripts.build, '|', p.scripts['scrub:dist-secrets'])"` |

## 4. 文档轮的机检件**纳入门**（且**必须自证能红**）

**本轮实测在册的 11 个**（`ls docs/0*/*.sh docs/team/*.sh`）；**其中 7 个会判 PASS/FAIL，4 个是辅助工具**（见"会 FAIL？"列）：

| 机检件 | 作用 | **会 FAIL？** | 复算 |
| --- | --- | :-: | --- |
| `docs/01-产品概念/_sens.sh` | 词表敏感性（禁用词须带删除标记） | **是**（`VERDICT PASS/FAIL`，rc 0/1） | `bash docs/01-产品概念/_sens.sh` |
| `docs/02-产品需求/_count.sh` | **权威计数器**（口径A = 需求总表行数） | **否**（只给数，不判定） | `bash docs/02-产品需求/_count.sh` |
| `docs/03-产品设计/_gate.sh` | 阶段 3 条款 / 链接 / 残留 | **是**（`VERDICT`） | `bash docs/03-产品设计/_gate.sh` |
| `docs/04-UI设计规范/_gate.sh` | 阶段 4 条款 ID / `BD` / 内联检查器 | **是**（`VERDICT`） | `bash docs/04-UI设计规范/_gate.sh` |
| `docs/05-开发文档/_gate.sh` | 阶段 5 `B*` / 三缺口 / 探针 | **是**（`VERDICT`） | `bash docs/05-开发文档/_gate.sh` |
| `docs/06-功能开发列表/_gate.sh` | 阶段 6 主键 1:1 / 六态 / 废弃域 | **是**（`VERDICT` + rc） | `bash docs/06-功能开发列表/_gate.sh` |
| `docs/07-团队与开发规范/_gate.sh` | **阶段 7**：角色面 / 机检件表 / `P` 条数 / 受控修订次数 / 形态 | **是**（`sys.exit(1 if … else 0)`） | `bash docs/07-团队与开发规范/_gate.sh` |
| `docs/08-其他/_gate.sh` | **阶段 8a**：必需文件齐 / 索引提到八区域 / 错误码可核 / 形态与死链（**4 判据**） | **是**（`VERDICT`） | `bash docs/08-其他/_gate.sh` |
| `docs/team/doc-map.sh` | **`docs/` 现状目录地图**（每目录篇数），供体量核对 | **否** | `bash docs/team/doc-map.sh` |
| `docs/team/fact-sweep.sh` | **P15 全库复述扫描（辅助工具，不产生 PASS/FAIL）** | **否** | `bash docs/team/fact-sweep.sh '拖拽区'` |
| `docs/team/objective-check.sh` | 目标达成核对（逐项打印 `PASS` / `见输出`，**无 FAIL 判定**） | **否** | `bash docs/team/objective-check.sh` |

**计数一致性（本节的判据，保留不放松）**：改完**再跑一遍** `ls docs/0*/*.sh docs/team/*.sh | wc -l` ⇒ **必须等于本表体行数**（本轮 = **11**）。
> ⚠️ **口径陷阱（实测踩过一次）**：**不要**再追加显式路径（如 `… docs/07-团队与开发规范/*.sh`）——`docs/0*` **已经覆盖 `docs/07`**，追加会把同一文件**数两遍**（在册 11 件时误加会得到 **12**）。这是 [**P14**](../team/stage-7-入口口径-Lead.md)（量法自证）的实例：**换法复算才发现多算了一个**。
> ⚠️ **该判据会"正当地"变红**：**新增机检件必须同步更新本表**（含"会 FAIL？"分类）。Stage 7 门 `A1` 就是这么做的——FAIL 时**点名"新增了哪个文件、请更新本表"** ⇒ **FAIL ≠ 判据坏了，而是"表要更新"**（[**P5/P10**](../team/stage-7-入口口径-Lead.md)）。**修法是更新表，不是放宽判据。**
**不会 FAIL 的 4 个：输出给谁判、不符怎么办（口径）**

| 工具 | 输出的用途 | **谁判 / 不符怎么办** |
| --- | --- | --- |
| `02/_count.sh` | **权威计数**（口径A = 需求总表行数） | **人判**：与台账主键行数**比对**；**不一致 = 缺陷**（不是"工具错了"）⇒ 报 Lead，由属主修台账或订正计数口径 |
| `team/fact-sweep.sh` | **P15 复述清单** | **人判**：扫出后**逐条判断**（**相容的不必改** — 工具自己会打印该反面提醒）；要改的按清单逐处改并留痕 |
| `team/objective-check.sh` | 目标达成**逐项核对报告**（`PASS` / `见输出`） | **人判**：`见输出` 的项**逐条追到落点**；追不到 = 未达成 ⇒ 报 Lead |
| `team/doc-map.sh` | `docs/` **现状目录地图**（体量与缺目录核对） | **人判**：目录缺失/异常增减 ⇒ 报 Lead |

⇒ **共同口径**：这 4 个**只出"读数/清单/报告"，不自己判 PASS/FAIL**；**判定与处置一律由人（Lead）做**，且**不符时先怀疑表格/台账、而不是先怀疑工具**（[**P14**](../team/stage-7-入口口径-Lead.md)：先自证量法）。

**同类口径核对**：机检件的**清单与"会 FAIL"分类的唯一出处 = 本节**；其它篇（如 [`01 §4`](01-工作流与阶段门.md)）**只引不列数**（`P17`）。⚠️ **本节曾写"8 个"**（写于 `fact-sweep.sh` 交付**之前**且**未随交付复跑命令**）——**这正是 [`05 §2 D1`](05-文档与代码规范.md)"数字旁必须有命令"要防的**：数字与它**自己给的复算命令**对不上。

**三条硬要求（都来自事故）**：
1. **上线前必须自证**：正本 **PASS** + **变异 FAIL**（[**P1**](../team/stage-7-入口口径-Lead.md)），且**变异要自证已生效**（先断言变异串在原文里，贴 before/after — [**P2**](../team/stage-7-入口口径-Lead.md)）；
2. **不能变红的检查不得作为"门"呈现**（[**P11**](../team/stage-7-入口口径-Lead.md)）：演示不出 ⇒ **修到能红，或删掉并指向权威判据**；
3. **"跳过"是假绿通道**（[**P13**](../team/stage-7-入口口径-Lead.md)）：输入缺失时**不得静默跳过**——**找不到即 FAIL**（"东西不存在"与"东西没问题"必须长得不一样）。

**嵌套守卫**（[**P12**](../team/stage-7-入口口径-Lead.md)）：允许"文档内联检查器**回调门**"（单一权威），但**必须**有 **`ARCBLOG_GATE_NESTED` 一类的嵌套守卫 + 硬超时**（超时视为 FAIL）。事故：门 A5 执行文档里的脚本、而该脚本回调同一门 ⇒ **无限递归、门挂死 60s+**；**静态审查看不出环路，只有真跑才暴露**。

## 4.1 机检件的**退出码统一定义**（**本节 = 定义点**）

| 退出码 | 含义 |
| :-: | --- |
| **0** | **PASS** |
| **1** | **FAIL**（判据不满足） |
| **2** | **环境异常**（文件缺失 / 依赖不可用 —— **不得当作 PASS**，见 [**P13**](../team/stage-7-入口口径-Lead.md)"跳过是假绿通道"） |

**两条要求**：① **每个阶段 `_gate.sh` 的头部注释必须含同一行退出码表**（复算：`grep -l '0=PASS' docs/0*/_gate.sh` ⇒ 覆盖全部 `_gate.sh`）；② 若发现哪个门**不符**（无该行或语义不同）⇒ **报 Lead 处理**，**不跨属主改**。
