## 1. 阶段五步（执行细则）

> **定义点 = [`docs/README.md`](../README.md) §2 首句**：**调研 → 主笔撰写 → 两路独立审查（产品/事实）→ 多轮修订 → Lead 核验定稿**。本篇补"**谁做 / 产物 / 停点**"。

| 步 | 谁做 | 产物落点 | **停点**（必须停下等谁） |
| :-: | --- | --- | --- |
| ① 调研 | 调研员（可并行；**一人一文件**） | `_research/**` | 主笔取用前不阻塞 |
| ② 撰写 | **主笔**（同阶段可多人，但**文件级分派**，见 [`00 §4`](00-角色与写入范围.md)） | `docs/0X-*/_提纲.md` → `docs/0X-*/*.md` | **提纲先过 Lead**；每篇写完回报一次 |
| ③ 两路独立审查 | PM（产品路）+ QA（事实路） | `docs/team/reviews/<Stage>v2-{产品,事实}审查.md` | **审查者不改被审文件** |
| ④ 多轮修订 | 主笔（+ 闭合复核） | 正文 + 各篇「变更记录」 | 每条意见必须给 **采纳/部分采纳/不采纳（写理由）** |
| ⑤ Lead 核验定稿 | **Lead**（不采信自述） | `docs/team/reviews/S<N>v2-定稿核验-Lead.md` | **放行后**下一阶段才可开 |

**【已实现】六份记录都按这五步走完**：`S1`–`S6-定稿核验-Lead.md` 各 1 份，每份都含「两路审查的 P1 与处置」节。

**安全阀**（主笔在**还能写好时**主动换人；本项目**实战两次**）见 §7。

| 规则 | 内容 |

## 3. 每阶段的交付物

| 类型 | 路径 | 上限 / 要求 |
| --- | --- | --- |
| 提纲（过程件） | `docs/0X-*/_提纲.md` | **≤200 行**；含文件清单、逐篇分节、门、待裁决 |
| 正文 | `docs/0X-*/*.md` | **每篇 ≤400 行**；头部五字段；文末**开放问题**（无则写"无"） |
| 拆篇 | `docs/0X-*a-*.md` | 超 400 行时拆，入口仍是 `0X` |
| 机检件 | `docs/0X-*/_gate.sh` / `_sens.sh` / `_count.sh` | **Lead 所有**（§4）；非文档，不计入行数 |

| 调研 | `_research/**` | 一人一文件；**不得改已冻结调研**（要纠正就新建一条并注明"更正 `S<n>-<m>`"） |

**形态判据**（README §3.3 的机检口径，本篇只给命令）：行数 `wc -l`（**不是** `len(text.split('\n'))`，见 §7）；行长 **Python `len(str)` 字符**（**禁 `awk length`**，数的是字节）；相对链接 **0 MISS**（豁免见 §4 的 `A4` 规则）。

## 4. 机检门制度（**新机检件上线前必须自证**）

### 4.1 属主与清单

| 项 | 规则 |
| --- | --- |
| **属主** | 所有阶段机检件 **Lead 所有**（`docs/0*/_*.sh`、`docs/team/*.sh`）；写手**不新增**机检件，需要时**报 Lead** |
| **清单与"会 FAIL？"分类** | **唯一出处 = [`03 §4`](03-质量门与命令手册.md)**（`dev-doc`）——本篇**只引、不列数**（`P17`：同一数字多处写必漂移） |
| 调用方式 | `bash docs/0X-*/_gate.sh`；**退出码语义（`0=PASS ｜ 1=FAIL ｜ 2=环境异常`）的唯一出处 = [`03 §4.1`](03-质量门与命令手册.md)** |

### 4.2 新机检件上线**四要件**（缺一不得作为"门"呈现）

| # | 要件 | 对应资产 |
| :-: | --- | --- |
| 1 | **正本 PASS**：在正本上跑一遍，必须 PASS | `P1` |
| 2 | **变异 FAIL**：对已知坏样本（回滚/注入）必须 FAIL | `P1` |
| 3 | **变异自证生效**：变异前先断言变异串在原文存在且 **count == 1**，贴 **before/after** | `P2`（→ [`02 §3`](02-独立审查与冻结纪律.md)）、`P3`（→ §5） |
| 4 | **输入缺失 ≠ PASS**：找不到输入必须 **FAIL 或 `rc=2` 环境异常**，**不得"跳过"** | `P13`（→ [`02 §3.2`](02-独立审查与冻结纪律.md)） |

**两条附加**：

- **`P11`｜不能变红的检查，不得作为"门"呈现**：内联检查器的**每一项**都要能演示 **正本 PASS + 变异 FAIL**；演示不出 ⇒ **修到能红，或删掉并指向权威判据**。来源事故：Stage 4 `07 §3` 的 `A1` **变异后仍 PASS** ⇒ 交付者**如实登记「本项未成立」**并声明以 `_gate.sh A4` 为准（`S4 §7`）。**一个不会红的判据比没有判据更危险**——它给出"已验证"的错觉。
- **`P12`｜门与文档不得互调而不设守卫**：允许"文档内联检查器**回调门**"（单一权威），但**必须**有**嵌套守卫**（如 `ARCBLOG_GATE_NESTED`）+ **硬超时**（超时视为 FAIL）。来源事故：门 `A5` 执行文档脚本、脚本**回调同一门** ⇒ **无限递归、门挂死 60 s+**；**静态审查看不出环路，只有真跑才暴露**（`S4 §7`）。

## 5. 编辑与补丁纪律（`P3`）

| 规则 | 判据 |
| --- | --- |
| **逐项 replace**，并报**命中/未命中** | 每项 replacement 输出 `命中` 或 `未命中`；**锚点不存在时整批不生效、不得半途落盘** |
| **锚点既不能太窄，也不能太宽** | `assert text.count(old) == 1`（**断匹配数恰为 1**）**或**直接**按行号锚定**；**"未命中"与"命中过多"都要拦** |

**来源事故（【已实现】，人民币级教训）**：`doc-owner` 用**不存在的锚点**触发断言 ⇒ 整批未生效（幸而可检测，`S3 §8-4`）；**同一人**被要求"删第 146 行"时用**宽松谓词**筛选，**多删了第 122 行**（正确的 `A1` 打印行）⇒ `S4 §7` 的加强条。

> **口诀**：**锚点太窄会静默不生效，锚点太宽会静默多删**——两者都不报错。

| # | 规则 | 反例（真实） |

## 7. 安全阀（主笔换人）与量法自证

| 项 | 内容 |
| --- | --- |
| **触发** | ① 主笔上下文预算耗尽；② 连续两轮无实质产出；③ 主笔**主动判断"再写会写浅"**（正解，不是失败） |
| **交接物三件** | ① **已落盘半成品**（提纲 + 已写篇 + 调研，全是文件）；② **续写登记**（谁写了哪几篇、哪几篇未写、口径基线）；③ **新主笔必须回仓库校验前任的数字**（不照抄） |
| **登记处** | 该阶段冻结记录的「作者交接」/「诚实登记的局限」节 + `docs/team/journal/` |
| **本项目两次实战** | ① Stage 5：`doc-owner → dev-doc`，新主笔接手后抓出 `00:81` 页面计数错（26 → 实测 30）；② Stage 7：`dev-doc → doc-std`，新主笔复测抓出 `reviews` 20→27、`journal` 13→14 |
| **反向纪律** | 能自己写好时**不许换**；交接必须**先落盘再叫人** |
| **判据（已裁 T5：沿用两次实战）** | 本节**每条交接物都能指到至少一个实例**（本项目已有**两次**换人）；只写触发条件 ⇒ 落不回实例、下一个人不知道"交接物长什么样" |

**量法自证（`P14`，定义点 = [`02 §6.1`](02-独立审查与冻结纪律.md)）**：换人交接时，**前任的数字与新主笔的数字不一致**是常态——两份都要给**量法 + 输出**，用**两个独立量法**复算，再判谁对。`S1 §7-4` 就是一次：**行数用 `wc -l`**（`len(split('\n'))` 会多算一个末尾空行）而**行长**才用 Python `len(str)`。
