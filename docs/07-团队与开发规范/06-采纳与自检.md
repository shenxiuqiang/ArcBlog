## 2. 采纳机制（**审查意见 → 采纳判定**）

### 2.1 三档判定（**每条都要给理由**）

| 档 | 何时用 | 必须写清 |
| :-: | --- | --- |
| **采纳** | 意见成立；**处置表逐条**给落点 | 改了什么 + **新 hash** |
| **部分采纳** | 方向对但**范围/落点需调整** | **采纳哪半、不采纳哪半、为什么** |
| **不采纳** | 意见不成立（**含"我认为不同族/不成立"**） | ⚠️ **必须写清为什么**，并**留痕**（不是沉默不改） |

### 2.2 两条硬要求

1. **不采纳也要留痕**：审查记录/变更记录里写明"**该条不采纳 + 理由**"——否则下一轮会**重复提出同一意见**（把"已裁定"当成"未处理"）。
2. **"不同族"这类判断必须给判据**，不能只表态。

### 2.3 本会话的**真实实例**（可作范例）

| 实例 | 判定 | 理由（留痕） |
| --- | --- | --- |
| `qa` 认为 `03` 的 `U1–U3` 与 `07` 的 `U*`"**不同族、不算悬空**" | **Lead 不采纳** | `07:43` 明写"**本篇是唯一分配点**…不得在没有定义的情况下引用" ⇒ **同号在两处指不同东西**正是该规则要防的歧义 ⇒ 要求消歧（最终 `03` 改 `TS-1…TS-3`） |
| `pm R4`（缺优先级口径） | **采纳** | 补 `03 §0` 口径 + **回扫 13 条**；`DEF-10` 因"不可见但**要动手**"维持 P2，并**据此收紧 P3 判据**（改口径边界、不改档位） |
| `qa P1-2`（`04 §4` 阻塞值与 `01` 矛盾） | **采纳（删列方案）** | 阻塞值是**台账字段**，唯一源 = `01`；且原三值按 `00 §2.2` **本身是错的**（`ENG-*` 属**本行工作** ⇒ 不得用 `待前置`） |
| `qa P3`（`monospace+copyable`"29 行含 1 行 `//`"） | **部分采纳** | **口径**按要求补全（`28 行 / 87 次 / 注释 0`）；但 qa 的 **29 复现不出**（全仓含该串的行里 `//` 注释行 = **0**）⇒ **差异不重要、口径写清才是要求**（本轮先给可复算口径，并请 qa 给 glob） |

### 2.4 收到意见后的**动作顺序**（照 [`stage-7 §2.1`](../team/stage-7-入口口径-Lead.md)）

**先核事实 → 再判采纳 → 后改文**：① 复现对方说的现象（**先自证我的量法** — `A11`）；② 判定档位并**写出理由**；③ 改文（**补丁带 `count == 1`** — `A6`）；④ 跑门 + 报 hash；⑤ **连带面扫全库**（`A8`，工具 = `bash docs/team/fact-sweep.sh '<短语>'`）；⑥ 若改的是冻结面 ⇒ **走六步**。

## 4. 一套完整例程（**交付前照着走**）

```text
① 写完后：逐条过 §1 A1–A14（答不出的当场补，不要"下次注意"）
② 形态：wc -l / Python len(str) / 链接自检
③ 数字：逐个数字补命令；计数补"glob + 出现数 + 行命中"
④ 引用：读完整节 + 读出限定范围；未落盘的标「Stage N 未落盘」
⑤ 复述：对每句事实性断言跑 `bash docs/team/fact-sweep.sh '<短语>'`，列清单并逐条判断
⑥ 派生表：逐字段问"这是引用还是自造"；自造 ⇒ 引或删
⑦ 门：validate（解析 ok/issues）+ npm test（passed）+（触 .aup/world 时）npm run build
⑧ 变更记录：改了必写一行；冻结面走六步
⑨ 汇报：路径 + wc -l + hash + 门输出（原样）+ 遗留；不报"打算做"
```
