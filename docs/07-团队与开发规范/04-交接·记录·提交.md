## 1. 提交纪律（**唯一提交人 = Lead**）

| # | 规则 | 判据 |
| :-: | --- | --- |
| **S1** | **唯一提交人 = Lead**，在**检查点**提交（阶段冻结后 / 每轮收尾） | `git log` 的 author 只有 Lead |
| **S2** | **teammate 禁止** `git commit` / `git push` / `git reset --hard` | 任何 teammate 提交即违规 |
| **S3** | **精确 `git add`**：**只 add 本线产物**（`docs/**`、入口三文件）；**不得 `git add -A`** | 提交的文件集合 = 本线清单 |
| **S4** | ⚠️ **只核路径不够：提交前必须 `git diff` 过内容** | 事故（2026-09-30）：`git add docs`（宽路径）把**另一会话**对已冻结文件 `docs/05-开发文档/02` 的修改与一份新 journal 一并纳入提交 `f77d680`。处置 = **追认**（内容正确、有实测依据，不回退他人工作）+ 更正版本标签 + **定新纪律**：任何 `docs/**` 内的外来改动，**先甄别（事实对齐 vs 越界改写）再决定纳入或分离** |
| **S5** | **push 由人类决定**（本会话 7 次提交全部**本地**，未 push） | 人类批准记录 |
| **S6** | 提交信息写清：**含哪些阶段 / 门结果 / 排除了哪些非本线改动** | 提交信息可读 |

## 2. ⚠️ 当前工作区状态（**不假装已经提交过**）

| 项 | 事实 |
| --- | --- |
| **人类指令** | **「期间不提交」**（本批全程有效） |
| **因此的现状** | **工作区未提交**；**基线 commit 仍是 `4597ba2`**（`git rev-parse HEAD` 实测）——`docs/01`–`docs/07` 的产出**都在工作区** |
| **基线口径** | 本轮所有文档里的"**基线 commit `4597ba2`**"指的都是**这个未变动的 HEAD**；**不要**把它读成"已提交" |
| **规范的写法** | 本篇写的是"**何时可提交 + 提交前必须核什么**"（S1–S6 与 §3 的检查点），**不是**"提交记录清单"——**本轮没有可供列举的提交** |

> **推论（重要）**：因为**未提交**，"**回滚**"在本轮**不是安全网**——`git reset --hard` 会抹掉**未提交的整轮工作**（历史事故 `BUG-079`）。⇒ **防丢失只能靠"Lead 及时在检查点提交"**，**不能**靠"反正能 reset"。

## 3. 检查点与"提交前必核"清单

**何时可提交**（三个条件**同时**成立）：

| # | 条件 | 判据 |
| :-: | --- | --- |
| 1 | 阶段（或轮次）**已冻结** | 该阶段的 `S*-定稿核验-Lead.md` 存在且状态为已放行 |
| 2 | **门全绿** | `arc dsl validate --json` → `ok: true` 且 `issues: []`；`npm test` → `fast tier passed`；触 `.aup`/`blocklet.yaml`/`world/**` 时**另有** `npm run build` 通过（[`03 §1`](03-质量门与命令手册.md)） |
| 3 | **人类检查点已过**（若本批含 §5 的动作） | 人类批准记录 |

**提交前必核（逐条，缺一不可）**：

| # | 核什么 | 命令/判据 |
| :-: | --- | --- |
| C1 | **只 add 本线** | `git status --porcelain` 逐条与该轮写范围对照 |
| C2 | **过 `git diff` 内容**（**不只核路径**） | 甄别外来改动：**事实对齐** ⇒ 可纳入；**越界改写** ⇒ **分离**（`S4` 事故） |
| C3 | **门结果**已记录（含**解析出的** `ok`/`passed`，非退出码） | [`03 §1`](03-质量门与命令手册.md) |
| C4 | **文档轮机检件**（若有）已跑且**正本 PASS** | [`03 §4`](03-质量门与命令手册.md) |
| C5 | **受控修订已回填**（若本批改过冻结面） | 六步齐（[`stage-7 §2.1`](../team/stage-7-入口口径-Lead.md)） |

## 6. 断点与恢复（**未提交状态下**）

| 场景 | 做法 |
| --- | --- |
| **会话中断** | 恢复靠**文件**：读 `docs/team/**` 的核验记录 + §4 的三个载体；**不靠记忆** |
| **误删/覆盖** | ⚠️ **不能**用 `git reset --hard`（会抹未提交工作 — `BUG-079`）；应**报 Lead**，由其决定**从其他来源恢复**（`dist/` 产物、他人副本、`git` 未提交的工作区） |
| **hash 漂移不明** | **挂起、不确认**，直到澄清（事故：属主看到"自己没做、也查不到来源"的漂移 ⇒ **非属主编辑必须在被编辑文件留痕**，见 [`05 §6`](05-文档与代码规范.md)） |
| **跨会话协作** | 每次交接**先报产物路径 + 验证命令 + 实际结果**（`AGENTS.md` 铁律 7）；**不报"我打算做"**（[**P16**](../team/stage-7-入口口径-Lead.md)） |
