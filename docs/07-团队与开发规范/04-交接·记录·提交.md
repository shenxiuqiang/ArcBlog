## 1. 交接靠文件，不靠记忆

| 规则 | 内容 |
| --- | --- |
| **结论落盘** | 任何"我们决定了 X"必须出现在 `docs/**`；`send_message` **只负责叫醒 + 一句摘要**，不是载体 |
| **交接物是文件** | 提纲 + 正文 + 调研 + 冻结记录；对话上下文**不是**交接物 |
| **叫醒消息格式** | 目标 + 产物路径 + 一句结论 + 请对方做什么（例："`02` 已写完，请两路审查，基线见消息尾部 sha256"） |
| **完成即汇报（固定格式）** | **产物路径 + 验证命令 + 实际结果**（`AGENTS.md` 铁律 6） |

### 1.1 本篇起的汇报加强版（Stage 7 实操）

```text
产物路径 + 验证命令 + 原样输出 + 行数 + sha256 + 遗留
```

**为什么加后三项**：① 行数对应 G6 的 ≤400 行；② `sha256` 让 Lead 的冻结快照**可逐字节复核**（[`02 §7.1`](02-独立审查与冻结纪律.md)）；③ "遗留"是待办载体二（§2）的入口。Lead 的核验记录就是按这个格式回填的（例：`S2-定稿核验-Lead.md` §1 标题"与主笔回报逐字节一致"）。

## 3. 提交纪律（**唯一提交人 = Lead**）

### 3.1 规则表

| # | 规则 | 判据 / 证据 |
| :-: | --- | --- |
| 1 | **唯一提交人 = Lead**；teammate **禁止** `git commit`/`push`/`reset` | `AGENTS.md` 铁律 4；【已实现】本轮 Stage 7 的提交 `2229367 docs(stage 7): workflow and stage gates` **由 Lead 做**，主笔只回报 `sha256` |
| 2 | **检查点提交** | 阶段冻结后 / 每轮收尾；不是每写一篇就提交 |
| 3 | **精确 add**：只 `git add` 本线产物（`docs/**`、`_docs/**`、三个入口文件） | **绝不 `git add -A`** |
| 4 | **⚠️ 提交前必须 `git diff` 过内容**，不只核路径 | `f77d680` 事故：`git add docs`（宽路径）把**另一会话**对已冻结 `05-开发文档/02` 的修改与一份新 journal 一并纳入 |
| 5 | **外来改动先甄别** | 三步：① 是**事实对齐**还是**越界改写**？② 有没有实测依据？③ 决定**纳入（追认 + 升版本）**还是**分离（不 add）** |
| 6 | 提交信息写清 | "含哪些阶段 / 门结果 / **排除了哪些非本线改动**" |
| 7 | **push 由人类决定** | 本轮 7 次提交全部本地，未 push |

### 3.3 为什么"只核路径"不够（本轮真实工作区）

```bash
$ git status --porcelain | wc -l
      18          # 时点快照（2026-09-30；**随阶段推进必变**，不是判据）
$ git log --oneline -1
0c046d6 docs(stage 8a): complete index side; stage 7 reviews in      # 同上，时点值
```

> **`git` 事实只写命令与口径，不写死值（R4）**：`HEAD` 的 sha 与工作区条目数**每轮都在变**（本阶段观察到的序列：`2229367`/20 → `aec2a10`/19 → `0c046d6`/18）。⇒ 下游要判"谁提交的"用**判据式命令**：`git log -1 --format='%an %s'`（提交人必须是 **Lead**）；要判"有没有别人的在途改动"用 `git status --porcelain | wc -l` **当场跑**。**上面两个值只是"取数时刻的快照"。**

工作区长期有**另一会话的在途改动**（`scripts/`、`.aup/locales`、`dist/**`…）⇒ `git add -A`／宽路径 `git add docs` 都可能把别人的工作卷进来。**判断依据只能是 `git diff` 的内容**。

## 4. 防丢失（BUG-079 的教训）

| 现象 | 根因 | 规范动作 |
| --- | --- | --- |
| 另一会话轮末把 `.aup/pages/**` 还原到 HEAD，**4/7 重构被抹且无副本** | 两个 Lead 会话**共用工作区**，无锁、无目录分区 | ① 产物落地即 `cp` **仓库外**副本 + 回报 `sha256`；② **每波开始先看 `git status`/`git log`**；③ **绝不 `git add -A`** |

**两条操作口径**

1. **落地即备份**：每篇正文/关键产物写完后 `cp <file> /tmp/s7-<name>.bak` 并回报 `sha256`（本轮每篇回报都带 hash）。
2. **开工先看历史**：新一波开始前跑 `git log --oneline -1` + `git status --porcelain | wc -l`，确认"有没有别人的在途改动 / 上次提交是谁的"。

> 与"唯一提交人 = Lead"**不冲突**：防丢失靠 **Lead 及时提交 + 仓库外副本**，**不靠放开 teammate 的 git 权限**（底稿 §2）。
