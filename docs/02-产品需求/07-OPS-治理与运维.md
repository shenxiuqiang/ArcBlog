## 3. 需求条目

### 3.1 PRD-OPS-01 · 巡检与告警（**回退事故的修复**）

> **已确认：维持（Lead 裁决 Q9，2026-09-30；原 O-OPS-3 = A）**：本条与 `?page=operations` 的**职责边界维持现状**（dashboard = 异常与快捷；operations = 节点身份与项目复盘）。**Stage 3 已确认维持**（见 [`docs/03-产品设计/00-设计原则与导航.md`](../03-产品设计/00-设计原则与导航.md) §3/§4），若后续要合并须回改本条并在变更记录留痕。

**§1 背景**：`03 §4（J4 节点运营）` J4-1；现状——`?page=dashboard` 的 `propBind` = **0**、无 `network/alerts` 键 ⇒ **异常提醒条已从源码回退**，而归档清单仍标 ✅（`R2 §0`、`S2-01`）。`spec:946` 承诺"30 秒发现异常 + 一次点击直达"。
**§2 范围**：做——一屏指出异常（角色/身份/Hub 关系/存储四类）+ 每项**一次点击直达**处置页。不做——不做后台轮询告警（无周期 worker，见 `PRD-NET-04`）。
**§3 验收标准**
- **A1** 四类异常各有构造用例，各自在 `?page=dashboard` 可见（DOM 可观察）。
- **A2** 每项异常**可点击直达**对应处置页（链接可达，不出现死链）。
- **A3** 全部正常时显示"无异常"空态**且给出下一步**（不是空白）。
- **B1（负例）** 不得用 toast/单次提示代替常驻异常区（回退事故即"提醒消失"）。
- **B2（负例）** 不得显示**无数据支撑**的健康绿灯（`propBind` 未绑定时应显示破折号 + 说明）。
- **C1** `npm test` 快层通过（含 UI 预算与运行时 id 守卫）。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`.aup/pages/admin/dashboard.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.2 PRD-OPS-02 · 自检与诊断

**§1 背景**：`03 §4（J4 节点运营）` J4-4；现状【已实现】——`?page=diagnostics` 列出自检项（与 `arcblog-doctor.mjs` 的权威清单一致），**但页内零执行**（`grep -cE '(exec:\|events=)'` = 0）。
**§2 范围**：做——**自检项可视化**（**不得写死项数**：项数由 `arcblog-doctor.mjs` 的权威清单 / `doctor --json` 输出取，页面与文档都不写数字）、每项给**可复制命令**、空/错态明确。不做——不做页内执行（平台无 `exec` 原语，见 §4）。**理由**：`diagnostics.aup:15` 自身声明"本页不写死任何数字"，文档写死会与页面纪律相抵（qa 事实审查）。
**§3 验收标准**
- **A1** 页面列出的自检项与 `arcblog-doctor.mjs` 的权威清单**集合相等**（**id 集合**一致；**不断言顺序**——qa 闭合复核 ND3：检查项记录 `{id,severity,ok,detail,ranAt,command}` **无 `index` 字段**，页面 `afs-list` 按 id 字典序、`doctor` 按执行序，两组顺序实测不同；**若将来确需顺序，须新增显式 `index` 字段并作为独立需求在 Stage 6 提出**，本阶段不加字段）。
- **A2** 每项给出可直接复制的命令（可观察：代码块文本存在）。
- **B1（负例）** **不得有"运行"按钮**（页内无法执行；假按钮 = 红线 1）。
- **B2（负例）** 不得把"页面显示通过"当作自检通过（**唯一判据 = 解析 `doctor --json` 的 `success` 字段与原始输出**——`arc afs exec`／`arc` 类命令**出错时退出码仍可能是 0**，见 `00 §9` 第 12 条）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：**`R3 §4-19`**——页面无哈希/时间/签名原语，且页内不能执行服务端命令；降级 = 只读展示 + 可复制命令。**§5 依赖**：无。**§6 写范围**：`.aup/pages/admin/diagnostics.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.3 PRD-OPS-03 · 数据维护（残留清理）

**§1 背景**：[`00 §12.1（上游断链接收）`](00-需求地图与规范.md) **第 1 条**（证据：`R1 §2（现状基线）`）；现状【已实现】CLI——`arcblog-clean.mjs` **默认 dry-run**、`--confirm` 才执行（**概念层零覆盖**，`S2-01` 断链①-1，脚本本体归 **Stage 5/7**；**其面向运营者的可见反馈**由本需求承接）。
**§2 范围**：做——清理**可预演**（列出将删项）、清理结果可核对。不做——不做清理脚本本身（归 Stage 5/7）；不做自动清理。
**§3 验收标准**
- **A1** dry-run 输出将删项清单，**实际零删除**（前后计数一致）。
- **A2** `--confirm` 后删除集合 = dry-run 列出的集合（逐项比对）。
- **B1（负例）** 无 `--confirm` 时**必须**零删除。
- **B2（负例）** 不得删除非测试前缀的记录（区分前缀规则可判）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`scripts/arcblog-clean.mjs`（阅读与反馈面）。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.4 PRD-OPS-04 · 部署反馈与密钥门禁告示

**§1 背景**：`R4 §3（事故复盘）` 记 BUG-067/BUG-074——**构建产物携带真实私钥**（`dist/` + Pages 两条通道，40 份副本、155 个部署）；`00 §12.1` 第 4 条把"构建/部署的**可见反馈** + 密钥门禁的**告知面**"划给本领域。
**§2 范围（Lead 裁决 O-OPS-1 = B：告示面落**页面只读提示条**）**：做——运营者能在界面上知道"当前构建是否通过密钥门"、部署产物是否干净。**形式约束（不得违反）**：提示条**只写一行 + 指向 runbook**；**不得**变成第二份必读文档；**不得**用 toast 代替。不做——不做扫描器与部署脚本本身（**Stage 5/7**）。**理由**：`PRD-OPS-04` 要的是"密钥门禁**在界面上被告知**"——runbook 解决"怎么做"，不解决"运营者知不知道"。
**§3 验收标准**
- **A1** 页面/文档给出**唯一安全构建入口**（`npm run build` = build + `scrub:dist-secrets`），并说明裸 `arc blocklet build` 的危险。
- **A2** 密钥门结果可观察（最近一次门禁结果与时间），**不以 `Status: up` 为判据**。
- **A3（O-OPS-1 约束）** 告示面是**一行只读提示条**且含指向 runbook 的链接；不得出现第二份需通读的文档入口。
- **B1（负例）** 不得提供"跳过密钥门"的入口或文档表述。
- **B2（负例）** 不得声称"部署成功即安全"（必须看密钥扫描结果）。
- **B3（负例）** 不得用 toast/一次性提示代替常驻提示条。
- **C1** `npm test` 快层通过（含 `arcblog-dist-secrets` 用例）。
**§4 平台边界**：**构建产物不受 blocklet 的 ignore 控制**（平台无该开关）⇒ 只能靠**外部 purge + 门禁**；细节指向 `05-开发文档/` 平台边界篇（Stage 5）。**§5 依赖**：无。**§6 写范围**：文档面（`docs/05-开发文档/` 交付时回填）+ 首页运维提示（若有）。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁 **O-OPS-1 = B**：页面只读提示条——见 §2 与 §5.1）。

### 3.5 PRD-OPS-05 · 退出与搬迁

**§1 背景**：`03 §8（J8 新建节点）` J8-3、`02 §5（O 节点运营）`（成功标准含"带着数据离开"）；现状——角色退出四步【已实现】；**数据导出/迁移**在概念层属"借的模式"（`01 §5.1（与相邻产品）`），**无落点**（`S2-01` 断链②-10）。
**§2 范围（Lead 裁决 O-OPS-2 = A：**全量导出不立项**）**：做——退出后的数据承诺（内容不消失、在途订单按当时版本结算、注册关系 Tombstone），以及**"可逐条读出"的断言**。**不做**——**不做一键全量导出**（不占需求位）。**理由（与 `PRD-ECO §3.8` 账本导出同源）**：全量导出是**数据出域**问题（字段清单、脱敏规则、授权人范围），需人类先定隐私口径；**人类可随时推翻本条**，但在那之前不占需求位。
**§3 验收标准**
- **A1** `revoke` 后：已发布内容**仍可读**；Hub 注册关系被标失效并留 Tombstone；在途订单按当时 `settlementVersion` 完成。
- **A2** `claim` 后角色可重新激活（无需重新购买）。
- **B1（负例）** 退出**不得**删除内容、账本、订单（只增不删）。
- **B2（负例）** 等待期内**不得**允许 `claim`（先 `revoking` 后 `claimable`）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无。**§5 依赖**：`PRD-ID-04`；**"数据可带走"以"可逐条读出"为断言口径**（不做全量导出，见 O-OPS-2）。**§6 写范围**：`scripts/arcblog-roles.mjs`、`scripts/arcblog-network.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：全量导出不立项）。

### 3.6 PRD-OPS-06 · 权限边界自证

**§1 背景**：`03 §4（J4 节点运营）`；现状【已实现】——未声明路径**默认拒绝**（`Forbidden: path is not a declared replicated collection`）；`config` 整树 admin；`networkRead` 只是**前缀增补**（`R3 §4-9` 同族）。
**§2 范围**：做——边界可自证（谁可读哪些前缀）。不做——不做权限编辑器。
**§3 验收标准**
- **A1** guest 读任一未声明路径 → 返回 `{"success":false,…,"Forbidden"}`（**判据 = 解析 JSON 的 `success` + 错误码字符串**，至少 3 条不同前缀各断言一次；**不得只断言退出码**——`arc afs exec` 出错时 `$?` 仍为 0，见 `00 §9` 第 12 条）。
- **A2** `config/**`、`economy/{orders,settlements,ledger,access-grants}` guest 全部被拒。
- **B1（负例）** **不得**用 `networkRead` 表达"收紧权限"（它不能收回权限）。
- **B2（负例）** 父前缀 guest 不得泄漏子目录列目录（`R3 §3 P1` 同族）。
- **C1** `scripts/arcblog-permissions.test.mjs` 通过。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`blocklet.yaml`（权限表）、`scripts/arcblog-permissions.test.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无。

| ~~O-OPS-3~~ | dashboard 与 operations 的职责边界 | **A：维持现状分工。**理由：① dashboard 异常与快捷是**回归修复点**（`PRD-OPS-01`），不要在同一轮又挪职责；② 目标 IA（spec §15.2 D 组）尚未实施，现在合并会与 Stage 3 撞车。**已在 `PRD-OPS-01` 顶部加「待 Stage 3 确认」栏** |
