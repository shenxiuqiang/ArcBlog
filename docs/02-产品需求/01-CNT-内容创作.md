## 3. 需求条目

### 3.1 PRD-CNT-01 · 控制台写入署名（**本领域 P0，全 Stage 2 先做**）

**§1 背景与来源**
- 概念层口径：`01 §4.2（最短路径）` 定为"**可发布；署名不可信**"——页面可提交，但署名走 `$session.*` 的写法今天不可信。
- 一手现状（`S2-03 §7`）：`exec` 的 `content` 内 `$session.` 共 **7** 处——`compose.aup:168`、`:169`、`pages.aup:168`（`authorDid` **3** 处）＋ `factory.aup:200-203`（链意图 `requestedBy` **4 处**，与 BUG-003 同族）。
- 归档来源：[`控制台署名需求（归档）`](../../_docs/team/requirements/REQ-041-console-author-identity.md)（Lead 已采纳）。**本需求引用它，不另起编号、不改写其结论。**

**§2 范围**
- **做**：把上述 **7 处**改为"页面只写意图 → 本机 worker 用既有 CLI 落库"，使落库署名恒为真实 DID；并交付**静态守卫**防复发。**同一条需求内分两组**（Lead 裁决 O-CNT-2）：
  - **A 组 · 内容署名（3 处）**：`compose.aup:168`（存草稿）、`:169`（发布）、`pages.aup:168`（静态页创建）——**必须**满足完整判定式（`^did:` ∧ ≠字面量 ∧ ≠空串）。
  - **B 组 · 链意图审计字段（4 处）**：`factory.aup:200-203` 的 `requestedBy`——验收**可略弱**（只要求 ≠ 字面量 ∧ ≠ 空串），因为它**不参与内容签名**；但**必须同批修、同一个守卫覆盖**。
- **不做**：① 不改 `visible`/表达式位的 `$session`（那是正当用法，改了会破门禁）；② 不引入页面侧哈希/签名（页面无该原语，`R3 §1`）；③ 不改 CLI 的 `--author-did` 语义；④ **不预选实现路径**（见下方"两条并列路径"）。
- **理由**：`arcblog-doctor.mjs:122` 只测**空**署名，字面量非空 ⇒ 今天唯一能防复发的是静态守卫。
- **编排：探针优先、PRD 并列两条路径不预选**（Lead 裁决 O-CNT-1）。探针结论直接决定成本量级，**在未验证前选任一条都是赌博**：

| 路径 | 形态 | 适用条件（探针结论） | 成本量级 |
| :-: | --- | --- | :-: |
| **路径 1 · 意图队列** | 页面写 `config/compose-intents/`（或复用 `page-intents/`）→ worker 走 CLI 落库 | 探针证明**页面 `content` 内无法表达真实 DID** | 大改（新增队列 + worker + 页面改线） |
| **路径 2 · 改一处写法** | 找到一种在 `content` 内表达真实 DID 的写法（如经 `args` 通道），保持页面直写 | 探针给出**可用写法且对未登录/其他身份不退化** | 小改（改 7 处写法 + 守卫） |

**前置门（不得绕过）**：**一次性登录态探针（P-0…P-5，见 §2.1）未跑 = 本需求不得进入实现**。需要登录会话时**报 Lead**（由 Lead 请人类提供），**执行者不得自行取 cookie**。

**§2.1 探针设计（P-0…P-5；内联自 [`S2-03 §5`](../08-其他/调研/S2-03-P0需求深挖-付费闭环与署名.md)，判定式在此唯一出处）**

| 步 | 动作 | 命令 / 判定 |
| :-: | --- | --- |
| **P-0** | **只读先行（今天可跑，零写入）**：建立负例基线 | `grep -rn 'authorDid: \$session\.' .aup/pages/` → **3 处**（`compose.aup:168`、`compose.aup:169`、`pages.aup:168`），另 `grep -rn 'requestedBy: \$session\.' .aup/pages/` → **4 处**（`factory.aup:200-203`）；再扫 `drafts`/`page-drafts` 是否存在字面量/空署名记录 |
| **P-1** | 登录后 `?page=compose` 提交 1 条草稿（固定前缀 slug，如 `qa-cnt01-probe`） | 需要一次可登录会话（Lead 向人类申请；**本轮受限**） |
| **P-2** | 回读落库形态 | `arc afs exec /blocklets/arcblog/.actions/read --args '{"path":"/instance/app/arcblog/drafts/qa-cnt01-probe.json"}' --json` |
| **P-3** | **判定** | `content.authorDid` 必须匹配 `^did:` **且** ≠ `$session.did` 字面量 **且** ≠ 空串；`authorName` 不得是 `$session.displayName` 字面量。三者任一不满足 ⇒ 页面路径**不可信** |
| **P-4** | 同法验证静态页面路径 | `?page=pages` 新建 `qa-cnt01-page` → 回读 `page-drafts/qa-cnt01-page.json`，判据同 P-3 |
| **P-5** | 清理 | 用既有 CLI 删除探针记录（**不静默改写历史**）；计数复原 |

**若 P-1 无法获得登录会话**：只做 **P-0** + 标**【未验证】并写明受限原因**，**不得**据 `_docs/arc-contracts.md` §28.7 直接断言"一定落成字面量或空串"（那是把**带引号**的实测外推到**不带引号**的写法）。

**§3 验收标准**
- **A 组（功能）**
  - **A1** 静态度量：`grep -rn 'authorDid: \$session\.' .aup/pages/ | wc -l` → **0**（改前为 **3**）；`grep -rn 'requestedBy: \$session\.' .aup/pages/ | wc -l` → **0**（改前为 **4**）。
  - **A2** 有登录会话时：`?page=compose` 新建草稿 `qa-cnt01-draft` → 回读 `AFS:drafts/qa-cnt01-draft.json`，`content.authorDid` 同时满足：匹配 `^did:` **∧ ≠** `$session.did` 字面量 **∧ ≠** 空串；`authorName` 不得是 `$session.displayName` 字面量。
  - **A3** 同法验 `?page=pages` 新建 `qa-cnt01-page` → `AFS:page-drafts/qa-cnt01-page.json`，判据同 A2；再走 Publish → `posts`/`pages` 副本的 `authorDid` **仍**满足该正则（发布重写不得覆盖）。
  - **A4** **B 组（链意图 4 处）**：`?page=factory` 触发一次链意图 → 回读 `AFS:config/chain-intents/<id>.json`，`requestedBy` ≠ `$session.did` 字面量 **∧** ≠ 空串；**并断言它仍未参与内容签名**（`arcblog-verify.mjs` 的覆盖字段不含 `requestedBy`）。
  - **A5** worker 落库后，页面能观察到 `pending → running → applied`（词表唯一出处 = `docs/03-产品设计/`，本文不定义）。
- **B 组（负例 / fail-closed）**
  - **B1** **worker 未运行时**：不得出现任何 `drafts/<slug>.json`（队列停在 `pending`，页面须有常驻说明）。
  - **B2** 构造一条 `authorDid` 为 `$session.did` 字面量的记录（仅一次性探针内）→ **A 组的守卫测试必须失败**；清理后必须通过（先红后绿对照）。
  - **B3** 未登录会话下 `?page=compose` 不得产生任何意图记录（门禁生效）。
  - **B4** 守卫测试**只扫 `exec` 的 `content` 段**：注入一条 `visible=$session.authenticated` 不得被判失败（防误伤）。
  - **B5** 探针记录必须用固定前缀并在 P-5 清理，清理后草稿计数**复原**（不静默改写历史）。
- **C 组（零回归与门）**

### 3.2 PRD-CNT-02 · 内容对象与元数据

**§1 背景与来源**：`03 §1（J1 创作者）` J1-2/5；现状 `R1 §2`【已实现】，但分类下拉**硬编码 3 项**（`compose.aup:146`），新建分类在编辑器选不到。
**§2 范围**：做——必填元数据（标题/slug/摘要/分类/标签/封面/SEO）齐全且**分类选项来自分类资源**；**标签治理（重命名/合并）走"页面写意图 → worker"**（Lead 裁决 O-CNT-4 = A）：页面写 `tags/intents/<id>.json`，由**已存在**的 `scripts/arcblog-tags.mjs apply|watch` 落库。不做——① 不新增可见性档位（平台只有 `public｜paid`，`R3 §1`）；② 不新建队列或 worker（复用既有通道）。
**理由（O-CNT-4）**：标签治理是**跨记录批量重写**（rename/merge 要扫全量），正是意图队列的设计场景；通道已存在，做这条等于把已有通道接回页面，成本远低于新建。
**§3 验收标准**
- **A1** 新建分类 `qa-cnt02-cat` 后，`?page=compose` 的分类控件**包含**该 slug（可观察：控件选项文本）。
- **A2** 表单字段数断言 = **12**（`grep -c '^\s*input ' .aup/pages/admin/compose.aup`）。
- **A3** 标签落库为数组（CLI 路径）或规范化字符串（页面路径），且**小写、≤10 个**（`world/post.yaml` 校验）。

### 3.4 PRD-CNT-04 · 发布与生命周期

**§1 背景与来源**：`03 §1（J1 创作者）` J1-4；现状【已实现】生命周期，但文章页只有 3 个 chip（`posts.aup:172-174`），**缺「全部」「回收站」**（`R2 §1.1` C-p5）。
**§2 范围**：做——补两个视图 + 发布前校验提示；不做——不改状态机本身（`draft→published→archived→published`、`→deleted` 软删）。
**§3 验收标准**
- **A1** `?page=posts` 呈现五个视图入口（全/已发布/草稿/归档/回收站），逐一点击可到达且列表非空语义正确。
- **A2** **分页契约（Lead 裁决 O-CNT-3，逐列表适用）**：① 每个 `total > pageSize` 的列表必须有**可见可操作的真入口**；② 每个 `total ≤ pageSize` 的列表必须**全量渲染**（一行不丢）且**平台不渲染控件、不得伪造入口**。判据：对每个视图分别记录 `total` 与 `pageSize`，两分支各给一次断言；**禁止**按字面"每处都要有翻页入口"（那是平台不可能成立的语义，`S2-02 §2` 第 6 行）。
- **A3** CLI 断言：`archive` 后记录出现在归档视图；`republish` 后回到已发布视图（`AFS` 记录 `status` 逐值核对）。
- **A4** 软删后记录**仍在** `drafts/`（`status=deleted`），可在回收站视图看到。
- **B1（负例）** 发布缺必填字段（标题/分类）→ 被拒且 `posts/` 零写入。
- **B2（负例）** 已发布记录不得因视图切换被删除（计数前后一致）。
- **B3（负例）** `total ≤ pageSize` 时若出现**分页控件或其替身**（如"下一页"假按钮）→ 判失败。
- **C1** `npm test` 快层通过（含分页/列表相关守卫）。
**§4 平台边界**：列表筛选不得依赖下推 `filter`（`R3 §2.1`：只对已内联记录可靠）——视图切换用**目录边界**或独立 `afs-list`，不得引入静默漏文；该条属**约束列**，不单独成需求。
**§5 依赖**：无。**§6 写范围**：`.aup/pages/admin/posts.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无。

**§4 平台边界**：**页内上传落盘**因平台原语限制暂不可用（`media.aup:152` 自认失败）——上传入口标【平台边界】+【规划中】，降级 = 页面只读 + 可复制 CLI 命令（`R3 §3 P3` 的"CLI 折叠"范式）；细节指向 `05-开发文档/` 平台边界篇（Stage 5）。**只读索引与清理不属平台边界**（已实现过，属回归）。**禁止**在本阶段承诺上传可用（`03 §11（体验红线）` 红线 1）。
