## 3. 需求条目

### 3.1 PRD-NET-01 · 节点自描述与健康（含**发布动作**）

**§1 背景**：`04 §5（网络与发现）`【已实现】术语与落点；`S2-01` 断链①-10——`discovery publish` / `health --publish` 的**发布动作**在概念层没有对应步骤（`03 §8（J8 新建节点）` J8-5 只写到"看到自己"）。
**§2 范围**：做——① Discovery Document 与 Node Health 可**发布并回读**；② 文档中的 `roles` / `capabilities` 与 `config/roles.json` 的判定**同源**；③ 如实标注 `endpoints` 为空及其原因。不做——不做 HTTP 端点（平台不可达）。
**§3 验收标准**
- **A1** `arcblog-network.mjs discovery publish` 后 `AFS:node/discovery.json` 存在且字段完整（`protocol/version/node/roles/capabilities/endpoints/transport`）。
- **A2** `health [--publish]` 后 `AFS:node/health.json` 的 `roles` 与 `?page=general` 的角色只读区**逐值一致**。
- **A3** `transport` 声明真实可达通道（`["afs","mcp"]`），`endpoints` 为空**并附原因**（不得省略原因）。
- **B1（负例）** 不得把 Discovery Document 写成 HTTP 服务可得（`/.well-known/arcblog` 返回 AUP 壳，`R3 §1`）。
- **B2（负例）** 节点未建立身份时发布必须 fail-closed（不得落空文档）。
- **C1** `npm test` 快层通过（含 node/network 相关用例）。
**§4 平台边界**：root 级自定义 HTTP 端点不可达（`R3 §2.6`；**§4 未收录 ⇒ 不臆造编号**）——网络层以 **AFS 资源**发布；降级细节指向 `05-开发文档/` 平台边界篇（Stage 5）。
**§5 依赖**：`PRD-ID-*`（节点身份）。**§6 写范围**：`scripts/arcblog-network.mjs`、`scripts/arcblog-node.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.2 PRD-NET-02 · Hub 注册关系（双向）

**§1 背景**：`03 §3（J3 Hub）` J3-1/2；现状【已实现】——关系行三个写动作 + CLI `register/add/approve/reject/remove --purge`；关系 id = `sha256(did)` 前 16 位，**AUP 无哈希原语**（`R3 §1`）⇒ 新关系只能走 worker。
**§2 范围**：做——双向建立与撤回、Tombstone 保留、`sync.*` 字段与关系行一致。不做——不做"注册成功即已同步"的误导（见 `PRD-NET-04`）。
**§3 验收标准**
- **A1** Studio 侧 `register` → 关系 `applied`；Hub 侧 `approve` → `indexed`（AFS 前后比对，不看 toast）。
- **A2** `remove` → 关系 `removed` 且**保留** `removedAt`（Tombstone），历史不丢。
- **A3** 关系行显示的 `direction` 与记录值逐值一致。
- **B1（负例）** **worker 未运行时不得改库**（页面只写意图）；重复点击 3 次 → 关系记录数**仍为 1**（幂等）。
- **B2（负例）** 不得用 `${args.hubDid}` 之类的字面量伪造关系 id（历史上出现过同类污染，`03 §1（J1 创作者）` J1-4 的教训）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无（本需求不触碰禁止项）。**§5 依赖**：`PRD-ID-*`（节点 DID）。**§6 写范围**：`.aup/pages/ops/hub.aup`、`config/hub-intents/`、`scripts/arcblog-network.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.3 PRD-NET-03 · Hub 派生索引与搜索

**§1 背景**：`03 §3（J3 Hub）` J3-4；现状【已实现】——`hub index rebuild/list/search`；索引**只含元数据、永不含正文**；全量扫描约 19s（`scripts/arcblog-network.mjs:22` 注释）。
**§2 范围**：做——索引重建、搜索、Tombstone、版本比对；不做——不做全库正文索引（正文永不进索引）。
**§3 验收标准**
- **A1** `hub index rebuild` 后索引条目数 = 收录 Studio 的已发布内容数（逐值，含 `version` + `contentHash`）。
- **A2** `version`/`contentHash` 未变 → 重跑 `skip`（幂等，条目**逐字节不变**）。
- **A3** 源侧删除内容 → 重建后该条转 `status=deleted` + `deletedAt`（Tombstone），**搜索永不返回** Tombstone。
- **A4** 搜索只返回元数据字段（断言返回体**不含正文**）。
- **B1（负例）** 不得把派生索引当权威：`rebuild` 后人工策展数据**不得被抹掉**（与 `PRD-NET-05` 联测）。
- **B2（负例）** 搜索关键字命中 Tombstone → 必须为空结果。
- **C1** `npm test` 快层通过。
**§4 平台边界**：**`hub/index` 是派生树且 `rebuild` 全量覆盖**（`R3 §1`）——凡人工策展数据必须落**非派生树**；该条属约束列。
**§5 依赖**：`PRD-NET-02`。**§6 写范围**：`scripts/arcblog-network.mjs`、`world/content-index.yaml`、`.aup/pages/ops/hub.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.4 PRD-NET-04 · 同步与新鲜度（**不得写"已同步"**）

**§1 背景**：`03 §3（J3 Hub）` J3-3、`01 §7.2（明确不做）` B6；现状——freshness 四态【已实现】；`hub sync` 写的是**声明值**（Hub 侧 AFS 逐字节不变）；`grep cron blocklet.yaml .aup/app.aup` = **0**（无周期任务）。
**§2 范围**：做——① freshness 四态如实显示；② 同步状态字段与记录一致；③ 周期同步的**目标形态与降级**。不做——不承诺"已同步"。
**§3 验收标准**
- **A1** 四态派生正确：失败→`offline`、未同步→`never`、超期→`stale`、期内→`fresh`（构造 4 个用例各断言一次）。
- **A2** 关系行的 `sync.status/lastSync/lastVersion/lastError` 与记录**逐值一致**（空值渲染平台破折号，不伪造）。
- **B1（负例）** **禁止**任何"已同步/已收录即生效"的措辞或状态色（`R3 §4-4`）。
- **B2（负例）** 无 `lastSync` 时不得显示绿色成功态。
- **C1** `npm test` 快层通过。
**§4 平台边界**：**`R3 §4-4`**——"登记成功 ≠ 已同步"；周期同步（cron）在平台命令面不可用（平台调度存在但 `arc` 面 0 命中）⇒ 今天的"周期"= 长驻 `watch`。降级路径指向 `05-开发文档/` 平台边界篇（Stage 5）。
**§5 依赖**：`PRD-NET-02`。**§6 写范围**：`scripts/lib/network.mjs`、`.aup/pages/ops/hub.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.5 PRD-NET-05 · 策展（**只做 topic + Featured**；Lead 裁决 O-NET-1 = A）

**§1 背景**：`03 §3（J3 Hub）` J3-4；现状【规划中】——无 topic schema；`hub/index` 是派生树（`rebuild` 会抹掉策展）；`?page=hub` 无策展面。
**§2 范围**：做——① 主题（topic）的定义与归属；② 推荐位（Featured）；③ 策展数据落**非派生树**。**不做**——不做推荐算法（`01 §7.3（明确不做）`）；**不做付费推广（Sponsored）**（见 §3.8「本阶段不做」——**不留半条需求**）。
**§3 验收标准**
- **A1** 策展记录落**非派生路径**，`hub index rebuild` 后策展**仍在**（前后比对）。
- **A2** Topic 关联的内容集合满足分页契约（`total > pageSize` 有真入口 / `≤` 不渲染不伪造）。
- **A3** Featured 与自然排序**可区分**（可观察标记 + 数据字段），且**不得**混排而不标注。
- **B1（负例）** 不得用派生索引承载策展（`rebuild` 后消失即失败）。
- **B2（负例）** **不得**在本需求范围内出现 Sponsored 的页面控件或字段（它是被裁掉的项，见 §3.8）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：`hub/index` 全量覆盖（`R3 §1`）——策展必须落非派生树；**topic schema 需先定**（属 `待决策`）。
**§5 依赖**：`PRD-NET-03`。**§6 写范围**：`world/topic.yaml`（新增，Stage 3/5 定形）、`.aup/pages/ops/hub.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：A = 先做 topic + Featured）。

### 3.6 PRD-NET-06 · 跨节点内容分发（**立项不实施**；Lead 裁决 O-NET-2 = A）

**§1 背景**：`01 §6.5（诚实边界）`——跨节点分发**我们尚未实现**；平台有通用搬运原语（`arc space sync`），但 `R3 §4-8` **明令禁止**写成"平台不支持跨节点同步"（反向断言同样禁止）。
**§2 范围**：做——**本阶段只立项**（需求 + 验收口径），**不实施**；理由：它是 `01 §6.1（主叙事 B）` 的**承重需求**，需求层缺位会让 Stage 3 无页面可设计、Stage 6 无功能点可跟踪。不做——不做 Hub-to-Hub 发现（第一版不要求，`spec §144`）。
**§3 验收标准**
- **A1** 若实现：搬运后的 Hub 侧记录带 `source` / `contentHash` / `cachedAt`（可判定，且与源侧 `contentHash` 相同）。
- **B1（负例）** 文档/页面**不得**出现"平台不支持跨节点同步"或"`arc space sync` 已跑通"（两个方向都禁止，`R3 §4-8`）。
- **B2（负例）** 未批准前不得产生任何跨实例写操作（本需求**只定义、不实施**）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：**`R3 §4-8`**；`arc space sync` 远程端点于本阶段**标【未验证】**（**受限原因**：自签证书报错、`http://` 走授权超时——**未取得一次成功端到端实测**）——既不能说"平台不支持"，也不能说"已跑通"。降级路径指向 `05-开发文档/` 平台边界篇（Stage 5）。
**§5 依赖**：**前置门 = Stage 5 平台可行性结论**（阻塞原因 `待平台能力`）；本阶段**只立项、不实施**，故不产生跨实例写操作。**§6 写范围**：本阶段不动代码（需求层先行）。**§7 结果记录**：未开工（**标【规划中】**）。**§8 开放问题**：无（已裁：A = 立项不实施）。

**§2 范围**：做——给出**可断言的治理清单**（如：任一实例可导出、Hub 互为独立单元）。不做——不做跨节点对账服务（平台边界）；**不在 PRD 正文维护"待决策清单"**（过程台账归 `docs/08-其他/决策/`，见 §4）。

- **B1（负例）** 不得声称存在网络级 HTTP 发现端点。
