## 1. 需求卡模板（每条 `PRD-` 一张卡）

| 字段 | 必填 | 说明 |
| :-: | :-: | --- |
| **编号** | ✅ | `PRD-<领域码>-<NN>`（7 个领域码见 `00 §2`）；**不跳号** |
| **名称** | ✅ | 一句祈使句（能验收的行为，不写实现手段） |
| **领域** | ✅ | `CNT/SITE/NET/ID/AGT/OPS/SET` 之一 |
| **概念追溯** | ✅ | **必须**指到概念条款：`` `01 §x` `` 或 `` `03 §Jx` ``（**G1**）；无追溯 = 孤立需求，**不得立项** |
| **能力组** | ✅ | 所属能力组（每篇领域 `§1` 的能力表行） |
| **优先级** | ✅ | `P0/P1/P2`；【决策待定】项**不排期** |
| **现状标签** | ✅ | **一个主标签 + 允许次级标签**：主标签 = **决定该行可否立项/能否依赖的那个**（取最严重/最阻塞者，如【平台边界】优先于【规划中】）；次级标签用中括号并列。门槛 = 总纲 §3.1；断言"今天的代码/实测"，**不是**实现状态 |
| **阻塞原因** | ✅ | `无｜待决策｜待批准｜待平台能力`（**与状态正交**；六态定义在 `docs/06-功能开发列表/`，本目录不写六态） |
| **证据四件套** | ✅ | ① `文件:行` ② 命令 ③ **原始输出摘要** ④ **验证者**（独立方）——见 §4 |
| **验收标准** | ✅ | 必须**能用现有命令跑**；跑不了的写明**前置**（真链/资金/人类批准）——见 §3 |
| **adapter 与 mock** | 涉及链时 ✅ | 写 `mock` / `ocap`，并写明**是否已在 mock 跑过**（Lead 要求） |
| **写范围** | ✅ | 允许改的路径 + **绝不改**的路径 |
| **跨域引用** | 视情况 | 引用其它域的 `PRD-` 号，**不重复定义**（`00 §5 S2-B` 的机制） |

## 2. 现状标签与阻塞怎么用（**六态不在本目录**）

| 项 | 归属 | 写法 |
| --- | --- | --- |
| **实现状态（六态 + 正交阻塞）** | **唯一出处 = `docs/06-功能开发列表/`**（Stage 6 落盘） | 本目录**不填六态**；台账写状态时按 `00 §3.1` 的四条输入要求（独立验证者 / 机制存在≠已接 / 通道可用≠产物就绪 / 概念追溯前置） |
| **现状事实标签（五类）** | 门槛 = **总纲 §3.1** | 每张卡填**一个主标签**（判据见 §1"现状标签"行：决定可否立项者）+ 可并列**次级标签** |
| **阻塞原因** | 本目录 | `无｜待决策｜待批准｜待平台能力`；【决策待定】的条目**不排期** |

**两条写法纪律**
1. **不得用"SDK/平台里有"当实现证据**（例：`listStakes` 曾"SDK 有、本项目适配器与 mock 都没有" ⇒ 当时只能标【规划中】、台账写 `未开工`/`开发中`；**2026-10-12 同步**：`ENG-02`/`ENG-03` 已接线 ⇒ 今天标【已实现】；**规则不变，例随事实更新**）；
2. **不得用"通道可用"当功能完成**（例：`/p/rss.xml` 通道【已实现】而产物曾不存在 ⇒ 当时标【规划中】+ 前置命令；**2026-10-12 同步**：生成已并入**部署管线步骤 3b**（`DEF-28`）⇒ 今天标【已实现】）。

## 3. 验收规范

| # | 规则 | 判据 |
| :-: | --- | --- |
| **A1** | **每条需求必须能追溯到概念条款** | 卡内"概念追溯"非空，且指向 `01 §…`/`03 §J…`（机器可查：正则 + 目标文件存在） |
| **A1′** | **平台事实型需求**的追溯写法：概念层没有对应条款时（如"索引陈旧导致过滤列表缺项"），**不得硬凑概念条款**；改写为 **`平台事实型`（见本节 A1′）** + **平台事实出处**（`docs/05-开发文档/02-平台能力与边界.md`）+ **本域的影响面说明**（为什么它仍是产品需求） | 卡内"概念条款"格 = `平台事实型（见 00a §3-A1′）`，且同行给出平台事实出处 |
| **A2** | **验收要能用现有命令跑**；跑不了的写明前置 | 卡内"验收标准"含 `arc `/`npm `/`node scripts/`/`grep ` 之一；否则必须写"前置 = 真链 / 资金 / **人类逐次批准**" |
| **A3** | **涉及链的需求写明 adapter 与 mock 状态** | 卡内出现 `mock`/`ocap`，并有一句"**已在 mock 跑过**"/"**mock 未跑**" |
| A4 | 【未验证】必须给**验证方法**（步骤 + 判定式） | 卡内"验证方法"非空；无方法 = 不合规 |
| A5 | 平台做不到的必须给**降级形态** | 卡内现状标签含【平台边界】时，必须给降级路径（引用 Stage 5） |

**两条"跑过 ≠ 写回"派生纪律**（沿用本项目已立的规矩）
1. 声称可机检/可执行的判据，**代码 + 命令 + 真实输出必须同处一篇**；只在临时脚本里跑通不算。
2. 引用**原始证据**（`docs/05-开发文档/附件/`、`docs/08-其他/附件/`）**必须读完整节**再引用——只引有利那半是本项目的真实事故。

## 4. 证据四件套（每条必填）

| # | 件 | 形态 | 反例（不合格） |
| :-: | --- | --- | --- |
| 1 | **文件:行** | `scripts/lib/chain.mjs:778-786` | "代码里有" |
| 2 | **命令** | 可复制、可复跑 | "跑一下就知道" |
| 3 | **原始输出摘要** | 关键行 + 判定（如 `issues: []`、`{"ok":true}`、条数） | 只写"通过" |
| 4 | **验证者** | **独立方**（≠ 实现人）；自证最高到"待验"（六态口径见 `docs/06-功能开发列表/`） | 自己签自己写"已验证" |

**补充**：涉及链的条目，证据里必须出现 **adapter** 与**是否 mock 跑过**（§3-A3）。

## 5. 事实标签用法（**门槛 = 总纲 §3.1**）

| 场景 | 该用什么 | 常见误用 |
| --- | --- | --- |
| 今天能跑、有产物 | 【已实现】 | 只有 SDK/通道 ⇒ 误标【已实现】 |
| 通道有、产物/接入缺 | 【规划中】 | 把"机制存在"写成【已实现】 |
| 平台做不到/已降级 | 【平台边界】 | 不写降级路径 |
| 选择未拍板 | 【决策待定】 | 把已裁写成待定，或反之 |
| 事实未知、需实测 | 【未验证】 | 不给验证方法 |

## 6. 机检（可粘贴；真实输出见回报）

```bash
python3 - <<'ZZ'
import re,glob
pat=re.compile(r'PRD-([A-Z]+)-(\d{2})')
codes={'CNT','SITE','NET','ID','AGT','OPS','SET'}
bad=[]
for f in sorted(glob.glob('docs/02-产品需求/0*.md')):
    s=open(f,encoding='utf-8').read()
    for m in pat.finditer(s):
        if m.group(1) not in codes: bad.append(f'{f}:{m.group(0)}')
print('A0 领域码合法:', bad or 'PASS')
# A1：概念追溯存在性（对每张卡粗检：卡内是否含 `01 §`/`03 §J`）
n=0
for f in sorted(glob.glob('docs/02-产品需求/0*.md')):
    for i,l in enumerate(open(f,encoding='utf-8').read().split('\n'),1):
        if pat.search(l) and ('01 §' in l or '03 §J' in l): n+=1
print('A1 带概念追溯的行数 =',n)
ZZ
```

**判据**：领域码合法（`CNT/SITE/NET/ID/AGT/OPS/SET` 之一）；每篇 `wc -l` ≤400；单行 `len(str)` ≤800；相对链接 0 MISS。
