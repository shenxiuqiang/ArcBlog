## 3. 需求条目

### 3.1 PRD-AGT-01 · 默认只读的暴露面

**§1 背景**：`01 §6.3（第二楔子）`；现状【已实现】——`arcblog-agent.mjs show|check`；**未配置的节点暴露面 = 公开内容只读**；策略受 Agent Access 总开关约束。
**§2 范围**：做——默认只读、总开关关闭后 fail-closed。不做——不做自定义 Agent 协议（复用 Runtime 的 `/mcp`）。
**§3 验收标准**
- **A1** 全新实例（无 grant）执行任一**写**工具 → 被拒且给出可复制的授权命令。
- **A2** `agent check` 在总开关关闭时**退出码非 0** 且报 `AGENT_DISABLED`。
- **B1（负例）** 无 grant 时**不得**产生任何 AFS 写入（前后逐字节比对）。
- **B2（负例）** 不得自造 `/mcp` 之外的 Agent 协议端点。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无（接入面由运行时提供，ArcBlog 只声明与审计）。**§5 依赖**：无。**§6 写范围**：`agents/arcblog-agent/**`、`scripts/arcblog-agent.mjs`、`scripts/lib/agents.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.2 PRD-AGT-02 · 能力分级与默认关闭

**§1 背景**：`04 §3（角色与能力）`；现状【已实现】——五级能力；工具目录实测 **9 read（2 unavailable）/ 4 write / 6 closed**；`settle_payment`/`change_wallet`/`change_role` 永不暴露。
**§2 范围**：做——分级可查、高风险默认关闭、`agent.admin` 不可授予。不做——不做工具级配额（V2）。
**§3 验收标准**
- **A1** 工具目录输出三分类计数与 `scripts/lib/agents.mjs` 的 `AGENT_TOOLS` **逐项一致**。
- **A2** `agent.admin` 出现在"不可授予"清单中，且 `authorize --capability agent.admin` **必须失败**。
- **B1（负例）** 高风险工具（结算/改钱包/改角色）**任何授权下都不得可执行**。
- **B2（负例）** 不得把 `unavailable` 的读工具显示为可用。
- **A3（目录一致性，Lead 裁决 O-AGT-1 = 进本阶段）** 页面宣称的工具清单/策略必须与 CLI 实际**逐项一致**：目录条目数 + 每条 name/kind/能力 → 与 `arcblog-agent.mjs show`（及 `--help`）输出**逐项比对**，**不一致即失败**。理由：这是"诚实展示"类需求，防的是**假目录**（归档期 BUG-006/BUG-013 同族）。
- **C1** `npm test` 快层通过（含目录一致性断言；进快层或快层可跑的静态对比）。
**§4 平台边界**：无。**§5 依赖**：`PRD-AGT-01`。**§6 写范围**：`scripts/lib/agents.mjs`、`.aup/pages/ops/agents.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：**进本阶段**）。

### 3.3 PRD-AGT-03 · 授权签发 / 撤销 / TTL（**含页面签发，走意图队列**）

**§1 背景**：`03 §5（J5 Agent）` J5-2/3；现状【已实现】CLI（`authorize`/`revoke`，强制 TTL），**页面无落点**（`agents.aup` 写入面 = 0，且**从未有过写接线**）。
**§2 范围（Lead 裁决 O-AGT-2 = 立项）**：做——① CLI 侧签发/撤销/TTL 强制；② **页面侧签发/撤销走"页面写意图 → 本机 worker 落库"**（与 `PRD-CNT-01` 同范式）。**理由**：`didHash` 需哈希原语，而 **AUP 无哈希原语**（`R3 §1`）⇒ 哈希只能在 worker 侧算。**不做**——不在页面直写、不在前端算哈希。
> **归档理由已被证伪，不得照抄**：归档 checklist 曾以"平台无哈希原语 ⇒ 无法寻址"作为**放弃页面入口**的理由；本仓**已有 8 条意图队列**（7×`config/*-intents` + `tags/intents`）证明该降级理由**不成立**——正确做法是**走队列**，不是放弃。引用归档时必须写明这一点。
**§3 验收标准**
- **A1** CLI 签发后 `AFS:config/agent-grants/<didHash>.json` 存在且 `expiresAt` = 签发时刻 + TTL。
- **A2** 页面签发：`AFS:config/agent-grants-intents/<id>.json` **+1**（以 AFS 为准）→ worker `apply` 后 grant 出现且 `didHash` 与 worker 侧算法一致。
- **A3** TTL 过期后同一 grant 的工具调用**必须被拒**（时间边界两侧各断言一次）。
- **A4** `revoke` 后立即失效（可观察：同一工具调用被拒）。
- **B1（负例）** TTL 缺失或为 0 → 签发必须失败（不得产生永久 grant）。
- **B2（负例）** 不得存在"无 grant 也能跑写工具"的旁路。
- **B3（硬负例，Lead 点名）** `authorize --capability agent.admin` **必须失败**（该能力**永不可授予**）。
- **B4（硬负例，Lead 点名）** 高风险工具（结算/改钱包/改角色）**在任何授权下都不得执行**。
- **B5（负例）** **worker 未运行时不得改库**（只写意图）；未登录不得产生意图。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无（grant 落 admin-only 的 `config/` 集合；页面不直写）。**§5 依赖**：`PRD-AGT-02`；页面部分依赖 `config/agent-grants-intents/`（新增队列目录，属 `config/` 已 admin）。**§6 写范围**：`scripts/arcblog-agent.mjs`、`config/agent-grants/`、`config/agent-grants-intents/`（新增）、`.aup/pages/ops/agents.aup`。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：立项，走意图队列）。

### 3.4 PRD-AGT-04 · 审计（**含页面只读视图**）

**§1 背景**：`03 §5（J5 Agent）` J5-4；现状【已实现】CLI `arcblog-audit.mjs log`，**页面无审计视图**。
**§2 范围（Lead 裁决 O-AGT-3 = 立项，只读 P2）**：做——① 每次操作留痕 Caller DID + Agent 身份 + 工具 + 结果；② **页面提供只读审计视图**。理由：`spec §15.8`/`§61` 承诺"能力边界**可见**、可控"，审计可见是"可见"的一半，**只读实现风险低**。不做——不做审计的远程上报、不做审计删除。
**§3 验收标准**
- **A1** 任一工具调用后审计出现 1 条记录，含 `caller`/`agent`/`tool`/`at`/`result`。
- **A2** 页面审计视图的每行与 `AFS` 审计记录**逐字段一致**（含空值渲染为平台破折号）。
- **A3** 审计条目**只增不删**（无删除入口，页面亦无）。
- **B1（负例）** 审计记录**不得**含私钥/助记词/令牌等敏感材料。
- **B2（负例）** 不得用 `toast` 或页面文案代替审计条目。
- **B3（负例）** 只读视图**不得**提供任何写接线（`.actions/write` = 0）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无。**§5 依赖**：`PRD-AGT-03`。**§6 写范围**：`scripts/arcblog-audit.mjs`、`.aup/pages/ops/agents.aup`（只读视图）。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：立项只读 P2）。

### 3.5 PRD-AGT-05 · 接入面与可见性

**§1 背景**：`03 §6（J6 访客）` J6-3；现状【已实现】——`/mcp`、AFS RPC、**`/p/llms.txt`** 由运行时提供；ArcBlog 只声明；**没有"Agent 读到了什么"的可见性**。（**术语统一**：全文一律写 `/p/llms.txt`；root 级 `/llms.txt` 与 `/.well-known/*`、`/api/*` 同属**平台不可达**，见 B1 与 `R3 §1`。）
**§2 范围**：做——如实声明可达通道与暴露面；不做——不做"AI 分析/推荐"（`spec §138` V2）。
**§3 验收标准**
- **A1** 声明文件里的通道与实测可达一致（`/mcp`、AFS RPC、`/p/llms.txt`）；**不得**声称 root 级 HTTP API。
- **A2** 暴露面清单 = 公开内容只读（新实例默认）。
- **B1（负例）** 不得声称根路径 `/.well-known/*` 或 `/api/*` 可用（`R3 §1`）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：root 级 HTTP 端点不可达（`R3 §2.6`；§4 未收录 ⇒ 不臆造编号）；接入面以**运行时提供 + AFS 声明**为准。**§5 依赖**：无。**§6 写范围**：`agents/**`、`.aup/pages/site/feeds.aup`（说明面）。**§7 结果记录**：未开工。**§8 开放问题**：无。
