### 3.3 PRD-ID-03 · 角色配置与判定（fail-closed）

**§1 背景**：`04 §3（角色与能力）`；现状【已实现】——`config/roles.json` 外部化（**地址绝不硬编码**）、`RoleStatus` 可查、五态单一真源 `STAKE_STATES`；**角色未验证 ⇒ 不授予能力**。
**§1.1 三套记录的语义（Lead 取证裁决，2026-09-30；**不是三个对等的真相**）**

| 记录 | 语义 | 能否用于链上断言 |
| --- | --- | --- |
| `node/factories.json` → **`nodes.<role>`** | **链 worker 写入的公开投影**（真链事实） | **可以 —— 唯一权威** |
| `config/roles.json` → `lifecycle` | **本机角色配置/生命周期**；**可能被 live 测试复位**（现存测试形残留 `asset-test-1`/`stake-test-1`，归档 `_docs/team/journal/round-26.md:86/158`） | **不可以** |
| `arcblog-roles.mjs status` | 由 config 派生的状态视图（`chainVerification`/`stakeState`/`active`…） | **不可以**（且**没有** `adapter`/`simulated`/`chainVerified` 字段） |

> **结论**：**链上状态唯一权威 = `node/factories.json#nodes.<role>`**；`config/roles.json` 与 `roles status` 是**本机视角**，**语义不同，不得互相做一致性比对**（这正是 `PRD-ID-03` A2 曾经不可执行的根因——改字段名救不了）。`config/roles.json.chainVerification` 是**本地验证标记**，**不是**链上已验证。
> **Stage 5 交付义务（登记）**：平台边界/数据口径篇须给出**"哪些文件可能被测试复位"的通用规则**（`config/roles.json` 是一个实例；`config/policy/active.json`、`categories` 等亦可能被定向 live 测试重写），并给出**读侧防污染**建议。
**§2 范围**：做——配置外部化、状态可查、fail-closed。不做——不改五态名称与顺序（唯一出处 = `04 §3（角色与能力）`）。
**§3 验收标准**
- **A1** 缺失/非法 `config/roles.json` 时角色判定**拒绝**且给出原因（不得默认激活）。
- **A2** **取 `node/factories.json` 的 `nodes.<role>` 子树**核对：`nodes.studio` = `{adapter:"ocap", simulated:false, chainVerified:true}`、`nodes.hub` = `{adapter:"mock", simulated:true, chainVerified:false}`。**不得**用 `arcblog-roles.mjs status`（它只输出 `chainVerification`/`stakeState`/`active` 等，**没有** `adapter`/`simulated`/`chainVerified` 三字段）；若确要用它，须先在 `00a` 登记字段映射。
- **A4（双子树辨析）** `node/factories.json` 有**两处**角色事实：`nodes.<role>`（**节点事实**）与 `factories.<role>`（**注册表投影**）——后者实测为 `{adapter:"unknown", simulated:null, chainVerified:false, simulationUnknown:true}`。**验收只认 `nodes.<role>`**，并必须在输出里标明取的是哪一棵。
- **A3** 五态取值只能是 `none/acquired/staked/revoking/claimable`（词表唯一出处 = `04 §3（角色与能力）`）。
- **B1（负例）** **不得**把未验证角色写成"已激活"，也不得授予其任何能力。
- **B2（负例）** **禁止**"Hub 角色链上已验证"式断言（Hub 是 mock）。
- **B3（负例，Lead 点名）** **不得用 `factories.<role>` 的 `adapter:"unknown"`／`simulationUnknown:true` 判定角色是否上链**——那是**注册表投影**，不是节点事实；凡以此三者任意其一得出"未上链/已上链"结论即判失败。
- **B4（负例，Lead 取证裁决）** **不得用 `config/roles.json` 或 `roles status` 断言"已上链"**——它们是本机视角（且可能被 live 测试复位），与 `nodes.<role>` **不得互相做一致性比对**（见 §1.1）。
- **B5（负例，引归档 round-26 B3 同源判据）** **不得把测试形残留呈现为链上事实**：出现 `asset-test-1`/`stake-test-1` 之类测试命名时，页面/文档只能标为**本机残留**并给清理指引，**不得**渲染成"已获得链上资产"。
- **C1** 快层：`arc dsl validate --json` → `issues: []`（`npm test` 快层亦须通过）；本条的角色生命周期验证需 `npm run test:file -- scripts/arcblog-roles.test.mjs`（**live：写共享实例且会复位 `config/roles.json`，先持 `docs/team/.gate-lock`**）——`arcblog-roles` **不在** `FAST_TESTS`（快层里的 `arcblog-roles-settings` 是**另一个**套件），**不得**写成"`npm test` 快层通过（含 `roles` 相关用例）"。
**§4 平台边界**：无。**§5 依赖**：`PRD-ID-02`。**§6 写范围**：`scripts/arcblog-roles.mjs`、`scripts/lib/roles.mjs`、`config/roles.json`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.4 PRD-ID-04 · 角色生命周期与 NFT

**§1 背景**：`03 §8（J8 新建节点）` J8-3；现状【已实现】——一键 acquire/stake/revoke/claim（写链意图 → worker 节点侧签名）；**Studio 真链四步各有 tx**，**Hub 仍 mock**（见 `01 §2.2（最小单位）`）。

- **B2（负例）** 不得在页面直接发交易（私钥不下发浏览器）；页面只写意图。
