## 3. 需求条目

### 3.1 PRD-SET-01 · 外观主题全站生效

**§1 背景**：`01 §2.2（最小单位）`（Basic 含 Theme）；现状【已实现】——`?page=appearance` + 主题桥 iframe（`frame theme-bridge-frame`）把 `data-tone`/`data-palette`/`data-mode` 写到宿主 `<html>`；**导航会重置属性**，故桥接用 MutationObserver + `localStorage` 缓存。
**§2 范围**：做——三键改动全站生效、刷新/导航后保持、无闪烁。不做——不做主题市场/自定义 CSS（`01 §7.3（明确不做）`）。
**§3 验收标准**
- **A1** 改 `palette` 后全站 `<html>` 的 `data-palette` 跟随（DOM 断言），且 `AFS:/instance/settings/arcblog/*` 落库。
- **A2** 导航后主题**不丢失**（连续点击 3 个菜单项后断言仍为新值）。
- **A3** 首屏无"先浅后深"错闪（可观察：`mode` 与站点实际外观一致；`localStorage['arcblog:theme:v1']` 命中时不重放错误态）。
- **B1（负例）** `app.aup` 的编译期 `mode` 与站点实际外观不一致时**必须**判失败（运行期每次导航都会写该属性，不一致即闪错主题）。
- **B2（负例）** 不得用内联样式覆盖 token 来"修主题"（`04 §9（已废弃/易混术语）` 的同类病）。
- **C1** `scripts/arcblog-theme.test.mjs` 通过（主题契约）。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`.aup/pages/admin/appearance.aup`、`.web/components/theme-bridge/**`、`app.aup`（mode 声明）。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.2 PRD-SET-02 · 实例级通用设置（**字段归属重整**，Lead 裁决 O-SET-1 = A）

**§1 背景**：`03 §4（J4 节点运营）` J4-2；现状【已实现】——`?page=general`（站点名/语言/时区等）；**同时 `?page=seo` 也写站点名/描述 ⇒ 两页各写一半**（`PRD-SITE-03`）。
**§2 范围（O-SET-1 = A）**：**重整为"通用 = 实例身份、SEO = 分发元数据"**——站点名/描述等**实例身份字段只在 `?page=general` 写**；`?page=seo` 只写分发元数据（OG/分享/feed 相关）。做——字段可写、公开面跟随、非法值明确拒绝。不做——不做多实例/多语言站点配置。
**§2.1 约束与判据**：**同一字段只能有一个写入页、不得留第二个入口**；**最终字段归属由 Stage 3 页面设计定稿**（本阶段只给"**不重整即失败**"的判据，防止两页各写一半继续漂移）。
**§3 验收标准**
- **A1** 页面写入后 `AFS:node/profile.json`（或 settings 记录）对应字段变化（AFS 前后比对）。
- **A2** 站点名变化在公开页标题可观察。
- **A3（O-SET-1 判据）** 逐字段核对：**每个实例身份字段在控制台恰有 1 个可写入口**；出现第二个入口即失败（静态可查各页 `exec` 的 `path` + 字段名）。
- **A4** `?page=seo` 的字段集合与 `?page=general` **无交集**（可观察：两页表单字段名去重后仍等于各自字段数之和）。
- **B1（负例）** 非法时区/空站点名必须被拒或落库后被读取侧显式忽略（**二选一并在验收里写明**，不得静默半生效）。
- **B2（负例）** 不得用 toast 作为唯一证据（以 AFS 记录为准，`R3 §4-20` 同族）。
- **B3（负例）** **不得**在 `?page=seo` 保留实例身份字段的写入入口（即"不重整即失败"）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无。**§5 依赖**：与 [`PRD-SITE-03`](02-SITE-发布与站点.md) 共用同一字段集，**归属变更须两篇同步**。**§6 写范围**：`.aup/pages/admin/general.aup`（**注：实际路径在 `admin/` 下**）、`.aup/pages/site/seo.aup`、`scripts/arcblog-settings.mjs`。**§7 结果记录**：未开工。**§8 开放问题**：无（已裁：重整；最终落点 Stage 3 定）。

### 3.3 PRD-SET-03 · 实例开关（**记录型 vs 有消费方**）

**§1 背景**：`config/switches` 三类开关；现状——**RSS 有消费方**（关掉后 channel 无 `<item>`）；**Comments 是 `recorded-only`**（有记录、无消费方）；Agent 开关受策略约束。
**§2 范围**：做——开关状态**真实反映系统行为**；对无消费方的开关**如实标注**。不做——不做"开关一开功能就有"的承诺（`01 §7.3（明确不做）` §138 推迟项）。
**§3 验收标准**
- **A1** RSS 开关关闭 → `/p/rss.xml` 的 channel 无 `<item>`；打开 → 恢复（两向断言）。
- **A2** Comments 开关的界面文案**明示"当前仅记录、无消费方"**（可观察文本）。
- **A3** Agent 开关关闭 → `agent check` 报 `AGENT_DISABLED`（与 `PRD-AGT-01` A2 同一事实，**不重复定义**）。
- **B1（负例）** 不得把 Comments 开关渲染为"评论已启用"（`recorded-only` 不得冒充可用能力）。
- **B2（负例）** 开关改动不得影响其它开关的语义（互不串扰）。
- **C1** `npm test` 快层通过。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`.aup/pages/site/feeds.aup`、`config/switches`。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.4 PRD-SET-04 · 控制台外壳（单一真源 + 全高布局）

**§1 背景**：`04 §9（已废弃/易混术语）` 禁止硬编码页数；现状【已实现】——侧栏由 `scripts/arcblog-console-nav.mjs` 从 `scripts/console-nav.mjs` 生成进**每个**控制台页（`--check` 进门）；当前项用平台 `active=true`（渲染为 `data-active`/`aria-current`）；控制台页根 `view` 的 `overflow` **必须** `visible`（否则 100vw 全出血被裁）。
**§2 范围**：做——单一真源、生成物不漂移、当前项正确、全高不被裁。不做——**不做按能力隐藏菜单**（平台边界，见 `PRD-ID-07`）。
**§3 验收标准**
- **A1** `node scripts/arcblog-console-nav.mjs --check` 通过（生成物与真源一致）。
- **A2** 每一控制台页的当前项**唯一**（`data-active="true"` 恰 1 个）且与页面标识一致。
- **A3** 全高布局：顶栏与侧栏**不被裁**（可观察：无横向滚动条；根 `view` 的 `overflow` 为 `visible`）。
- **B1（负例）** **不得**出现手写的第二份侧栏（真源必须唯一）。
- **B2（负例）** 侧栏标签、页头标题、门禁卡标题**三处必须一致**（同一操作同一模式，`03 §11（体验红线）` 红线 5）。
- **C1** `scripts/arcblog-console-nav.test.mjs`、`scripts/arcblog-runtime-ids.test.mjs`、`scripts/arcblog-ui-budget.mjs` 在快层通过。
**§4 平台边界**：`include` 运行时不可用 ⇒ **生成器投影是唯一正解**（不二次转述，见平台边界篇）；细节指向 `05-开发文档/`（Stage 5）。**§5 依赖**：无。**§6 写范围**：`scripts/console-nav.mjs`、`scripts/arcblog-console-nav.mjs`、`.aup/pages/**`（生成物）。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.5 PRD-SET-05 · 本地化

**§1 背景**：`04 §9（已废弃/易混术语）`；现状【已实现】+【规划中】——locale 文件是 **flat dotted key**（`page.key`），`arc dsl generate` 只追加不删除；**`wrapper.*` 只能手改 locales**；平台 `arc dsl lint` 报 `dead_locale_keys`；**不得**跑 `lint --fix` 全量（会删运行期才用的 id）。
**§2 范围**：做——en/zh 键集一致、无死键、无字面 `$t()`。不做——不做第三语言（V2）。
**§3 验收标准**
- **A1** `.aup/locales/en.json` 与 `zh.json` 键集**逐字节一致**（键名集合比较）。
- **A2** `arc dsl lint` 的 `dead_locale_keys` 计数**取自命令本身**（不硬编码数字），且为 0 或每一项都有保留理由。
- **A3** 页面上不出现字面 `$t(...)` 文本（可观察：抽查 5 页源文本）。
- **B1（负例）** 不得运行 `arc dsl lint --fix` 全量（会删运行期寻址的 id —— 由 `arcblog-runtime-ids.test.mjs` 守卫）。
- **B2（负例）** 不得把 `wrapper.*` 键只写在 `wrapper.aup` 的 `i18n {}` 里（运行期不生效，必须改 locales 文件）。
- **C1** `npm test` 快层通过（含 i18n 用例）。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`.aup/locales/*.json`、各页 `i18n {}` 块。**§7 结果记录**：未开工。**§8 开放问题**：无。

### 3.6 PRD-SET-06 · 设置项的权限边界

**§1 背景**：`03 §4（J4 节点运营）`；现状【已实现】——**`config` 整树 admin**（含嵌套集合，避免枚举）；站点设置写面 `minRole: admin`。
**§2 范围**：做——设置项写面 admin-only、guest 读不到敏感设置。不做——不做按角色的设置分区。
**§3 验收标准**
- **A1** guest 写任一设置 → 被拒且零写入。
- **A2** guest 读 `config/**` → `Forbidden`（**不得**泄漏子目录列目录）。
- **B1（负例）** 不得把 `config/roles.json` 写成 guest-readable（归档 `persistence.md` 曾与 `blocklet.yaml` 冲突，以 `blocklet.yaml` 为准）。
- **B2（负例）** 不得用 `networkRead` 表达"只读但不可写"的错觉（它只管读前缀增补）。
- **C1** `scripts/arcblog-permissions.test.mjs` 通过。
**§4 平台边界**：无。**§5 依赖**：无。**§6 写范围**：`blocklet.yaml`（权限表）。**§7 结果记录**：未开工。**§8 开放问题**：无。
