## 3. 需求条目

### 3.1 PRD-ECO-01 · 付费阅读闭环（**P0-A，全 Stage 2 经济线第一优先**）

**§1 背景与来源（三条硬事实，均为 `S2-03` 一手实跑）**
1. **断点在浏览器第 3–5 步，且比"没有收银台"更硬**：`reader.aup` / `store.aup` / `access.aup` 的 `grep -c '\.actions/write'` **= 0 / 0 / 0**；`store.aup:10` 自认 "there is no checkout here"；**`reader.aup:29-33` 不读 `state.post.productId`**（`world/post.yaml:28` 有该字段）⇒ **价格无处渲染**。
2. **全文连 CLI 都断链**：实跑 `access check --content <id> --reader <did>` → `allowed: true`，**紧接** `access read` 同参 → **`{"ok":false,"code":"NOT_FOUND"}`**；且 `AFS:paid/` 目录 `LIST_ERROR Path not found`（**该目录在本实例不存在**）。
3. **支付面是声明式的**：`ADAPTERS = ['none','manual']`、`transactionHash` 恒空；**记录层**（order/grant/ledger/refund）完整且实测可用。
- 概念层口径：`01 §6.5（诚实边界）` = "**有机制、无闭环**"，**禁止**写成"付费阅读已可用"。

**§2 范围**
- **第一批只做三步**（Lead 指定）：① **看到价格**（读 **guest 可读** 的 `economy/products/<productId>.json`；`store` 直接列目录，`reader` 受"动态第二记录取数"**【未验证】**约束）；② **发起购买**（页面写意图）；③ **operator 支付**（本机 worker/CLI，人工核对 `paymentRef`）。
- **不做**：① **全文消费方不做**（标【平台边界】，见 §4）；② 不做真链支付/退款转账（批次 3，**需人类逐次批准**）；③ 不改 `ADAPTERS` 枚举；④ 不做订阅自动扣款（`spec §138` 推迟）；⑤ **不做账本导出**（见 §3.8）。
- **价格可见的实现路径 = 读 guest 可读的 Product 记录**（Lead **改判 2026-09-30，撤回**原 `O-ECO-1 = A` 的"投影进公开 post 记录"方案）。**撤回理由**：① `world/post.yaml:26` 明文 `productId: string # spec §45: the price lives on the Product, never on the post`，且**无** `priceAmount`/`priceAsset` 字段 ⇒ 投影**既需新增 schema 字段（被本条约束 2 禁止）、又直接违反 spec §45**；② `blocklet.yaml:124-126` 的 `economy/products` 是 **`role: guest`（公开可读）**，不是"墙内"。**唯一真源 = `economy/products`（spec §45）**。
  - **受阻点（如实写）**：读者页面按 **`state.post.productId` 这个动态 id** 取第二条记录能否成立，**属【未验证】**（`propBind` 路径是**静态**的；`afs-list` 过滤走索引且**有陈旧风险**）。
  - **降级（探针前可用）**：`reader` 只显示"**这是付费内容** + 去商店链接"；**价格在 `store` 页展示**（`store` 用 `afs-list` 列 `economy/products`，guest 可读）。
  - **前置门（Stage 5）**：必须给出"读者页能否按 `productId` 取 Product 记录"的探针结论——**能** ⇒ 直读；**不能** ⇒ 记录平台边界 + 保留降级。**探针未跑，设计里价格行只写【未验证】+ 降级，不得写"价格已可取"**。
  - **三条约束（改写后）**：① **页面/worker 不得写价格或任何派生值**——价格只从 `economy/products` 读；② **不得新增 schema 字段**（含 `posts` 上的价格字段），确需新增**先报 Lead**；③ **`posts` 上只保留 `productId` 作为指向 Product 的引用**（spec §45：价格**永不**在 post 上）。
- 购买走 `config/order-intents/<id>.json`（`config` 整树 admin）；`buyerDid` **复用 `PRD-CNT-01` 探针结论**——探针未跑，本需求的 `buyerDid` 取值**不得**猜。


**§3 验收标准**
- **A 组（功能）**
  - **A1** guest 访问 `/posts/{paid-slug}` → 渲染出与 `AFS:economy/products/<productId>.json` **逐值一致**的 `priceAmount` 与 `priceAsset`（两条记录比对）。
  - **A2** 点击购买 → `AFS:config/order-intents/<id>.json` **+1**（**以 AFS 为准，不以 toast 为准**，`R3 §4-20`）。
  - **A3** worker `apply` 后 → `AFS:economy/orders` 记录数 **+1** 且 `status=pending`；该 order 的 `buyerDid` 匹配 `^did:(key|blocklet):`、**≠** `$session.did` 字面量、**≠** 空串（取值口径同 `PRD-CNT-01`）。
  - **A4** operator 执行 `order pay`（`--adapter manual` + `paymentRef`）→ `status=paid`；`access check --content <id> --reader <buyerDid>` 由 `allowed:false` → **`allowed:true`**（**顺序断言**）。
  - **A5** Grant 记录落 `AFS:economy/access-grants/<orderId>.json`，字段与 `04 §4（经济）` 定义一致（`contentId/readerDid/orderId/grantedAt/expiresAt`）。
  - **A6** 页面观察：`?page=orders` 的行状态与 `AFS` 记录**逐值一致**；页面不出现"支付完成"之类无记录支撑的成功态。
  - **A7（取数探针，前置门）**：读者页按 `state.post.productId` 读 `economy/products/<id>.json` —— **能取到** ⇒ 价格与 Product 记录**逐值一致**，缺失/404 给**明确缺失态**；**取不到** ⇒ 走降级（"付费内容 + 去商店"），**不算失败**。
  - **A8（无派生写入）**：对同一篇重跑任何 worker，`posts/<slug>.json` 的字段集**不变**（**不得**出现价格字段）；价格变化一律发生在 Product 记录上。
- **B 组（负例 / fail-closed）**
  - **B1** **`adapter: none` 时 `order pay` 必须 `VALIDATION` 失败且零写入**（`R3 §1` 声明式支付）。
  - **B2** **未持 Grant 的 reader DID**：`access read` 必须 `{"ok":false,"code":"FORBIDDEN"}`，且 `paid/` 记录数**不变**。
  - **B3（闭环类必备负例，`00 §9` 第 6 条）** **全文消费方不可用是当前事实**：`access check` 为 `true` 时 `access read` 仍可能 `NOT_FOUND`（`paid/` 不存在）——判据 = **解析 JSON 的 `success:false` + 错误码 `NOT_FOUND`**（**不得只断言退出码**，`arc afs exec` 出错时 `$?` 仍为 0，见 `00 §9` 第 12 条），并留**原始输出摘要**作凭证；**该负例是"闭环未完成时的失败证据"，必须保留；功能实现后仍作为回归凭证保留**，**不得**被后续实现悄悄删掉。
  - **B4** `tip`（`kind: tip`）**不得**产生 Access Grant。
  - **B5** 重复点击购买 3 次 → order 记录数**仍为 1**（id 由 worker 派生，幂等）。
  - **B6** 未登录会话下购买入口**不得**产生意图记录（门禁生效）。
  - **B7（取不到 Product 不得假装有价）**：读者页按 `productId` **取不到** Product 记录时，**不得**显示任何价格数字或"免费"字样 —— 只能显示"这是付费内容 + 去商店"（降级）或**明确缺失态**。
  - **B8（无派生字段）**：`posts/<slug>.json` **不得**出现价格类字段（`priceAmount`/`priceAsset` 或任何第四个派生字段）；价格变化只发生在 `economy/products` 上（spec §45）。
- **C 组（零回归与门）**
  - **C1** `?page=access` / `?page=orders` 的 `.actions/write` 计数**保持 0**（资金页不因本需求变成写面）。
  - **C2** `arc dsl validate --json` → `issues: []`；`npm test` 快层通过；改 `.aup` 后 `npm run build` 通过且 `dist/` 无密钥材料；**重启 + 复挂**后复验（`R3 §5 C1/C2`）。
  - **C3** 页面**不得**出现"链上支付/已结算"措辞（`R3 §4-5`）；`transactionHash` 为空时如实显示"未上链/待验证"，**绝不伪造哈希**。

### 3.8 PRD-ECO-08 · 读者可核对"我付的这笔钱有什么凭据"（**P0 断链的收口**）

**§1 背景**：`01 §6.5（诚实边界）` 把付费闭环写成五步，**第 5 步 = 凭据**；[`02 §2（RD 付费读者）`](../01-产品概念/02-用户与角色.md) 把"**我付的钱有凭据**"列为读者 Job，并把"每笔钱有可核对凭据"标【决策待定】。现状：`?page=access` 是**管理员只读**（`access.aup` 的 `.actions/write` = **0**），而 `economy/access-grants/` 是 **admin-only** ⇒ **读者侧今天读不到自己的 Grant**（`S2-01 §3.2` 断链② 第 9 条归 ECO）。
> 本条即 [`00 §12.2（上游断链接收）`](00-需求地图与规范.md) 第 9 条的落点——**立项，不是"不做"**（Lead 裁决：概念层承诺不允许既无需求又无"不做"）。

**§2 范围**：做——① 读者能看到"我买过什么"的**可核对凭据**（订单号 + 内容 + 金额 + 时间 + 凭据状态）；② 凭据信息与 `AFS` 记录**逐字段一致**；③ 页面给出**如何核对**的指引（可由 operator/CLI 提供逐条核对）。不做——不做"页面内自行解全文"（属 `PRD-ECO-01` 的平台边界）；不做凭据导出（与 §3.9 同一隐私口径）。
**§3 验收标准**
- **A1** 读者侧可见其 own 订单与 Grant 的**投影**字段（订单号/内容标识/金额/时间/状态），值取自节点方**已核对的投影记录**。
- **A2** 每条凭据给出**核对路径**（可复制命令或 operator 指引），且该路径今天**真能跑通**（不是"将来会"）。
- **A3** 空态：无购买时显示明确空态 + 下一步，**不显示 0 元/假凭据**。
- **B1（负例）** **不得伪造凭据**：不得在无 `AFS` 记录支撑时渲染任何"已购买/已解锁"凭据。
- **B2（负例）** **不得显示假 0**（金额缺失时必须显示"未知/待核对"，不得 `0`）。
- **B3（负例）** 不得通过该视图泄漏他人凭据（A 读者看不到 B 读者的订单/Grant，guest 404，**DOM 零泄漏**）。
- **C1** `npm test` 快层通过。
**§4 平台边界与降级**：**`economy/access-grants/` 与 `economy/orders/` 是 admin-only ⇒ 浏览器内读者不可直读**（`R3 §1` 能力矩阵）。**降级路径**（本阶段形态）：由 **operator/CLI 提供可核对凭据**（`arcblog-economy.mjs order list`/`access read` 的输出）+ 页面给出**只读指引与核对步骤**；**不承诺**"读者自助在线核验"闭环。细节指向 `05-开发文档/` 平台边界篇（Stage 5）。
**§5 依赖**：`PRD-ECO-01`（订单与 Grant 的产生路径）、`PRD-ECO-03`；**Stage 5 平台边界结论**决定是否可升级为读者自助核验。
**§6 写范围**：`.aup/pages/economy/access.aup`（读者侧只读投影，Stage 3 定名）。**§7 结果记录**：未开工（**【平台边界】**降级形态先行）。**§8 开放问题**：无（已裁：立项 + 平台边界降级）。
**§9 回看条件（可观察阈值）**：**A.** 平台能表达 **per-reader 读权限**（`access-grants` 可授权给 owner DID）；**B.** Stage 5 给出"浏览器内 per-reader 守卫"的可替代形态（见 `PRD-ECO-01 §4` 第 4 行交付义务）；**C.** 出现读者侧凭据诉求的**可观察证据**（支持请求/使用数据）。三者任一成立即重估为"读者自助核验"。
