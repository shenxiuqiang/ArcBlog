## A. 领域划分（8 个）

| 码 | 领域 | 为什么单列（不合并的理由） | 主要上游 |
| :-: | --- | --- | --- |
| **CNT** | 内容创作 | 创作者的第一条路径，也是**唯一有成熟闭环**的路径（`03 §1` J1）；与"站点分发"不同层 | `03 §1`、`02 §1` |
| **SITE** | 发布与站点 | 公开发布面（首页/文章页/静态页/SEO/RSS）是**读者侧**能力，作者不可见也可用；与创作解耦 | `03 §2/§6`、`02 §2/§3` |
| **NET** | 发现与网络 | Studio↔Hub 的注册/索引/发现是**网络层**，节点角色驱动；与站内展示无关 | `03 §3/§8`、`02 §4/§5` |
| **ECO** | 经济与付费 | 商品/订单/结算/账本/授权是一个**独立账域**，且含**头号未闭环**（`03 §2.1`） | `03 §2/§4`、`02 §2` |
| **ID** | 身份与角色 | DID 身份、角色资产、质押五态、Capability 是所有领域的前置（`04 §2/§3`） | `03 §8`、`02 §5` |
| **AGT** | Agent 接入 | 唯一"非人类调用者"领域，权限模型与审计独立（`01 §6.3（第二楔子）`） | `03 §5`、`02 §6` |
| **OPS** | 治理与运维 | 异常发现、诊断、退出与搬迁；服务"节点运营者"而非"内容"（`03 §4`） | `03 §4`、`02 §5` |
| **SET** | 设置与外观 | 站点级配置与主题是**跨领域横切**面，改动影响 CNT/SITE 但归属独立 | `01 §7（明确不做）`、`02 §5` |

**为什么是这 8 个（而不是更少/更多）**：① 与 `03` 的 J1–J8 有明确映射（见 §F 追溯）；② 与 `04 §2–§6` 的术语簇一一对应，避免出现"术语有出处、需求无归属"；③ **不按页面分**（页面属 Stage 3），**不按角色分**（角色横切领域，见 `02 §0`）。

## D. 验收标准模板（每条需求四件套）

```text
REQ-XXX-NN  <一行需求（可判定，写"谁在什么触点得到什么"）>
├─ 上游      : 01 §x / 03 Jx（概念锚点，必填）
├─ 验收      : <一条可执行命令 或 一条可观察行为>        ← 禁止"体验更好""更完善"
├─ 证据形态  : <AFS 记录路径 / 命令输出+退出码 / 页面可观察态 / 截图>
└─ 负例      : <必须失败的路径 + 期望的错误码或行为>      ← 缺负例视为未完成
```

**五条硬规则**：① 平台做不到的必须引 `R3 §4-N` 并给降级路径，**不得承诺**（门 G5）；② 涉及资金/上链的必须写**前置批准点**（`03 §12.2（已裁决）` O1：资金动作需人类批准）；③ 涉及页面写入的必须写"入队 ≠ 生效"（意图队列）；④ 每条需求必须能被 QA 判**通过/不通过/受限未验证**三值之一；⑤ 证据基线写 commit sha。

**第 6 条硬规则（Lead 本轮新增，全 Stage 2 强制）**：**每条 `§x` 引用必须在括号里写下该节标题的前 4 个字**，便于复核。示例：`01 §4（最短路径：…）`、`03 §2（J2 读者）`；`03` 的节标题本身就是 `J<n> 简称` 形式，括号写 `J<n> 简称` 即可。**理由**：Stage 1 事实审查抓到我的错锚（`03 §7` 被我当"退出旅程"、实为 J7 平台方），而"复读节标题"是唯一能自动发现的检查手段。

**S2-02 的吸收**：调研 [`S2-02-需求规范与验收标准.md`](../08-其他/调研/S2-02-需求规范与验收标准.md) 已落盘，其 §1.2（12 字段总表）、§2（10 对好/坏对照）、§3.3（状态推进与证据绑定）、§4（追溯矩阵与脚本化校验）、§5（H1–H8 防漂移硬规则）、§6（8 个反例）**全部采纳**，正文规范落到 `00-需求地图与规范.md`；**唯一不采纳**的是其 §3.1 的 `PRD-` 编号与"禁止 `REQ-`"（与裁决 S2-2 冲突，按裁决执行）。
