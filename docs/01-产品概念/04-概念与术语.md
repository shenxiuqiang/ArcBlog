## 2. 写作纪律（禁用写法）

本节约束的是**写法**，不是词表：术语一旦登记，其余文档**只引用、不重定义**。

| 规则 | 内容 |
| --- | --- |
| **不得用"机制存在"当"本项目已接"** | 例（**2026-10-12 同步**）：链上枚举 `listStakes` 曾"SDK 里有、本项目适配器与 mock 都没有" ⇒ 当时落地侧一律【规划中】；**现已接线**（`ENG-02`/`ENG-03`）⇒ 今天标【已实现】。**规则不变，例随事实更新** |
| **不得用"通道可用"当"产物就绪"** | 例（**2026-10-12 同步**）：`/p/rss.xml` 通道【已实现】而 `.web-cache/rss.xml` 曾不存在（需手跑 `arcblog-rss.mjs`）⇒ 当时标【规划中】+ 前置命令；**现生成已并入部署管线步骤 3b**（`DEF-28`）⇒ 今天标【已实现】；⚠️ 裸 `arc blocklet build` 会抹掉它 |
| **禁止无据的程度词** | "应该能""大概支持""更好""更完善"；"平台不支持 X"必须举证（唯一出处 = [`docs/05-开发文档/02`](../05-开发文档/02-平台能力与边界.md)） |
| **数字一律从命令取** | 计数、页数、工具条数**不得写死**，也不得写"预期 / 约 X"；给可复算命令 |
