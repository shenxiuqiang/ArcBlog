## 0. 七类角色总览

R2 §1 给出 7 类角色。本文为每类设一个**稳定代号**（避免与调研编号 R1–R4 混淆），并映射回 R2 原编号：

### 0.1 角色与节点形态是**两个正交维度**（易混，先立规矩）

| 维度 | 取值 | 出处 |
| --- | --- | --- |
| **人/机器角色**（谁在用） | C / RD / V / H / O / A / G 七类 | R2 §1 |
| **节点运行状态**（这个实例是什么） | Basic / Studio / Hub / Studio+Hub | spec §7:271–376；`01 §2.2` |

**规矩**：`Studio` / `Hub` 是**节点状态**，不是用户类型。同一个 Hub 运营者（H）可以运营 Basic/Studio/Hub 任意状态的实例；同一个创作者（C）在 Basic 实例上也能完成 J1 的主链路。**禁止**把两者写成一张表（R2 §6 摘要第 1 条明确要求）。

### 0.2 三类主体与"软件之外的角色"

- **在软件内操作的人**：C、RD、V、H、O、A。
- **在软件之外但决定网络形态的角色**：G（平台方/治理者）——它维护 ArcBlog 软件与官方 Hub，但**不是任何实例的运维**（R2 §1.7）。角色资产发行方（Factory owner）属此类，且 ArcBlog 不实现它（`01 §7.1` P1）。
