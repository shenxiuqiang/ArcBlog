## C. 五问（已按 Lead 裁决定稿；正文落 `01-产品定位与边界.md`）

**① 是什么（D2 = A+B 合体，两行都要）**
> 主措辞（非技术）：任何人都能自己部署、自己拥有内容和读者关系的博客软件；各自部署的实例通过可验证的角色互相发现、互相分发，而不是所有人挤在同一个平台上。
> 技术副标题（紧跟一行）：以 DID 为身份、以 AFS 为资源层的内容节点软件。

**② 给谁解决什么** — 创作者（内容与读者关系带不走）/ 节点运营者（缺可运行软件与可信角色机制）/ 读者（想直接支持且不交出身份）。优先级按 **D5 = B**：创作者为入口、运营者为第二价值放大器，**标【决策待定】+ 人类追认**。

**③ 第一次完成的一件事（D4 = A 创作者）** — DID 登录 → 写一篇 → `/posts/{slug}` → RSS（【已实现】）。运营者最短路径（部署 + 发布 + 注册到一个 Hub）作**第二条**旅程，不占五问③。

**④ 不可替代性（D3 = B 主叙事）** — 主叙事 = **发现本身是一个可验证归属、可分成、按角色参与的开放网络**；A（身份内容归属）作**前提**（单独不成立：自托管 CMS + 身份可携带已部分覆盖）；C（Agent 一等公民）作**第二个楔子**，不当主叙事。Nina Protocol 类比须写明"模式借自音乐领域、内容阅读场景尚无完全可比产品"。**已按 R2 §3 完成对标（8 个产品），结论见 `01 §5/§6`；诚实边界见 `01 §6.5`（有机制、无闭环）。**

**⑤ 明确不做（三层，见 `01 §7`）** — 产品选择（spec §8.1/§139/§142）；平台强制（逐条引 `S1-03 §4` 编号，不二次转述）；推迟（spec §138）。
