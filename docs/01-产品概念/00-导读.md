## 3. 三条核心口径

1. **聚合由用户自己的 agent 完成**：网络里没有一个统一的聚合入口，"今天值得看什么"由各人自己的 agent 汇总；
2. **发现 = 链上注册表**：所有节点把 studio NFT 质押到**同一个 factory 地址**，查该地址的质押列表即**全部在运行节点**；节点的可达信息（`endpoint`/`region`）写在 **NFT 的 `data.value`** 里；
3. **产品只做"写作 + 发现"两件事**：不内置支付、结算、收益分配与访问控制；节点只做"写、发、被读、被汇总"。

**四条不变口径**（与上述三条并列，逐条有下游落点）

| # | 口径 | 落点 |
| :-: | --- | --- |
| 1 | **内容归创作者、读者关系不被平台持有** | `01 §2 P1`、`02 §4` |
| 2 | **能力 = 角色派生 + fail closed**（未验证即不授予） | `04 §1` 能力档；`docs/02-产品需求/04-ID` |
| 3 | **发布必须落在应用之外**（AUP 应用无运行时依赖） | `01 §4.2` 缺陷 4、`03 §J4` 步 7 |
| 4 | **只读出口走 `/p/` 路径**（根级自定义 HTTP 端点被平台壳吞掉） | `01 §4.2` 缺陷 3；`docs/05-开发文档/02` 能力 #49 |

## 4. 事实标签怎么读（**不重定义**）

五类标签的**定义与唯一出处 = [`docs/README.md`](../README.md) §3.1**（【已实现】【规划中】【平台边界】【决策待定】【未验证】）。本目录只做两件事：

| 本目录的用法 | 说明 |
| --- | --- |
| **区分"机制存在"与"本项目已接"** | 例：链上发现机制 **【已实现】**（有生产代码证据），但**本项目适配器与 mock 都还没有枚举接口**、且 **mock 链从未跑过** ⇒ 落地侧标 **【规划中】** |
| **【未验证】必须给验证方法** | 例：NFT 转让 = **【未验证】**，验证方法 = beta 链 + TBA 测试币上的 `TransferTx` 探针（**执行前需人类批准**），**不得写成"已经可以买卖"** |

**禁止写法**："应该能""大概支持""更好""更完善"；"平台不支持 X"也必须举证。
