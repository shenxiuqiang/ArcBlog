| 步 | 触点 | 动作 | 状态 |

**"订阅"的三种含义（明确区分）**

| # | 含义 | 落在哪 | 状态 |
| :-: | --- | --- | --- |
| 1 | 浏览器书签 / 本地列表 | 读者自己的设备 | 【已实现】 |

| 3 | **把"盯这件事"交给自己的 agent** | 读者的 agent（J4） | **【规划中】** |

**卡点**：**读者关系不被平台持有**是承诺（`01 P1`），但也意味着**平台侧没有"我的订阅"页**——订阅状态属于读者或读者的 agent，不属于节点运营者；读者要"被汇总过的列表"**必须先开 agent**（今天的头号体验缺口）。

| 4 | 链上 NFT `data.value` | 写入 **`endpoint` / `region` / `appName`**（可达信息） | 【已实现】（本机记录 `endpoint`/`region`：`scripts/arcblog-node-nft.mjs:82-86`）；链上写入接口 `updateAsset`（SDK 有、本项目未接：`grep -c updateAsset scripts/lib/chain.mjs` = **0**） |

**卡点与现状（**这一条最关键**）**
| # | 卡点 | 标签 | 说明 / 验证方法 |
| :-: | --- | --- | --- |
| 1 | **本项目枚举能力缺失**：适配器（mock 与 ocap）**都没有 `listStakes`**（`grep` = 0），`config/mock-chain.json` 不存在 ⇒ **mock 链从未跑过** | **【规划中】** | 验证 = mock 链上两节点各质押一个资产后按 factory 枚举（判据：返回条数 = 质押数；未质押的不出现） |
| 2 | 链上**真链**的分页/延迟/上限未知（生产用法是 `size=10` + cursor） | **【未验证】** | 验证 = mock 版判定式 + 真链只读查询（需资金/人类批准的动作另计） |

> **一句话**：**"加入网络"这条路上，机制是通的、软件的两半只差"枚举"这一半。**

## J4 · 【主干】开 agent → 汇总 → chat → 生成 → 发布

| 步 | 触点 | 动作 | 状态 |
| :-: | --- | --- | --- |
| 1 | 用户的 agent（**开在哪**待裁，见开放问题） | 开启 agent；**记忆先落本地** | 【已实现】（工具面）/ **【规划中】**（记忆）；DID Space 备份 **【规划中】** |
| 2 | 链上注册表 | **发现**：查 factory 地址的质押列表 ⇒ 全部节点；解析每个 NFT 的 `data.value` 取 `endpoint`/`region` | 机制 **【已实现】**；本项目枚举 **【规划中】**（同 J3 卡点 1） |
| 3 | 各节点公开面：`/p/llms.txt` + 运行时 `/mcp`（**【已实现】**）；`/p/rss.xml`（**需该节点先生成**，见 J1 第 5 步 ⇒ **【规划中】**） | 读取公开内容（**匿名只读**，无需 Key） | 【已实现】/【规划中】分列（`/p/llms.txt` 实测 200；`/p/rss.xml` 实测 404） |
| 4 | agent 内部 | **汇总**：采集 → 预筛 → 评分 → 写作 → 结构化 → 归组 → 成刊 | **【规划中】**（聚合/聚簇层不存在） |
| 5 | 用户 ↔ agent | **chat**：基于汇总结果对话（"为什么这条入选"可解释） | **【规划中】** |
| 6 | agent → 草稿 | **生成**博客草稿（`create_draft`/`update_draft`） | 【已实现】（工具存在）；编排 **【规划中】** |
| 7 | 运营侧 CLI `arcblog-lifecycle.mjs publish` | **发布到自己的节点**（可 `--sign-key` 签名） | **【平台边界】**：应用内不可发（无运行时依赖）⇒ 发布必须在**应用之外**（口径 §4.3） |

**设计要点（形态设计，**推断非原话**）**：① 先定**一份公开投影**（`/p/`），聚合侧只写一套适配器；② 用 **snapshot + changes（带游标）**，避免把撤回当新内容；③ 必须携带**来源节点的 `discoveredAt`**，不能只带发布时间；④ **匿名只读 + 条件请求 + 降级阶梯**；⑤ **可解释排序 + 保守合并门槛**，热度阈值按自己的节点频率**重新标定**。

**卡点**：① **发现工具仍 `unavailable`**（`list_studios`/`get_studio`，`scripts/lib/agents.mjs:74-75`）——注册表在**链**上，工具侧尚未接线；② **智能层（聚合/对话/生成编排）不存在**；③ **agent 的 DID 与授权面**需在实现层确认；④ 外部框架（如 AIGNE）的许可为 **Elastic-2.0**（非 OSI 开源，限制"作为托管服务对外提供"）⇒ **概念层不绑定框架**。

## J5 · 退出与转让

| 步 | 触点 | 动作 | 状态 |
| :-: | --- | --- | --- |
| 1 | CLI `arcblog-node-nft.mjs revoke --role studio` | **解除质押** | 【已实现】 |
| 2 | 链上 `updateAsset({address, moniker, data:{typeUrl:'json', value}})` | **清空质押时写入的节点字段**（`endpoint`/`region`/`appName`）；**mint 时写入的 `owner`/`pk` 不动**（工厂规格 `docs/05-开发文档/附件/ArcBlog-nft-factory.md §2`，**原始证据**） | 接口在 SDK（**本项目未接**：`grep -c updateAsset scripts/lib/chain.mjs` = **0**）；**语义已定（V3 裁决）** |
| 3 | 列表侧 | 判断该节点"已下线" | **【已实现】判定口径（已裁）：以 stake 记录为准**（链上事实）；**不靠** "data 解析失败"这类间接信号 |
| 4 | 链上 **`TransferTx{to,value,assets[],data}`** 经 **`signTransferTx` → `sendTransferTx`** | **转让/出售 NFT**，买家可继续使用（质押/改 data） | **【规划中】已立项（V2 裁决）**：接口已锁定（`@ocap/client` 的 `node.d.ts:2422/324/362/400`），**在 beta 链用 TBA 测试币验证**（`scripts/lib/chain.mjs:150-156`）；**尚未跑过** ⇒ 不得写成"已经可以买卖" |
| 5 | 买家 | 继续运营该节点（重新质押 + 写 `endpoint`） | **【规划中】**（依赖第 4 步；beta/TBA 验证后升级） |

**验证方法（【未验证】必须给）**
| 探针 | 方法 | 判定式 |
| --- | --- | --- |
| **P-3**（**beta 链**转让） | 用 `TransferTx{assets:[nft]}` 把一个 NFT 转给另一地址（**beta + TBA 测试币，不需真资金**；证据 `scripts/lib/chain.mjs:150-156`） | 转后 `getAssetState.owner` = 新地址；买方**能质押/改 data** |
| **P-4**（权限） | 转让后由**买方**调用 `updateAsset` | 允许 = 设计成立；拒绝 = 需链下协调 |

**写作纪律**：转让 = **【规划中】已立项**（接口与测试环境已定），但**未跑过** ⇒ **不得**写成"已经可以买卖"；P-3/P-4 判定式保留，**执行环境 = beta/TBA**。
