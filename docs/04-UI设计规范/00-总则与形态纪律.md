## 3. 形态纪律（**计数的三件套**）

| # | 纪律 | 判据 |
| :-: | --- | --- |
| **M1** | **不写"预期条数/页面数"**；凡数字给**实测 + 口径 + 可复算命令** | 数字旁必须有口径与命令（人工审查） |
| **M2** | 每篇 ≤400 行、单行 ≤800 **字符**（Python `len(str)`，**禁 `awk length`**）、**行数用 `wc -l`** | 命令可复跑 |
| **M3** | 变更进文末表 | 每篇有「变更记录」 |
| **M4** | **前向引用必须标注**（该行含链接且标「（未落盘）」）；否则链接 0 MISS | 链接自检脚本 |
| **M5** | **判据要能红、不能假红**：新机检件先跑正本 + 做**变异**（before/after 都贴） | `_gate.sh` 输出 |

## 4. **页面增删的连带后果**

| 受影响物 | 为什么 | 条款要求 |
| --- | --- | --- |
| `scripts/console-nav.mjs` 的 `CONSOLE_SECTIONS` 与生成器 | 侧栏被**复制进每个控制台页**；行集合变了必须重生成 | **增删行 ⇒ 必须重跑 `node scripts/arcblog-console-nav.mjs`**；否则 `scripts/arcblog-console-nav.test.mjs`（含 `assert.ok(path, …not found)`）**必红** |
| `arcblog-ui-budget` **棘轮** | 断言 `files.length == CONSOLE_SECTIONS.length + 1` ⇒ 增删行必然改变等式 | **基线随之调整**，取值**以测试实际输出为准（不写死数字）**；棘轮**只降不升** |
| ~~`arcblog-runtime-ids`~~ | **不在其列**：该测试只守 `wrapper.aup` 的三个 id（`site-header`/hero frame/theme-bridge frame），**不遍历页面** | **不得**把增删页面写成"会让 `runtime-ids` 变红" |

**教训（写入纪律）**：**"看起来会红的门" ≠ "真的会红的门"**——尤其当它要作为下游施工依据时，**必须读断言**，不能凭文件名推断。
