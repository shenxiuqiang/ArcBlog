## 1. 角色清单（7 类）

### 1.1 R1 创作者 / 博主（Basic 个人节点 → Studio）
- **画像**：会 Markdown、未必会 shell。设备＝笔记本+手机；频率＝每周 1–3 篇。身份＝DID 钱包（无邮箱密码）。
- **目标（JTBD）**：把想法低摩擦变成一篇可被搜到、可被分享、可被付费的文章；"我的内容是我的"。
- **当前痛点（带证据）**：
  1. **发布即降级**：compose 的写动作把署名写成未插值模板 `authorDid: $session.did`（`compose.aup:168`、`:169`；平台实测 `arc-contracts.md:1432-1442` §28.7，且 `$session.*` 在 `exec.content` 内不插值）。页面**不报错**，toast 成功 ⇒ 数据质量隐性风险（PM 报告:53，P1/REQ-041）。
  2. **写不出"付费文章"**：compose 只有 9 个输入（`compose.aup:139-160`），**没有可见性选择、没有商品绑定**（`grep visibility|productId` = 0），而 spec §15.4 要求五档可见性 + §45 付费只挂 Product ⇒ 从控制台无法让一篇文章变成付费内容。
  3. **分类是假的**：分类页可增删分类，但 compose 的下拉把选项**硬编码**为 `[technology, design, life]`（`compose.aup:146`），新建的分类在编辑器里选不到。
  4. **中文界面混英文字段名**：同一页里 `SEO Title` / `OG Title` / `OG Description` 未本地化（`compose.aup:156-160`）；订单/账本/策略另有 55 个 zh=en 的原始字段标签（PM 报告:61，P3）。
  5. **回看一团乱**：文章页只有 published / drafts / archived 三个 chip（`posts.aup:172-174`），spec §15.4 承诺的「全部｜回收站」缺 2（PM 报告:56）。
  6. **静态页改了要走 CLI**：`?page=pages` 只有"创建/上线/下线/删除"，没有编辑（PM 报告:55），改一页 About 必须离开后台改文件跑 `arcblog-pages.mjs update`。
- **成功标准**：新文章**默认**就带作者 DID、可被 Hub 索引、有 OG 卡片（spec:976 / :1073）；从空白到上线不超过 3 个页面（spec:974）；`arcblog-doctor.mjs` 的 `authorship` 恒 `ok=true`。

### 1.2 R2 付费读者 / 订阅读者
- **画像**：从社交/搜索落地，**没有钱包**或只有交易所账户；愿意为单篇付费，不愿意为"注册"付费。设备＝手机为主。
- **目标**：读完这篇 / 长期跟这个作者 / 我付的钱有凭据。
- **当前痛点**：
  1. **付不了钱**：reader 页的付费卡只写"购买后才会下发全文"（`reader.aup:7`、`:29-33`），**页面无任何购买动作**（`reader.aup` `write=0 exec=0`）；商店页自认"不含收银台"（`store.aup:10`）⇒「付费解锁」这条主旅程在浏览器里**无路径**（不是受限，是缺失）。
  2. **付费后也解锁不了**：全文靠 `arcblog-economy.mjs access read --content <slug> --reader <did>`（CLAUDE.md 命令面）取；`?page=access` 是**管理员只读**列表（`access.aup:129`），公开面无任何 grant 消费方 ⇒ 读者即使有 Grant 也看不到全文。
  3. **登录入口找不到**：公共页头只有一个"管理后台"菜单项（`wrapper.aup:42`），读者要登录只能从页脚的"阅读清单"（`?page=saved`）进（`index.aup:29`）猜。
  4. **评论/关注/订阅绑定都没有**：`comments-surface` 与 Follow、订阅绑 DID 在清单里是 ⬜（清单:191-193），`.aup` 命中 0。
- **成功标准**：付费前能看到"买什么/多少钱/谁收款"；付费后**同页**解锁且刷新仍解锁；每笔钱有可核对的凭据（spec §50 六问对读者可见的部分）。

### 1.3 R3 站点访客 / 搜索引擎与 AI 爬虫
- **画像**：不出钱的绝大多数人；也可能是一台 Agent。只看首页和文章页，路径依赖外链。
- **目标**：5 秒判断"这里有没有我要的"；可分享的标题/封面；能按主题继续逛。
- **当前痛点**：
  1. **没有发现面**：首页只有 hero + 一列最新 10 篇（`index.aup:8-27`），分类名只是纯文本（`index.aup:15`）、**不可点**；无标签页、无搜索（`searchable-dropdown` 命中 0；平台 AFS 的 `search` 动作也不存在，`arc-contracts.md:383`）；站点绑定只有 `/posts`、`/posts/{slug}`、`/store`、`/pages/{slug}`（`blocklet.yaml:47-78`），**没有 /tags、/categories**。
  2. **SEO 面比承诺薄**：站点根 `/sitemap.xml`、`/rss.xml`、`/robots.txt` 返回 AUP 壳而非真实文件，真文件只在 `/p/` 下（`arc-contracts.md:198`、`:200`、`:367`）；平台无法把 AFS 记录烘焙成静态 SEO 页（`arc-contracts.md:342-367` §8）；阅读页也没有输出 `ogImage/ogTitle`（清单 :100，`grep` = 0）⇒ 分享卡片实际不成立。
  3. **付费墙对访客是死路**（同 R2 痛点 1）。
- **成功标准**：同一篇内容在搜索/社交/RSS/Agent 四个面上都有合法元数据（spec:1073）；点分类能逛到同类文章。

### 1.4 R4 Hub 运营者（发现/聚合节点）
- **画像**：半个运维 + 半个编辑。目标不是写文章，而是"我的索引里有什么、谁在收录、策展做得好不好"。
- **目标（JTBD）**：接入 Studio → 维护索引 → 策展 Topics/Featured → 让上游 `sponsored` 与自然发现可分。
- **当前痛点**：
  1. **策展面缺失**：spec §15.6 要求 Topics 创建/收录 + Featured/Trending 策展 + Sponsored 标记，清单 :120 仍 🟡、:153 ⬜（依赖派生索引与读模型）；Hub Topics 阶段 0 结论＝无 topic schema，且 `hub/index` 是派生（rebuild 会抹掉策展）。
  2. **审批与索引力不从心**：关系行只有通过/终止/彻底删除（`hub.aup` 三个写动作），主动收录、`hub sync`、`index rebuild` 仍是 CLI（清单 :118-119；`index rebuild` 全量扫描实测约 19s，页面已如实披露量级）。
  3. **周期同步没有落点**：清单 :170 ⬜ —— `grep cron blocklet.yaml .aup/app.aup` = 0；`hub sync` 是手动命令，且实测是**声明值**（Hub 侧 AFS 逐字节不变）。
  4. **权重与收益算不清**：`?page=ledger` 只读、`?page=orders` 只读，Hub 视角的"我分到多少"没有专属视图。
- **成功标准**：索引异常能定位到具体 Studio 与具体文章（spec:1125）；任一 Hub 失败不阻塞其它 Hub（spec:1117）。

### 1.5 R5 节点运营者 / 自托管运维者（自建 Studio / Hub）
- **画像**：自托管，**没有平台运维团队**（spec:1284）。能跑 CLI，但不该被要求跑 CLI。设备＝桌面。
- **目标**：节点别挂、角色别丢、数据能带走、异常 30 秒内发现。
- **当前痛点**：
  1. **巡检页被静默回退**：spec:946 要求"任何异常 30 秒内发现 + 一次点击直达"；实测 `dashboard.aup` `propBind=0`、无 network/alerts 键，而清单 :132 仍标 ✅（PM 报告:52）。异常（同步失败/结算失败/授权过期）在控制台**没有任何落点**。
  2. **节点身份没有菜单入口**：spec §15.10 明列「网络 → 节点身份」，但 21 页目标 IA 里没有这一行；`?page=operations` 只读、`?page=seo` 才写 Node Profile ⇒ spec 自相矛盾（PM 报告:60，Lead 判为"标准缺口"，改 spec 须人类批准）。
  3. **能力驱动菜单不可表达**：spec §15.1 硬规则 1/2（按 Capability 隐藏）未实现，`scripts/console-nav.mjs` 的 capability 命中 = 0、侧栏唯一条件是 `visible=$session.authenticated` ⇒ Basic 节点也会看到"网络/经济"菜单（清单 :131，R27 探针判为平台边界）。
  4. **"高级"有两套折叠**：5 页用平台 `view mode=tabs`、5 页用手写 `set {open}`（设计报告:55）⇒ 用户对"高级在哪"形成不了稳定预期。
  5. **资金动作只有 CLI**：退款/结算/改收款地址在页面上均无入口（`orders/ledger` 写入面 = 0），且 spec §89/§90 的不可逆语义尚未定回退口径（PM 报告:58 裁决点 5）。
  6. **诊断页是"命令复制台"**：`?page=diagnostics` 页内零执行（`grep exec|events=` = 0，清单 :130）——诚实，但对"没 shell 的人"等于没有。
- **成功标准**：不接触服务器完成健康自检、日志导出与数据备份（spec:1285）；"任何人都能带着自己的数据离开"（spec:1286）。

### 1.6 R6 Agent 接入方 / 开发者
- **画像**：外部 AI Agent 的开发者，或把自己的 Agent 指向本站的运营者。以 `/mcp`、`/api/afs/rpc`、`llms.txt` 接入（spec:2562）。
- **目标**：用最小权限读内容/写草稿；发布与花钱必须拿到显式、短期、可撤销的授权。
- **当前痛点**：
  1. **授权签不出来（页面侧）**：spec §15.8 要求"签发（能力+TTL）/撤销/高风险二次确认"，`?page=agents` 是**只读页**（`grep '\.actions/write'` = 0，且从未有过写接线）⇒ 无 shell 的运营者无法授权 Agent（PM 报告:57）。
  2. **工具目录是静态镜像**：清单 :125 自认页面工具名与 CLI 实时输出的一致性**没有测试覆盖**，CLI 目录一变就要人工同步。
  3. **审计只有 CLI**：spec §15.8 要求 Agent 操作日志成页，`arcblog-audit.mjs` 有、页面没有（清单 :127 判 ✅ 但界面落在 CLI）。
- **成功标准**：从未配置过的节点暴露面＝"公开内容只读"（spec:1208）；`agent.admin` 在界面上根本不存在授权入口（spec:1222）。

### 1.7 R7 平台方 / 治理者（协议与分发维护者）
- **画像**：维护 ArcBlog 软件与官方 Hub，不是任何实例的运维。
- **目标**：软件≠网络（spec:4692）；不出现唯一官方 Hub（spec:4712 的 "One Hub, not The Hub"）；实例各自负责自己的数据与合规。
- **当前痛点**：
  1. **对网络层的可观测性只在 AFS 里**：HTTP `/.well-known/arcblog`、`/api/*` 在该平台不可行（`arc-contracts.md` §7，`README`/CLAUDE.md 记录），发现只能靠 AFS ⇒ 治理方无法用常规手段抽样核验全网。
  2. **Hub 间发现明确不做**：spec:4770 第一版不要求 Hub-to-Hub，清单 :194 ⬜；官方 Hub 与社区 Hub 之间没有共同的可比对账口径（只有单节点 `network.mjs health`）。
  3. **策展/推广的可信性无界面**：Sponsored 与自然发现必须区分（spec:1135），但清单 :153 ⬜ ⇒ 治理方无法从产品面证明"排序没被买走"。
- **成功标准**：任何实例的数据可导出、可迁移（spec:140/§141）；Hub 之间互为独立单元，任一离线不影响他人（spec:3037）。

## 5. 反例：不要做的体验（5 条，取自归档审查报告）

1. **假按钮 / 无写接线的"看起来能点"** —— 反面是"页面上有动作但落不了库"。正面范式：无写接线的页面必须明写"CLI 执行"并给可复制命令（`media.aup:154-155`、`orders.aup:4`）。**禁止**在没有 worker 的情况下摆出会成功的按钮（UI 标准 §4.9）。
2. **空态不给下一步** —— `dashboard.aup:155/:176` 把唯一指引放进 `emptyText`，而平台运行期不解析 `$t()`、空列表渲染英文默认文案（`arc-contracts.md:745` §20）⇒ 指引等于不存在（设计报告:53）。空态必须落在**可见的页面级说明卡**上（正确范式 `media.aup:15`、`pages.aup:33`）。
3. **中文页混英文字段名** —— `zh.json:528` 的 `orders.label-buyer` = `buyerDid`、`:541` = `settlementVersion`，`compose.aup:156-160` 直接写 `SEO Title`/`OG Title`（PM 报告:61）。可以展示原始**值**，但**标签**必须是中文。
4. **已验收功能被静默回退，而清单仍记 ✅** —— `dashboard.aup` 的 network/alerts 与 `media.aup` 的清理按钮都被回滚，清单 :132/:111 状态未变（PM 报告:52/54，Lead 复核:228/230）。修复功能时**必须同步状态列**，且回滚恢复要逐页校验内容（Lead §9.3 指出恢复提交本身丢了两个功能）。
5. **同一意图两套交互 + 同一页三个名字** —— "高级"折叠 5 页用页签、5 页用手写 `set {open}`（设计报告:55）；`?page=posts` 在侧栏/门禁/页头有三个名字，`?page=media` 的门禁标题一度写成"运维"（另一个页面的名字，设计报告:54/56）。规则应硬化：**侧栏标签 = 页头标题 = 门禁卡标题；同一操作用同一模式触发**。

## 6. 本轮受限未验证（如实标注）

## 摘要（给主笔，10 条以内）

1. **7 类角色**：R1 创作者/博主、R2 付费读者、R3 访客与爬虫、R4 Hub 运营者、R5 节点运营者、R6 Agent 接入方、R7 平台方；四类节点形态（Basic/Studio/Hub/两者）映射到 spec §7/§8，不要写成"网站账号"。
2. **最硬的一个断点：付费闭环在浏览器里不存在**——`reader.aup:29-33` 承诺"购买后下发全文"却无购买动作（write/exec=0），`store.aup:10` 自认"不含收银台"，全文只能 CLI 取（`access read`）。这是"顾客能看见价格却付不了钱"，应列为产品概念文档的头号未闭环旅程。
3. **第二硬：控制台写出来的记录署名可能是错的**——`compose.aup:168/169` 的 `authorDid: $session.did` 不插值（§28.7 实测），页面却回报成功。写盘瞬间破坏"内容可归属/可签名"这一根本承诺。
