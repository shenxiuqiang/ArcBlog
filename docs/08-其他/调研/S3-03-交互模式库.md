## 0. 用法与三条前置事实

- 模式 = 「何时用 + 结构 + 状态与降级 + 验收判据」四段；**四段缺一不算模式**（只写"长什么样"是样式表，不是模式）。
- 平台三条事实贯穿全库：`emptyText` 运行期不解析 `$t()`（`契约:745`）；`state={value:"${…}"}` 不插值、`value="${…}"` 插值（`契约:739`）；单记录 `propBind` 首屏竞态、初始解析不触发重渲染（`契约:903`）。
- 「控制台」= `?page=<name>` 的 21 个节（数量取自 `scripts/console-nav.mjs`，**不写死**，`UI标准:113`）；公共站点页不受 `UI标准` 约束（`UI标准:12`），本库 §1 只覆盖控制台，公共面缺口见 §2。

## 1. 模式清单（M01–M15）

### M01 · 门禁卡（未登录门）
- **何时用**：guest 打开任一控制台节；无 `$session.authenticated` 即渲染，**不渲染任何后台数据骨架**（`UI标准:651`）。
- **结构（线框）**：`view(padding 20px, card token) visible="!$session.authenticated"` → `h2 :gate-title level=2 (15px)` + `p :gate-desc intent=muted` + `row cross=start { action -> navigate "/.well-known/service/login?return_to=…" variant=primary label=:login }`。`gate-title` 必须与本页页头 `title` **逐字相同**。
- **状态与降级**：门禁卡是登录门、**不是**内容卡，`padding` 固定 20px，豁免控制台 14px（Lead D4，`UI标准:392`）；标题写错页名 = P1 缺陷（`media.aup:8` 写"运维"而本页 `title` 是"媒体"，`评审:51`）；文案必须能回答"这一页登录后干什么"（`compose-edit` 借用 compose 文案属缺陷，`评审:52`）。
- **验收**：guest 探针文本含本页 `title`；`gate-title == 页头 title == 侧栏标签短式`（`UI标准:303-307`）；每页恰好 1 张。**实例**：`?page=dashboard`（`.aup/pages/admin/dashboard.aup:22`）、`?page=media`、`?page=compose-edit`。

### M02 · 意图队列卡（`pending｜running｜applied｜rejected｜noop`）
- **何时用**：控件**不能直写**目标记录时（平台 authority sidecar 拒绝重写、页面无哈希/聚合原语）——这是本后台的标准写入范式（`UI标准:583`；BUG-068：5 个预设按钮 + Save adapter 全 no-op）。
- **结构（线框）**
```text
标题 → 一句话说明（做什么/为什么排队）→ 图例 → afs-list(<stable-id>, pagination=manual pageSize=10, subscribe=true)
  → 每行：终态 + 具体原因(message/error) → 行内 Clear(destructive + confirm)
  → 常驻规则说明（"点击只入队；worker 运行前目标记录逐字节不变；toast 不是证据"）
  → CLI 出路（折叠进「高级」，且不得是唯一路径）
```
- **状态与降级**：状态词表**唯一真源** `scripts/lib/intents.mjs:33`（`INTENT_STATUS`/`TERMINAL_STATUSES`/`IN_FLIGHT_STATUSES`），页面图例逐字对齐，不得另造 `done/failed/success`（`UI标准:585`，BUG-045 同族）；`running` 要么 worker 真写、要么三处对齐改述（BUG-073，`UI标准:589`）；**不得无条件渲染"队列为空"**（BUG-072，`UI标准:591`）。
- **验收**：点击后目标记录 **sha256 不变**而队列 +1；worker 后目标真变；重跑 = `applied: 0` + 零改动（幂等）；非法输入 = `rejected` + 原因 + 零改动；已等值 = `noop` + 零字节；队列路径对 guest 403；**toast 不算证据**（`UI标准:593`、`契约:1500`）。**实例**：`.aup/pages/ops/hub.aup:211,214-227`、`.aup/pages/economy/policy.aup:264`、`.aup/pages/ops/factory.aup:242,253`。

### M03 · 诚实降级（平台破折号 + 常驻说明）
- **何时用**：`propBind` 未解析、记录确实没有该字段、平台不提供聚合原语（AUP 无 `length`）。
- **结构（线框）**：`[key-value-list 该行留空 → 平台渲染 "—"]` + 同卡 `p :xxx-standing-note scale=caption intent=muted`（无条件渲染）。
- **状态与降级**：**唯一**允许形态 = 如实留白 + 常驻说明；**禁止**渲染成 `0` / `Online` / 绿灯 / 空串 / 自造「尚无数据」字面（R24 口径：用平台破折号、页面零新增字串，`UI标准:552`）；常驻说明**不得断言为空**（页级元素探测不到列表长度，BUG-052/056/072 —— 合法路径只有 ① 状态中性说明 ② 插值 `visible="${state.x}"`，`UI标准:556`）；首屏未就绪 = 两段式取数，破折号 ≠ 记录不存在（`UI标准:558-562`、`契约:903`）。
- **验收**：页面无自定义空值字面；受影响卡带常驻说明且**无条件渲染**；读数用**第二次**（切页/刷新后）且每次新开页复跑。**实例**：`.aup/pages/economy/policy.aup:62`（`policy-standing-note`，BUG-072 修法）、`?page=dashboard` 网络卡 `net-empty-note`、`.aup/pages/economy/orders.aup:60,206`。

### M04 · 空态（含"下一步"指引）
- **何时用**：列表为空 / 新节点首次登录。
- **结构（线框）**：`[页级常驻卡，不放插画]` 一句现状 + 一句价值 + 一个动作 → `p :empty-guidance scale=sm intent=muted` + `row { action -> page compose size=sm label=:empty-cta }`。
- **状态与降级**：**硬规则**——空态指引**不得**写在 `emptyText` 上（`契约:745` 实测不求值，`dashboard` 曾因此丢失指引，`评审:53`）；`emptyText` 只用于"这一行没有内容"的极简说明；列表空态只能由**页级常驻元素**承载（`UI标准:468,564`）。
- **验收**：页面存在承载"下一步动作"的可见元素（非 `emptyText`）；`UI标准` §9「空状态有引导和动作」。**实例**：`.aup/pages/admin/dashboard.aup:11,152,155`（常驻说明 + `:empty-cta` 动作，REVIEW 第 4 条的落地修法）；范式 `.aup/pages/ops/media.aup:15,177`。

### M05 · 错误与拒绝（含原因与恢复路径）
- **何时用**：写入失败、意图 `rejected`、权限被拒、平台能力缺失。
- **结构（线框）**：行内 `p "${entry.content.message}"` / `p "${entry.content.error}" scale=sm intent=warning`；卡级三要素 = 发生了什么 + 为什么 + 怎么办（带重试 / 跳转 / 可复制 CLI）。
- **状态与降级**：Error 必须附**具体失败项**（"同步失败：Hub 无响应"），不得只写"失败"（`UI标准:427`）；局部失败局部呈现，一个 Hub 失败不阻塞整页（`UI标准:488`）；平台做不到时**不保留控件**，改常驻说明 + CLI（`UI标准:575`）。
- **验收**：`rejected` 行 `message` 非空；错误文案含恢复路径；无"操作失败"式空话；负例 = 非法输入必须被拒且**零写入**（`PRD-CNT-02` B1/B2、`PRD-ECO-03` B1）。**实例**：`.aup/pages/ops/factory.aup:242`；`.aup/pages/economy/policy.aup:234`（`onErrorToast: $t(policy.rejected)`）。

### M06 · 确认与二次确认（destructive / 高风险）
- **何时用**：不可逆操作（删除、退款、撤销质押、清队列）；高风险授权（`agent.publish`/economy）。
- **结构（线框）**：`action variant=destructive size=sm icon=trash label=:act-delete confirm={title: :act-delete-title, message: :act-delete-msg}` —— `message` 写清后果；高风险授权 = 二次确认 + 明确权限范围（`UI标准:497`）。
- **状态与降级**：常规操作（保存/发布）**直接执行 + 轻提示**，不弹窗；成功反馈优先原地状态变化，不弹"操作成功"（`UI标准:495-498`）；confirm 文案必须写明边界，例："只删该意图记录，不撤销 worker 已应用的改动"（`UI标准:587`）。
- **验收**：每个 `variant=destructive` 的 `action` 都有 `confirm=`；无 success dialog；删除类操作在 AFS 前后计数一致（未确认项不动，`PRD-CNT-05` B1）。**实例**：`.aup/pages/economy/policy.aup:278`（Clear）、`.aup/pages/admin/pages.aup:190,212`、`.aup/pages/site/categories.aup:229-230`。

### M07 · 行内动作（列表行内的次要/危险操作）
- **何时用**：列表行上的查看/编辑/归档/删除等非导航动作。
- **结构（线框）**：`row role=item style={background: transparent, borderBottom: 1px var(--color-border), padding: "8px 0"}` → `view(flex:1, minWidth:0){ h3 + p scale=sm intent=muted }` → `row cross=start { action size=sm … | action variant=destructive size=sm icon=trash … }`。
- **状态与降级**：行内写操作**原地执行、不跳转**（`UI标准:195`）；行背景透明 + `autoSelect=false`，否则首行显示为选中底（`UI标准:384,441`）；固定尺寸元素必须 `flexGrow:0` + `flexBasis`，只写 `flexGrow:0` 会塌成 0 宽（`UI标准:542`、BUG-033）。
- **验收**：行 `cross=start`（否则按钮被拉伸到卡片等高）；命中区 ≥24×24（`UI标准:704`）；destructive 静息/hover ≥4.5:1（`UI标准:703`）。**实例**：`.aup/pages/economy/policy.aup:332-333`、`.aup/pages/admin/pages.aup:189-190`、`.aup/pages/admin/posts.aup:196-197`。

### M08 · 批量动作（集合级处理，含"确认清单"语义）
- **何时用**：一次处理多条记录——清空队列、孤儿媒体清理、分类合并迁移。
- **结构（线框）**：批量 = 列表 + 逐行动作（M07）+ 显式确认清单；CLI 只作用于「确认清单 ∩ 仍满足条件」的集合；迁移类动作先改写引用、再删源记录，由 worker 执行（绝不留下悬空引用）。
- **状态与降级**：**未确认的 id 不得被删除**（`PRD-CNT-05` B1）；重复执行同一集合第二次必须 `noop` 且记录不变（A4）；合并/迁移必须由 worker 执行并给常驻说明（`.aup/pages/site/categories.aup:36-37`）。
- **验收**：AFS 前后计数一致（未确认项）；`changed = 确认清单 ∩ 孤儿`（`PRD-CNT-05` A3）；merge/remove 后**无悬空分类**。**实例**：`?page=categories`（`.aup/pages/site/categories.aup:229-230`）、`?page=policy`/`?page=hub`/`?page=tags` 的队列 Clear。

### M09 · 列表与分页（真入口 vs 平台不渲染）
- **何时用**：**每一个** `afs-list`。
- **结构（线框）**：`afs-list <stable-id> layout=list itemStyle=row subscribe=true clickMode=none autoSelect=false pagination=manual pageSize=N [pageSizeOptions=[N]] from "/instance/app/arcblog/<dir>"`，紧邻 `p :pagesize-note scale=caption intent=muted`（无条件渲染）。
- **状态与降级**：`total > pageSize` 必须有**可见可操作真入口**（点击写 URL `<id>.page=<n>`，真切片）；`total <= pageSize` **全量渲染 + 平台不渲染控件 + 不得伪造入口**（`UI标准:511-515`，红线 L-R23-2）；禁用 `pagination=auto`（只截断 + 无限续载，无页码入口）；BUG-063：`localStorage['aup-list-pagesize:<id>']` 会覆盖页面默认值、选到 ≥ 总数会让平台**移除整个分页器（含选择器）**，故必须带常驻恢复说明（四要素，`UI标准:519-538`）。
- **验收**：逐页探针 `{page, listIndex, renderedRows, pageSize, hasEntry}` 且 `renderedRows <= pageSize`；深链 `<id>.page=3` 可还原、越界钳到末页、末页 `Next` disabled；受影响列表的常驻说明在**分页器消失后仍存在**（`UI标准:544`、`契约 §38`）。**实例**：`.aup/pages/economy/orders.aup:177-178`、`.aup/pages/admin/posts.aup:181,247`、8 页 `pagesize-note`（`ledger`/`orders`/`policy`/`access`/`dashboard`/`posts`/`tags`/`store`）。

### M10 · 详情投影（`propBind` 两段式取数）
- **何时用**：单记录卡片（节点档案/健康/发现、策略、factory 摘要、编辑器回填）。
- **结构（线框）**：`page <name> { propBind={post: "/instance/app/arcblog/posts/$params.slug.json"} … }`；卡内读取 `${state.post.*}`；可见性用插值 `visible="${state.post.coverImage}"`（表达式形式只求值一次）。
- **状态与降级**：首屏**不解析**（渲染早于绑定解析，初始解析不触发重渲染）→ 破折号/空白 = "记录没有该值"**或**"绑定未解析"，**不得**据此断言"没有记录"；恢复 = 页内切页往返或 reload；受影响卡必须带常驻说明写明这一点（`UI标准:558-562`、`契约:903`）。
- **验收**：**两段式第二次读数**（或刷新后）作准，且每次新开页复跑；断言不得用 `?? 0` 之类兜底掩盖"没取到数"。**实例**：`.aup/pages/ops/factory.aup`（`state.summary`）、`.aup/pages/ops/operations.aup`、`.aup/pages/admin/compose-edit.aup`、`.aup/pages/economy/policy.aup`。

### M11 · 表单与校验（受控 select，避免非法组合）
- **何时用**：任何写入表单（写文章、设置、创建记录）。
- **结构（线框）**：`input value="${state.x}"`（禁止 `state={value:"${…}"}` —— 渲染成字面量，`契约:739`）；枚举字段用 `input type=select options=[{label: :choose, value: ""}, {label, value}…] value="${state.x}" required=true`。
- **状态与降级**：非法组合**必须在控件层不可能被选中**（受控 `select` + 白名单枚举，`.aup/pages/admin/general.aup:232,241` 是范式）；分类下拉若硬编码 3 项则新建分类选不到（`.aup/pages/admin/compose.aup:146` 现状 = 缺陷，`03-使用旅程` J1-5）；空值/类型错误交给 schema 与平台校验（`required=true`），**fail-closed**。
- **验收**：页面无字面量 `${…}` 渲染；白名单外的值提交必须被拒且**零写入**（`PRD-CNT-02` B1/B2、`PRD-ECO-02` B1）；表单字段数不回归（`PRD-CNT-01` C2：compose = 12）。**实例**：`.aup/pages/admin/general.aup:232,241`（受控 select）；反例 `.aup/pages/admin/compose.aup:146`。

### M12 · 复制命令卡（CLI 折叠，平台的"诚实出路"）
- **何时用**：平台确实做不到的写/读能力（页内上传、链上写、账本查询、Agent 授权）。
- **结构（线框）**：`key-value-list <id> dense=true fields=[{label: :cmd-x, value: "node scripts/arcblog-<domain>.mjs <verb>", monospace: true, copyable: true}]`；位置在三级「高级」页签/折叠区内（`UI标准:298` 落地顺序 ③）。
- **状态与降级**：命令卡是**降级路径**，不是唯一路径时须写明"页面可做什么、CLI 补什么"；页面必须写明「需 CLI / worker：<命令>」+ 原因（`UI标准:573-575`）；命令必须**今天真能跑通**，不得写"将来会"（`PRD-ECO-08` A2）。
- **验收**：每个复制行指向真实存在的脚本子命令且该队列有消费者（`grep -n "apply\|watch" scripts/arcblog-<domain>.mjs`，`UI标准:579`）；同屏技术标识 ≤2（命令行也计入）。**实例**：`.aup/pages/ops/media.aup:184`（`adv-cmds` 一行收敛 6 个子命令）、`.aup/pages/ops/agents.aup`（`agent-grant-cmds`）、`.aup/pages/ops/hub.aup`（高级折叠内 CLI + queue）。

### M13 · 页签与分组（信息分级）
- **何时用**：同一节内有多级信息（一级核心 / 二级摘要 / 三级技术细节），或列表 + 详情两个子视图。
- **结构（线框）**：`view mode=tabs { view label=:index-title { …一级/二级… }  view label=:adv-title { …三级… } }`。
- **状态与降级**：三级（DID/哈希/AFS 路径/原始 JSON/CLI 命令/链内部值/诊断内部项）**默认不可见**，折叠或独立高级页；三级与一级同屏平铺 = 不通过（`UI标准:296-298`）；合法机制只有 ①`mode=tabs`（新页与重写页一律用它）②′ 手写 `set state {open}`（历史页登记，**不得新用**）③ 复制行（`UI标准:290`）；同一页不得两套并存（`评审:55` 第 6 条）。
- **验收**：同屏技术标识 ≤2；折叠内**不得**藏唯一主操作；每页折叠机制唯一。**实例**：范式 `.aup/pages/ops/media.aup:157,184`、`.aup/pages/admin/compose.aup:154`；历史形态 `.aup/pages/ops/factory.aup`（手写 `state {open}`）。

### M14 · 导航与当前项（`active=true`）
- **何时用**：侧栏每一行、控制台内每一次点击。
- **结构（线框）**：`action "$t(wrapper.nav-<key>)" -> page <name> active=true`（仅本页那一行）；内容区链接 `-> page` 同标签页整页替换；记录绑定页/非 HTML 资源 → `view href="…" target=_blank`。
- **状态与降级**：当前行由**平台 `active=true`** 渲染为 `data-active="true"` + `aria-current="page"` 并按 accent token 上色——**不手写颜色**、不用 `variant=primary`（会居中标签）（`UI标准:68,71,122`）；侧栏由生成器投影（AUP 无可用跨页片段），改菜单只改 `scripts/console-nav.mjs`；组名不得与任何行名同词（`UI017:112`）。
- **验收**：每页 `active=true` **恰好 1 处**（21/21 页实测，`UI标准:122`；`compose-edit` 0 且不属于 21 节）；内容区**不存在会把控制台整页替换掉的链接**（等价断言：`candidates ≥ 1 且 total = 0`，`UI标准:730-748`）；`console-nav --check` 绿。**实例**：`.aup/pages/admin/dashboard.aup:32` 等 21 页各 1。

### M15 · 权限与能力（隐藏而非置灰 + 状态双编码 + 原始值可见）
- **何时用**：无能力、未激活角色、锁定字段、状态展示。
- **结构（线框）**：无能力 → `visible=$session.authenticated` 隐藏（不是 `disabled`）；未激活角色 → 路线图引导（购买→质押→激活）；状态行 → `p "●" scale=sm intent=muted title=…` + `p "${entry.content.status}" scale=sm` + 图例常驻；角色五态 → `None ─ Acquired ─ ●Staked ─ Revoking ─ Claimable`（当前态高亮，下一步动作紧跟）。
- **状态与降级**：`$session` 只有 did/displayName/authenticated，**没有 role** ⇒ 菜单无法按能力隐藏，非管理员按 guest 计（`UI标准:680`、`契约 §28.1`）；状态**不得只靠颜色**（点 + 文字双编码），**不得**只把真值放进 `title`，**不得**把不同真实状态断言成同一句话（`UI标准:433`）；本地化不可按记录值切换（动态 `$t()` 原样渲染）⇒ 中性标签 + 原始枚举值可见 + 常驻说明（`UI标准:432`）；`withheld` 必须显示 `roleStatus().reason` **原始英文值**；五态与 `scripts/lib/roles.mjs` 的 `STAKE_STATES` 逐字同源（`UI标准:639-640`）。
- **验收**：无 fake-disabled 控件；withheld 原因可见；地址/网络输入框 = 0（改配置只走 CLI）；不得把记录残留 `assetId`/`stakeId` 写成"链上已验证"（`UI标准:641-642,714`）。**实例**：`.aup/pages/ops/agents.aup:185-190`（`status-unavailable` + 行内原因 + `tools-legend`）、`.aup/pages/ops/hub.aup:25,187`（`relations-legend`）、`.aup/pages/admin/general.aup:370`（role-verify 队列）。

## 摘要（给主笔，10 条以内）

1. 模式库共 **15 个**（M01–M15），四段齐全：门禁卡 / 意图队列卡 / 诚实降级 / 空态 / 错误与拒绝 / 确认与二次确认 / 行内动作 / 批量动作 / 列表与分页 / 详情投影 `propBind` / 表单与校验 / 复制命令卡 / 页签与分组 / 导航与当前项 / 权限与能力。
2. **第一红线是"诚实"**：假 0、假绿灯、假按钮、把"已入队"写成"已生效"四类，全部有平台实测或 BUG 编号作证（`UI标准` §4.8/§4.9 + BUG-052/056/068/072）。
3. **意图队列卡是本后台唯一的写入范式**（8 条队列），词表唯一真源在 `scripts/lib/intents.mjs`，页面图例必须逐字对齐；验收一律以 AFS 前后 sha256 为准，toast 不算证据。
4. **常驻说明（`scale=caption intent=muted`）是平台的通用补丁位**：分页恢复（BUG-063）、诚实降级、空态、队列规则四处都用它；它不是装饰，是可验收的承载元素。
5. **分页只有一套口径**：`pagination=manual pageSize=N`；`total<=pageSize` 平台不渲染，**不得补假入口**；可能分页的列表必须带常驻恢复说明。
6. **`emptyText` 与动态 `$t()` 是两条平台死路**（`契约 §20`/`§28.8`），空态与状态文案必须走页级常驻元素 + 原始值可见。
7. **"三处同名"与"每页恰一行 `active=true`"是最便宜、最可机检的两条一致性规则**，建议直接进 Stage 4 规范条款。
8. **§2 映射显示 7 处设计缺口**：dry-run 预览确认（OPS-03）、构建/发布状态（OPS-04）、拒绝路径自证（OPS-06）、Agent 审计视图（AGT-04）、Hub 收益视图（ECO-07）、策展标记（NET-05）、公共面（CNT-03/ECO-08/SITE-04）——这些是 Stage 3 产品设计文档要补的模式。
9. **反模式共 14 对**，最危险的三对是"置灰代替隐藏""无条件空态断言""内联样式吃预算"——前两者已有 BUG 编号，第三者已让 `posts`/`hub` 未通过 §9 验收清单。
10. **两个待 Lead 裁决的机制口子**：手写 `state {open}` 折叠是否合法（Q1）、复合原型 `P1+P5` 是否合法（Q2）——不裁，Stage 4 无法写出可判定的折叠与原型条款。
