## 0. 一句话结论

归档期的**流程**是成功的（83 份可复现 BUG、32 份独立 QA 报告、59 节实测平台契约都产出了真结论），
**文档形态**是失败的（同一事实多出处、变更写进标题行、过程日志与产品事实同层）。新体系要**继承流程、重建形态**：
把归档期被反复验证有效的纪律（可复跑证据、独立审查、写范围、fail-closed、收口 runbook）搬进 `docs/07-团队与开发规范/`，
把归档期被反复证伪的形态做法**明令禁止**。

## 1. 文档反模式清单（10 条）

### A1 同一事实多处定义 → 计数漂移（最贵的形态病）
- 现象：同一组"功能清单计数"在 4 个文件里各写一遍，各自随轮次改，互不同步。
- 证据：`_docs/ArcBlog-feature-checklist.md:42`（合计 **86/4/18/2 = 110**）与同文件 `:44`（**未完成项汇总 = ⬜19 + 🟡7 = 26 项**，实际应为 ⬜18+🟡4=22）；同一数字又抄进 `_docs/team/backlog.md:52`（**82/7/19/110**）、`_docs/team/journal/round-22.md:3`（82/7/19）、`_docs/team/journal/round-26.md:4`（86/4/18）。
- 后果：审计者无法回答"到底还剩几项"；`docs/README.md:12` 已把该症状列为重建理由。
- 对策：**一个事实一个出处**——计数只由正文表实时算出（脚本生成总览），禁止手写；其它文件只链接（`docs/README.md:19`、`:99`）。

### A2 变更记录写进标题行 / 版本行
- 现象：把整轮变更日志塞进文档第 5 行的"文档版本"里，单行数千字符。
- 证据：`_docs/ArcBlog-admin-ui-design.md:5` = **3419 字符**的单行版本行（V1.10 及其全部历史）；`_docs/ArcBlog-product-technical-spec.md` 的 §0 变更段同样在头部堆叠。
- 后果：任何 diff 都不可读；审阅者必须整行读完才知道改了哪一节；"逐字节未动"这类断言只能靠人信。
- 对策：版本行只留 `v1.0`，变更进文末**变更记录表**（一行一改，含日期/版本/章节/一句话）（`docs/README.md:90`、`:99`）。

### A3 汇总与明细不同步（状态列漂移的根源）
- 现象：同一文件里"总览表"和"未完成项汇总段"各有一套数，且只在改一处时更新。
- 证据：`_docs/ArcBlog-feature-checklist.md:44` 的 26 项（⬜19+🟡7）vs `:42` 的 22 项；`_docs/ArcBlog-feature-checklist.md:259` 自认**"修正 R24 只改总览未改正文的计数不一致"**——同一类错误至少复发一次。
- 后果：状态不可信，读者宁可去读代码；"清单漂移"成为长期税。
- 对策：汇总**不手写**，由明细生成；明细行状态变更须在同一提交内改（`docs/README.md:116` 可追溯、`:119` 无内部矛盾）。

### A4 单条横幅上千字：规划 / 裁定 / 复盘混在一条
- 现象：backlog 用"规划横幅"承载轮初计划 + Lead 裁定 + 轮末复盘，一条就是一篇论文。
- 证据：`_docs/team/backlog.md:20` = **3677 字符**、`:30` = 4374、`:34` = 4229、`:28` = 3572、`:26` = 3811（同形横幅 `:22`–`:54` 连续 18 条）；同一份内容在 `_docs/team/journal/round-22.md:3`、`:8` 又整段重抄。
- 后果：backlog 4504 行、无法排序/裁剪；"本轮要做什么"被淹没；同事实两处维护。
- 对策：**看板只放一行一条**（编号/状态/一行目标/链接），计划与复盘留在 `docs/team/journal/`；长内容写文件、看板只引用（`docs/README.md:38`、`:98`）。

### A5 表格备注列被写成轮次史诗
- 现象：功能清单一行塞进历轮收口、平台边界、遗留、缺陷编号。
- 证据：`_docs/ArcBlog-feature-checklist.md:112` = **1561 字符**的单行、`:132` = 1031、`:129` = 978、`:61` = 798、`:107` = 545。
- 后果：表格失去可扫描性；改一格要动 1500 字符（易截断，见 A9）；人无法"5 分钟核对一遍状态"。
- 对策：一行 = 一个功能 + 一个状态；历史进版本控制，细节进对应设计/开发文档（`docs/README.md:98`、`:99`）。

### A6 把过程日志当产品文档
- 现象：功能清单里挂"维护记录"表，49 行里每行是一整轮的工作复盘。
- 证据：`_docs/ArcBlog-feature-checklist.md:215`–`:263`（维护记录 49 行，如 `:259`/`:260` 单行即一轮完整总结）；`_docs/ArcBlog-feature-checklist.md` 与 `_docs/team/journal/round-*.md` 内容大面积重复。
- 后果：产品事实（这功能现在什么状态）与过程（这一轮怎么吵的）同层，读者必须先过滤叙事才能拿到事实。
- 对策：**产品文档只写事实与状态**，过程写 `docs/team/journal/`；交界处用一行链接（`docs/README.md:37`、`:144`）。

### A7 文档里出现无法复现的断言
- 现象：把一次观察写成"平台必然如此"，后来复测不成立。
- 证据：`_docs/team/bugs/BUG-008-*.md:1`（UI 标准 §9 附注"实测 2"写成 1）；`_docs/team/bugs/BUG-018-*.md:4`（`arc-contracts.md §29.2` 的"平台必然拒绝"在 R10 环境不可复现）；`_docs/team/bugs/BUG-061-*.md:3`（"media 不支持 `data:` URI"被实测**证伪**）；`_docs/team/bugs/BUG-062-*.md:3`（"冷载必然为空"不可复现）；`_docs/team/journal/round-22.md:8` 为此立"**必须先更正、后落笔**"前置。
- 后果：一条错误平台事实会让后续所有 agent 按错前提写代码（`_docs/team/requirements/SPEC-APPROVAL-001-spec-revision-requests.md:13` 列了 3 条 P0/P1 同型）。
- 对策：平台/实现断言必须带**复跑命令 + 原始输出 + 复现条件**，并允许被新实测推翻（`docs/README.md:20`、`:108`；四类标签【已实现】【规划中】【平台边界】【决策待定】）。

### A8 同一概念多套状态词表
- 现象：同一个"意图状态"在三个页面/三份代码里叫三种名字。
- 证据：`_docs/team/bugs/BUG-045-two-status-vocabularies-coexist.md:31`（categories `pending|applied|rejected|noop` vs tags `pending|done|noop|failed`，页面图例还把 `pending` 画成 `queued` = 三套叫法），严重级 P1；`_docs/team/bugs/BUG-073-*.md:1`（图例宣传的 `running` 永不出现）。
- 后果：用户与 agent 都读不懂状态；跨页面对不上；P1 阻断了一整个轮次的放行。
- 对策：词表在**唯一出处**定义（`docs/README.md:131` 已把"意图队列"状态词表指到 `03-产品设计/`），任何新状态先登记再用（`:136`）。

### A9 巨型单文件 + 结构被截断
- 现象：一份文件承载全部平台事实 / 全部需求 / 全部产品方向。
- 证据：`_docs/arc-contracts.md` **2585 行 / 59 节**、`_docs/ArcBlog-product-technical-spec.md` **5571 行**、`_docs/team/backlog.md` **4504 行**；`_docs/team/backlog.md:20` 等横幅在实际读取时被截断为 2000 字符（同文件多处可见截断标记）。
- 后果：无法整体复核；长行/长文件被工具截断后，结论只剩前半段（`_docs/team/bugs/BUG-076-ui-budget-general-tech-baseline-not-reproducible.md` 的 Dev 段落即因此类截断风险被单独复核）。
- 对策：每篇 ≤400 行，超了就拆 + 目录 README 建索引（`docs/README.md:98`）；平台事实按主题分篇，不建"万法归宗"文件。

### A10 权威链自指 / 指向不存在或只读的东西
- 现象：新体系的规则、入口、事实仍在归档里，或指针指向已移动的路径。
- 证据：`docs/README.md:149` 明写"团队角色、写范围与协作协议在 Stage 7 定稿前**沿用归档版规则**"（即新体系的宪法把**只读参考区**当权威）；`CLAUDE.md:3` 加了一条全局替换规则——"本文件下文出现的所有 `docs/<文件名>` 一律读作 `_docs/<文件名>`"；`AGENTS.md` 的"权威来源"表在本次调研期间才从 `docs/…` 改为 `_docs/…`。
- 后果：任一读者按字面路径找文件会失败；"唯一出处"从第一天就被破坏；权威链出现环（新→归档→新）。
- 对策：`docs/**` 只引用已存在的 `docs/**`；必须引用归档时写"归档依据 `_docs/...:行`"，并**同时**把该条流程规则重写到 `docs/07-团队与开发规范/`（`docs/README.md:41`、`:59`、`:120` 无死链）。

## 2. 流程有效实践（12 条，带证据）

### P1 交接靠文件，不靠消息
- 做法：需求/缺陷/测试结论/设计/日志各有固定路径与模板，`send_message` 只负责"叫醒 + 一句摘要"。
- 证据：`_docs/team/README.md:31`（"文件才是交接物…不要把结论只写在消息里"）、`:124-134`（交接协议表）、`_docs/team/templates/`（bug-report / test-report / design-proposal 三套骨架）。
- 为何有效：83 份 BUG + 32 份 QA 报告 + 29 份 journal 全部可被后来者按编号精确定位。

### P2 每条断言带可复跑命令与原始输出
- 做法：BUG 模板强制"复现命令与最小步骤 + 期望/实际 + 证据输出（含退出码）"。
- 证据：`_docs/team/templates/bug-report.md`（骨架 §复现 / §证据输出『退出码：<n>』）；实例 `_docs/team/bugs/BUG-063-pagesize-override-irreversible.md:19-25`、`_docs/team/bugs/BUG-067-blocklet-build-mirrors-node-key-and-env-local.md:17-23`、`:41-67`。
- 为何有效：多个 BUG（063/067/076）在半年后仍能被 QA 逐值复跑通过。

### P3 独立审查不接受自述（自证必须显式标注）
- 做法：QA 自己重跑门、按 REQ 逐条判；Dev 的自证段落必须自贴"非独立 QA"标签。
- 证据：`_docs/team/roles/qa.md:9`（"你的价值来自**不信任自述**"）、`:25`（"不采信 Dev 贴的输出"）；`_docs/team/bugs/BUG-076-*.md:81-83`（"**自证，非独立 QA**"+"下列每条都是真实命令 + 真实输出"）；`_docs/team/bugs/BUG-063-*.md:82`（QA 复验记录："独立取证，不采信 Dev 自述"）。
- 为何有效：BUG-063 正是靠独立复验推翻了 Dev 报告里"能再切回"的写法（`BUG-063:78`）。

### P4 平台边界先实测再写进文档，且可被证伪
- 做法：平台结论必须附核验命令，冲突时以实测为准；被证伪的结论在落笔前更正。
- 证据：`_docs/arc-contracts.md:6-7`（"不臆造 ARC API…任何一条都可能被一次新的 `explain`/`--help`/`/.knowledge` 推翻"）；`_docs/team/journal/round-22.md:8`（BUG-061/062 的"**落笔前置**"）。
- 为何有效：`_docs/arc-contracts.md` §38–§56 共 19 节都是这种形态，成了整个项目最可复用的资产。

### P5 意图队列范式：页面只写意图，worker 落地
- 做法：按钮写 `config/<domain>-intents/<id>.json`，本机 worker 用 CLI 落库；验收看 AFS 前后差异，不看 toast。
- 证据：`_docs/team/test-reports/round-25.md:17`（"页面点击**只入队**、`active.json` 逐字节不变；worker 运行后对应字段真变"）；`_docs/ArcBlog-feature-checklist.md:112`（tags/categories/media/hub/chain 五处同范式）。
- 为何有效：把"权限/密钥/权限面"留在 CLI 侧，页面无需任何新授权，`blocklet.yaml` 零改动。

### P6 fail-closed 与诚实降级（宁可如实标注，不造假状态）
- 做法：能力不可达时页面写常驻说明 + 可复制命令，不伪造 0 / 绿灯 / 假按钮。
- 证据：`_docs/team/bugs/BUG-063-*.md:9`、`:135`（"平台限制**没有**被消除；本轮交付的是诚实缓解 + 恢复路径 + 边界登记"）；`_docs/team/test-reports/round-23.md:26`（小/空列表平台不渲染控件 → **拒绝**伪造入口）。
- 为何有效：避免把风险藏在 UI 里；后续 agent 不会基于假状态继续开发。

### P7 写范围隔离 + `.gate-lock` 串行
- 做法：每个角色只有明确写范围；跑写实例的测试前先在 `docs/team/.gate-lock` 写 `owner + 开始时间`，跑完删除。
- 证据：`_docs/team/README.md:32`（"写范围只是提示性路径，**不是锁**"）、`:72-74`、`:140-154`、`:183-190`；`_docs/team/roles/qa.md:32`（"不动源码…哪怕是一行文案"）。
- 为何有效：并发写实例会产生**随机假失败**（`_docs/team/README.md:188` 实测 `NOT_FOUND`，单跑 12/12 全绿），锁把"真红/假红"分开。

### P8 每步全绿的门，红门不得提交
- 做法：门 = `arc dsl validate --json`（issues 空）+ `npm test`（快层 ~1s，不写实例）+ 改了 `.aup` 才 `npm run build`；分级、限时、超时即失败。
- 证据：`_docs/team/README.md:158-171`、`_docs/team/bootstrap.md:250-286`（含 runner 的 25s/文件 + 30s 总预算，"挂死绝不伪装成慢"）、`_docs/team/roles/dev.md:112`（"绝不把红仓库交给 QA"）。
- 为何有效：把 21 分钟的全量 live 层降级为定向单跑后，轮次仍能抓到真回归（私钥泄漏、factory 注册表覆盖、写冲突）。

### P9 好结论必须回写权威，且同轮完成
- 做法：设计/产品结论由指定角色在**同一轮**写进标准/backlog，不允许只存在于对话里。
- 证据：`_docs/team/bootstrap.md:515-517`（"提案被采纳时**同一轮**修订，不允许只在对话里存在"）、`:523`（每 3 波回看闭环，"标准不能自欺"）。
- 为何有效：UI 标准的 §9 条目 12→14→19 条是只增不减地长出来的，可审计。

### P10 缺陷裁决三选一，不允许悬挂；P0/P1 不允许顺延
- 做法：每条 BUG 必须裁为"本轮修 / 下一轮修 / 不修（理由 + spec 章节）"，并在 journal 逐条列出。
- 证据：`_docs/team/roles/pm.md:130`、`:139`（"P0 不允许裁决为'下一轮修'或'不修'"）、`:138`（裁决结果在 journal 逐条列出并通知 QA）。
- 为何有效：83 份 BUG 里没有"永久 open 且无人管"的条目；R22 一次结清八项。

### P11 轮末收口 runbook：固定顺序，Lead 独占
- 做法：七步固定顺序（确认产物已提交 → 等 locales 写者停 → `generate --write` → 手删死键 → runtime-id 守卫 → 预算基线 → 门 + 精确提交）。
- 证据：`_docs/team/bootstrap.md:287-315`（含"禁用 `arc dsl lint --fix`"的理由）、`:250`（"规则唯一权威位置"）。
- 为何有效：并行改写后共享文件（locales / 生成物 / 基线）顺序错了就产生死键或假绿。

### P12 产物落地即留仓库外副本 + 尽快提交
- 做法：每完成一个产物 `cp` 到 `/tmp/<task>-<name>` 并回报 sha256；不长时间"只写不提交"。
- 证据：`_docs/team/bootstrap.md:316-335`（§7「提交保护与跨会话共存（BUG-079 的教训）」）、`:324`。
- 为何有效：BUG-079 中正是 `/tmp` 副本救回了 hub 与 diagnostics 两个页面。

## 3. 事故复盘（6 起最贵的）

### R1 BUG-079 跨会话工作区回滚（丢工作且不可恢复）
- 事件：另一会话的轮次收口在 13:16:01 / 13:17:04 / 13:17:52 三次把 `.aup/pages/**` 还原到 HEAD 并据此重生成 locales。
- 根因：两个 Lead 会话**共用同一工作区**，却没有共享任务板、锁或目录分区；"非本轮改动 = 杂质"的收口仪式对未提交工作没有任何保护。
- 代价：7 个页面重构中 4 个被抹且无副本（约 1 人时/页重放）；`dist/` 与 Pages 部署产物两处"副本"同时失效；`git fsck` 悬空对象只含更旧版本（`_docs/team/bugs/BUG-079-*.md:22-24`、`:40-42`）。
- 制度化对策：**Lead** 在**每个产物落地后立即提交**（只加该产物路径），并在**每波开始时** `bootstrap.md` §7 五条纪律（副本 + 尽快提交 + 绝不 `git add -A` + 共享文件唯一写者 + 先看 `git log/status`）；根治需人类裁决 = 目录分区或 `git worktree`。

### R2 BUG-067 + BUG-074 构建产物携带真实私钥（两条通道）
- 事件：① 裸 `arc blocklet build` 把仓库根 `node.key`(119B) 与 `.env.local`(499B，含链助记词) 复制进 `dist/` 并写入 `dist/.afs/manifest.json`（993 文件清单列出两者）；② 一条**独立通道**：Pages 部署产物 `~/.arc/pages/projects/arcblog/deployments/<id>/files/node.key` 含私钥原文，`bundle.json` 把内容**全文内联**，共 155 个历史部署目录。
- 根因：平台把**仓库根整树**当发布根，`arc blocklet build --help` 无 `--exclude/--ignore`，且不认 `.blockletignore`；第一版 scrub 只覆盖 `dist/**`。
- 代价：真实私钥落在 40 份副本（17×`node.key` + 23×`.env.local`）中；内容签名密钥一旦轮换需重签全部既有内容（`BUG-074:38`）。
- 制度化对策：**Dev** 每次改 `.aup` 只准走 `npm run build`（= build + `scrub:dist-secrets`）；**QA** 在批次末跑 `npm run verify:artifacts`（`--dir/--pages` 两通道，存在则扫、不存在显式 skip）；**Lead** 在合并点确认 `dist-secrets --check` 为 ok，且**文档里不得再出现裸 build 命令**（BUG-071：`AGENTS.md`/`CLAUDE.md` 曾把它写成质量门）；清理历史副本与是否轮换密钥 = **必须人类批准**。

### R3 BUG-063 分页器不可逆（平台 UX 陷阱）
- 事件：把 `afs-list` 的每页条数选择器改成 ≥ `total` 后，平台**整个分页器（含选择器本身）被移除**，页面内再无入口改回；`localStorage['aup-list-pagesize:<id>']` 长期覆盖节点 `pageSize`。
- 根因：分页块只在 `pageSize>0 && total>pageSize && pagination==="manual"` 时构造，而 localStorage 覆盖值优先（`BUG-063:36`）。
- 代价：84 行的账本页被拉到 56092px；受影响的 8 个控制台列表 + 公共 `store` 全部只能靠清站点数据恢复；Dev 报告一度写成"可以再切回"，被 QA 独立复验推翻。
- 制度化对策：**Dev** 在 8 页加无条件常驻说明 + 恢复路径（`BUG-063:98-102`）；**Lead** 把它登记为平台边界（`arc-contracts.md §38`）而不是"已修复"；**PM** 明确保留"限制未消除"的开放状态，由"诚实缓解是否足够"来裁决（`BUG-063:135`）。

### R4 BUG-076 + BUG-080 预算基线不可复现 → 快层红
- 事件：`scripts/ui-budget-baseline.json` 的 `general.tech` 由 20 抬到 32，而实测值 14，且**无法用 `--write-baseline` 复现**（该命令会写成 14）→ 说明是手改；22 页里 `tech` 基线全部高于实测。R28 又因 4 个页面源码变更未重录基线导致 `npm test` 1 红（7 项回归）。
- 根因：基线没有锚定它测的那份源码，且"重录"可以手改而不留痕；棘轮只断言"不变差"，放宽不会被拦。
- 代价：棘轮对 `general.tech` 被放宽 18（未来最多 +18 个节点不被拦）；批次放行门槛一度不达成（`BUG-080:7`）。
- 制度化对策：**Dev** 修测量确定性（`readdirSync().sort()`、同名 stem 抛错）并给基线加 `_sources` 源码 sha256 锚定；`--write-baseline` 必须打印逐页 diff（工具产出说明，不靠手写报告）；**Lead** 在合并点显式重录并把逐页差异写进 journal（`BUG-080:109-120`）。

### R5 BUG-045 同一控制台三套意图状态叫法（P1 阻断放行）
- 事件：categories 用 `applied|rejected`，tags 用 `done|failed`（页面还画成 `queued`），同一控制台同时在线且都能被真实写入。
- 根因：Lead 的字面判据与既有实现冲突，而"词表唯一"这个口径没有写在任何**单一权威**处，靠每轮 REQ 复述。
- 代价：R18 判 `VERDICT=fail, BLOCKING=1`，加开 R18F 修复窗口，并顺带发现第三个队列（`config/chain-intents`）也在词表外（BUG-051）。
- 制度化对策：词表进**唯一出处**（新体系 = `03-产品设计/` 的意图队列节 + `docs/README.md:131`），**Dev** 写入端只允许引用常量（`INTENT_STATUS.*`）；**QA** 在批次末做全仓词表一致性抽验。

### R6 BUG-012 行内动作把模板字面量写进记录（污染公开 feed）
- 事件：`?page=posts` 行内 Publish/Delete 的 `exec` args 里 `${entry.content.*}` 不求值，结果把字面量 `posts/${entry.content.slug}.json` 写进公开目录并弹"Published."成功提示。
- 根因：把"UI 提示成功"当成写入成功的证据；该写入路径连续三轮被标为"受限未验证"。
- 代价：公开 feed/RSS 被污染（P1），须加开 R9F 修复窗口并全仓普查同类写法（posts/pages/hub 三处）。
- 制度化对策：**Dev** 用隐藏输入 + `${args.e*}` 通道，并在 `arc-contracts.md §29` 沉淀"exec 求值上下文"；**QA** 的写入类验收一律"页面真实点击 → `arc afs` 读回前后对比"，**toast 不是证据**（`_docs/team/test-reports/round-25.md:17`）。

## 4. 状态与证据体系建议（给 Stage 6「功能开发列表」）

**核心诊断**：checklist 的病不是"状态词选错"，而是**汇总手写、明细过长、证据与状态不绑定**。新表必须让"改状态"和"给证据"变成同一个动作。

**建议的状态枚举（单一词表，一列；不用 emoji 混排）**

| 状态 | 含义 | 允许进入的条件（缺一不可） |
| --- | --- | --- |
| `未开工` | 上游已定稿，尚无实现 | 有需求编号；无实现证据 |
| `开发中` | 本批次在写 | 有任务/产物路径 |
| `已实现待验` | 代码在位，未独立验证 | 有产物路径 + 自测命令 + 退出码 |
| `已验证` | 独立验证通过 | 有验证人 + 日期 + 命令与退出码 + 基线 commit |
| `平台边界` | 平台做不到，已降级 | 引用 `05-开发文档` 平台边界篇的条目号 + 降级路径 |
| `已废弃` | 上游删除或方向改变 | 引用做出该决定的决策记录号 |

**正交的"阻塞原因"（独立一列，不得与状态混写）**：`待决策` / `待批准` / `待平台能力` / 无。
理由：归档期把"🟡 部分实现"同时用来表达"没写完""平台不支持""等批准"三种含义（`_docs/ArcBlog-feature-checklist.md:92`、`:100` 与 `docs/README.md:132` 的角色生命周期词表并列即可见混乱）。

**列的必填证据（每列缺失即视为该行无效）**

| 列 | 必填 | 格式与校验 |
| --- | --- | --- |
| 功能点 ID | 是 | 稳定编号，永不复用（学 `_docs/team/templates/bug-report.md` 的"全局唯一、顺序递增、不复用"） |
| 上游需求 | 是 | `docs/02-产品需求/…` 锚点；不得指向 `_docs/**`（`docs/README.md:41`） |
| 状态 | 是 | 上表六值之一 |
| 阻塞原因 | 是（可填"无"） | 四值之一；`待批准/待决策` 必须写决策人 |
| 证据 | 是 | `文件:行` 或 `命令` + 退出码；平台边界填 `平台边界篇 §n` |
| 验证人 / 日期 | `已验证` 必填 | 姓名/角色 + ISO 日期；**自证不得填此列** |
| 基线 | 是 | commit sha（`docs/README.md:93` 证据基线） |
| 未覆盖范围 | 是（可填"无"） | 例如"仅 mock 适配器"、"未跑真实链"——学 QA 的"受限未验证 ≠ 通过"（`_docs/team/roles/qa.md:75`） |

**三条硬规则**
1. **总览与分组计数由脚本从正文生成**，提交时校验一致；手写计数视为缺陷（治 A1/A3）。
2. **备注列 ≤ 2 行**；超出部分写进对应设计/开发文档并在备注里链接（治 A5）。
3. **状态变更 + 证据 + 变更记录表一行**在同一提交内完成，变更记录在文末表格而非版本行（治 A2）。
