  "previewOnly": true, "body": ""          ← 公开副本正文为空（拆分生效，spec §24）

**结论（不得软化）**：闭环的**中间四步（3/4/8/9）在浏览器里不存在**；两端（价格元数据、订单/账本记录形态）是真实的。
这是 [`01 §6.5`](../../01-产品概念/01-产品定位与边界.md) 记的"有机制、无闭环"，**不得写成"付费阅读已可用"**。

### 4. 验收标准候选（≥6，含负例）

- **AC-A1（负例基线）** `grep -c '\.actions/write' .aup/pages/reader.aup .aup/pages/store.aup` → `0` / `0`；`store.aup:10` 的 `howto-desc` 必须仍含"no checkout here"。**改动后此负例应变为正例，但不得出现假按钮**（`03 §11` 红线 1）。
- **AC-A2** `/posts/{paid-slug}` 在 guest 会话下渲染出与 `economy/products/<productId>.json` **逐值一致**的 `priceAmount` 与 `priceAsset`（比对命令：`arc afs exec …/.actions/read` 两条记录）。
- **AC-A3** 发起购买后：`arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"/instance/app/arcblog/economy/orders"}'` 的记录数 **+1**（不是靠 toast，`arc-contracts §29.4`）。
- **AC-A4** 该 order 的 `buyerDid` 匹配 `^did:(key|blocklet):`，且 **≠** `$session.did` 字面量、**≠** 空串。
- **AC-A5** 支付前 `node scripts/arcblog-economy.mjs access check --content <contentId> --reader <buyerDid>` → `allowed: false`；`order pay` 后 → `allowed: true`（**顺序断言**，spec §88 verify → grant → settle）。
- **AC-A6（负例）** 未持有 grant 的读者 DID：`access read` 必须 `{"ok":false,"code":"FORBIDDEN"}`，且 `paid/` 目录记录数**不变**。
- **AC-A7（负例）** `adapter: none` 时 `order pay` 必须 `VALIDATION` 失败并**零写入**（`arcblog-economy.mjs:199-201`）。
- **AC-A8（负例）** 退款后 `access check` 回到 `allowed: false`，且 `ledger` 出现 `<orderId>:refund:<type>` 条目（`economy.mjs:376`）——原结算记录**不得被删除**（append-only，spec §92）。
- **AC-A9** `?page=access` / `?page=orders` 的 `grep -c '\.actions/write'` 保持 `0`（资金页不因本需求变成写面）。

## 第二部分 · P0-B 控制台写入署名

### 5. 落库形态未知项 + 探针设计

**已实测**：`exec` 的 `content` 里 `$session.*` **不插值**（`_docs/arc-contracts.md` §28.7 `:1432-1442`：`requestedBy: "$session.did"` 落库为字面量 `"$session.did"`，同记录 `"${generate.timeiso}"` 正确插值；`BUG-003`）。

**未验证（必须写清）**：**页面提交后的真实落库形态未验证**——`compose.aup:168/169`、`pages.aup:168` 的 `authorDid: $session.did` 究竟是落成①字面量 `$session.did`、②空串、还是③别的形态，**今天没有任何一次登录态回读证据**（`REVIEW §6-3` 自述"落库形态仍属受限未验证"）。旁证只有 `node scripts/arcblog-doctor.mjs --json` → `authorship: {"ok":true,"detail":"49 records, all attributed"}`（**潜伏**：当前语料由 CLI 创建）。

> ⚠️ 一处必须写清的错位：CLI 侧 `authorDid: base.authorDid || ''`（`scripts/arcblog-lifecycle.mjs:306`）使之**可以为空串**；而页面写的是**未加引号的裸 token** `authorDid: $session.did`（`compose.aup:168`），其字面量形态与 §28.7 的 `"$session.did"`（带引号）**不是同一条实测**。二者结局可能不同——这正是探针要钉死的。

**探针设计（一次登录态会话；只读回读 + 1 条可清理记录）**

| 步 | 动作 | 命令 / 判定 |
| :-: | --- | --- |
| P-0 | **只读先行（今天可跑，零写入）**：建立负例基线 | `grep -rn 'authorDid: \$session\.' .aup/pages/` → **4 处**（实测：`compose.aup:168`、`compose.aup:169`、`pages.aup:168`、`factory.aup:200-203` 的 `requestedBy:` 4 行）；`arc afs exec …/.actions/list --args '{"path":"/instance/app/arcblog/drafts"}'` 与 `page-drafts` 扫是否存在字面量/空署名记录 |
| P-1 | 登录后 `?page=compose` 提交 1 条草稿（固定前缀 slug，如 `qa-req041-probe`，标题/正文必填） | 需要一次可登录会话（QA/Lead 提供；本轮受限） |
| P-2 | 回读落库形态 | `arc afs exec /blocklets/arcblog/.actions/read --args '{"path":"/instance/app/arcblog/drafts/qa-req041-probe.json"}' --json` |
| P-3 | **判定** | `content.authorDid` 必须匹配 `^did:` **且** ≠ `$session.did` 字面量 **且** ≠ 空串；`authorName` 不得是 `$session.displayName` 字面量。三者任一不满足 ⇒ 页面路径**不可信** |
| P-4 | 同法验证页面路径 | `?page=pages` 新建 `qa-req041-page` → 回读 `page-drafts/qa-req041-page.json`，判据同 P-3 |
| P-5 | 清理 | 用既有 CLI 删除探针记录（**不静默改写历史**，REQ-041 §2）；计数复原 |

**若 P-1 无法获得登录会话**：只做 P-0 + 在文档里标【受限未验证】，**不得**据 §28.7 直接断言"一定落成字面量或空串"（那是把带引号的实测外推到不带引号的写法）。

## 第三部分 · 依赖与排序建议

### 9. 两条 P0 的相互依赖与排序

```text
P0-B（署名）────────────┐
  真实 DID 的取值方式是     │  P0-A 的 G2「发起购买」必须写入 buyerDid
  所有"页面写身份"的公共前置 └─▶ P0-A（付费闭环）的收银台意图记录
```

1. **先做 P0-B，且先做它的探针（半天级）**。理由三条：
   - **P0-A 依赖 P0-B 的结论**：收银台意图里的 `buyerDid` 与订单的 `buyerDid` 同属"页面写真实身份"问题；探针结论不明时做 A，等于把 BUG-003 从 `authorDid` 复制到 `buyerDid`（`factory.aup:200-203` 已经是现成先例）。
   - **P0-B 无不可逆语义、无资金**：可单独交付、可回退（停 worker），符合 `03 §12.2` 裁决 ④（前置 = 一次性登录态探针）。
   - **P0-B 的守卫是 A 的安全网**：AC-B5 的静态守卫一旦进快层，A 的新增写面会被同一条门守住。
2. **P0-A 必须被两道门卡住，不得抢跑**：`03 §12.2` 裁决 ① 明确 ① Stage 5 先给平台可行性结论、② **涉及资金的动作需人类批准**。本调研把"资金可达面"钉到 §2-G6（**浏览器内无法做 per-reader 付费全文守卫**），因此 **P0-A 的第一批交付不应包含"读完文"**，只应包含"看到价格 + 发起购买 + operator 支付"的诚实路径；
3. **建议落地批次**：
   - **批次 1（P0-B）**：探针 → 方案 A/B 二选一 → 4 处修复 + 守卫进快层。
   - **批次 2（P0-A 前半）**：价格投影 + 收银台意图队列（**复用批次 1 的身份取值结论**）+ operator 支付；`paid/` 全文消费方**明确标【平台边界】，留待 Stage 5 平台边界篇给降级路径**（`01 §7.2` 的写法）。
   - **批次 3（资金，需人类逐次批准）**：真链支付/退款，属 REQ-021 §7 的 P2/P3，**不在 Stage 2 承诺交付时间**（`03 §12.2` 裁决 ① 末句）。

### 10. `## 摘要（给主笔，10 条以内）`

1. **付费闭环的断点在浏览器里的第 3–5 步，不在记录层**：`reader.aup`/`store.aup`/`access.aup` 的 `.actions/write` 计数 **= 0/0/0**；`store.aup:10` 页面自认"there is no checkout here"。记录层（order/grant/ledger/refund）**完整且实测可用**（`econ-test-*` 记录已读到）。
2. **全文消费方今天即使在 CLI 也断链**：实跑 `access check --content econ-test-content-1790621440546 --reader did:key:zEconBuyer` → `allowed: true`，紧接着 `access read` → `NOT_FOUND (paid content not found)`；且 `/instance/app/arcblog/paid` 目录 **不存在**（`LIST_ERROR Path not found`）。**"Grant 有了、全文没了"是比"没有收银台"更硬的事实**。
3. **价格今天无处可取**：`world/post.yaml:28` 有 `productId`，但 `reader.aup:29-33` 不引用；页面无法跨目录按 `productId` 匹配（无比较表达式、`filter` 只对已内联记录可靠）⇒ 最小形态是**把价格投影进公开 post 记录**。
4. **`ADAPTERS = ['none','manual']`（`arcblog-economy.mjs:51`）**，`transactionHash` 恒空；按 `S1-03 §4-5`，**任何"链上支付/已结算"的措辞都是禁止断言**。
5. **P0-B 的探针是本 Stage 最便宜的高价值动作**：`grep` 已确认 **7 处** `$session.` 落在 `exec` 的 `content` 里（`authorDid` 3 处 + `requestedBy` 4 处，后者是本轮新增发现）；但**页面提交后的真实落库形态至今未验证**，判定式写死为"匹配 `^did:` 且 ≠ `$session.did` 字面量与空串"。
6. **一条必须写进需求的错位**：CLI 侧署名可为**空串**（`arcblog-lifecycle.mjs:306`），页面侧写的是**不带引号的裸 token**——§28.7 实测的是**带引号**的写法。**不得把 §28.7 直接外推为"一定落成字面量或空串"**。
7. **doctor 抓不到这个缺陷**：`arcblog-doctor.mjs:122` 只报**空** `authorDid`，字面量 `$session.did` 非空。因此 REQ-041 的守卫测试（`OPP-002` 规则 1）不是"锦上添花"，而是**唯一能防复发的手段**。
8. **排序：P0-B（探针 → 守卫 → 4 处修复）先做**，因为 P0-A 的 `buyerDid` 依赖同一结论；P0-A 的第一批**只做"看到价格 + 发起购买 + operator 支付"**，全文消费方标【平台边界】（浏览器内无法做 per-reader 守卫，`S1-03 §1` provider 挂载不可寻址 + 根动作无 caller）。
9. **两处需要人类批准的闸门**：任何产生订单/支付/退款记录的实现（P0-A 批次 2/3）；以及 Stage 5 的平台可行性结论（`03 §12.2` 裁决 ①）。
10. **本文件的受限项**：① 登录态探针（P-1～P-5）未执行——无登录会话；② 运行期实例滞后于源码，`arc-contracts §35(5)` 的"改 `.aup` 必重启才生效"未在本轮复核；③ 所有"页面登录后渲染"结论均为**静态源码判定**。
