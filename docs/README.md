## 1. 这套文档是什么

ArcBlog 的文档不是"代码注释的搬运"，而是**产品与实现之间那份可验收的契约**：谁在什么时候必须知道什么、用什么证据判断做对了、以及**做不到时如实说**。

本体系的三条主线：

1. 网络里只有 studio 节点，**聚合由 agent 承担**；
2. **发现靠链，不靠目录服务**——所有节点把 studio NFT 质押到**同一个 factory 地址**，查该地址的质押资产列表即全部节点；
3. **产品尽可能简单**——经济体系（付费阅读/打赏/分成/结算/账本）**整体删除**。

## 3. 写文档的规范

### 3.1 事实标签（五类，**唯一出处 = 本节**）

**定义**

| 标签 | **判定门槛（必须能回答"凭什么标它"）** |
| --- | --- |
| **【已实现】** | 仓库里**有可指到的调用点/产物**，且**本实例上已成立**（不是"代码里有"）。判据 = `文件:行` + 能跑的验证 |
| **【规划中】** | **机制/接口存在于平台或代码里，但本项目尚未接上或产物未生成**。判据 = 指出"缺哪一半" |
| **【平台边界】** | **平台不提供该能力**（有实测/文档证据）⇒ 必须给**降级路径**。判据 = 引平台能力条 + 降级写法 |
| **【决策待定】** | 事实已清楚，**只是人还没拍**。判据 = 写明候选与裁决人 |
| **【未验证】** | **事实还不知道**，需一次探针。**必须同时给验证步骤与判定式** |

> ⚠️ **最容易混的两对**：① **机制在平台有 vs 本项目已接** —— 前者是【规划中】不是【已实现】（例：`listStakes` 在 SDK 里有、本项目未接）；② **平台边界 vs 未验证** —— "平台不提供"是【平台边界】并要降级路径，"平台可能提供但没测"是【未验证】并要探针。**同一件事只能有一个标签**。

**写法规则**

- **触发点 = 断言**：凡对「实现状态」或「平台能力」作断言处，**必须**使用其中之一；禁止"应该能""大概支持"。
- **不要求每篇出现全部五类**——只谈结构/条款而不作状态断言的文档可以一处都不出现，但**头部必须声明词表出处**。
- **凡【未验证】必须同时写出验证步骤与判定式**；验证完成后立刻改成其它标签并留证据。
- **别把"应该能"写成事实**——本项目最贵的两次事故都是这样来的。

### 3.2 定义点 vs 落盘点

**同一事实只在一处定义，其它地方引用**。写文档前先问："这条的唯一定义点在哪？"

| 事实 | 唯一定义点（逐阶段填） |
| --- | --- |
| 五类事实标签 | 本文件 §3.1 |
| 概念与术语 | `01-产品概念/04-概念与术语.md` |
| 六态（**实现状态**） | `06-功能开发列表/`（Stage 6 落）—— **`02-产品需求/` 不定义、不写实现状态**，只写五类**现状事实标签** |
| 平台能力与边界 | `05-开发文档/02` |
| 未验证与探针 | `05-开发文档/07 §1` |
| 链上注册表机制 | `05-开发文档/02`（Stage 5 落；口径 §2 是当前权威） |

### 3.3 形态纪律（可机检）

| 项 | 规则 |
| --- | --- |
| 单文件行数 | ≤ **400** 行（过程件 ≤200） |
| 单行长度 | ≤ **800 字符** —— **用 Python `len(str)` 判断，禁用 `awk length`**（数的是字节；本项目已三次踩坑） |
| 头部 | 五字段：状态 / 版本 / 上游 / 下游 / 证据基线 |
| 文末 | 开放问题（无则写"无"） |
| 链接 | 相对链接必须可达；**引用 `附件/` 的原始证据必须全路径**并注明它是**原始证据转录、不是现行结论**（概念层已无"归档"这一层） |
| **前向引用** | 引用**尚未落盘**的后续阶段文档（如 Stage 1 引 `docs/05-开发文档/02`）时，**必须写明"（Stage N 未落盘）"**。**不要**把不存在的路径当"唯一出处"——**没有"改引归档"这条退路了**（归档层已删除）。**⚠️ 门与规则的调和（2026-10-01）**：`链接 0 MISS` 的机检**必须豁免"已声明的前向引用"**，判据二选一即可 —— ① 该行**同时含链接**与 **`（Stage N）`／`未落盘`**；② 链接目标**在本目录的 `_提纲.md` 里被列为计划文件**（覆盖**同批在写**的情形，如 Stage 4 的 `00` 引正在写的 `03-状态与降级`）。**否则写手被逼在"引未来文档"与"过门"之间二选一** |
| **引用原始证据** | **必须读完整节并检查邻近的反证行**——只引"有利的那一半"会把【规划中】写成【已实现】（2026-10-01 `/p/rss.xml` 事故）。**会变更的编号**（如旧能力 `#49`）**不得**当稳定标识，要引事实句 |
| 证据 | **跑过 ≠ 写回**：可机检的条款必须"代码 + 命令 + 真实输出"同处一篇 |

## 4. 协作纪律

1. **写范围**：只写自己负责的目录；需要越界时 **停手 → 报 Lead → 由 Lead 建任务/扩权/亲自做**。
2. **唯一提交人 = Lead**，提交前 `git diff` 过**内容**（不只核路径）。⚠️ **本轮人类要求"先不提交"** ⇒ 所有产出留工作区。
3. **不臆造 ARC API**：先 `arc <cmd> --help` / `explain` 核验；平台做不到的写进 `05-开发文档/02` 并给降级路径。
4. **每步全绿**：`arc dsl validate --json`（`issues: []`）+ `npm test`（快层，不写实例）；改了 `.aup`/`blocklet.yaml`/`world/**` 还要 `npm run build`。
5. **不跑全量 `npm run test:live`**（~21 分钟且写共享实例）；要覆盖 CLI/AFS/链适配器时定向单跑 `npm run test:file -- scripts/<file>.test.mjs`，先写 `docs/team/.gate-lock`、跑完删除。
6. **原始证据的逐字转录**在 `docs/05-开发文档/附件/` 与 `docs/08-其他/附件/`（**只读、不是现行结论**）；**现行结论一律以 `docs/01`–`docs/08` 正文为准**。
7. **禁止删除 `node.key` / `.env.local`**。
8. **交接靠文件，不靠记忆**：结论落 `docs/0X-*/**`；过程记录 → `docs/team/**`。
