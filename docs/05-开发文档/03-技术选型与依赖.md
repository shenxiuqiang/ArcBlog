## 2. 运行时基线

| 项 | 实测 | 复算命令 |
| --- | --- | --- |
| 应用形态 | AUP DSL（`.aup/**`）+ 运营侧 Node CLI（`scripts/*.mjs`） | `ls .aup/pages/*/*.aup .aup/pages/*.aup \| wc -l` → **25** |
| **无 bundler / 无 dev server** | 是（AUP 平台运行时渲染） | — |
| Node 版本要求 | `package.json` **未声明 `engines`** ⇒ 以本机实际为准 | `node -e "const d=require('./package.json');console.log(d.engines)"` → `undefined` |
| 测试入口 | 快层 `npm test`（不写实例）/ 全量 `npm run test:live`（**不得**作常规门） | `node -e "const d=require('./package.json');console.log(Object.keys(d.scripts))"` |

> **纪律**：Node 版本**不写死**（无 `engines` 声明）；如需固定，须**新增声明**并走受控修订。

## 3. AIGNE 的选型依据与**未决**

| # | 事实（实测/调研） | 对选型的影响 |
| :-: | --- | --- |
| **L1** | 许可 = **Elastic-2.0**（**非 OSI 开源**），限制"**作为托管服务对外提供**" | **许可风险须由人类承担/裁定** |
| **L2** | **ESM-only**；**Node ≥ 20** | 与现有 CJS 脚本混用时需适配层 |
| **L3** | `DIDSpacesMemory` 需要**逐 space 的凭据**（`blocklet-xxx`）；**文档未说明** per-user 的取得/委托/撤销 | 「用户自己的空间」**今天不是自动的** |
| **L4** | MCP **双向可用**：客户端写法 `MCPAgent.from({ url, transport: "streamableHttp", opts: { requestInit: { headers: { Authorization } } } })` | 与"只读出口 + `/mcp`"路线**相容** |
| **L5** | 引入会带来**依赖面扩张**（框架 + 其传递依赖） | 与"应用无运行时依赖"的现状**不同层**：只能落在**运营侧** |

> **限定范围**：L1–L5 回答的是**能力与许可面**，**不**回答"AIGNE 适合本项目"。

**未决**（编号前缀 `TS-` = type-selection，**避开 [`07`](07-未决技术问题与探针计划.md) 的 `U*` 唯一分配集**）

| # | 未决项 | 归属 |
| :-: | --- | --- |
| **TS-1** | **是否引入** AIGNE（许可 L1 + 依赖 L5 的收益/代价） | **人类决策** |
| **TS-2** | 若引入，**落在哪一层**（运营侧脚本 / 独立 Blocklet / 用户机器） | **人类决策**（与 [`docs/01-产品概念/03 §J4`](../01-产品概念/03-使用旅程.md) 的"agent 开在哪"同题） |
| **TS-3** | **许可风险谁承担**（Elastic-2.0 的托管限制对本项目分发形态的影响） | **人类决策** |

**结论（本篇口径）**：**技术选型未完成**——本篇只给**依据与限制**；**不得**写成"已选型完成"，也**不得**把 AIGNE 写成既有架构的一部分（**概念层不绑定框架**）。

## 4. 一旦引入 AIGNE 的前置条件（**登记，不承诺**）

| # | 前置（**编号 `PRE-*`**：2026-10-12 从 `P-*` 改名——原写法与 [`07`](07-未决技术问题与探针计划.md) 的**探针号 `P-1`–`P-4` 撞号**） | 判据 |
| :-: | --- | --- |
| PRE-1 | 人类批准 **TS-1/TS-2/TS-3** | 有裁决记录（[`docs/team/reviews/`](../team/reviews/)） |
| PRE-2 | 许可影响评估完成 | 明确"是否对外提供托管"及对应合规动作 |
| PRE-3 | 记忆的 per-user 凭据方案明确 | `DIDSpacesMemory` 的取得/委托/撤销**有方案**（今天**无文档** ⇒ 【未验证】） |
| PRE-4 | 依赖面评估 | 新增依赖**不进入 AUP 应用**（与 [`00 §2`](00-架构总览.md) 一致） |

**【未验证】验证方法（PRE-3）**：用一个测试 space 走通"取得凭据 → 读写记忆 → 撤销"三步；**判定式** = 三步各有一条原始输出（含错误分支），且撤销后写入被拒。
