## 2. 降级模式库（**P1–P12**；需求/设计/UI 引**模式号**即可）

| # | 模式 | 适用（`02` 条目） | 形态（写法） | 判据 |
| :-: | --- | --- | --- | --- |
| **P1** | **意图队列 + CLI `apply\|watch`** | 需写权限但不能同步完成的动作 | 页面**只写意图**（`config/*-intents/`），worker/CLI 落盘；队列卡显示**五态** | 状态列取自记录本体；**禁**把"已入队"当"已生效" |
| **P2** | **诚实降级**（平台破折号 + 常驻说明） | **B1–B5、B9、B11、B12**、`G1`–`G3` | `—` + **常驻说明** + **下一步**；**不**用假 0 / 假绿灯 | 说明句含"为什么 + 怎么做"；见 [`04-UI设计规范/03 §1`](../04-UI设计规范/03-状态与降级.md)。⚠️ **`B10` 不在本模式适用域**：它是**有意豁免**（覆盖边界），**在本配置下没有降级路径**，**只有登记**（见 §4 末） |
| **P3** | **CLI 折叠为"高级" + 可复制命令** | **B2/B3**、页内写受限项 | `key-value-list`（`monospace` + `copyable`）折叠在高级区；**页面不执行** | 命令可选中/可复制（`02 C9`）；**不给**等价按钮 |
| **P4** | **角色 / 能力 fail-closed** | 资格与能力（`PRD-ID-03/05`） | 未验证 ⇒ **不授予**任何能力；`reason` 必须显示 | `scripts/lib/roles.mjs:136`；能力派生 `:163-170` |
| **P5** | **生成器投影**（取代跨页片段） | **F4**（外壳/侧栏） | 改**唯一真源** `scripts/console-nav.mjs` → 跑 `node scripts/arcblog-console-nav.mjs` → `--check` 门 | 增删行**必红**两个测试（见 [`05-测试分层与质量门`](05-测试分层与质量门.md)） |
| **P6** | **目录边界 / `propBind` 取代条件筛选** | **B5**（索引陈旧） | 按**目录**或**单记录**读；复杂筛选搬 CLI | 禁 filter 列表当"全部" |
| **P7** | **`/p/` 出口**（取代根级端点） | **B1** | 一切对外只读面走 `/p/`（`/p/llms.txt`、`/p/rss.xml`） | 根级路径**不写**为可用 |
| **P8** | **文案与能力同步降级**（禁假绿灯） | **B9**、**F2/F6** | 能力未就绪 ⇒ **文案同步**改成"未就绪 + 前置命令" | 反例判据：`grep 'always on' .aup/pages/` 命中行须与"分发面/产物已就绪"语义同现（详见 [`04-UI设计规范/04 §4`](../04-UI设计规范/04-文案与i18n.md)） |
| **P9** | **范围化表述**（引用原始证据必须带"限定范围"） | **B7/B8** 的教训（**写作模式**） | 引结论时**同行答出**"作用在哪个元素/哪条路径" | 答不出 ⇒ 不许写成通用条款；记 [`07`](07-未决技术问题与探针计划.md) 的探针而非断言 |
| **P10** | **预计算投影**（CLI/worker 算好，页面只显示） | **B13**（异步数据条件渲染产出假事实）+ 一切"页面无法判断"的场合 | 决策在 **CLI/worker** 里算完写进记录（`node/factories.json`、`node/registry.json`、`node/anomalies.json`），页面**无条件**渲染那段**现成文本**；页面**不**分支于 `$state.*` | 页面内 `grep -c 'visible=.*\$state' .aup/pages/*/*.aup .aup/pages/*.aup`<页>.aup` = **0**（`visible=$state.x` 恒真、`!${…}` 恒隐藏、裸形式冻结于首帧）；投影记录里能指到生成命令 |
| **P11** | **冷启动面**（`surface url` + item recipe） | **B14**（单记录 `propBind` 首访不取数） | 单记录页用 `surface url=$state.loc editable=false`，并**每实例装一次** `<记录目录>/.aup/item.json`（`node scripts/arcblog-recipes.mjs install`）；`propBind` 只留给**写**面（`exec` 需 `state.*`） | 冷启动（无缓存首访）即出正文：`curl` 直连绑定路径不返回原始 JSON；`recipes check` 通过 |
| **P12** | **署名走 CLI**（页面只写占位） | **B18**（运行时只在文本节点解析 `$session.*`） | 页面写入的 `authorDid`/`authorName` 落**占位**；真正的署名、`contentHash`、`contentSignature`、`version` 由 `node scripts/arcblog-lifecycle.mjs publish --sign-key node.key` 落 | 记录里 `authorDid` 是 `did:*` 而非字面量 `$session.did`；`node scripts/arcblog-verify.mjs content --slug <slug>` 通过 |

> **覆盖口径（2026-10-12 Lead 补）**：本库按**形状**映射，**不逐条穷举** `B*`。新增边界要么在上表找到同形状的模式（`B13`→`P10`、`B14`→`P11`、`B18`→`P12`），要么在 [`02`](02-平台能力与边界.md) 的**自己那一行**里给出降级，或**显式声明"无降级路径"**（例：`B10` 见本节末、`B15`/`B16`/`B19`/`B21` 属平台默认外壳/构建告警，无用户可见降级）。
> ⚠️ **同前缀不同域**：本库的 `P1`–`P12` 是**降级模式**；缺陷卷的 `P0`–`P3` 是**严重度档**。引用时须带限定词（"降级模式 `P10`" / "P2 档缺陷"），避免与 [`03`](../06-功能开发列表/03-缺陷与待修.md) 的档位混淆。
