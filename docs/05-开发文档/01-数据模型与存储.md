## 1. 集合与 schema 总表

```bash
$ awk '/^replicated:/{f=1;next} f&&/^[a-zA-Z]/{f=0} f&&/^  [a-z]/{print $1}' blocklet.yaml | wc -l
20
$ awk '/^replicated:/{f=1;next} f&&/^[a-zA-Z]/{f=0} f&&/^  [a-z]/{print $1}' blocklet.yaml | tr '\n' ' '
posts: drafts: paid: heroes: node: categories: tags: media: config: economy-policy: economy-products: economy-orders: economy-settlements: economy-ledger: economy-access-grants: economy-refunds: economy-attributions: pages: page-drafts: hub:
$ ls world/*.yaml | wc -l

$ ls world/ | grep -iE 'hero|tag' || echo 'NO hero/tag schema'
NO hero/tag schema
```

| `economy/settlements/<orderId>.json` | `settlement` | **admin** | CLI `settle`（重复结算 = no-op） |
| `economy/ledger/<orderId>:<type>.json` | `ledger-entry` | **admin** | CLI（append-only，**确定性 id**） |
| `economy/access-grants/<orderId>.json` | `access-grant` | **admin** | CLI（`order pay` 后） |
| `economy/refunds/<orderId>.json` | **`refund`** | **admin** | CLI `order refund`（**追加事件**，不删原订单） |

| `/instance/settings/arcblog/` | —（平台 settings 注册表，**封闭**） | — | theme bridge 读；CLI/页面写 |

**对账**：上表 20 个集合 = `replicated` 的 **20** 条（`posts/drafts/paid/heroes/node/categories/tags/media/config/economy-{policy,products,orders,settlements,ledger,access-grants,refunds,attributions}/pages/page-drafts/hub`），逐条一一对应。
**无 schema 的三棵树 = `heroes/`、`tags/`、`node/factories.json` + 队列树**（`world/` 22 个 schema 覆盖其余）；这一口径与 [`07 §5 Q8`](07-未决技术问题与探针计划.md) 一致（R3 已把两篇统一为"**无 schema**"）。
**读权限的权威 = `blocklet.yaml` 的 `replicated.<collection>.readRole`/`minRole`**；`networkRead` 只是**前缀许可**，不能收回授权。

## 2. 写入路径矩阵（**每集合的每条写入路径**）

| 集合 | 页面路径 | CLI / 消费方路径 | 幂等性 |
| --- | --- | --- | --- |
| `posts`/`drafts` | `exec /.actions/write`（`compose`/`compose-edit`/`preview`） | `arcblog-lifecycle publish/archive/delete` | 同 slug 覆盖；**编辑不改 id** |
| `paid` | **无**（页面永不读付费全文） | `arcblog-lifecycle`（`visibility: paid`） | 每 slug 一份 |
| `pages`/`page-drafts` | 队列 `config/page-intents` → [`arcblog-pages`](00-架构总览.md) `apply\|watch` | `arcblog-pages online/offline/delete` | 上下线幂等（跨两目录两步） |
| `heroes` | 页面写（`heroes` 页两条动作） | 无 CLI 消费者 | 由 `sort` 排序，重复写不产生第二份 |
| `media` | **无**（页面仅索引/清理意图） | `arcblog-media add/remove --force`；队列 `config/media-intents` | `remove` 有引用冲突即拒 |
| `categories` | 队列 `config/category-intents` → `arcblog-category apply\|watch` | `arcblog-category` | 合并/重命名幂等（**消费方未运行不得改库**） |
| `tags` | 队列 `tags/intents` → `arcblog-tags apply\|watch` | `arcblog-tags list/merge/project` | 投影可随时重建（**永不是第二真源**） |
| `node/*` | 无 | `arcblog-node`、`arcblog-network` | 覆盖写 |
| **`node/factories.json`** | 无（页面只读） | 链 CLI/worker 每步后写 | 全量重算（**含 SVG**） |
| `config/roles.json` | 无（页面只读） | `arcblog-roles state set` | **fail-closed**；`revoking` 会 Tombstone Hub 关系 |
| `config/agent-grants` | `agents` 页 | `arcblog-agent authorize` | 同 `didHash` 覆盖；**TTL 到期即拒** |
| `economy/orders` | **无**（页面只读） | **仅 CLI** `arcblog-economy order create\|pay\|refund` | 以 **AFS 记录数 +1** 为准（**toast 不算证据**） |
| `economy/ledger` | 无 | `order pay`/`refund`/结算 | **append-only**，id = `<orderId>:<type>` |
| `economy/refunds` | 无 | `order refund` | 按 `orderId` 追加，**不删原订单** |
| `economy/access-grants` | 无 | `order pay` 后 | 每 order 一份 |
| `economy/attributions` | 无 | `arcblog-attribution verify --store` | 验签通过才落；未验证折回创作者 |
| `hub/registrations` | 页面（队列 `config/hub-intents`） | `arcblog-network hub register\|refresh` | 注册幂等；`tombstone` 只增 |
| `hub/index` | 无（页面只读） | `arcblog-network hub index rebuild` | **全量覆盖**（人工策展必须落非派生树） |
| `/user/arcblog/bookmarks` | 页面（`saved`）`exec /.actions/write` | `arcblog-bookmarks add/remove` | 同 slug 覆盖；按调用者 DID 隔离 |

**⚠️【规划中】（R4）**：队列 `config/order-intents/` 与"`arcblog-economy order apply`"属 **`PRD-ECO-01` 的规划**，**今天不存在**：`node scripts/arcblog-economy.mjs --help` 无 `order apply` 子命令（只有 `policy apply`，源码 `scripts/arcblog-economy.mjs:1374`），全仓 `order-intents` **除本文档外 0 命中**。⇒ 订单的现状路径 = **仅 CLI**（`order create|pay|refund`）；**页面入队 ≠ 生效**的队列化是规划项，不得写成现状。

**14 页有写接线**（`S5-01` 实测）；**8 条队列各有唯一消费方**（见 §3/§5）。**页面写接线 = `exec "/.actions/write"` 或 `/.actions/delete`**（无此二者的页**不得**声称"页面可写"）。

## 4. 投影与只读面

| 投影 | 生成者 | 权威关系 |
| --- | --- | --- |
| **`node/factories.json`** | 链 CI/worker | **链上事实唯一权威 = `nodes.<role>`**；`factories.<role>` 是**注册表投影**（`adapter:"unknown"`、`simulationUnknown:true`），**不得**用来判"已上链" |
| `node/discovery.json` | `arcblog-network hub refresh` | 只读派生；**不得**写"已同步" |

## 6. 数据完整性与读取口径

- **必填**：`title`/`slug`/`author-did`；分类白名单从 `categories/` 读（空则回退 `technology|design|life`）；tags = 小写下划线、≤10；`coverImage`/`ogImage` 必须 http(s)。
- **索引陈旧（C1 相关）**：`afs-list` 的 `filter`/`serverFilters` 走索引，**编辑后索引条目 stale** ⇒ 影响列表的写入必须**同时刷新索引**（见 `06-运维场景手册`）。
- **分页口径**：**唯一定义 = [`04-流程 §2.1`](../03-产品设计/04-流程与跨页契约.md)（C1）**；本篇不复述。
- **`content.` 前缀探针（Stage 5 必查，见 `07 §4`）**：`store.aup:21` 现用 `filter={field:"content.visibility"}`。契约 §44.1 记载 **`content.status`/`content.category` 一律 0 命中（静默）** ⇒ 需**只读对比**（同集合用带前缀 / 不带前缀两种 `where` 比较命中数）。**在实测出结论前，本文不得断言"商店目录恒空"**。
- **append-only**：`economy/ledger` 只增不删；`deterministic id` 使按 order 读取 O(1)，全量读取须分页。
