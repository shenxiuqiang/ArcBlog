## 1. 唯一安全构建入口：`npm run build`

```jsonc
// package.json:12-14
"scrub:dist-secrets": "node scripts/arcblog-dist-secrets.mjs",
"verify:artifacts": "node scripts/arcblog-dist-secrets.mjs --check && node scripts/arcblog-dist-secrets.mjs --check --pages",
"build": "arc blocklet build && npm run scrub:dist-secrets"
```

| 入口 | 语义（`--help` 原文） | 结论 |
| --- | --- | --- |
| `arc blocklet build [dir]` | “Build Pages-ready dist/ (**copies files** + writes `.afs/manifest.json` + flat manifest)” | **整树拷贝**：仓库根有什么就拷什么 |
| `npm run build` | 上一步 + `scrub:dist-secrets` | ✅ **唯一安全入口** |

**事故（BUG-067，必须记住）**：裸 `arc blocklet build` 把仓库根的 `node.key`（Ed25519 私钥）与 `.env.local`（链助记词）**原样复制**进 `dist/`，并写进 `dist/.afs/manifest.json`；平台**没有** exclude/ignore 开关——`arc blocklet build --help` 只有 `--output` / `--dry-run` / `--clean`，`.blockletignore` 不认（`_docs/arc-contracts.md` §39(1)；[`02`](02-平台能力与边界.md) 能力 #69）。
**因此**：任何写进脚本 / 文档 / 口头交底的"构建命令"**只能是 `npm run build`**。

**擦除规则**（`scripts/arcblog-dist-secrets.mjs`）

| 规则 | 实现 | 行 |
| --- | --- | --- |
| 名字即密钥 | `SECRET_BASENAMES = {node.key, .env.local}` | `:30` |
| PEM 私钥头 | `PRIVATE_KEY_RE = /-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----/` | `:33` |
| 只看 key-ish 文件的内容 | `KEYISH_RE`（`*.key/.pem/.p12/.pfx/.jks/.keystore`、`id_*`）——避免把"记录该 bug 的文档"当泄漏删掉 | `:42` |
| 越界即拒 | `assertInside(dist, target)`：只允许 `<repo>/dist` 子树 | `:48-55` |

**两条密钥通道都要扫**（只扫 `dist/` 不够）：

```bash
$ node scripts/arcblog-dist-secrets.mjs --check            # ① dist/（缺 dist 视为失败）
$ node scripts/arcblog-dist-secrets.mjs --check --pages    # ② ~/.arc/pages/.../deployments（缺目录 = 显式 skip, rc 0）
$ npm run verify:artifacts                                 # ①② 一条命令，rc≠0 阻断发布
```

本轮实测（原样输出）：

```bash
$ node scripts/arcblog-dist-secrets.mjs --check; echo "rc=$?"
{ "action": "check", "target": ".../dist", "targetKind": "dist", "distExists": true,
  "skipped": false, "ok": true, "files": [], "privateKeyFiles": [], "manifestEntries": [] }
rc=0
```

> **铁律**（`AGENTS.md` §4）：仓库根的 `node.key` / `.env.local` **永不删 / 不移 / 不改**。清理只允许删**副本**（`dist/` 内的、或 Pages 部署目录内的）。

## 2. `.aup` 改动的生效路径（**唯一一条**，四步 + 一条读证明）

```bash
# 0) 改完 .aup 源码后
arc dsl validate --json          # issues 必须 []
arc dsl generate --write         # 重新生成 app.json / pages/*.json / locales（默认 dry-run！）
npm test                         # 快层门（漂移 / i18n / 运行时 id / 预算）——见 05 篇
npm run build                    # 只有这条会 scrub 密钥并刷新 dist/

# 1) 让 :4939（daemon 挂载的源码树）生效 —— 唯一路径
arc service restart -i default   # ← 唯一会重编译 .aup 的动作（"生效"的那一步；源须已由 --blocklet 记在实例上）
arc blocklet run . -i default    # ← 复挂：只对 AFS RPC 面 /blocklets/<name> 必需（HTTP 页面文案不依赖它）

# 2) 读证明恢复（判据不是退出码、不是 "Status: up"）
arc afs exec /blocklets/arcblog/.actions/read \
  --args '{"path":"/instance/app/arcblog/node/profile.json"}' --json

# 3) 只有需要 Pages 面时才部署
node scripts/arcblog-deploy.mjs
```

| 步 | 为什么必须 | 不做的后果 |
| --- | --- | --- |
| `validate` | DSL 主门 | 语法/引用错会带着坏页面上线 |
| `generate --write` | **默认 dry-run**，不写盘就什么都没有 | 页面/文案与源码不一致，快层的漂移门会红 |
| `npm test` | 侧栏 / i18n / 运行时 id / 预算漂移 | 生成物与源码分叉（[`05`](05-测试分层与质量门.md)） |
| `npm run build` | 刷新 `dist/` + 擦密钥 | `dist/` 陈旧（快层的 `dist-secrets` 会红）或带密钥 |
| `restart`（+ 复挂） | 平台**不是热更新**（[`02`](02-平台能力与边界.md) 能力 #70）：**只有 `restart` 会重编译 `.aup`** | 不 restart ⇒ 页面仍是**旧**文案；不**复挂** ⇒ AFS RPC 报 `No module found for path: …`（见 [`06`](06-运维场景手册.md) O1），但 HTTP 面照常 200 |
| 一条 `/instance` 读 | 唯一可信的成功判据 | `arc blocklet run` 在坏挂载下会**静默 exit 0**（[`06`](06-运维场景手册.md) O12） |

**必须知道的假象（实测，`_docs/arc-contracts.md` §35(5)）**：改 `.aup` → `generate --write` → `build` → `arc blocklet run` **连跑 3 次**、甚至 `touch` 源文件，运行中的 daemon 仍渲染**旧**页面（启动时 `Resolved AUP app blocklet "arcblog" via AFS` 缓存了 bundle，日志无 `dev watch` 事件）。
⇒ **"页面没变"不能判"改动没生效"，也不能判"已修好"**：页面/文案类验收**必须包含一次重启**。

**复现与三条排除（2026-09-30，隔离实例 + 标记法，见 [`issue #2 验证`](../team/journal/2026-09-30-issue-2-ARC_BLOCKLET_DIR-验证.md) §4）**：在 guest 可见文案上打唯一标记、用无头浏览器读 `innerText`，逐步施加「改 `.aup` 源 → `arc dsl generate --write` → `arc blocklet build` → `touch` → `arc blocklet run`×2」——**每一步都仍读到旧文案**，只有 `arc service restart` 后读到新文案（8 步阶梯表见报告 §4.4）。另两条同样被排除的"热更新"想象：

- **`ARC_BLOCKLET_DIR=/path/to/blocklet arc service start` 无效**：该环境变量在 `arc` 2.0 **已删除且被静默忽略**（`Sources: -`、`blocklets: []`、blocklet 主机 404，且**连 warning 都没有**——退役的 `ARC_HOME` 反而会 warning）。官方 [`arc service`](https://www.arcblock.io/zh/docs/arc-cli/command-reference-service/)「已删除与已退役」表明写「**`ARC_BLOCKLET_DIR` 已删除。传 `--blocklet`**」；`--blocklet` 才是现代写法，而它只把源**记在实例上**。
- **`arc deploy <path>` 的 *hot-adds if the instance is running* 不是热更新**：实测它只把注册/挂载热加进运行中的 daemon，`.aup` 不重编译（同一份输出的末行也写着 `Recorded on the instance; arc service restart … keeps it`）。

**两个"面"不要混**（[`02a`](02a-平台禁止与降级模式.md) F19/F20）

| 面 | 服务于 | 让改动生效的方式 |
| --- | --- | --- |
| **挂载面（HTTP 页面）** `http://arcblog.localhost:4939` | daemon 在 boot 时编译并服务的**源码树** | `arc service restart -i default`（源已由 `--blocklet` 记在实例上时即够）；另需 `/blocklets/<id>` 的 AFS RPC 时再补 `arc blocklet run . -i default` |
| **Pages 面** `~/.arc/pages/projects/<p>/deployments/deploy-*` | 部署历史副本 | `arc blocklet instance deploy .` |

**`instance deploy` 不会让 `:4939` 生效**；`arc service url` 显示哪个面，就按哪个面刷新。

## 3. 三类生成产物与 `dist/` 内容

### 3.1 `arc dsl generate` 的三类产物

`arc dsl generate --help` 原文：“**Generate app.json and page JSON artifacts from app.aup**”；flags：`--check`（“Fail if generated artifacts would change”，**默认 false**）、`--write`（“Rewrite generated artifacts in place”，**默认 false**）⇒ **默认 dry-run**。

| # | 产物 | 本轮实测 | 说明 |
| :-: | --- | --- | --- |
| 1 | `.aup/app.json` + `.aup/wrapper.json` | `app.json` 的 `pages` 键 = **30** | 每页的 `tree` 指向源 `.aup`；`wrapper.json` 是外壳编译树（含 `site-header`） |
| 2 | `.aup/pages/<name>.json` | **7** 个（about / author / index / page-view / preview / reader / store） | **其余 23 页运行期从 `.aup` 源编译**；`--check` 是否覆盖这 7 个之外的文件见 §7 开放问题 |
| 3 | `.aup/locales/{en,zh}.json` | 2 个文件，flat dotted key | `wrapper.*` 是**手工维护**唯一例外（`generate` 不产出、也不修剪） |

```bash
$ node -e 'const a=require("./.aup/app.json");console.log("pages=",Object.keys(a.pages||{}).length)'
pages= 30
$ ls .aup/pages/*.json | wc -l
7
$ ls .aup/locales/
en.json  zh.json
```

> **页面文件计数口径**：`.aup/pages/**/*.aup` 实测 **30**（admin 8 / site 5 / ops 5 / economy 4 / 顶层 8）——`00-架构总览.md:81` **已由 Lead 于 2026-09-30 受控修订为实测 30**（原勘误 X1 **已闭合**，见 [`07 §1.1`](07-未决技术问题与探针计划.md)）。

### 3.2 `dist/` 内容

`dist/` = **仓库根整树镜像** + 三个生成物：

```bash
$ find dist -type f | wc -l

$ node -e 'const m=require("./dist/.afs/manifest.json");console.log("keys="+Object.keys(m).join(","),"files="+m.files.length)'

package-lock.json  package.json  pages  README.md  scripts  seed  skills-lock.json  world
```

| 项 | 值 | 备注 |
| --- | --- | --- |
| `.afs/manifest.json` | **1183** 条 path | 平台产出；密钥若被拷贝会出现在这里 |
| `.afs/preflight.json`、`blocklet.dist.json` | 生成物 | 后者的挂载声明见下 |
| `dist/scripts/*.mjs` | **64** = 32 CLI + 32 测试 | **脚本与测试随包发布** ⇒ `dist/` 的密钥面更宽（[`03 §5`](03-技术选型与依赖.md) N8） |
| 不含 | `_docs/`、`node_modules/` | `dist/docs/` 存在（镜像新 `docs/`） |

**挂载声明**（`dist/blocklet.dist.json`，原样读取）：

```text
mounts     : agents/arcblog-agent → /agents/arcblog-agent ｜ pages → /pages
indexMount : pages → /
requirements.probes（4 条，均 required: true）:
  /instance/app/arcblog/posts                (list) ｜ /p/en/hero-carousel  (list)
  /instance/app/arcblog/economy/products     (list) ｜ /p/en/theme-bridge   (list)
```

> **`required: true` 是整包生死开关**：坏 mount target 会让整个 blocklet 不激活，而 `arc blocklet run` **静默 exit 0**（[`02`](02-平台能力与边界.md) 能力 #68）⇒ 激活判据**读 `/blocklets/<id>`**，绝不用退出码。

## 4. 部署与实例（Pages 面）

`arc blocklet instance deploy --help` 原文：“Deploy a **published blocklet dist/** to local Pages + bind domain” ⇒ **发布根是 `dist/`**（本轮实测取证）。
**发布根「仓库根」旧说法的真正出处 = `_docs/operations-runbook.md:868`**（原文：`arc deploy` / `arc blocklet instance deploy` treat the **repository root** as the publish root）；而 **`_docs/arc-contracts.md` §43(3) 是反向警示**（"…并且**不得**把仓库根当发布根。"）——**它与我们的实测一致，不是过时项**。本体系以 **CLI 原文/实测为准（发布根 = `dist/`）**；`_docs/**` 是只读归档、**禁止修改**，故只在此登记订正（**归属订正**：裁决 2026-09-30 首版把出处误归给 `§43(3)`，v1.1 受控修订改正；见 §7 D4）。

**唯一推荐入口 = 脚本**（四步不可乱序、不可跳过；`scripts/arcblog-deploy.mjs:10-17`）：

```bash
$ node scripts/arcblog-deploy.mjs --dry-run     # 先看它将执行什么，不改任何东西
$ node scripts/arcblog-deploy.mjs --json        # 机器可读结果
```

| 步 | 动作 | 失败模式 |
| :-: | --- | --- |
| 1 | `npm run build` | 裸 build 会带密钥（BUG-067） ⇒ 本脚本只调 `npm run build` |
| 2 | `npm run verify:artifacts` | `dist` 或 Pages 通道带密钥 ⇒ `exit 1` + 列路径 |
| 3 | `arc blocklet instance deploy . --domain arcblog.localhost` | `blocklet is not published` / 域名冲突 |
| 4 | 部署后校验：新部署无密钥 + HTTP 200 + **服务页与源码一致** | ①③④ 分别查 build 并行覆盖 / daemon 状态 / 是否有别的构建在写 `dist/` |

**脚本的边界**（`arcblog-deploy.mjs:19-26`）：**从不**碰仓库根 `node.key`/`.env.local`、不写 `dist/` 与 `~/.arc/pages` 之外、**不重启 daemon**、**不跑 live 层**。
**锁感知**：脚本在 `docs/team/.gate-lock` 存在时**告警**（`:100-102`）——它不会自动等待，需要人判断。
**构建会把锁镜像进 `dist/`**：持锁期间跑 `npm run build` ⇒ `dist/docs/team/.gate-lock` 出现，提交前必须删（`_docs/arc-contracts.md` §36(5)）。本轮实测 `dist` 无该镜像：

```bash
$ test -e dist/docs/team/.gate-lock && echo MIRROR || echo no-mirror
no-mirror
```

## 5. 运行环境：链由**环境变量**驱动（fail-closed）

**三条铁律**（[`03 §2`](03-技术选型与依赖.md)；`chain.mjs:162-279`）

1. **预设选择**：`ARCBLOG_CHAIN_ENV=beta|main` 只**填默认值**（GraphQL host / network / chain id / mint token / decimals，唯一出处 `CHAIN_PRESETS`，`chain.mjs:162-177`）。**未知值 fail-closed**（`:199-207`）。
2. **显式变量优先**：`ARCBLOG_CHAIN_HOST` / `_NETWORK` / `_CHAIN_ID` / `_TOKEN_ID` / `_TOKEN_DECIMALS`（+ `ARCBLOG_CHAIN_MNEMONIC`）**永远覆盖预设**（`:223-248`）；完整优先级 = `flag ＞ 显式 ARCBLOG_CHAIN_* ＞ config/roles.json ＞ 预设 ＞ mock 默认`（`:212-216`）。
3. **缺件 fail-closed**：`--adapter ocap` 必须先凑齐 **network + chainHost + tokenId** 三件套，再要助记词；缺任一件 ⇒ `CHAIN_UNAVAILABLE`，**不写任何记录**（`REAL_CHAIN_REQUIRED`，`:186`；`:632-643`）。预设与 `config/roles.json` 不一致 ⇒ 报 `ARCBLOG_CHAIN_ENV=… conflicts with config/roles.json`，**不允许混环境**（`:254-267`）。

**示例只写占位符（硬纪律）**——**不得**出现真实链地址或代币符号：

```bash
# 仿真（默认，不需要 npm install、不需要任何 ARCBLOG_CHAIN_*）
node scripts/arcblog-node-nft.mjs status --role studio --adapter mock

# 真链（占位符；真实值由运维从安全的密钥环境注入，永不写进仓库/页面/文档）
ARCBLOG_CHAIN_ENV=<beta|main> \
ARCBLOG_CHAIN_MNEMONIC='<mnemonic-placeholder>' \
node scripts/arcblog-chain-worker.mjs run --adapter ocap
```

| 禁止 | 依据 |
| --- | --- |
| 页面 / DSL 里出现链地址或 token symbol | [`00 §1`](00-架构总览.md) ④ 层；`CLAUDE.md` 链环境节 |
| 用 `instance deploy` 证明链配置生效 | [`02a`](02a-平台禁止与降级模式.md) F20（部署只更新 Pages 面） |
| 把 `mock` 结果写成"链上已验证" | [`02a`](02a-平台禁止与降级模式.md) F6；[`02`](02-平台能力与边界.md) 能力 #43 |
| 把真实助记词 / token id 写进本目录任何文件 | 本篇纪律；[`03 §2`](03-技术选型与依赖.md) 示例纪律 |

## 6. 命令手册（可复制）

| 命令 | 作用 | 期望结果 |
| --- | --- | --- |
| `arc dsl validate --json` | DSL 主门 | `ok: true` + `issues: []` |
| `arc dsl generate --write` | 落盘三类生成物 | 无输出即成功；`--check` 只用来看漂移（见 §7 O3） |
| `npm test` | 快层门（`05` 篇） | 全绿；`dist/` 必须存在 |
| `npm run build` | **唯一安全构建** | `dist/` 刷新 + 密钥擦除 |
| `npm run verify:artifacts` | 两通道密钥门 | rc = 0；否则列路径 |
| `arc service restart -i default` | 重启 daemon；**唯一**会重编译 `.aup` 的动作（源须已由 `--blocklet` 记在实例上） | 不 restart ⇒ 页面仍旧文案 |
| `arc blocklet run . -i default` | 复挂 AFS RPC 模块（`/blocklets/<id>`） | 只影响 AFS RPC 面；HTTP 页面不依赖它；**不是 reload 路径** |
| `arc afs exec /blocklets/arcblog/.actions/read --args '{"path":"…"}' --json` | 读证明 | 返回记录内容（root `arc afs ls` **看不到** `/instance/**`） |
| `node scripts/arcblog-deploy.mjs --dry-run` | 预演部署四步 | 打印命令，不改任何东西 |
| `node scripts/arcblog-doctor.mjs` | 实例契约体检 | 报告资源/身份/归属/残渣 |
