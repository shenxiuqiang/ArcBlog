## 4. 为什么**不**全量跑 live（四条，都可复跑验证）

1. **成本大于收益**：~21 min（R7 实测 1236 s）**大于**它检查的实现量；用户裁定 2026-09-27 起不作常规门（`CLAUDE.md` Quality gates）。
2. **非幂等**：全部写**同一个** `default` 实例；`economy/ledger` append-only（spec §92），残渣永久累积（实测 `config/trusted-hubs` 159 条、`economy/ledger` 138 条、`drafts` 46 条）。
3. **并行即污染**：必须串行 `concurrency 1`——并行时 `doctor` 约 **1/3** 概率读到别的文件半写状态（`run-tests.mjs:34-38`）。
4. **可替代**：改动触及 CLI / AFS 记录 / 链适配器 / daemon 路由 ⇒ **定向单文件**即可保住真正抓到过回归的覆盖（私钥泄漏、工厂注册表覆盖、roles 写冲突、SVG 陈旧）。

**批处理裁定（沿用）**：逐轮 QA 暂停；每轮只跑 **Lead 门（validate + 快层 + build）**，独立 QA 在**批次末统一做一次**（或人类点名）。

## 5. `test:file` + `.gate-lock`：写实例的串行纪律

```bash
# 1) 先持锁（谁要写实例测试，谁先写锁）
$ printf 'dev-doc %s\n' "$(date -u +%FT%TZ)" > docs/team/.gate-lock
# 2) 再跑一个文件（串行）
$ npm run test:file -- scripts/arcblog-media.test.mjs     # = node --test --test-concurrency=1
# 3) 跑完立刻解锁
$ rm docs/team/.gate-lock
```

| 规则 | 内容 | 理由 |
| --- | --- | --- |
| ① 互斥 | 同一时刻**只允许一个**进程使用实例 | 共享 `default` 实例，无隔离 |
| ② 先锁后跑 | 跑**写实例**测试**先**写 `docs/team/.gate-lock`（owner + 时间），跑完删除 | 后来者可判断"谁在跑" |
| ③ 见锁即等 | 锁存在就等，**不并行** | 半写状态会伪造失败 |
| ④ 快层不受锁 | `npm test`（快层）**不需要**锁 | 不写实例 |

**两个必须知道的坑**

- **锁会被镜像进 `dist/`**：持锁期间跑 `npm run build` ⇒ `dist/docs/team/.gate-lock` 出现，**提交前必须删该镜像**（`_docs/arc-contracts.md` §36(5)）。检查：`test -e dist/docs/team/.gate-lock`。
- **部署脚本只告警、不等待**：`scripts/arcblog-deploy.mjs:100-102` 检测到锁只打印一行提醒，**不阻塞** ⇒ 有锁时的部署是否继续由人判断。

> **权威归口**：本节写的是**今天必须遵守的操作纪律**；团队协作规范的**唯一定义点归 Stage 7**（[`docs/README.md`](../README.md) §6「质量门 → `07-团队与开发规范/`」）。归档期的原始约定见 `_docs/team/README.md` §6.1（**归档不是权威**，见总纲 §7）。

## 6. 如何区分"真红 / 假红"

| # | 判据 | 结论 |
| :-: | --- | --- |
| 1 | **单跑那个失败文件**：`npm run test:file -- scripts/<f>.test.mjs` | 绿 ⇒ 并发污染（**假红**）；仍红 ⇒ **真 bug** |
| 2 | 报告类型是 `TIMEOUT`（`run-tests.mjs:302-307`） | **不是**代码失败：SIGKILL 后**后续文件根本没启动**；调 `ARCBLOG_TEST_TIMEOUT_MS` 或拆文件 |
| 3 | 报告类型是 `BUDGET`（`:309-315`） | **不是**代码失败：总预算耗尽，`N file(s) were NOT run`；调 `ARCBLOG_TEST_BUDGET_MS` |
| 4 | live 失败 | runner **保留残渣**（`:322`）供检视；`ARCBLOG_NO_CLEAN=1` 主动保留，`ARCBLOG_CLEAN_DRY_RUN=1` 只报告不删 |
| 5 | 用 `npm test -- --changed` | **未登记 `GUARDS` 的套件永远被选中**（`:137-144`）——"没跑"不等于"没覆盖"，**不得**用快层的假绿替代全量 |

**一条元判据**：平台 `arc` 命令**出错时 `$?` 可能仍为 0**（[`00 §2`](00-架构总览.md) 共同铁律）⇒ 断言必须解析 JSON `success`/错误码；只有**自建 CLI** 的退出码可用。

## 8. 与 Stage 4 `_sens.sh` 的关系（**引用，不重定义**）

`docs/03-产品设计/_sens.sh` 是**判据敏感性工具**：把文档里的判据块抽出来 → 造反例副本 → 跑块，**正本必须全绿、指定反例必须红**（脚本头注：`ce1/ce2b/ce3b` 必须红，`ce2a/ce3a` 必须绿）。
它回答的问题与质量门**不同**：质量门问"**实现**有没有坏"，`_sens.sh` 问"**判据本身有没有判别力**"。

| 维度 | 质量门（本篇 §7） | `_sens.sh`（Stage 3 引入） |
| --- | --- | --- |
