## 1. 两层测试（**门 = 快层**）

| 层 | 命令 | 规模口径 | 是否写实例 | 何时跑 |
| --- | --- | --- | --- | --- |
| **快层（THE gate）** | `npm test`（= `node scripts/run-tests.mjs fast`） | **以运行输出为准**（**耗时每次不同、不写死**） | **否**（白名单内都不写实例） | **每一轮**（改了东西就跑） |
| **全量 live** | `npm run test:live` | ~**21 min**（Round 7 实测 212 pass / 0 fail / 1236 s，60 测试记录被清理） | **是**（改共享 dev 实例） | **仅人类明确要求的轮次**；**不是每轮门**（用户裁定 2026-09-27） |
| **live 层定向全审计**（2026-10-12，Lead） | 逐文件 `npm run test:file -- scripts/<f>.test.mjs`（持 `.gate-lock`、一次一个进程） | **27 个文件全跑**：settings 8 / node 18 / roles 19 / pages 10 / category 17 / tags 14 / lifecycle 6 / query-posts 8 / media 22 / audit 3 / content-hash 4 / content-sign 5 / doctor 13 / clean 7 / recipes 11 / hero-carousel 4 / rss 2 / memory-cli 2 / chain-worker 8 / node-factory-markers 5 / attribution 6 / daily-report 1 / dist-secrets 5 / node-nft 22 / node-nft-transfer 7 / agent-publish-flow 1 / agent-draft 2 / agent 29。**抓到并修掉 2 条陈旧断言**（`agent` 的 `get_studio` 参数、`clean` 的单规则不变量）⇒ 见规范 `R9`：live 套件不每轮跑，契约变更必须重推它 | **是**（写共享实例） | **每批实现收口时一次**（替代全量 `test:live` 的等价覆盖） |
| 单文件（定向） | `npm run test:file -- scripts/<file>.test.mjs` | 一个文件 | **是**（除已进快层者） | 触及 CLI / AFS 记录 / 链适配器 / daemon 路由时**替代**全量 |
| 全部 | `npm run test:all` | 快 + live | **是** | 人类明确要求 |

**计数纪律**：**文件数与用例数一律从运行输出取，不写死**。

## 3. 页面增删的连带后果（**以断言为准**：2 个真会红、1 个不会）

| 受影响物 | 断言（**已读源码**） | 后果 | 条款要求 |
| --- | --- | --- | --- |
| `scripts/arcblog-console-nav.test.mjs` | `:41` `assert.ok(path, \`console page ${name} not found under .aup/pages/\`)` | **增删行必红** | 增删行 ⇒ **必须重跑** `node scripts/arcblog-console-nav.mjs` |
| `scripts/arcblog-ui-budget.test.mjs` | `:51` `assert.equal(files.length, CONSOLE_SECTIONS.length + 1)` | **增删行必红**（等式改变） | 基线**随之调整**，取值**以测试实际输出为准**；棘轮**只降不升** |
| ~~`arcblog-runtime-ids`~~ | `:13-15` 只守 `wrapper.aup` 的 `site-header` 等 id，**不遍历页面** | **不会红** | ⚠️ **不得**把增删页写成"会让 `runtime-ids` 变红" |

> **教训（写入纪律）**：**"看起来会红的门" ≠ "真的会红的门"** ⇒ 凡把测试当作下游施工依据，**必须读断言**。
> **镜像**：**"看起来绿的门" ≠ "真的守住了"** ⇒ 还要读**断言上方的理由注释**（有意豁免 ≠ 缺陷）。

## 4. 单跑与锁纪律（`.gate-lock`）

| 项 | 规则 |
| --- | --- |
| 何时需要锁 | 跑**任何写实例**的测试（`test:live` / `test:file`）时 |
| 形态 | 先写 `docs/team/.gate-lock`，**跑完删除**（今天该文件**不存在** = 无人在跑） |
| 并发 | live 层**一次一个进程**（共享 dev 实例） |
| 替代 | 触及 CLI / AFS 记录 / 链适配器 / daemon 路由 ⇒ **定向单跑**，不跑全量 |
| 残留 | `ARCBLOG_NO_CLEAN=1` 保留现场；`npm run test:clean`（= `arcblog-clean.mjs --confirm`）手工清扫 |

## 5. 每轮必跑的命令（**门**）

```bash
$ arc dsl validate --json     # 1) DSL 校验：issues 必须 []
$ npm test                    # 2) 快层：必须 passed（文件数与耗时**从输出取**）
$ npm run build               # 3) 仅当改了 .aup / blocklet.yaml / world/**：
                              #    = arc blocklet build && npm run scrub:dist-secrets（唯一安全入口）
```
- **`npm run build` 的理由**：裸 `arc blocklet build` 会把仓库根的 `node.key`/`.env.local` 复制进 `dist/` 并写进 `dist/.afs/manifest.json`（**BUG-067**，平台**无** ignore 开关）⇒ **只用 `npm run build`**（其第二步 `scrub:dist-secrets` 是后置擦除）。
- **红门不得交接**：`issues: []` + 快层 passed 是**最低**要求。

## 8. 守卫的非空纪律（**每个守卫必须证明自己不是"空比较"**）

**为什么单列**：快层守卫的典型形状是「解析一批东西 → 把违规子集与 `[]` 比较」。这个形状有个隐蔽失效：**解析器一旦失效（正则写错、路径改名、glob 写错），比较就在空集合上运行、报告成功**——守卫永远绿着，什么都不查。2026-10-12 实测两次：`ENG-29` 的取值词表守卫把 `\b` 写成了字面反斜杠+b（**空比较**，红证明当场揭穿），以及 `visible-conditions` 原先**没有页面数下限**（页面 glob 断掉就会空过）。

**纪律**（新增守卫必须满足其一，并在注释里写明是哪一种）：

| 方式 | 例（都是可核的） |
| --- | --- |
| **显式下限** `assert.ok(x >= N)` / `> 0` | `ENG-22`（台账↔PRD）56 行、`ENG-23`（台账证据）≥56 行、运行期 id 守卫 `paginated > 0`、可见性守卫 ≥20 个页面文件 |
| **精确集合** `deepEqual(实得, 应有的完整列表)` | `console-nav` 侧栏行 = `CONSOLE_SECTIONS.length + 1`、`ui-budget` `files.length`、`theme`/`probe-verdicts` 的 id 集 |
| **正向 fixture**（喂一个**应当命中**的样本） | `dist-secrets` 的临时 dist 里必须抓到 `.env.local`+`node.key`、`visible-conditions` 与 `page-grants` 的"提取器真的看得见东西吗" |

**2026-10-12 全量元审计**（27 个快层套件逐一分类）：16 个有显式下限、4 个是精确集合、其余靠正向 fixture 或存在性断言；**发现并补齐 2 个缺口**（可见性守卫的页面数下限、台账证据守卫的 ≥56 行下限），两个都用"**把扫描面变空**"的方式证明会红（分别报 `page files scanned: 0` 与 `台账行数解析: 0`）。

> 与之配套的纪律来自 `ENG-29`：**新守卫必须先"故意弄红"再提交**；只看到绿色不算验证。
