### 2.1 U1 · `variant` prop 是否被 DSL 接受

| 项 | 内容 |
| --- | --- |
| **未验证什么** | 给侧栏容器加 `variant="nav-sidebar"` 后，(a) `arc dsl validate` 是否接受；(b) 是否落成 `data-variant`；(c) 平台 `≤640px` 断点规则是否因此命中 |
| **为什么现在验不了** | `arc dsl schema --json` 全文 `variant` **0** 次；schema 对 prop 是 `additionalProperties: true` ⇒ "过校验 + 渲染无效果"是常态；本轮无写权限 |
| **步骤（可复制）** | ① `cp .aup/pages/admin/posts.aup /tmp/u1-posts.aup.bak`；② 侧栏容器加 `variant="nav-sidebar"`（**只改一处**）；③ `arc dsl validate --json`；④ `arc dsl generate --write && npm test && npm run build`；⑤ `arc service restart -i default && arc blocklet run . -i default`；⑥ 375×812 探针读：容器是否出现 `data-variant="nav-sidebar"`、父行 computed `flex-direction`、`overflowY`；⑦ 回滚（见上方共同回滚） |
| **判定式** | **A（接受）**：`validate.issues = []` **且** DOM 出现 `data-variant="nav-sidebar"` **且** 375 下父行 `flex-direction: column` **或** `overflowY: auto`；**B（不接受）**：`validate` 报未知 prop，**或** `issues=[]` 但 DOM 无 `data-variant`（渲染无效果） |
| **A ⇒ 降级路径** | 直接采用平台 variant 与两级导航 API（`02` 能力 #33）、吃平台 `overflow-y:auto`（#32）；**删除**自写折叠方案，`03-模式 §5` 范围收窄 |
| **B ⇒ 降级路径** | 断点只能靠 **Web Device 组件写真 CSS**（`.web/` 是唯一能写 `@media` 的地方，`.aup/` 实测 0 处）+ 侧栏让出内联 `width`；**不写进设计**任何"自动折叠"承诺 |
| **阻塞对象** | `PRD-SET-04`、`03-流程 §5` 第 3/10 条、`S3-03 §5`（窄屏折叠全部方案） |

### 2.4 U12 · 已登录会话下根自定义动作是否仍拿不到 `caller`

| **为什么现在验不了** | §46.9 问题 1 **只测了匿名**；本轮禁取 cookie / 禁登录 |

| **判定式** | **A（拿得到）**：已登录时 `caller` 为非空 DID 且等于 `$session.did`；**B（拿不到）**：`caller` 缺失 / 空 / 与匿名结果相同 |
| **A ⇒ 降级路径** | 浏览器内 **per-reader 守卫**可成立（服务端拿得到读者身份） |
| **B ⇒ 降级路径** | 守卫下沉到 **CLI/worker + 意图队列**（页面只写意图）；`PRD-ECO-01 §4` 第 4 行交付义务改写为"服务端不信任浏览器声明" |
| **阻塞对象** | **`PRD-ECO-01 §4` 第 4 行交付义务**、`PRD-ECO-08 §4` |

## 4. `store.aup:21` 的 `content.` 前缀 —— **只读对比探针**（P1，最先跑）

### 4.1 现状（两个事实的冲突）

| 事实 | 证据 |
| --- | --- |
| 页面写的是**带前缀**字段：`filter={field: "content.visibility", match: public}` | `.aup/pages/store.aup:21`（原文） |
| 平台实测：`where`/`select`/`groupBy` **不得带 `content.` 前缀**，带上就**一律 0 命中且静默不报错** | `_docs/arc-contracts.md` §44.1；[`02`](02-平台能力与边界.md) 能力 #18 |

**由此推出的假设**（**假设，不是结论**）：商店目录的 `filter` 可能**恒不命中** ⇒ 目录看起来是空的。
**纪律（Lead 明确要求）**：**实测出结论前，任何文档不得断言"商店恒空"**（`01 §6`、[`06`](06-运维场景手册.md) O14 同规）。

### 4.2 探针：同集合、带/不带前缀，比较**命中数**（只读）

```bash
# 前置：确认集合里有公开商品（只读）
$ arc afs exec /blocklets/arcblog/.actions/list \
    --args '{"path":"/instance/app/arcblog/economy/products"}' --json

# A) 带前缀（复现页面写法）
$ arc afs exec /blocklets/arcblog/.actions/query \
    --args '{"path":"/instance/app/arcblog/economy/products","where":{"content.visibility":"public"}}' --json

# B) 不带前缀（契约 §44.1 的正确写法）
$ arc afs exec /blocklets/arcblog/.actions/query \
    --args '{"path":"/instance/app/arcblog/economy/products","where":{"visibility":"public"}}' --json
```

> **白名单声明**：以上三条**均为只读**（`query`/`list` 不改记录），但本轮只读白名单只放行 `arc afs exec …/.actions/{list,read}` ⇒ **A/B 两条本轮未执行**。执行时**不需要写权限、不需要重启**，只需有人放行 `.actions/query`。

**判定式**

| 结果 | 判据 | 结论与处置 |
| --- | --- | --- |
| **R1** | `count(A) == 0` **且** `count(B) > 0` | 前缀是根因 ⇒ **登记 Stage 6 缺陷候选**：把 `filter` 改为 `{field: "visibility"}` 并复验页面命中；同时按 `02` 能力 #17 检查索引 stale |
| **R2** | `count(A) == count(B) > 0` | 前缀**不是**本条根因（页面写法被容忍）⇒ 转查 `layout`/`autoSelect`/`role=item` 等渲染约束与索引 stale |
| **R3** | `count(B) == 0` | 集合里没有 `visibility:public` 的记录（或索引未内联）⇒ 先造一条公开商品再重跑；**不得**据此写"商店恒空" |
| **R4** | `count(A) > 0` **且** `count(B) > 0` 且不等 | 需要**逐条 id 对比**（`list` 差集）判断是"前缀过滤失效"还是"索引覆盖不全" |

**两条降级路径**

- **若 R1（前缀是根因）**：`store` 页改 `filter` 字段名（去掉 `content.` 前缀），并在 [`06`](06-运维场景手册.md) O14 记录修复；若改动涉及"筛选依赖索引"，同时按 `02` 能力 #17 加"目录边界 / `propBind`"退路。
- **若 R1 不成立**：**不得**改 `filter`；把重心移到索引 stale（#17）与渲染约束（#25/#26 `role=item`/`autoSelect`/行宽）——它们是同类"看起来空"的已实测成因。

**阻塞对象**：`PRD-ECO-06` A3（商店目录可用性）、[`06`](06-运维场景手册.md) O14、Stage 6 缺陷候选清单。
