## 4. `store.aup:21` 的 `content.` 前缀 —— **只读对比探针**（P1，最先跑）

### 4.1 现状（两个事实的冲突）

| 事实 | 证据 |
| --- | --- |
| 页面写的是**带前缀**字段：`filter={field: "content.visibility", match: public}` | `.aup/pages/store.aup:21`（原文） |
| 平台实测：`where`/`select`/`groupBy` **不得带 `content.` 前缀**，带上就**一律 0 命中且静默不报错** | `_docs/arc-contracts.md` §44.1；[`02`](02-平台能力与边界.md) 能力 #18 |

**由此推出的假设**（**假设，不是结论**）：商店目录的 `filter` 可能**恒不命中** ⇒ 目录看起来是空的。
**纪律（Lead 明确要求）**：**实测出结论前，任何文档不得断言"商店恒空"**（[`01 §6`](01-数据模型与存储.md)、[`06`](06-运维场景手册.md) O14 同规）。

### 4.2 探针：同集合、带/不带前缀，比较**命中数**（只读）

```bash
# 前置：确认集合里有公开商品（只读）
$ arc afs exec /blocklets/arcblog/.actions/list \
    --args '{"path":"/instance/app/arcblog/economy/products"}' --json

# A) 带前缀（复现页面写法）
$ arc afs exec /blocklets/arcblog/.actions/query \
    --args '{"path":"/instance/app/arcblog/economy/products","where":{"content.visibility":"public"}}' --json

# B) 不带前缀（契约 §44.1 的正确写法）
$ arc afs exec /blocklets/arcblog/.actions/query \
    --args '{"path":"/instance/app/arcblog/economy/products","where":{"visibility":"public"}}' --json
```

> **白名单声明**：以上三条**均为只读**（`query`/`list` 不改记录），但本轮只读白名单只放行 `arc afs exec …/.actions/{list,read}` ⇒ **A/B 两条本轮未执行**。执行时**不需要写权限、不需要重启**，只需有人放行 `.actions/query`。

**判定式**

| 结果 | 判据 | 结论与处置 |
| --- | --- | --- |
| **R1** | `count(A) == 0` **且** `count(B) > 0` | 前缀是根因 ⇒ **登记 Stage 6 缺陷候选**：把 `filter` 改为 `{field: "visibility"}` 并复验页面命中；同时按 `02` 能力 #17 检查索引 stale |
| **R2** | `count(A) == count(B) > 0` | 前缀**不是**本条根因（页面写法被容忍）⇒ 转查 `layout`/`autoSelect`/`role=item` 等渲染约束与索引 stale |
| **R3** | `count(B) == 0` | 集合里没有 `visibility:public` 的记录（或索引未内联）⇒ 先造一条公开商品再重跑；**不得**据此写"商店恒空" |
| **R4** | `count(A) > 0` **且** `count(B) > 0` 且不等 | 需要**逐条 id 对比**（`list` 差集）判断是"前缀过滤失效"还是"索引覆盖不全" |

**两条降级路径**

- **若 R1（前缀是根因）**：`store` 页改 `filter` 字段名（去掉 `content.` 前缀），并在 [`06`](06-运维场景手册.md) O14 记录修复；若改动涉及"筛选依赖索引"，同时按 `02` 能力 #17 加"目录边界 / `propBind`"退路。
- **若 R1 不成立**：**不得**改 `filter`；把重心移到索引 stale（#17）与渲染约束（#25/#26 `role=item`/`autoSelect`/行宽）——它们是同类"看起来空"的已实测成因。

**阻塞对象**：`PRD-ECO-06` A3（商店目录可用性）、[`06`](06-运维场景手册.md) O14、Stage 6 缺陷候选清单。
