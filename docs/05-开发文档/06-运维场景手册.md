## 1. 通用诊断动作（任何场景先做这四步）

```bash
# ① 面：现在服务的是哪个实例/域名
arc service list && arc service url
# ② 挂载：blocklet 是否真的在（不要看退出码）
arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"/instance/app/arcblog"}' --json
# ③ 日志：daemon 启动时间与挂载/注册失败
grep -E "Resolved AUP app blocklet|register .* failed" ~/.afs/daemon.log
# ④ 记录：AFS 前后比对（记录数 / sha256），而不是看页面提示
arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"<集合路径>"}' --json
```

| 判据 | 可信 | 不可信 |
| --- | --- | --- |
| `arc service status` = `up` | 只说明**进程**活着 | **不能**说明挂载在、页面对 |
| `arc blocklet run` 退出码 | ❌ 坏挂载下**静默 exit 0**（[`02`](02-平台能力与边界.md) 能力 #68） | 用退出码判"激活成功" |
| 一次 `/instance` 读（②） | ✅ 挂载恢复的判据 | — |
| 页面 `toast` / `title` | ❌（BUG-012 / BUG-068） | 判"写成功" |

## 2. 场景手册（14 个）

### O1 · 实例起来了但页面 404 / 所有 `/instance` 读报 `No module found`
- **症状**：`arc service status` 显示 `up`，但 `?page=posts` 404；读报 `No module found for path: /blocklets/arcblog/.actions/… in namespace 'default'`。
- **诊断**：
  ```bash
  arc service status
  arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"/instance/app/arcblog"}' --json
  ```
- **处置**：这是**复挂丢失**，不是记录坏了（`restart` 会丢掉 `/blocklets/<name>`）：
  ```bash
  arc blocklet run . -i default      # 复挂
  arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"/instance/app/arcblog"}' --json   # 读证明
  ```
- **预防**：所有重启脚本里**固定跟一条 `arc blocklet run`**；验收判据 = 读证明，**不是** `Status: up`。

### O2 · 改了 `.aup` 但页面 / 文案没变
- **症状**：改源码 + `generate --write` + `build` + `blocklet run` 之后，运行中的 daemon 仍渲染旧页面。
- **诊断**：比对 daemon 启动时间与源文件 mtime；`grep "Resolved AUP app blocklet" ~/.afs/daemon.log`（只有启动时那一行）。
- **处置**：`arc service restart -i default` + `arc blocklet run . -i default`；**`arc blocklet run` 不是 reload 路径**。
- **预防**：页面/文案类改动的验收清单**固定含一次重启**（[`04 §2`](04-构建·部署·运行.md)）。

### O3 · 部署成功了但浏览器还是旧的
- **症状**：`arc blocklet instance deploy` 成功，页面仍旧。
- **诊断**：
  ```bash
  arc service url
  # 比较部署副本与源：字节数 / 文件名
  wc -c ~/.arc/pages/projects/arcblog/deployments/<newest>/files/.aup/pages/<x>.aup .aup/pages/<x>.aup
  ```
- **处置**：确认看的是哪个面——挂载面 ⇒ `restart` + 复挂；Pages 面 ⇒ 重新 deploy；浏览器硬刷新（`Cmd+Shift+R`）。
- **预防**：两个面写清（[`04 §2`](04-构建·部署·运行.md) 表）；**不得**用"部署成功"证明"`:4939` 生效了"。

### O4 · 队列里有意图但一直没执行（**先判断是哪条队列**）
- **症状**：页面写了 `pending`，几十秒后仍是 `pending`。
- **诊断（第一步：枚举 8 条队列，找到有意图的那条）**：
  ```bash
  # 逐条查（8 条真实队列名单的唯一定义 = 01 §3）
  for q in category chain hub media page policy role-verify; do
    printf "%-14s %s\n" "$q" "$(arc afs exec /blocklets/arcblog/.actions/list \
      --args "{\"path\":\"/instance/app/arcblog/config/$q-intents\"}" --json 2>&1 | grep -c '"path"')"
  done
  arc afs exec /blocklets/arcblog/.actions/list --args '{"path":"/instance/app/arcblog/tags/intents"}' --json
  ```
  **本轮原样输出**（2026-09-30，只读）：`category 0 ｜ chain 6 ｜ hub 0 ｜ media 0 ｜ page 0 ｜ policy 4 ｜ role-verify 1`；
  `tags/intents` → `{"success": false, "error": {"code": "LIST_ERROR", "message": "Path not found: /app/arcblog/tags/intents"}}`。
  **队列目录不存在 = 0 条（或 `LIST_ERROR: Path not found`），不是错误。**
- **处置（第二步：按队列跑它的消费方；名单/命令唯一出处 = [`01 §3`](01-数据模型与存储.md)/[`01 §5`](01-数据模型与存储.md)）**：

  | 队列 | 消费命令（一次） | 长驻 |
  | --- | --- | --- |
  | `config/category-intents` | `node scripts/arcblog-category.mjs apply` | `… watch` |
  | `config/chain-intents` | `node scripts/arcblog-chain-worker.mjs run` | `… watch` |
  | `config/hub-intents` | `node scripts/arcblog-network.mjs apply` | `… watch` |
  | `config/media-intents` | `node scripts/arcblog-media.mjs apply` | `… watch` |
  | `config/page-intents` | `node scripts/arcblog-pages.mjs apply` | `… watch` |
  | `config/policy-intents` | `node scripts/arcblog-economy.mjs policy apply` | `… policy watch` |
  | `config/role-verify-intents` | `node scripts/arcblog-roles.mjs verify apply` | `… verify watch` |
  | `tags/intents` | `node scripts/arcblog-tags.mjs apply` | `… watch` |

  判据仍以 **AFS 读回**为准（终态词表见 [`01 §3`](01-数据模型与存储.md)）：意图从 `pending` 变 `applied`/`rejected`/`noop` 且带非空 `message`。
- **预防**：长驻 `watch` 与失败语义是**已知缺口**（平台无调度命令面，[`02`](02-平台能力与边界.md) 能力 #54；候选见 [`07 §6`](07-未决技术问题与探针计划.md) G1–G8 与 F1）；值班时把"谁在跑哪条 `watch`"写进交接。

### O5 · 链写失败 / 页面拿不到价格
- **症状**：`CHAIN_UNAVAILABLE`；对账 `queried:false`；order 停在 `pending`。
- **诊断**：看错误码与缺失项（缺 `ARCBLOG_CHAIN_HOST` / `_TOKEN_ID` / `_NETWORK` / `_MNEMONIC`）；见 §3 优先级。
- **处置**：补齐**安全注入**的环境变量（见 §3 占位符写法），或改 `--adapter mock` 做仿真。**order 保持 `pending`，不许留假成功。**
- **预防**：只读对账四分类必须带 `queried` 原因；`mock` 结果**永不得**写成"链上已验证"（[`02a`](02a-平台禁止与降级模式.md) F6）。

### O6 · 测试残留污染数据 / 控制台列表冒出用例记录
- **症状**：`drafts`/`economy/*`/`config/trusted-hubs` 里出现 `*-test-*` 记录；Creator Studio 列表被污染。
- **诊断**：
  ```bash
  node scripts/arcblog-clean.mjs          # 干跑：found / byDir / byPrefix / sample
  node scripts/arcblog-doctor.mjs         # 残渣体量（doctor 报 warn）
  ```
- **处置**：人审干跑结果后 `node scripts/arcblog-clean.mjs --confirm`（或 `--dir <子目录>`）。**`posts/` 与 `heroes/` 永不被扫**（已发布内容不是残渣）。
- **预防**：新测试写记录**必须**把前缀加进 `scripts/lib/doctor.mjs:108-165` 的 `TEST_RECORD_PREFIXES`，否则永久堆积（曾有 **107** 条 `lifecycle-test-*`）。

### O7 · `npm test` 红在 `dist/` 密钥门（dist 里出现密钥）
- **症状**：报错文本 `key files inside dist/ (run \`npm run scrub:dist-secrets\`)`。
- **诊断**：`node scripts/arcblog-dist-secrets.mjs --check`（输出 `files` / `privateKeyFiles` / `manifestEntries`）。
- **处置**：`npm run scrub:dist-secrets` → 再 `--check` 归零。**绝不删仓库根的源文件**（`node.key` / `.env.local` 永不删/移/改）。
- **预防**：一切构建入口只走 `npm run build`；比对 `sha256(node.key)` 前后不变。

### O8 · 发布前门红，指名 `deploy-*/files/node.key`
- **症状**：`verify:artifacts` 的 Pages 通道报密钥副本（历史 BUG-074 曾有 17–40 份真私钥；`bundle.json` 还全文内联）。
- **诊断**：`node scripts/arcblog-dist-secrets.mjs --check --pages --project arcblog`。
- **处置**：**只删副本**（需人工批准）：`rm -f ~/.arc/pages/projects/<p>/deployments/*/files/{node.key,.env.local}`，再重跑 `npm run verify:artifacts`。
- **预防**：发布前**两通道**都扫；**不要**清理历史部署或轮换 `node.key`（会破坏内容签名，除非人类批准）。

### O9 · `npm test` 报 `dist/ is missing — run 'arc blocklet build' first`
- **症状**：快层直接红，任何用例都没跑。
- **诊断**：`test -e dist/.afs/manifest.json`。
- **处置**：`npm run build`（会顺手 scrub）。
- **预防**：快层**硬依赖** `dist/` 存在且干净（[`05 §2`](05-测试分层与质量门.md)）；拉新仓库 / 清理后先 `npm run build`。

### O10 · 页面显示字面 `$t(wrapper.nav-author)` / `arc dsl lint` 报死键
- **症状**：界面上出现 `$t(...)` 原文，或 i18n 套件红在 `dead locale keys`。
- **诊断**：`arc dsl lint --json`；`grep -n '"wrapper\.' .aup/locales/zh.json`。
- **处置**：`wrapper.*` 键**只能在 `.aup/locales/{en,zh}.json` 手改**（`generate` 永不生成、不修剪）；页面键补进**渲染它的那一页**的 `i18n {}`。
- **预防**：**禁** `arc dsl lint --fix` 全量（会剥掉运行时寻址的 id）；新键在渲染它的那一页声明。

### O11 · 列表突然不渲染分页器，页面又变长
- **症状**：`afs-list` 的 `Show` 选择器与分页器消失；同页记录一次性铺开。
- **诊断**：`localStorage['aup-list-pagesize:<list id>']`（BUG-063：选到 ≥ 总数的值会**移除整个分页器**，含选择器本身）。
- **处置**：在任意页执行
  ```js
  Object.keys(localStorage).filter(k=>k.startsWith('aup-list-pagesize:')).forEach(k=>localStorage.removeItem(k))
  ```
  然后刷新。
- **预防**：探针 / 测试**每个身份每种语言用新 context**，别把共享 profile 的该键带进断言（BUG-064）。

### O12 · 挂载写错后**整站起不来**，且 `arc blocklet run` 静默 exit 0
- **症状**：站点全挂，CLI 却"成功"。
- **诊断**：读 `/blocklets/<id>`（不是退出码）；`grep 'register .* failed' ~/.afs/daemon.log`。
- **处置**：把坏挂载的 `required` 改成 `false`（降级：该挂载失败、站点照常），重建后复挂。
- **预防**：**`required: true` 是整包生死开关**；`build` **不校验** mount target（[`02`](02-平台能力与边界.md) 能力 #68；[`04 §3`](04-构建·部署·运行.md) 的 probe 表）。

### O13 · `.gate-lock` 泄漏（别人空等）或被镜像进 `dist/`
- **症状**：`docs/team/.gate-lock` 长期存在但没人在跑；或提交前发现 `dist/docs/team/.gate-lock`。
- **诊断**：
  ```bash
  cat docs/team/.gate-lock 2>/dev/null; test -e dist/docs/team/.gate-lock && echo MIRROR || echo no-mirror
  ```
- **处置**：确认无写实例任务在跑后 `rm docs/team/.gate-lock`；镜像文件直接删（它只是构建期副本）。
- **预防**：持锁者**跑完立刻删**；`npm run build` 前先解 / 跑完检查一次镜像（[`05 §5`](05-测试分层与质量门.md) 两个坑）。

### O14 · 商店目录看起来是空的（`store.aup:21` 的 `content.` 前缀疑云）
- **症状**：`/?page=store` 商品列表为空，但 `economy/products` 里确实有记录。
- **诊断**：**先跑只读对比探针**（[`07 §4`](07-未决技术问题与探针计划.md)）：同集合分别用带 `content.` 前缀与不带前缀的 `where` 比较**命中数**。
- **处置**：**实测前不得断言"商店恒空"**；按探针结果二选一：命中数相同 ⇒ 前缀不是根因（查别处）；不带前缀命中多 ⇒ 登记 Stage 6 缺陷候选并改 `filter`。
- **预防**：任何下推筛选（`filter`/`serverFilters`）都遵守"**不得带 `content.` 前缀**"（[`02`](02-平台能力与边界.md) 能力 #18）+ 编辑后索引 stale（#17）⇒ **不要用筛选做门禁**。

## 3. 链与环境（**示例只用占位符**）

**优先级（唯一出处 `scripts/lib/chain.mjs:212-216`）**：
`CLI flag ＞ 显式 ARCBLOG_CHAIN_* ＞ config/roles.json ＞ ARCBLOG_CHAIN_ENV 预设 ＞ mock 默认`

| 变量 | 作用 | 不设的后果 |
| --- | --- | --- |
| `ARCBLOG_CHAIN_ENV=<beta\|main>` | **只填默认值**（host / network / chain id / token / decimals，`CHAIN_PRESETS`） | 不选预设 ⇒ 走 mock 或要求显式变量 |
| `ARCBLOG_CHAIN_HOST` / `_NETWORK` / `_CHAIN_ID` / `_TOKEN_ID` / `_TOKEN_DECIMALS` | **显式覆盖预设**（永远优先） | 缺三件套 ⇒ `CHAIN_UNAVAILABLE` |
| `ARCBLOG_CHAIN_MNEMONIC` | 钱包助记词（**不是**三件套之一，但没有它照样拒签） | `CHAIN_UNAVAILABLE`；**记录零写入** |
| `ARCBLOG_CHAIN_ADAPTER` | 等价于 `--adapter` | 默认 `mock` |

**fail-closed 两条**：① 未知的 `ARCBLOG_CHAIN_ENV` 直接报错（不得回落）；② 预设与 `config/roles.json` 不一致 ⇒ 报 `ARCBLOG_CHAIN_ENV=… conflicts with config/roles.json (…)`，**禁止混环境**。

```bash
# 仿真（默认；不需要 npm install，不需要任何 ARCBLOG_CHAIN_*）
node scripts/arcblog-node-nft.mjs status --role studio --adapter mock

# 真链（占位符；真实值由运维从安全密钥环境注入，永不写进仓库 / 页面 / 文档）
ARCBLOG_CHAIN_ENV=<beta|main> \
ARCBLOG_CHAIN_MNEMONIC='<mnemonic-placeholder>' \
node scripts/arcblog-chain-worker.mjs run --adapter ocap

# 只读对账（判据：queried 与四分类，而不是"看起来对"）
node scripts/arcblog-economy.mjs order status --id <order-id>
```

> **硬纪律**：`.aup` / 页面 / DSL 里**不得**出现链地址或代币符号（[`00 §1`](00-架构总览.md) ④ 层）；本手册**不得**出现真实 host / token id / mnemonic。

## 4. 清理与残留

```bash
node scripts/arcblog-clean.mjs                 # 默认干跑（不删任何东西）
node scripts/arcblog-clean.mjs --confirm       # 真删（破坏性，需人审）
node scripts/arcblog-clean.mjs --dir <子目录>  # 只清一个目录
node scripts/arcblog-doctor.mjs                # 残渣体量与契约体检
```

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 清理范围 | **20 个目录**（`economy/*` 7、`config/*` 6（含 `config` 本身）、`node`、`hub/*` 2、`drafts`、`page-drafts`、`paid`、`media`）；实测 `node --input-type=module -e 'import {CLEAN_DIRS} from "./scripts/arcblog-clean.mjs";console.log(CLEAN_DIRS.length)'` → `20` | `scripts/arcblog-clean.mjs:35-66` |
