## 2. O1 · 链环境切换（beta / 主网）

| 项 | 内容 |
| --- | --- |
| **选择方式** | **由环境变量决定，绝不写在代码/页面里**：`ARCBLOG_CHAIN_ENV=beta\|main` 只**填默认值**（GraphQL host、network、chain id、mint token、decimals = `CHAIN_PRESETS`）；显式 `ARCBLOG_CHAIN_HOST\|NETWORK\|CHAIN_ID\|TOKEN_ID\|TOKEN_DECIMALS\|MNEMONIC` **总是优先**；`config/roles.json` 是唯一记录级回退 |
| **fail closed** | 记录的 `network` 与所选 preset **不一致时拒写**（不混环境）；`--adapter ocap` 在任何链写**之前**要求 **network + chainHost + tokenId** 三元组，之后仍需钱包助记词（env / `.env.local`，gitignored），否则返回 **`CHAIN_UNAVAILABLE`** |
| **测试环境** | **beta = TBA**（原文：*"The native token on beta chain is TBA"*，`scripts/lib/chain.mjs:148-158` 的注释与来源行）⇒ **`P-3` 转让可在 beta 跑，不需要真资金** |
| **禁止** | 页面/DSL 里**不得**出现链地址或代币符号；控制台只读公开投影 `node/factories.json` |
| **验证** | `node scripts/arcblog-node.mjs check`；读回 `node/factories.json` 的 `adapter`/`network` |

## 3. O2–O4 · 节点 NFT 生命周期（**已跑通的四步**）

```bash
node scripts/arcblog-node-nft.mjs acquire --role studio [--stake 1] [--endpoint <url>] [--region <r>]
node scripts/arcblog-node-nft.mjs stake   --role studio [--asset <addr>] [--waiting-period 30]
node scripts/arcblog-node-nft.mjs revoke  --role studio [--now <iso>]
node scripts/arcblog-node-nft.mjs claim   --role studio [--now <iso>]
node scripts/arcblog-node-nft.mjs status  [--role studio]
```
- 每步把**链上事实回写 AFS**：`config/node-nft.json`（asset/stake/owner/pk/endpoint/region/state/tx）+ `config/roles.json` 的**五态**（`none → acquired → staked → revoking → claimable`）。
- **`stake()` 的 receiver = 工厂地址**（`scripts/lib/chain.mjs:778-786`）⇒ 这是"**一个地址 ⇒ 全部节点**"的基础。
- ⚠️ **工厂回退**：`scripts/lib/chain.mjs:783` 在 `studio` 缺项时会回退到另一个已配置的角色工厂 ⇒ 回退一旦触发，上面那条"一个地址"的前提**不成立**（见 [`02 §3 D1`](02-平台能力与边界.md)）。
- ⚠️ **`--adapter mock` 的持久化不存在**（`config/mock-chain.json` **ABSENT**）⇒ **mock 链从未在本机跑过**；`P-1`/`P-4` 的 mock 基线**待建**。

## 5. O8 · 生成 RSS（**`B2`**）

```bash
node scripts/arcblog-rss.mjs --feed-link "$BASE" > .web-cache/rss.xml
```
| 项 | 内容 |
| --- | --- |
| **为什么必须人跑** | 平台**自动生成** `robots.txt`/`sitemap.xml`/`llms.txt`，**但不生成 RSS**（`docs/05-开发文档/附件/arc-contracts.md:448-454`，**原始证据**） |
| **写哪里** | **仓库根** `.web-cache/rss.xml`。⚠️ 写 `dist/.web-cache/` ⇒ `/p/rss.xml` **仍 404**（实测：写根目录**立即 200、无需重启**） |
| **持久性** | 根 `.web-cache/` 在 `.gitignore` ⇒ **重建/清理后需重新生成** |
| **验证** | `curl -s -o /dev/null -w '%{http_code}' /p/rss.xml` → **200**（2026-10-12 实测：生成根 `.web-cache/rss.xml` 后 **200 / application/xml / 1362 B / 3 items**；未生成时 **404**） |
| **禁止** | 界面**不得**声称"RSS 已就绪 / always on"（**`B9`** 的假绿灯；改法见 [`02a P8`](02a-平台禁止与降级模式.md)） |

## 6. O9 · 发布内容（**`B3`**：发布在应用之外）

```bash
node scripts/arcblog-lifecycle.mjs publish --title "…" --author-did did:key:z… \
  --body-file post.md --category technology --tags "a,b" [--sign-key node.key]
```
- **为什么在应用外**：AUP 应用**无运行时依赖** ⇒ 页面只能**写意图**；发布走**运营侧 CLI**。
- **可信署名**：`--sign-key node.key`（Ed25519 内容签名）；页面写入的署名落库形态**【未验证】**（[`02 B4`](02-平台能力与边界.md) / [`07`](07-未决技术问题与探针计划.md) 的 `U6`）。
- **验证**：`node scripts/arcblog-verify.mjs content --slug <x>`（内容哈希 + 签名校验）；`/posts/{slug}` 返回 200。

## 7. O10 · 构建与密钥卫生（**BUG-067**）

| 项 | 内容 |
| --- | --- |
| **唯一安全入口** | `npm run build`（= `arc blocklet build && npm run scrub:dist-secrets`） |
| **为什么** | 裸 `arc blocklet build` 会把仓库根的 **`node.key`**（Ed25519 私钥）与 **`.env.local`**（链助记词）**原样复制**进 `dist/` 并写进 `dist/.afs/manifest.json`；平台**没有** exclude/ignore 开关（`--help` 只有 `--output`/`--dry-run`/`--clean`；`.blockletignore` 不认） |
| **后置擦除** | `scrub:dist-secrets`（`scripts/arcblog-dist-secrets.mjs`）是第二步；它也**受快层** `arcblog-dist-secrets` 守卫 |
| **禁忌** | **不得删除** `node.key` / `.env.local`（丢了等于丢节点身份）；**绝不提交**、**绝不写进 AFS**；须在**仓库之外**离线备份 |
| **变更后必跑** | 改了 `.aup` / `blocklet.yaml` / `world/**` ⇒ **必须** `npm run build` |
