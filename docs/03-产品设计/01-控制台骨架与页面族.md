## 1. 统一骨架（**唯一配方**，全控制台 22 页共用）

```text
app-header(品牌 + 主题切换)                       ← 固定在滚动容器之外
view  height=100vh  overflow=visible             ← 根 view：overflow 不得为 hidden
├─ 侧栏  生成物（21 行，来自 scripts/console-nav.mjs）
└─ 内容区  唯一滚动容器
   └─ 页头卡  标题(短式) + 一句话用途 + 唯一 primary 动作
   └─ 内容卡 …（每页 1–6 张；卡片顺序 = 信息分级顺序）
```

**四条硬约束（违反即 Stage 4 截图判违规）**：① 页头/动作条**在滚动容器之外**（禁吸附/悬浮，`00-原则 §6` 第 4 条）；② 每页**恰 1 个 primary**；③ 每页**恰 1 行** `active=true`；④ **门禁卡标题 = 页头 title = 侧栏短式**（三处同名）。

**根高度规范配方（Lead 裁决 R1，2026-09-30）**：**`height: calc(100vh - 48px)` + `overflow: visible`**（48px = shell 页头高度；实测 20/22 控制台页在用）。
**2 处偏差的查证结论**：`admin/general.aup:100`、`admin/diagnostics.aup:29` 的根 `view` 写 `100vh`——**无结构性理由**：① 这两页**自身内层侧栏行仍写 `calc(100vh - 48px)`**（自相矛盾，根比内容高 48px）；② 控制台 22 页**均不含 `app-header`**（页头来自 `wrapper.aup:42`），不存在"无页头所以不用减 48"的差异。⇒ **判为历史遗留，处置 = 统一为规范配方**（登记为实现项，Stage 5/6 落地）。
**验收**：`grep -rn 'height: "100vh"' .aup/pages/` → **0**（**公开面本就不设根高度**，见 `02-公开面 §1`）。**禁止**只写"两种都有"——那是"同一事实两处定义"的病根。

**门禁标签证据（R4：过期证据已替换）**：以下两处**当前成立**，引用时必须用它们——`admin/general.aup`（**门禁写 Settings**，而**页头/侧栏是 General**——方向按 pm R11 更正）、`economy/policy.aup`（门禁写 **Economy** 而页面是 **Split policy**）。**不再引用** `S3-03` 所记的 `media.aup:8`（现已是 `Media`，证据过期）。

## 8. 响应式（**Q7 更新：平台已支持，我们未接入**）

**事实（[`S3-窄屏行为实测`](../team/reviews/S3-窄屏行为实测.md)）**：平台**已写好**响应式 CSS——`@media (max-width:640px) .aup-view[data-layout="row"]:has(> [data-variant="nav-sidebar"]){flex-direction:column}` + `[data-variant="nav-sidebar"]{width:100%;max-height:40vh;border-bottom:…}`；`≤768` 另有 `[data-mode="shell"] … [data-role="sidebar"]{display:none}`。**但** `.aup/` 内 `@media` **0** 处、`console-nav.mjs` 断点逻辑 **0**、`nav-sidebar` 命中 **0**、21 页共用**无 variant** 的同一份侧栏 ⇒ **平台规则永不命中**。侧栏 `clamp(200px,15vw,280px)` 四视口**恒为 200px**（15vw 低于下限），375 下占视口 **53%**。

| 项 | 结论 |
| --- | --- |
| **主路径（【规划中】+ 前置探针）** | 生成器（`scripts/console-nav.mjs` → 21 页）给侧栏 `view` 加 **`variant="nav-sidebar"`**（**一处改动覆盖 21 页**）。**仍属【未验证】的只有一项**：**AUP DSL 是否接受 `variant` 这个 prop**（旁证：`wrapper.aup:41 view mode=shell` → `wrapper.json` 的 `"mode":"shell"`，说明 `view` 接受会编译成 `data-*` 的语义 prop） |
| **验收（375 视口，一次 1 页探针）** | ① **侧栏实际宽度 ≈ 视口宽（不是 200px）**——内联 `width` 未让出时**必失败**；② DOM 出现 `data-variant="nav-sidebar"`，且组头走平台 `variant="nav-group"` / `text[variant~="nav-label"]`（**平台原生两级导航，不再手写折叠**）；③ 侧栏 `flex-direction: column`、位于内容**之上**；④ **默认态 5 组头同屏可见**；⑤ **滚动到底后全部行可达可点**（40vh 硬上限 ⇒ 超出必须滚动）；⑥ `sidebar.scrollWidth === sidebar.clientWidth`（条内不横滚；`overflowX` 计算值亦为 `auto`，故须独立断言） |
| **前置门** | **探针未跑不得进实现**（与 `PRD-CNT-01` 同纪律） |
| **实现前置（Lead 补充，qa 静态核查暴露）** | 平台除了 `≤640` 的样式表规则，还有**基础规则**给 `[data-variant="nav-sidebar"]` 设 `flex:0 0 min(220px,24vw)` / `width:min(220px,24vw)` / `min-width:148px` / `max-width:220px` / `max-height:calc(100vh - 3.5rem)` / `overflow-y:auto`。**而侧栏当前的宽度是页面内联** `style={width: "clamp(200px,15vw,280px)"}` —— **内联优先于样式表** ⇒ 只加 `variant` 的结果是"**堆在内容上方但仍 200px 宽**"（折叠只完成一半）。⇒ **采纳 `variant` 时必须同时移除/让出侧栏的内联宽度控制**；采纳后**宽度控制权从页面转移到平台**（区间 `min 148 / max 220`，与现行 200px 兼容，但**后续不得再改内联宽度**） |
| **平台没给的那半截** | 折叠成顶部条后只有 `max-height:40vh`，**21 项导航如何可达**（横滚 / 「更多」/ 分组）平台**未规定** ⇒ **方案与可判定验收写进 `03-模式`** |
| **640–1200 分档** | 768 若保留 200px 侧栏，内容只剩 **≈568px**（`--aup-content-max` = 1200px）⇒ "640–1200 是否也折叠"按**内容可用宽**算（**不凭感觉**），决策写进 `03-模式` |
| **公开面** | `/` 四视口**全绿**（`scrollWidth == clientWidth`、无裁切）；`site-header` **48 → 56px**（≤768）⇒ 公开面**不设根高度**（见 `02-公开面 §1`），不受 R1 影响 |
| **full-page 组合契约（登记 Stage 6）** | 平台有 full-page 组合契约，可替掉现有 `width:100vw; marginLeft:calc(50% - 50vw)` 手写全出血 hack（**实现改动**） |
| **工具缺口（登记）** | `scripts/arcblog-browser-probe.mjs` **不支持 `--viewport`**（`qa` 只能连 CDP 自行 `setDeviceMetricsOverride`）⇒ 登记为 **Stage 6 功能点候选**（在 `04-流程` 交接节）；**规范条款**：**探针测不了的项必须写明替代测法** |
| **诚实边界** | 无会话时控制台只渲染登录门 ⇒ **带侧栏几何无法在无登录下实测**；本项结论依赖**登录态探针** |
