## 2. Lead 指定的三个挑战点（结论）

### 2.1 挑战点①「`00 §3` 的 9 条废弃是否真给替代 + 落在具体篇」→ **8/9 实质合格，1 条指错篇（P1，R4）**
逐条核对替代格（`00:53-61`）：#1 → `03-模式 §5` 六条验收 + `L05` ✔；#2 → `S01+S03+S05` ✔；#3 → `N03+N05` ✔；#4 → "新写法（`03-状态与降级` 条款）" **未给条款号**（应为 S06）△；#5 → `L05` + `00-原则 §6` 第 4 条 ✔；#6 → `K4` + `S4-03 §5` ✔；#7 → `K4` ratchet 语义 ✔；#8 → **`03-模式 §2` 邻域 ✗（该节是折叠/页签，复原型规则在 `00-原则 §5 Q2`）**；#9 → `N04` + `03-模式 M15` ✔。⇒ 结论：**替代都指向了条款 ID（不是"见后续/见 Stage X"）**，这条纪律执行得比 Stage 3 好；**唯一实质缺陷是 #8 的落点错篇**——后人按替代去 `03-模式 §2` 找不到"复合原型"规则。

### 2.2 挑战点②「`07 §1` 的 39 条是否条条有正文出处」→ **无悬空条款（全部有正文），但计数错（P1，R3）**
- **逐 ID 反查**：41 个 ID 全部能在 `01`–`06` 找到正文/判据段（`for id in …; grep -l "$id" 0[1-6]-*.md` → **0 个 `NOBODY`**）：L01–L05→`01`、C01–C07+K4→`02`、S01–S08→`03`、T01–T07→`04`、V01–V06+D2→`05`、N01–N06→`06`。**空表/只列编号的问题不存在**——这条 Lead 的核验方向成立，我确认。
- **但表头与统计错**：标题"39 条"实为 **41 行**；统计"25+9+5=39"与表内不符；`07 §2` 标题"14 条"实为 17 项（R3）。
- 另：`S4-03` 的 39 条**全部被 `07 §1` 接住**（L/C/S/T/V/N 六族 ID 逐一命中，无遗漏）。

### 2.3 挑战点③「`07 §3` 的 9 条人工条款能否执行」→ **按单表不能（P1，R1）**
我按 `07 §3` 去审一页的实测结论：**可判的 5 条**——`L04`（方法里含两个等式）、`V04`（阈值 `≥4.5:1` 在 `07 §1` 条款里）、`V05`（`≥24×24` 在条款里）、`V06`（`scrollWidth-clientWidth`）、`N03`（`candidates ≥ 1 且 total = 0`）、`S08`（词集 ⊆ `INTENT_STATUSES`，从模块导入）；**判不了/需自行补标准的 3–4 条**——`T05`（"指代一致，不逐字比较"是主观判断，且 `S4-03 H9` 的"三套名字/只改一处"没搬过来）、`V03`（没说"只有颜色无文字 / 真值只在 `title`"算不合格）、`N05`（无阈值 + 对照面是归档功能清单，见 R9）、`L04`（"内容列"未给选区定义，`S4-03 H1` 有"排除 `.aup-app-header` 与含 `[data-active]` 的侧栏"）。根因 = **丢了 `S4-03 §3` 的第 5 列「什么算不合格」**（一行之差，9 条全覆盖）+ **S05/S06 两条人工判据没有落点**。
