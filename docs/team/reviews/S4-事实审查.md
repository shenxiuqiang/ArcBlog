### 2.2 Lead 点名的疑问：`BD-06` 变异是否真不变红？—— **确认不变红**，且已定位根因

```text
BEFORE: | | `BD-06` | 页内上传不可用 ⇒ 复制 CLI 命令 | 负例：无 `type="file"`/拖拽区；正例：含 `arcblog-media` | 需页面 |

```

**根因（我做出来的）**：A1 的两条 ID 正则都是

```python
r'\*\*([A-Z]{1,3}[0-9]{1,2})\*\*|`([A-Z]{1,3}[0-9]{1,2})`'
```

**不允许连字符** ⇒ 8 条 `BD-0x` 对 `defined` 与 `covered` **双向隐形**：

```text
正则匹配 **BD-06** → False ｜ `BD-06` → False ｜ **C7** → True ｜ `C7` → True
defined(cell1, 0[0-6]) = 61 ；其中 BD-0x 个数 = 0      ← 69 − 8 = 61（差正好 = BD 全族）
```

⇒ **不是"覆盖集未与表体绑定"**：`defined`/`covered` 的取数确实在解析表体（`cells[1]` / `cells[2]`），**只是正则把带连字符的 ID 全过滤掉了**。证据：我把**非连字符** ID `C7` 的反引号去掉后——

```text
A1 条款覆盖: FAIL （各篇定义 61 ｜ 总表覆盖 61 ｜ 未覆盖 1）      ← A1 能红 ✅
```

⇒ **A1 对非 `BD-*` 的 ID 是有判别力的**；盲区恰是 8 条 `BD-0x`（= 平台边界条款，Stage 4 最该守住的一族）。
