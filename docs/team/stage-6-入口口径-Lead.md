## 1. 本阶段的三件硬任务

1. **定义六态与阻塞**（**唯一定义点**）：`未开工｜开发中｜已实现待验｜已验证｜平台边界｜已废弃` + 正交阻塞；
2. **以 `PRD-<领域码>-<NN>` 为主键回填实现状态**（56 行 1:1），每行带**证据四件套**；
3. **结清两处账**：① **工具面裁剪**（19 → 13）；② **已废弃门面在台账里记「已废弃」而非「未开工」**。

## 3. 回填纪律（**最容易错的地方**）

| 纪律 | 判据 |
| --- | --- |
| **"机制存在" ≠ "本项目已接"** | 判据 = **仓库里能指到调用点/产物**。例：`listStakes` **SDK 有**、`grep -c listStakes scripts/lib/chain.mjs` = **0** ⇒ 写 **`未开工`/`开发中`**，**不得**写 `已实现待验` |
| **"跑过 ≠ 写回"** | **⚠️ 2026-10-01 受控修正（Lead 自己写严了，与 `00 §2.1` 冲突）**：本行原写"凡写 `已验证`/**`已实现待验`**，必须能指到**原样输出**"——而 `00 §2.1` 只在 **`已验证`** 要原样输出摘要，`已实现待验` 要的是「**完整调用点/产物 + 有可跑命令**」。**以 `00` 为准**（它是定稿定义点）。两处强度不同 ⇒ 执行者按哪条都"有理"，**冲突本身才是缺陷**。
> **正确的完整口径（三条一起读）**：① `已实现待验` ⇒ 须指到**调用点/产物**（`file:line` 或明确产物）**＋ 一条可跑命令**；② `已验证` ⇒ 另需**独立方署名 + 原样输出摘要 + 基线 commit**；③ **`输出=待补` 只允许出现在 `未开工`/`开发中`/`平台边界`**（**机检上限**，见 `_gate.sh` 的 `A6`）——即：**状态一旦升到 `已实现待验`，就不许再拿"待补"当证据**。 |
| **`已验证` 只由独立方给出** | 台账行有**独立验证者**署名（验证人 ≠ 实现人），且带**命令 + 解析出的 `success`/错误码 + 原始输出摘要 + 基线 commit** |
| **已废弃的门面记 `已废弃`，不记 `未开工`** | 判据：**曾经存在、现已被口径删除** ⇒ 记 `已废弃`；"还没做"才记 `未开工` |
