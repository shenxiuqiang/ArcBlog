## C. 五问（定稿草案；正文据此落笔）

### C-1 ① 是什么（**重写**）

> **主措辞（非技术；正文 `01 §1.1` 原文）**：ArcBlog 是一套任何人都能自己部署、自己拥有的博客软件——文章与读者关系都在你这里。你的节点把身份登记在同一份**链上名册**里，所以「网络上有哪些节点正在运行」是一次公开查询就能拿到的事实，而不是某家公司的目录。把这份名册读成「今天值得看什么」的是 **agent**：它替你把网络汇总好，你据此形成观点，写成自己的文章，发回自己的节点。
>
> **技术副标题（紧跟一行，不替代主措辞）**：以 DID 为身份、以 AFS 为资源层的发布型 Blocklet；节点身份 = 质押到共享 factory 地址的 studio NFT，其 `data.value` 携带 `endpoint` / `region` / `appName`；发现 = 链上注册表查询；聚合 = 运营侧 agent。

**一句话口径**：把「互相发现」落成「**一份公共名册 + 可替换的 agent**」，而不是靠彼此授予的角色。

### C-2 ② 给谁解决什么问题

| 受益人 | 今天的问题 | ArcBlog 给的东西 | 代价 |
| --- | --- | --- | --- |
| **C 创作者** | 内容与读者关系托管在别人平台上，改规则 / 关站 / 抽成时带不走 | 身份 = DID；内容在 AFS 可自托管、可迁移；读者关系不归节点 | 自托管 / 自运维；公开面受平台边界限制 |
| **O 节点运营者** | 部署了也没有「被找到」的确定性；过去靠把内容交给某个 Hub | **被找到不再需要中介**：质押到共享 factory 地址即进入公共名册；`endpoint` 写在 NFT data 里 | 需获取并质押 studio NFT；退出有等待期；**枚举侧今天仍未实现**（【规划中】） |
| **R 读者** | 读什么由平台的算法决定；想直接支持创作者还得交出身份 | 直接读节点公开面（`/posts/{slug}`、`/p/rss.xml`），或直接读 agent 汇总好的结果；可用 DID 会话保存阅读清单 | 账号体系与主流平台不同；**今天没有站内发现面** |
| **A agent 接入方**（主干） | 想读全网要写 N 套适配器；想让自己的节点被读又只能等平台收录 | 公共名册 + 统一公开读取层（`/p/`、`/mcp`、AFS `networkRead`）；agent 可自开、可替换 | agent 跑在哪、模型费谁付 = 【决策待定】；**AIGNE agent 自身无身份**，追责只能由 ArcBlog 侧承担 |
| **G 平台方 / 治理者** | 想维护的是软件与规则，不是内容池 | 软件 ≠ 网络；名册只有一份，内容池一个也没有 | 网络层可观测性只在 AFS 里（平台边界） |

**优先级【决策待定 D6】**：候选 A = 创作者为入口、**agent 接入方为第二放大器**（本阶段提议）；候选 B = 「节点运营者为第二放大器」。

### C-3 ③ 第一次完成的一件事（**主体待裁**）

- **候选 A（创作者）**：DID 登录 → 写一篇 → `URL:/posts/{slug}` → `URL:/p/rss.xml`。**今天可提交**，但**署名不可信**（页面 `exec` 把 `$session.did` 落成字面量，`compose.aup:168`）；署名可信必须走 `CLI publish`。
- **候选 B（agent 接入方，新增）**：部署节点 → 质押 studio NFT → 开 agent → 汇总 → chat → 生成 → 发布到自己的节点（= `03` J3 + J4）。**没有任何一步在浏览器里闭环**。
- **处置**：主体选择 = **【决策待定】D6**；正文必须把两个候选都写清，**不得自行拍板**。

### C-4 ④ 不可替代性（**重写**；四段论 + 诚实边界）

> **主命题：agent 把网络里值得看的汇总好，你据此形成观点并发布。**

1. **「谁被看见」不由某个平台的算法决定**：所有 studio 节点把 NFT 质押到**同一个 factory 地址**，因此 `listStakes({addressFilter:{receiver:factory}})` 一次查询 = 全部在运行的节点。**没有「The Hub」，也就没有谁能单方面决定「你能不能被发现」、或把排名卖掉。**
   - 证据：质押侧【已实现】（`scripts/lib/chain.mjs:778`，`to = factory.address`）；**枚举侧【规划中】**（`list_studios`/`get_studio` 仍是 `status:'unavailable'`，`scripts/lib/agents.mjs:74-75`；适配器与 mock 都没有 `listStakes`）。
2. **聚合权归用户，不归平台**：agent 走各节点公开面（`/p/` + 运行时 `/mcp` + AFS `networkRead`）做「多信源 → 精选 → 聚簇 → 热度」的汇总。这套形态**不是本产品的发明**——[AIHOT](https://github.com/KKKKhazix/AIHOT) 已在真实产品里跑通；**对编排不满意，任何人都可以自己再开一个**，因为节点集合是公共的。
3. **汇总不是终点，发布才是**：agent 的输出落到**你自己的** chat 与草稿；你形成观点、写新文章、发布回自己的节点（`CLI publish --sign-key`，【已实现】）。这一步把价值闭环收回 §1.2 的两条硬约束：**内容与读者关系始终在你这里**。
4. **身份与内容归属是前提，不是卖点**（既有判断：Ghost 的自托管与 AT Protocol 的身份可携带已部分覆盖它）；它的作用是让「读」与「被读」之间**不需要中介**。

**对标限定（不得省略）**：自述 8 个对标产品中 **4–5 项非一手核验** ⇒ 只能写「**据现有取证未发现**」，不得写「已证明不存在」。

**反例 c6′**：「我弄个 RSS 阅读器 + 一个大模型就够了」→ **部分成立**：阅读侧确实成立。差异只在两处：① 节点集合是**链上可枚举的公共事实**（不是一份订阅清单）；② 这条回路的终点是**发布回你自己的节点**——RSS 阅读器不给你这一端。**同时必须承认：这条回路今天未跑通**（上表）。
